# GH11 — Page Campagnes vide : « Créer la première campagne » mal encodé

Type : bug — issue #11

## Root cause

Le fichier source `apps/desktop/src/renderer/components/system/CampaignListView.tsx` contenait
littéralement du texte « mojibake » : à un moment (commit `4b81cbe`, v0.0.4), le fichier UTF-8 a
été relu comme Windows-1252 puis réenregistré en UTF-8 (avec BOM). Chaque caractère accentué
est devenu deux ou trois caractères (`é` → `Ã©`, `è` → `Ã¨`, `…` → `â€¦`). Le rendu n'était
donc pas en cause : React affichait fidèlement des chaînes déjà corrompues dans le code.

Trois chaînes visibles par l'utilisateur étaient touchées :

| Ligne | Avant                         | Après                       |
|-------|-------------------------------|-----------------------------|
| 78    | `Chargementâ€¦`               | `Chargement…`               |
| 107   | `CrÃ©er la premiÃ¨re campagne` | `Créer la première campagne` |
| 112   | `Aucun rÃ©sultat`             | `Aucun résultat`            |

Le panneau latéral (« Créer la première ») vit dans un autre fichier, qui n'a pas été touché :
d'où la différence constatée.

## Correctif

Transcodage inverse (encodage cp1252 → décodage UTF-8) appliqué uniquement aux trois chaînes
ci-dessus. Le BOM et les fins de ligne CRLF du fichier sont conservés pour garder un diff
minimal.

**commentaires** (lignes 57–71, 134–138) : aucun impact sur l'interface. À traiter dans une
issue séparée si besoin.
