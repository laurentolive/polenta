# GH117 — Vue document : erreur `getGraphBounds` au démontage d'un diagramme draw.io statique

## Symptôme

Après le démontage d'un diagramme draw.io rendu en lecture (vue document / Vue Word,
`StaticRichTextViewer` → `renderStaticDrawio`, T163), la page lève ~200 ms plus tard :

```
TypeError: Cannot read properties of null (reading 'getGraphBounds')
```

Sans effet visible pour l'utilisateur, mais l'erreur fait échouer les e2e qui contrôlent la
console (ex. `gh105-cross-repo-links.spec.ts` L4, échec intermittent).

## Root cause

Le teardown libère le graphe mxGraph alors qu'un callback de taille du viewer vendoré peut encore
tomber.

- `GraphViewer.addSizeHandler` (`public/vendor/drawio-viewer.min.js`) attache un `ResizeSensor`
  qui, avec `GraphViewer.useResizeObserver`, crée un `ResizeObserver` anonyme sur le conteneur
  `.mxgraph` — **jamais déconnecté**, debounce 200 ms. Son callback commence par
  `this.graph.getGraphBounds()` sans garde.
- `renderStaticDrawio` → `disposeViewer` (`apps/desktop/src/renderer/lib/staticDrawio.ts`)
  faisait `graph.destroy()` puis `viewer.graph = null` immédiatement.
- Au démontage, le conteneur détaché passe à 0×0 : l'observer note le changement, et 200 ms plus
  tard le callback lit `this.graph` → `null` → exception.

Le commentaire de `disposeViewer` ne prévoyait que le callback dark-mode (`matchMedia`), qui lui
garde sur `this.graph != null`. Le viewer interactif (`DrawioEmbedView`) n'est pas concerné : il
ne libère jamais le graphe.

## Correctif

`disposeViewer` (`staticDrawio.ts`) :

1. détache tout de suite le conteneur `.mxgraph` (`graph.container.remove()`) — détaché, il ne
   peut plus changer de taille, donc plus déclencher de nouveau callback ;
2. diffère `graph.destroy()` + `viewer.graph = null` de `DISPOSE_DELAY_MS` (1 s), au-delà du
   debounce de 200 ms : le dernier callback de taille trouve encore un graphe vivant (il travaille
   sur un conteneur détaché, sans effet).

Aucun changement du viewer vendoré.

  type de la démo portant un diagramme, diagramme rendu, passage en vue tableau, attente 1,5 s ;
