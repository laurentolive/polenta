# GH12 — « Nouvelle campagne » depuis le panneau : aucun test proposé

**Issue** : laurentolive/polenta#12 (doublon fermé : #35)

## Root cause

« + Nouvelle campagne » (panneau Campagnes : `SystemPanel.newCampaign()` et
`CampaignListView.newCampaign()`) ouvre `/campaign/new` en lui passant la sélection courante de
la vue système dans `component` et `level`. Or, dans ce contexte, `level` désigne le **type de
campagne** (ex. `PRODUCT_CAMP`).

`campaign.new.tsx` utilisait ce `level` pour filtrer les tests candidats
(`objectTypeRef === <component>::<level>`). Comme aucun test n'a un type de campagne, la liste
était toujours vide.

Le défaut existe depuis le commit initial. Il touche aussi le sélecteur GH33, qui reçoit les mêmes
candidats.

## Correctif appliqué

`apps/desktop/src/renderer/routes/campaign.new.tsx` : `level` ne sert de filtre que s'il
désigne un type de **test** du schéma (`getTestTypeRefs`). Dans ce cas, on filtre sur
`<component>::<level>`, ou sur `*::<level>` sans composant.

Dans les autres cas, on filtre sur le composant seul (`<component>::*`), et tous les tests sont
proposés s'il n'y a pas de composant.

Ce qui ne change pas :
- **Statut des tests** : la création propose toujours les tests de tous statuts. C'est la
  décision prise pour ce bug. L'alignement sur les seuls tests approuvés, mentionné dans le texte
  de l'issue, n'est pas fait ici.
- **Champs de la campagne** : `component` et `level` sont toujours enregistrés dans la campagne
  (filtres d'appartenance, SPEC-TESTS §4.1).
- **Préremplissage depuis l'analyse d'impact** (T46) : inchangé.

## Comment vérifier

1. Ouvrir un projet qui a des tests et un type de campagne, puis aller dans Campagnes et cliquer
   sur « + Nouvelle campagne ».
2. L'URL contient `level=<type de campagne>`. « Sélectionner des tests… » propose maintenant les
   tests du composant, de tous statuts.
3. Depuis un contexte où `level` est un type de test, seuls les tests de ce type sont proposés
   (comportement inchangé).

Vérifié dans l'application (pilotage Playwright, copie du projet `handstickProduct`). Avec
`component=root&level=PRODUCT_CAMP`, le sélecteur propose 217 tests (tous les tests `root::*`,
brouillons compris), contre 0 avant le correctif. `pnpm typecheck` : 0 erreur.
