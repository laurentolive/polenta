# GH120 — Mentions de licences tierces incomplètes dans le package desktop

## Root cause

Audit des licences des dépendances livrées (préalable à un éventuel changement de licence de
Polenta) : aucune dépendance GPL/AGPL imposée, mais trois manques de conformité aux licences
permissives elles-mêmes.

1. `DRAWIO-VIEWER-LICENSE.txt` (draw.io viewer vendorisé, T47) annonçait le texte complet de
   l'Apache-2.0 mais ne contenait qu'un lien. L'Apache-2.0 §4a impose d'en fournir une copie.
2. Aucun fichier de mentions tierces n'était livré. Le renderer est bundlé par Vite : les en-têtes
   de licence des dépendances bundlées (React, Vega…) disparaissent, alors que MIT / BSD / ISC /
   Apache exigent que la notice de copyright et le texte de licence accompagnent la copie distribuée.
3. `buffers@0.1.1` (exceljs → unzipper 0.10 → binary → buffers) ne déclare **aucune** licence
   (ni fichier, ni README, ni registre npm ; repo amont supprimé) : par défaut, tous droits réservés.

## Correctif

| Fichier | Modification |
|---|---|
| `apps/desktop/src/renderer/public/vendor/DRAWIO-VIEWER-LICENSE.txt` | texte complet de l'Apache-2.0 |
| `package.json` (racine) | `pnpm.overrides` `exceljs>unzipper: ^0.12.3` — unzipper 0.12 n'utilise plus binary/buffers (supprime aussi fstream, rimraf 2, mkdirp 0.5…) |
| `apps/desktop/scripts/generate-third-party-notices.ts` | nouveau : `THIRD-PARTY-NOTICES.txt` depuis `pnpm licenses list --prod` + fichiers vendorisés ; **échoue** si une dépendance de prod n'a pas de licence permissive (liste blanche SPDX ; `A OR B` → première option permissive retenue et indiquée) |
| `apps/desktop/package.json` | script `build:notices`, appelé par `package` ; `build:web` écrit aussi `out/web/THIRD-PARTY-NOTICES.txt` (servi par le client web) |
| `apps/desktop/electron-builder.config.ts` | `out/notices/THIRD-PARTY-NOTICES.txt` → `resources/THIRD-PARTY-NOTICES.txt` (extraResources), exclu de l'asar |

Override unzipper sans risque fonctionnel : exceljs n'utilise unzipper que dans son lecteur en flux
(`stream.xlsx.WorkbookReader`, API `unzip.Parse({forceStream})` inchangée en 0.12) ; Polenta lit
les classeurs par `workbook.xlsx.readFile` (JSZip).

Electron et Chromium restent couverts par `LICENSE.electron.txt` et `LICENSES.chromium.html`,
qu'electron-builder pose à côté de l'exécutable.

## Comment vérifier

- `pnpm --filter @polenta/desktop build:notices` → 444 paquets + 1 vendorisé, aucun refus.
- `pnpm why buffers -r` → vide.
- `pnpm --filter @polenta/desktop package` → `dist/win-unpacked/resources/THIRD-PARTY-NOTICES.txt`
  présent (vérifié : ~800 Ko, 444 entrées).
- Typecheck OK, `pnpm test` : 710/710. `check-gh49.ts` : échecs S1–S3 préexistants sur main
  (chaînes « Polenta » dans i18n/code), sans lien avec ce ticket.
