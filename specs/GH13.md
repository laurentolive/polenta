# GH13 — Rapport d'impact : tests liés par un lien test → exigence absents

Type : bug — issue #13

## Root cause

`TraceabilityService.getImpactReport` (`apps/desktop/src/main/services/traceability.service.ts`)
met d'abord en file toutes les **sources** des liens qui ciblent l'exigence, typées
`requirement`, sans distinguer un test. Avec un lien `TEST-X → SYS-Y`, `TEST-X` était donc
dépilé comme exigence et marqué visité. Comme ce n'est pas une exigence, il était ensuite
ignoré. L'entrée `test_case` ajoutée ensuite pour ce même test était sautée parce que
l'identifiant était déjà visité. Avec un lien `SYS-Y → TEST-X`, la première boucle ne
voyait pas le test (il est cible), d'où l'asymétrie.

## Correctif

- L'ensemble `tcIds` des tests est calculé avant la première boucle.
- Les deux parcours « sources de lien → exigences dépendantes » (profondeur 1 et profondeurs
  suivantes) excluent les sources qui sont des tests. Les tests restent mis en file
  uniquement par la boucle de couverture, qui suit le lien dans les deux sens, comme
  `matchCoverageLink`.

Aucun autre changement de comportement : à une profondeur > 1, les tests n'étaient déjà
pas listés, puisqu'ils étaient dépilés comme exigences introuvables.

## Vérification

- Test unitaire `apps/desktop/src/main/services/traceability.impact-report.gh13.test.ts` :
  lien test → exigence, lien exigence → test, et test + exigence dépendante. Il échoue sans
  le correctif (2/3) et passe avec.
- Manuel : créer un lien depuis l'éditeur d'un test vers `SYS-Y`, puis ouvrir le rapport
  d'impact de `SYS-Y` : le test est listé, avec son dernier résultat de run.
