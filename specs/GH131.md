# GH131 — Build du client web en échec : `@aws-sdk/client-s3` non résolu

## Symptôme

`docker build -f apps/desktop/Dockerfile.web …` échoue sur `main` (1e54ce8) dans `pnpm build:web` :

```
✘ [ERROR] Could not resolve "@aws-sdk/client-s3"
../../node_modules/.pnpm/unzipper@0.12.5/node_modules/unzipper/lib/Open/index.js:98:60
```

## Root cause

GH120 a ajouté l'override `exceljs>unzipper: ^0.12.3` (retrait de `buffers@0.1.1`, sans licence).
`unzipper` 0.12 expose une entrée `Open.s3_v3` qui fait un `require('@aws-sdk/client-s3')` à
l'appel ; ce paquet n'est pas installé. esbuild (`scripts/build-web-server.ts`, bundle complet du
serveur web) résout tous les `require` statiques et échoue. Le build desktop n'est pas touché :
electron-vite externalise les dépendances.

## Correctif

`@aws-sdk/client-s3` ajouté aux `external` de `scripts/build-web-server.ts`. Polenta n'utilise pas
l'entrée S3 d'unzipper (exceljs lit des fichiers locaux) : le `require` n'est jamais exécuté.

## Vérifier

```
docker build -f apps/desktop/Dockerfile.web --build-arg POLENTA_BRAND=polenta -t polenta-web:test .
```

passe ; l'image ainsi construite (0.1.2) sert en production l'instance déployée en mode Caddy externe
(client web en HTTP 200, connexion OIDC à la forge).
