# GH134 — Correcteur orthographique (et menu d'édition) au clic droit dans l'appli desktop

## Root cause

Electron n'affiche aucun menu contextuel si l'application n'en fournit pas. `apps/desktop/src/main/index.ts`
ne gérait pas l'événement `context-menu` du `webContents` : le correcteur orthographique de Chromium
soulignait bien les fautes, mais le clic droit n'ouvrait rien — ni suggestions, ni Couper/Copier/Coller.
Le client web n'est pas concerné (le navigateur fournit son propre menu).

## Correctif

- `apps/desktop/src/main/host/context-menu.ts` (nouveau) :
  - `buildContextMenuTemplate(params, actions)` — logique pure : sur un mot mal orthographié d'un champ
    éditable, une entrée par suggestion (ou « Aucune suggestion » désactivée) puis « Ajouter au
    dictionnaire » ; dans un champ éditable, Couper/Copier/Coller/Tout sélectionner (activés selon
    `editFlags`) ; hors champ avec une sélection, « Copier » seul ; sinon rien.
  - `attachContextMenu(win)` — branche le gabarit sur `webContents.on('context-menu')` et l'affiche
    s'il n'est pas vide.
- `apps/desktop/src/main/index.ts` : `attachContextMenu(win)` dans `createAppWindow`.
- Les menus propres à Polenta (arbre des éléments, tableaux du richtext) appellent `preventDefault`
  côté renderer : Electron n'émet alors pas `context-menu`, ils ne sont pas doublés.
- Tests : `src/main/host/context-menu.test.ts` (ajouté à `test.include` de `vitest.config.ts`).

## Vérifier

1. `pnpm --filter @polenta/desktop typecheck` et `pnpm --filter @polenta/desktop exec vitest run src/main/host`.
2. `pnpm --filter @polenta/desktop dev`, taper un mot mal orthographié dans un champ texte ou richtext,
   clic droit → suggestions + « Ajouter au dictionnaire » + commandes d'édition ; choisir une suggestion
   remplace le mot.
3. Clic droit dans une cellule de tableau du richtext et dans l'arbre → seuls les menus Polenta s'ouvrent.
4. Clic droit sur du texte sélectionné hors champ → « Copier » seul ; sur une zone vide → aucun menu.
