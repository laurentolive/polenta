# GH138 — Checkout d'une branche distante : branche locale qui la suit, pas de detached HEAD

## Symptôme

Arbre de versions → clic droit sur l'étiquette `origin/<branche>` → « Checkout branche » : le repo
passe en HEAD détaché, aucune branche locale `<branche>` n'est créée et l'édition est bloquée.

## Root cause

Le menu de branche de `routes/graph.tsx` passe le nom de l'étiquette tel quel (`origin/toolTest`) à
`api.sync.checkoutBranch`, et `SyncService.checkoutBranch()` fait `git.checkout({ ref: name })`.
Sur une ref distante, isomorphic-git détache HEAD.

## Correctif

`SyncService.checkoutBranch()` (main) se comporte comme `git switch <branche>` quand `name` est une
étiquette distante `<remote>/<branche>` (remote déclaré, `refs/remotes/<remote>/<branche>` existante,
et pas de branche locale portant littéralement ce nom) :

- branche locale absente → créée sur `origin/<branche>`, amont configuré
  (`branch.<b>.remote` / `branch.<b>.merge`), puis checkoutée ;
- branche locale présente → checkoutée **sans être déplacée** ; le résultat dit où elle en est :
  `up-to-date`, `behind`, `ahead` ou `diverged`.

La méthode renvoie désormais `CheckoutBranchResult { branch, remote?, remoteRef? }` (miroir dans
`@polenta/api-client`). Les appels existants avec un nom de branche locale sont inchangés.

Renderer (`routes/graph.tsx`) :
- l'épinglage dans les manifestes parents (T82) utilise `result.branch` (`toolTest`), plus
  l'étiquette `origin/toolTest` ;
- bandeau `RemoteCheckoutNotice` au-dessus du graphe : en retard → « Avance rapide » (merge de
  `origin/<branche>` dans la branche courante, qui est une avance rapide puisque la locale est
  ancêtre) ; en avance ou divergée → signalé, rien n'est écrasé.

Hors périmètre (« idéalement » dans l'issue) : proposer les branches distantes sans locale dans le
sélecteur de branche du panneau Version. À ouvrir en évolution si souhaité.

## Vérifier

Automatique : `src/main/services/sync.service.gh138.test.ts` (créée + amont, en retard, divergée, à
jour, branche locale avec « / »).

Manuel :
1. Poste A : créer `toolTest` depuis `main`, y faire un commit, la pousser.
2. Poste B (copie avec seulement `main` en local) : Arbre de versions → clic droit sur
   `origin/toolTest` → « Checkout branche » : `toolTest` est la branche courante (sélecteur du
   panneau Version), pas de HEAD détaché, l'édition est possible.
3. Poste A : nouveau commit poussé sur `toolTest`. Poste B : basculer sur `main`, synchroniser, puis
   « Checkout branche » sur `origin/toolTest` : bandeau « en retard » ; « Avance rapide » aligne
   `toolTest` sur `origin/toolTest`.
4. Commit local non poussé sur `toolTest` au poste B + nouveau commit au poste A : le checkout de
   `origin/toolTest` bascule sur la locale et signale la divergence ; aucun commit n'est perdu.
