# GH144 — Onglet de catégorie sans type de cette catégorie

## Root cause

`SystemViewContext.tsx`, calcul de `effectiveType` : le dernier repli était `objectTypes[0]`, sans
filtre de catégorie. Quand le composant n'a aucun type de la catégorie de l'onglet (ex. aucun type
`campaign` dans l'onglet Campagnes), le premier type du composant (une exigence) était retenu, et le
panneau comme la vue centrale affichaient ses objets. Le premier repli, par nom (`type` de l'URL),
ne filtrait pas non plus la catégorie.

## Correctif

- `effectiveType` est choisi uniquement parmi les types de la catégorie de l'onglet ; s'il n'y en a
  aucun, il vaut `undefined`.
- Nouveau composant `components/system/NoTypeForCategory.tsx` : « Aucun type « Campagnes » configuré
  pour ce composant. » et un bouton « Ouvrir le Modèle de données » (route `/schema`). Affiché par le
  panneau latéral (`SystemPanel`) et la vue (`SystemView`) quand le composant a des types mais aucun
  de cette catégorie.
- Libellés FR/EN `sidebar.system.noTypeForCategory` et `sidebar.system.openDataModel`.

## Vérification

- e2e : `e2e-web/gh144-category-without-type.spec.ts` — schéma sans type campagne : l'onglet
  Campagnes affiche le message et le bouton, aucun ID d'exigence ; le bouton ouvre `/schema`.
  L'onglet Exigences est inchangé.
- Manuel : projet dont aucun nœud n'a de type `campaign`, ouvrir l'onglet Campagnes.
