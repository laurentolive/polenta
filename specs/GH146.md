# GH146 — Campagne créée depuis l'analyse d'impact : invisible dans la liste

## Root cause

Deux défauts cumulés :

1. `/campaign/new` (`apps/desktop/src/renderer/routes/campaign.new.tsx`) gardait dans `type` le
   **nom** du type de campagne (`getAllObjectTypes(...)[0].name`) et l'écrivait tel quel dans
   `objectTypeRef`, sans le nœud (`campagne-test` au lieu de `root::campagne-test`). Depuis
   l'analyse d'impact, `component` et `level` arrivent vides (`elementSearch` de
   `impact-analysis.tsx`) et étaient écrits vides.
2. `CampaignsService.list()` écartait toute campagne sans `component` dès qu'un composant était
   sélectionné, alors que le filtre `level` prévoit déjà un repli sur `objectTypeRef` (GH59).

## Correctif

- `useProjectSchema.ts` : `getObjectTypeRefs(schema, category)` (généralise `getTestTypeRefs`,
  qui l'appelle désormais) donne la ref `<nœud>::<type>` de chaque type.
- `campaign.new.tsx` : la liste des types et `type` portent la ref complète ; `objectTypeRef` est
  donc complet. À défaut de `component` / `level` fournis, ils sont déduits du type choisi. Depuis
  le panneau Campagnes, le type correspondant à `level` est présélectionné.
- `CampaignsService.list()` : à défaut de `component`, le nœud se lit dans `objectTypeRef` ; une
  campagne sans l'un ni l'autre reste visible (même règle que `level`). Les campagnes déjà créées
  avec le défaut (ex. `CAMP-0004` de l'issue) réapparaissent sans migration.

## Comment vérifier

- Test automatique : `campaigns.service.list.test.ts` (GH146).
- Manuel : analyse d'impact → « Générer la campagne » → créer. Le fichier contient
  `objectTypeRef: root::campagne-test`, `component: root`, `level: campagne-test`, et la campagne
  est listée dans l'onglet Campagnes du composant.
