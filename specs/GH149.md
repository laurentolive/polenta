# GH149 — Statut « draft » écrit en dur à la création

## Root cause

`RequirementsService.create()` et `TestsService.create()` (`apps/desktop/src/main/services/`)
écrivaient `status: 'draft'` en dur. Ces méthodes servent à la fois l'appli (création depuis la
vue système, `req.new`, `test.new`) et le MCP (`bulk_import_requirements` / `bulk_import_tests`).
Sur un schéma dont les statuts ne contiennent pas `draft` (ex. `brouillon`, `a-valider`…), tout
objet créé portait un statut invalide, `history.status[0]` compris. Les DTO de création
(`CreateRequirementSchema`, `CreateTestCaseSchema`) n'avaient pas de champ `status`, donc le MCP
ne pouvait pas le choisir.

L'éditeur affichait déjà le premier statut du type par défaut (`EditView.tsx`,
`typeDef.statuses[0]`) : l'écart n'était visible qu'à l'écriture.

## Correctif

- `@polenta/types` : `initialStatus(typeDef)` (premier statut du type, repli `draft` si type
  introuvable ou sans statuts) et `isUnknownStatus(typeDef, status)`.
- `CreateRequirementSchema` / `CreateTestCaseSchema` : `status` facultatif.
- `RequirementsService.create` / `TestsService.create` : `dto.status ?? initialStatus(typeDef)` ;
  un statut fourni et inconnu du type est refusé (erreur).
- `validateBulkEntries` (règle 5) : un `status` inconnu du type est signalé dès le passage à blanc
  (`field: 'status'`).
- Description du tool `bulk_import_requirements` et gabarit `AGENTS.md` (v6) : le statut vient du
  schéma.

Hors périmètre : les campagnes gardent `planned` (catégorie `campaign` à statuts fixes, cf.
`packages/types/src/schema.ts`). Un statut « initial » explicite (`isInitial`) n'est pas ajouté au
schéma : l'ordre de `statuses[]` suffit et c'est déjà la règle de l'éditeur.

## Comment vérifier

- Test automatique : `apps/desktop/src/main/services/initial-status.gh149.test.ts`.
- Manuel : schéma dont le premier statut d'un type d'exigence est `brouillon` ; créer une exigence
  depuis l'appli puis via `bulk_import_requirements` (`dryRun: false`) → `status: brouillon` dans le
  YAML et dans `history.status[0]`. `bulk_import_requirements` avec `status: draft` en passage à
  blanc → erreur « statut inconnu ».
