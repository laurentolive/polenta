# GH152 — Ctrl+Z/Y/S dans l'éditeur richtext déclenchent aussi l'annulation globale de l'arbre

Issue : #152 — type `bug`. Relevé par la revue de code de GH123.

## Symptôme

Vue Exigences : après une opération sur l'arbre (création, déplacement, renommage), placer le curseur
dans un champ richtext et faire Ctrl+Z annule **aussi** l'opération sur l'arbre. Même chose pour
Ctrl+Y / Ctrl+Shift+Z (rétablir) et Ctrl+S (enregistrement de l'arbre).

## Root cause

Le gestionnaire `keydown` global de `SystemViewContext.tsx` (raccourcis de l'arbre) ne laissait passer
les raccourcis qu'en dehors d'un `INPUT` / `TEXTAREA`. L'éditeur richtext (TipTap / ProseMirror) est un
élément `contenteditable` : il n'était pas exclu, donc la touche était traitée deux fois — par l'éditeur
et par l'arbre.

## Correctif

- `isEditableTarget` (créé par GH123 dans `components/layout/sidebarCollapse.ts`) déplacé dans
  `renderer/lib/editableTarget.ts`, partagé par les deux gestionnaires : `input`, `textarea`, `select`,
  `contenteditable` (ou descendant).
- `SystemViewContext.tsx` : `if (isEditableTarget(document.activeElement)) return` remplace le test
  `INPUT`/`TEXTAREA`.

Effet de bord voulu : dans un `select` ou un `contenteditable`, Échap ne ferme plus le filtre de l'arbre —
comportement déjà en vigueur dans un `input` (dont le champ de filtre lui-même).

Pas de vérification `defaultPrevented` ajoutée : aucun autre gestionnaire ne traite Ctrl+Z/Y/S
(correctif minimal).

## Tester manuellement

1. Vue Exigences : clic droit sous l'arbre → « Créer un dossier » → Entrée.
2. Cliquer une exigence dans le tableau, puis dans son énoncé (richtext) ; taper du texte, Ctrl+Z.
3. Attendu : seul le texte est annulé, le dossier reste, le bouton ↩ reste actif.
4. Hors champ (clic sur l'arbre), Ctrl+Z → le dossier est bien annulé.
