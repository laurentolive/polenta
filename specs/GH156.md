# GH156 — App desktop 0.1.3 : crash au démarrage « Cannot find module '@aws-sdk/client-s3' »

## Symptôme

Mise à jour in-app 0.1.2 → 0.1.3 : au lancement, « A JavaScript error occurred in the main
process — Error: Cannot find module '@aws-sdk/client-s3' » (`resources\app.asar\out\main\index.js`).

## Root cause

Même origine que GH131, côté desktop cette fois. GH120 a ajouté l'override `exceljs>unzipper: ^0.12.3` ;
`unzipper` 0.12 fait un `require('@aws-sdk/client-s3')` **paresseux** dans `Open.s3_v3` (jamais
appelé : exceljs lit des fichiers locaux). Or exceljs est bundlé dans le main (exclu
d'`externalizeDepsPlugin`) : le plugin commonjs de Rollup convertit ce `require` en import et le
**remonte en tête du bundle** (`const require$$3 = require("@aws-sdk/client-s3")`, ligne 22 de
`out/main/index.js`), exécuté au boot. Le paquet n'étant pas installé, le main plante.

GH131 avait conclu à tort que le build desktop n'était pas touché : le build passe (le module non
résolu devient un `require` externe), c'est le **lancement** de l'app packagée qui échoue.

## Correctif

`apps/desktop/electron.vite.config.ts`, bundle main : `build.commonjsOptions.ignore:
['@aws-sdk/client-s3']` — le plugin commonjs laisse ce `require` intact, à sa place dans `s3_v3`,
donc jamais exécuté.

## Vérifier

1. `pnpm --filter @polenta/desktop build` puis `grep -n "@aws-sdk/client-s3" apps/desktop/out/main/index.js` :
   une seule occurrence, indentée dans `s3_v3` (`const { GetObjectCommand, HeadObjectCommand } = require(...)`),
   plus aucune en tête de fichier.
2. `pnpm --filter @polenta/desktop package`, installer `dist/Polenta-Setup-0.1.3.exe` (après avoir
   fermé toute instance de Polenta) : l'app démarre sans boîte d'erreur ; un export Excel fonctionne.
