# GH163 — Conserver le commentaire de modification

Statut : spec en attente de validation (questions en fin de document).

## Contexte

`UpdateRequirementSchema` (`packages/zod-schemas/src/requirement.schema.ts`) déclare un
`modificationComment` facultatif, mais aucun service ne le lit ni ne l'écrit : il est accepté puis
perdu, depuis l'appli comme depuis le MCP. `update_requirements` / `update_tests` (GH150) ne
l'exposent pas tant que ce ticket n'est pas traité.

L'historique des champs suivis (GH77, `history` du fichier, `HistoryEntry { value?, at, by, source? }`)
ne porte aucun texte libre aujourd'hui. Le message de commit de « Publier » regroupe toutes les
modifications d'une publication : il ne dit pas pourquoi un objet précis a changé.

## Fonctionnement proposé

1. **Stockage** : champ facultatif `comment` sur l'**entrée d'historique** créée par la modification
   (`HistoryEntry.comment`), écrit par `HistoryService.stamp` quand l'écriture ajoute au moins une
   entrée. Le commentaire est donc rattaché à un changement de valeur suivi (statut ou champ
   `trackHistory: true`).
2. **Saisie dans l'appli** : au changement de statut (formulaire, colonne Statut, bouton « Repasser en
   brouillon »), un champ « Commentaire (facultatif) ». Pas de saisie à chaque autosave d'un champ texte.
3. **MCP** : `update_requirements` / `update_tests` acceptent `modificationComment`, écrit sur les
   entrées d'historique créées par l'entrée.
4. **Lecture** : `get_history` (MCP) et l'onglet Historique de l'appli affichent le commentaire.
5. Champ ajouté à `UpdateTestCaseSchema` (même nom), `TransitionRequirementSchema.comment` réutilisé.

## Critères d'acceptation

1. Passer une exigence `approved` → `draft` avec un commentaire : l'entrée `history.status` porte
   `comment`.
2. Modification sans changement suivi (ex. champ texte non suivi) avec un commentaire : rien n'est
   écrit (documenté), pas d'erreur.
3. `update_requirements` avec `modificationComment` : commentaire présent sur les entrées créées.
4. `get_history` et l'onglet Historique affichent le commentaire.
5. Les fichiers sans commentaire sont inchangés (pas de clé `comment` vide).

## Hors scope

- Commentaire obligatoire (configurable par type) : ticket séparé si besoin.
- Commentaire sur une modification qui ne touche aucun champ suivi.

## Questions

1. **Où le conserver ?** A. Sur l'entrée d'historique (proposé ci-dessus : rattaché au changement,
   déjà daté et signé). B. Champ système `lastModificationComment` sur l'objet (écrasé à chaque fois).
   *Recommandé : A.*
2. **Quand le saisir dans l'appli ?** A. Seulement au changement de statut. B. Aussi sur un champ
   suivi modifié dans le formulaire. *Recommandé : A pour commencer.*
3. **Commentaire sans changement suivi** (MCP) : ignoré silencieusement, ou erreur explicite sur
   l'entrée ? *Recommandé : avertissement dans le résultat, pas d'erreur.*
