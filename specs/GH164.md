# GH164 — Test qui quitte le statut approuvé : version non incrémentée

## Root cause

`TestsService.update()` (`apps/desktop/src/main/services/tests.service.ts`) change le statut
(`...(dto.status && { status })`) et pose la revalidation (T172), mais n'incrémente jamais la
version. Seul `openDraft()` le faisait. Pour une exigence, `transition()` incrémente la version dès
qu'elle quitte un statut `isApproval` (T150). Les tests passant par la colonne Statut de la vue
tableau, le panneau de recherche ou `update_tests` (MCP, GH150) gardaient donc leur version.

## Correctif

Dans `update()`, même règle que `RequirementsService.transition()` : si le statut courant est
`isApproval` et que `dto.status` est différent, `version + 1`. La définition du type est lue une
seule fois et sert aussi au calcul de `leftApproval`.

## Comment vérifier

- Test : `apps/desktop/src/main/services/tests-version.gh164.test.ts`.
- Manuel : un test `approved`, colonne Statut de la vue tableau → `draft` : la version passe de N à N+1.
