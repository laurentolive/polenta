# GH167 — Le fichier `.{user}.pref` est proposé au commit git

## Root cause

`*.pref` n'est écrit dans le `.gitignore` que lorsque Polenta crée le projet
(`workspace.service.ts`) ou un nœud (`schema.service.ts`). Un repo cloné, adopté via
« ouvrir un projet existant » ou antérieur à ces écritures n'a pas la ligne : `writePref`
(`pref-store.util.ts`) crée alors un `.{user}.pref` non ignoré, que le `statusMatrix` de
`sync.service.ts` liste comme changement à committer.

## Correctif

`writePref` appelle `ensurePrefIgnored(repoPath)` avant d'écrire : ajoute `*.pref` au
`.gitignore` du repo s'il manque (crée le fichier au besoin, pas de doublon, respecte un
dernier saut de ligne absent). Même principe que `ensureCacheIgnored` pour
`tree.cache.yaml` (T156). Tous les écrivains du `.pref` passent par `writePref`.

Hors périmètre : un `.pref` **déjà commité** reste suivi (le `.gitignore` n'agit pas sur un
fichier indexé) — à retirer à la main avec `git rm --cached .<user>.pref`.

## Vérification

- Tests unitaires : `apps/desktop/src/main/services/pref-store.util.test.ts`.
- Manuel : ouvrir un repo Polenta dont le `.gitignore` ne contient pas `*.pref`, changer une
  préférence (ex. visibilité des colonnes) → `*.pref` est ajouté au `.gitignore` ; seul le
  `.gitignore` modifié apparaît dans l'écran de commit, pas le `.pref`.
