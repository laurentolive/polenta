# GH176 — Campagnes : configurer les colonnes affichées dans le sélecteur de tests

Issue : [#176](https://github.com/laurentolive/polenta/issues/176) — type `feature`

## Contexte

Le sélecteur de tests d'une campagne (`TestPickerModal`, étape 1, onglet « Tests » — GH33)
affiche les tests du type choisi dans la Vue Excel en mode sélection (`TestPickerGrid`). Ses
colonnes sont **reprises en lecture seule** des préférences Vue Excel de l'utilisateur pour ce
type (`fieldVisibility["<nœud>::<type>"].excel`), plus la colonne Statut toujours forcée (GH68).
Aucun moyen de les changer depuis la modale : pour voir une autre colonne pendant la sélection
(un champ, une colonne de liens, une colonne calculée « Dernier résultat »…), il faut fermer la
modale, aller changer la Vue Excel du type, puis revenir — et la sélection en cours est perdue.

## Besoin

Dans le sélecteur, l'utilisateur configure les colonnes affichées **comme dans la Vue Excel**
(panneau ⚙️ « Champs visibles »), sans quitter la modale et sans perdre sa sélection.

## Décision : préférence propre au sélecteur (validée)

Les colonnes du sélecteur sont une **préférence distincte** de celle de la Vue Excel, par
utilisateur et par type de test :

- tant que l'utilisateur n'a rien changé dans le sélecteur pour ce type, le sélecteur suit la
  Vue Excel (comportement GH33 actuel, y compris le défaut d'équipe `polenta-config` quand la
  Vue Excel n'a pas de choix personnel) ;
- dès qu'il change une colonne dans le sélecteur, ce choix est enregistré pour le sélecteur et
  retrouvé à la prochaine ouverture (même campagne ou autre) ;
- la Vue Excel n'est **jamais** modifiée par ce qui se fait dans le sélecteur, et inversement
  une fois le choix propre au sélecteur posé.

Alternatives écartées : partager la préférence avec la Vue Excel (on « salit » la vue de travail
avec des colonnes utiles seulement pour choisir des tests) ; choix temporaire non enregistré (à
refaire à chaque campagne).

## Comportement attendu

### Bouton et panneau

1. Un bouton ⚙️ (même icône et infobulle que dans la Vue Système) est ajouté dans la barre
   d'outils de l'onglet « Tests » de l'étape 1, à droite des options de filtre. Il est absent de
   l'onglet « Depuis une campagne » (GH64) et de l'étape 2.
2. Il ouvre un panneau « Champs visibles » au **contenu identique à celui de l'onglet Tableau**
   du panneau de la Vue Excel, pour le type de test affiché :
   - case « Afficher les titres des dossiers » (T162) ;
   - champs système et champs personnalisés du type (pas `coverageStatus`, réservé aux exigences) ;
   - colonnes calculées applicables au type, y compris colonnes éclatées en sous-colonnes
     (GH70 / GH126), avec les mêmes états « calcul en cours » / ⚠ erreur / « aucune colonne » ;
   - Étapes ;
   - colonnes de liens pertinentes pour le type ;
   - bouton « Réinitialiser ».
   Il n'a **pas** d'onglets Tableau / Document (le sélecteur n'a qu'une vue).
3. Le panneau s'affiche au-dessus de la modale, se ferme par ✕, clic à l'extérieur ou `Échap`.
   `Échap` ferme le panneau **sans** fermer la modale (même règle que le popover de filtre
   colonne, GH33).

### Effet d'un changement

4. Cocher / décocher une case met à jour la grille immédiatement : la colonne apparaît ou
   disparaît, la **sélection en cours, le filtre global, les filtres colonne, le repli des
   dossiers et les colonnes figées sont conservés**. Un filtre colonne posé sur une colonne qu'on
   masque cesse de s'appliquer (comme dans la Vue Excel).
5. Une colonne recochée reprend sa place dans l'ordre canonique du panneau (règle de la Vue Excel).
6. Une colonne calculée cochée est calculée à la demande, comme dans la Vue Excel ; ouvrir ⚙️
   lance le calcul des colonnes éclatées pour lister leurs sous-colonnes.
7. **Colonne Statut** : toujours affichée dans le sélecteur (GH68 — tous les statuts sont
   proposés). Dans le panneau, sa case est cochée et **désactivée**, avec une infobulle
   expliquant qu'elle est toujours affichée ici. Quand la liste suivie ne contient pas `status`
   (cas de la Vue Excel), elle reste insérée après `id`, comme aujourd'hui.
8. Changer de type de test dans la combobox affiche les colonnes de ce type (choix du sélecteur
   s'il existe, sinon Vue Excel). Le panneau, s'il est ouvert, se ferme.

### Persistance

9. Stockage dans le même fichier personnel `.{githubaccount}.pref`, même entrée
   `fieldVisibility["<nœud>::<type>"]`, deux nouvelles clés facultatives :
   - `picker: string[]` — colonnes du sélecteur ;
   - `showFoldersPicker: boolean` — titres de dossiers affichés dans le sélecteur.
   Clé absente ⇒ valeur reprise de la Vue Excel (`excel` / `showFoldersExcel`, ou leur défaut).
   Les deux clés sont indépendantes : changer seulement les colonnes n'écrit pas
   `showFoldersPicker`, et inversement.
10. Écrire ces clés ne modifie aucune autre clé de l'entrée (`excel`, `word`, `edit`,
    `showFolders*`, `collapsedFolders*`, `freezeColCountExcel`). Inversement, une écriture
    ultérieure depuis la Vue Système (Vue Excel ouverte dans un autre onglet, par exemple) ne doit
    **pas effacer** `picker` / `showFoldersPicker`. Point à traiter au design : aujourd'hui la Vue
    Système réécrit l'objet complet depuis une copie en mémoire.
11. **Réinitialiser** supprime `picker` et `showFoldersPicker` de l'entrée : le sélecteur suit à
    nouveau la Vue Excel du type (et ses évolutions futures). Il ne touche pas à la Vue Excel.
    (Même esprit que l'attendu de #139 pour la Vue Excel : revenir au défaut, ne pas figer une
    copie.)
12. Une clé de `picker` qui ne correspond plus à rien (champ retiré du schéma, requête supprimée
    ou rendue privée, sous-colonne disparue, type de lien supprimé) est ignorée à l'affichage et
    jamais réécrite d'elle-même — même règle que la Vue Excel.
13. Repli des dossiers et colonnes figées : inchangés (initialisés depuis la Vue Excel, locaux à
    la modale, jamais enregistrés — GH33).

### Plateformes

14. Même comportement sur le desktop et le client web (le `.pref` passe par la même API
    `pref:get-field-visibility` / `pref:set-field-visibility`).

## Critères d'acceptation

- **CA1** — Sélecteur ouvert sur un type sans choix propre : colonnes = Vue Excel du type +
  Statut (inchangé par rapport à GH33).
- **CA2** — ⚙️ ouvre un panneau listant les mêmes entrées que l'onglet Tableau de la Vue Excel
  pour ce type, sans onglets ; la case Statut est cochée et désactivée.
- **CA3** — Cocher une colonne de liens puis une colonne calculée : les deux apparaissent dans la
  grille sans perdre les cases cochées ni le filtre en cours ; le compteur « N sélectionnés… »
  est inchangé.
- **CA4** — Fermer la modale (valider ou annuler), la rouvrir (même campagne ou une autre) : les
  colonnes choisies sont toujours là. Le `.pref` contient `fieldVisibility[<type>].picker`.
- **CA5** — Après CA4, la Vue Excel du type affiche toujours ses colonnes d'origine ; sa clé
  `excel` est inchangée dans le `.pref`.
- **CA6** — Modifier ensuite les colonnes de la Vue Excel (Vue Système ouverte) : le sélecteur
  garde ses propres colonnes, et `picker` est toujours présent dans le `.pref`.
- **CA7** — « Réinitialiser » dans le sélecteur : `picker` et `showFoldersPicker` disparaissent du
  `.pref` ; le sélecteur affiche à nouveau les colonnes de la Vue Excel.
- **CA8** — Décocher « Afficher les titres des dossiers » dans le sélecteur : liste plate dans le
  sélecteur, la Vue Excel garde ses titres de dossiers.
- **CA9** — `Échap` avec le panneau ouvert ferme le panneau seulement ; un second `Échap` suit le
  comportement habituel de la modale (confirmation si la sélection a changé).
- **CA10** — Deux types de test : un choix fait sur le type A n'affecte pas le type B.
