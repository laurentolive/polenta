# GH178 — Diff en mode Rendu (bascule Raw / Rendu dans les vues de diff)

Issue : #178 · Type : feature

## 1. Contexte

Trois écrans affichent aujourd'hui le diff d'un fichier, tous en **texte ligne à ligne du YAML
brut** (`computeLineDiff`, dupliqué dans les deux routes) :

| Écran | Route | Avant | Après |
|---|---|---|---|
| Comparaison entre deux refs (panneau Version, sélecteur « Comparer ») | `/version-diff` | ref 1 (`sha1`) | ref 2 (`sha2`) |
| Modifications locales (sections Stagés / Modifications du panneau Version) | `/diff` sans `commitSha` | `HEAD` | working tree |
| Fichier d'un commit (détail d'un commit dans la vue graphe) | `/diff?commitSha=…` | parent du commit | commit |

Pour une exigence ou un test, comprendre ce qui a changé oblige à lire le YAML : champs
`richtext` en Markdown sur plusieurs lignes, blocs draw.io, étapes de test, statuts et valeurs
d'enum sous leur nom technique.

Le mode **Rendu** existe déjà dans l'éditeur de résolution de conflits (GH37 sprint 2,
`components/merge/RenderedObjectPane.tsx`), mais on ne le voit qu'au cours d'un merge en conflit.

## 2. Description fonctionnelle

Les trois écrans de diff proposent une bascule **Raw / Rendu** dans le sous-en-tête du diff (à côté
du nom du fichier et du compteur `+n / −n`).

- **Raw** : le diff texte actuel, inchangé.
- **Rendu** : l'objet affiché comme dans l'outil, sur **deux colonnes** : **Avant** à gauche,
  **Après** à droite, avec un défilement synchronisé. Chaque colonne a pour titre son côté et sa ref
  courte (`Avant · a1b2c3d`, `Après · working tree`…).

### 2.1 Fichiers concernés par le mode Rendu

Le Rendu est proposé pour :

- un fichier YAML d'**exigence** ou de **test** dont l'`objectTypeRef` se résout dans le schéma
  (§2.5) ;
- un fichier **`.drawio`** (§2.8).

Pour tout autre fichier, la bascule n'est **pas affichée** et l'écran reste en Raw : `links.yaml`,
`.polenta/**` (schéma, arbres, tombstones), `parameters.yaml`, campagnes, images, fichiers de
suivi…

Si les deux versions sont illisibles comme objet (YAML invalide, contenu qui n'est pas un objet),
le mode Rendu affiche un message « Rendu indisponible pour ce contenu — voir Raw ». La bascule reste
proposée.

### 2.2 Contenu d'une colonne

Chaque colonne reprend la présentation en lecture seule de `RenderedObjectPane` :

- titre, statut (libellé du schéma), préconditions (test), champs du schéma dans l'ordre du schéma,
  étapes (test, tableau des étapes), postconditions (test) ;
- champs présents dans les données mais absents du schéma : valeur brute ;
- autres propriétés racine (`version`, `needsRevalidation`, `jiraLinks`…) en fin de colonne, valeur
  brute ;
- `id`, `projectId`, `branchId`, `objectTypeRef` et `history` ne sont pas affichés dans les unités
  (l'ID figure dans le titre de colonne). `history` varie à chaque écriture et duplique le statut :
  il reste visible en Raw.

Libellés : statut et valeurs d'`enum` / `multi_enum` affichés par leur `label` du schéma, à défaut
par le nom technique.

### 2.3 Mise en évidence des modifications

Une **unité** (titre, statut, un champ, préconditions, étapes, postconditions, une propriété
racine) est modifiée quand sa valeur diffère entre les deux versions. Les unités sont alignées
entre les deux colonnes : la même unité est à la même hauteur des deux côtés, y compris quand elle
est absente d'un côté (emplacement vide « — absent »).

- Unité modifiée : fond **suppression** (rouge) à gauche, fond **ajout** (vert) à droite, avec les
  jetons de thème `status-danger-bg` / `status-success-bg` déjà utilisés par le diff Raw.
- Unité inchangée : affichage normal.
- Case **« Masquer les inchangés »** dans le sous-en-tête : les unités inchangées sont repliées
  en une ligne « n champs inchangés » (dépliable). L'état est mémorisé comme le mode (§2.6).

### 2.4 Diff mot à mot

À l'intérieur d'une unité modifiée :

- **Texte et richtext** (champs `text` / `richtext`, titre, préconditions, postconditions) : diff
  **mot à mot** sur le texte. Les mots supprimés sont barrés et marqués en rouge dans la colonne
  Avant, les mots ajoutés surlignés en vert dans la colonne Après. Le reste du texte garde son
  rendu normal (paragraphes, listes, gras, tableaux).
  - Un changement de mise en forme sans changement de texte (ex. passage en gras) : l'unité est
    marquée modifiée (§2.3), sans marquage mot à mot.
  - **Diagramme draw.io ou image** dans un richtext : chaque colonne affiche le diagramme ou
    l'image **à la version de la colonne** (le fichier `.drawio` / l'image référencé est lu à la ref
    Avant ou Après, à la ref du working tree pour les modifications locales), jamais la version
    courante du working tree pour les deux côtés. Le bloc est entouré d'un cadre (rouge à gauche,
    vert à droite) quand il est ajouté, retiré, que sa référence change (fichier, page/nœud,
    taille, rognage) ou que **le contenu référencé diffère** entre les deux versions (page du
    `.drawio` ou fichier image modifié), même si le texte du richtext n'a pas bougé.
    Fichier référencé absent d'une version : badge d'erreur habituel du viewer dans cette colonne.
- **Étapes de test** : alignement étape par étape. Une étape ajoutée ou retirée est marquée en
  entier, et le diff mot à mot s'applique aux cellules action / résultat attendu d'une étape
  modifiée.
- **Valeur scalaire** (enum, nombre, booléen, date, statut) : valeur entière marquée, pas de diff
  mot à mot.
- **Valeur structurée sans widget** (propriété inconnue, liste) : rendu brut YAML, unité marquée.

### 2.5 Schéma utilisé

Le type de l'objet (champs, libellés, statuts) se résout dans le **schéma de la version Après**
(`.polenta/schema.yaml` à la ref Après ; working tree pour les modifications locales). À défaut, le
schéma Avant est utilisé, puis le schéma courant du repo. La même définition sert aux deux colonnes.
Ainsi un champ ajouté au schéma entre les deux refs s'affiche à sa place dans les deux colonnes,
avec « — absent » côté Avant.

Les définitions de type d'un composant (objectTypeRef `<composant>::<type>`) se résolvent dans le
repo qui contient le fichier comparé, comme dans l'éditeur.

### 2.6 Mode par défaut et mémorisation

- Première ouverture : **Rendu** pour un fichier qui le permet.
- Ensuite, le dernier mode choisi (et l'état de « Masquer les inchangés ») est mémorisé par
  utilisateur sur ce poste (`localStorage`). Il est commun aux trois écrans, mais distinct des
  préférences de la résolution de conflits.
- Un fichier sans Rendu s'affiche en Raw sans modifier la préférence.

### 2.7 Fichier ajouté ou supprimé

- Fichier ajouté (absent côté Avant) : la colonne Avant affiche « Fichier absent de cette
  version » ; la colonne Après affiche l'objet complet, toutes les unités marquées en ajout.
- Fichier supprimé : symétrique.

### 2.8 Fichier `.drawio`

En Rendu, chaque colonne affiche le diagramme **à sa version**, rendu par le viewer draw.io en
lecture seule (même rendu que les diagrammes de la Vue Word) :

- toutes les pages du fichier, l'une sous l'autre, chacune précédée de son nom ;
- pages alignées par nom entre les deux colonnes (emplacement « — absente » quand une page n'existe
  que d'un côté) ;
- page dont le contenu diffère : cadre rouge à gauche, vert à droite ; page ajoutée / retirée :
  marquée en entier ; page identique : affichage normal (repliable par « Masquer les inchangés ») ;
- fichier ajouté / supprimé : comme §2.7 ;
- fichier illisible (XML invalide, compression inconnue) d'un côté : message « Rendu indisponible »
  dans cette colonne.

Le diff reste au niveau de la page : les formes ajoutées, retirées ou déplacées ne sont pas
marquées individuellement.

## 3. Cas d'usage

1. **Énoncé reformulé** : `statement` modifié entre deux baselines. En Rendu, l'énoncé apparaît dans
   les deux colonnes ; « 500 ms » est barré à gauche et « 300 ms » surligné à droite. Les autres
   champs ne sont pas marqués.
2. **Changement de statut** : `draft` → `review`. L'unité Statut est marquée et affiche « Brouillon »
   à gauche, « En review » à droite. Le changement de `history` n'est pas affiché.
3. **Test : étape insérée** : une étape ajoutée en position 2. Elle est marquée en vert à droite,
   avec un emplacement vide aligné à gauche. Les étapes suivantes ne sont pas marquées comme
   modifiées.
4. **Diagramme modifié** : le fichier `diagrams/power-block.drawio` référencé par l'énoncé d'une
   exigence a changé entre les deux refs, en même temps que l'exigence. Chaque colonne montre le
   diagramme de sa ref, et le cadre est rouge à gauche et vert à droite.
5. **Fichier `.drawio` seul** dans la liste des fichiers comparés : en Rendu, deux colonnes avec les
   pages rendues ; la page modifiée est encadrée.
6. **Fichier `links.yaml`** : pas de bascule, diff Raw.
7. **Modification locale non commitée** d'une exigence, ouverte depuis la section Modifications :
   Avant = `HEAD`, Après = working tree, même rendu.
8. **Commit du graphe** qui crée un test : colonne Avant « Fichier absent de cette version »,
   colonne Après = test complet marqué en ajout.

## 4. Critères d'acceptation

1. Les trois écrans (`/version-diff`, `/diff` working tree, `/diff` commit) affichent la bascule
   Raw / Rendu pour un fichier d'exigence, de test ou `.drawio`, et ne l'affichent pas pour les
   autres fichiers.
2. Le mode Raw est identique au diff actuel (mêmes lignes, mêmes compteurs `+n / −n`).
3. En Rendu, les deux colonnes sont alignées unité par unité et défilent ensemble.
4. Toute unité dont la valeur diffère est marquée, et aucune unité identique ne l'est. La seule
   exception est `history`, qui n'est pas affiché.
5. Dans un champ texte / richtext modifié, seuls les mots changés sont barrés (gauche) ou surlignés
   (droite).
6. Statuts et valeurs d'enum sont affichés par leur libellé du schéma Après.
7. Fichier ajouté / supprimé : une colonne indique l'absence, l'autre montre l'objet complet.
8. « Masquer les inchangés » replie les unités inchangées. Mode et case sont restaurés à la
   réouverture d'un diff, y compris après redémarrage de l'application.
9. Un diagramme ou une image d'un richtext est lu à la version de sa colonne : un `.drawio`
   modifié entre les deux refs s'affiche différemment dans les deux colonnes, et son bloc est
   encadré.
10. Un fichier `.drawio` en Rendu montre ses pages à chaque version ; seules les pages ajoutées,
    retirées ou modifiées sont encadrées.
11. YAML invalide d'un côté : le message « Rendu indisponible » s'affiche en Rendu, et le Raw
    fonctionne.
12. Aucune écriture dans le repo ni dans le working tree à l'affichage d'un diff.
13. Le client web (GH44) offre le même comportement (mêmes routes du renderer).

## 5. Hors scope

- Rendu des **campagnes**, de `links.yaml`, des paramètres, des arbres et des images seules (Raw
  seulement, comme la résolution de conflits — `SPEC-TECH-stack.md` §6).
- Diff **graphique** d'un diagramme draw.io (formes ajoutées / déplacées) : seuls la page ou le bloc
  entiers sont marqués.
- Mode Rendu des `.drawio` dans la résolution de conflits (GH37) : inchangé (Raw).
- Affichage des **liens** de l'objet (ils vivent dans `links.yaml`, pas dans le fichier comparé).
- Édition depuis la vue de diff (lecture seule).
- Diff d'objets entre deux repos différents.
- Avant/après de l'énoncé dans l'analyse d'impact (#145) : le diff mot à mot construit ici pourra
  y être réutilisé, mais ce ticket ne modifie pas l'analyse d'impact.
- Mode Rendu de la résolution de conflits (GH37) : inchangé.

## 6. Indicateur

Aucun nouvel indicateur : le marquage des changements est un affichage des données brutes de deux
versions, au service d'une fonction de Polenta (consulter un diff).
