# GH180 — Arbres d'affichage : rangement curaté seul (moins de conflits git)

Issue : #180 — étapes A + B de la proposition (C : format plat + rang fractionnaire,
D : merge driver sémantique → hors scope, ticket ultérieur éventuel).

## Problème

`.polenta/trees/<nœud>/<type>.yaml` changeait à presque chaque action :

1. chaque création d'objet l'écrivait (`appendToTree`, ajout en fin de `root`) → deux branches
   qui créent chacune un objet modifient la même fin de fichier → conflit systématique ;
2. l'arbre servait d'inventaire (T138) : un objet absent n'était pas affiché ;
3. chaque élément recopiait le titre de son objet (`name`).

## Comportement

**A — inventaire = fichiers objets.**
- `TreeService.get` complète l'arbre stocké avec les objets du type (`<nœud>::<type>`, index
  exigences + tests) absents du fichier : ajoutés en fin de racine, triés par ID, nœud d'id stable
  `item-<ID>` (deux lectures donnent le même arbre — pas de faux « modifié » dans l'UI).
- `RequirementsService.create` / `TestsService.create` n'écrivent plus l'arbre (côté app et MCP).
- `TreeService.save` n'écrit pas la queue de racine que `get` reconstruirait à l'identique :
  éléments sans enfant, présents une seule fois, en ordre d'ID strictement croissant. Un arbre
  sans rangement n'est pas créé sur disque.

**B — pas de titre recopié.**
- Un élément lié à un objet est stocké sans `name` ; `get` le remplit avec le `title` courant
  (repli : `name` d'un ancien fichier, puis l'ID pour un objet disparu). Les dossiers gardent
  leur `name`.
- Renderer : toute mise à jour de titre invalide la requête `['tree', repoPath]`.

**Compatibilité.** Les anciens fichiers (avec `name`, avec tous les objets) restent lisibles ; ils
sont réduits à la prochaine sauvegarde issue d'un rangement — pas de migration de masse.

## Critères d'acceptation

1. Créer un objet (UI en fin de liste, MCP) ne modifie pas `.polenta/trees/` (fichier inchangé ou
   absent).
2. Un objet présent dans `requirements/`/`tests/` mais absent de l'arbre est affiché dans la Vue
   Système / Excel / Word / impression, en fin de racine, trié par ID.
3. Ranger un objet dans un dossier ou hors ordre écrit le fichier, sans `name` sur les éléments.
4. Renommer un élément met à jour le titre de l'objet ; le libellé affiché suit le titre.
5. Un ancien fichier avec `name` s'affiche avec le titre courant de l'objet.

## Hors scope

- Format plat + rang fractionnaire (C), merge driver isomorphic-git pour les arbres (D).
- Rafraîchir en direct les libellés de la Vue Système sur une modification externe du titre
  (comportement inchangé : l'arbre affiché n'est réinitialisé qu'au changement de type).
