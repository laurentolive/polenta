# GH183 — Vue « Constellation » des exigences

Issue : #183. Maquette validée par Benoit et Laurent le 27/10 (construite sur les données réelles
d'un projet client : 54 exigences, 48 raffinements, 0 cas de test).

## Description fonctionnelle

Une vue visuelle et cliquable de l'arbre de raffinement des exigences et de sa couverture par les
tests, accessible depuis le panneau **Analyse d'impact** (entrée « Constellation des exigences »),
route `/constellation?projectId=…`.

- **Disposition** : les exigences sans parent sont au centre ; chacune ouvre un *pétale* (secteur
  angulaire) vers les exigences qui la raffinent. Avec plusieurs types d'exigence, un anneau par
  type, rangés par profondeur moyenne (ex. métier au centre, fonctionnelle, technique au bord) ;
  avec un seul type, un anneau par profondeur. Le titre de chaque racine suit l'arc de son pétale.
- **Liens** : tous les liens dont les deux extrémités sont des exigences du workspace. Par défaut
  la source d'un lien raffine sa cible ; un bouton « Inverser le sens » couvre les modèles où c'est
  l'inverse. Avec plusieurs types de lien exigence ↔ exigence, une case par type permet de les
  masquer.
- **Couverture** : une exigence terminale est couverte si `coverageStatus ≠ not_covered` (moteur de
  traçabilité). Un nœud affiche en halo doré la part des exigences terminales couvertes sous lui ;
  pointillé = aucune.
- **Couleur** : par type d'objet (défaut) ou par un champ `enum` des types d'exigence (service,
  domaine…).
- **Interaction** : survol = lignée allumée (ancêtres + descendants) et infobulle ; clic = fiche
  (statut, type, énoncé, couverture, liens groupés par libellé du schéma, bouton « Ouvrir » vers
  `/req/<id>` dans un nouvel onglet) ; clic dans le vide = vue d'ensemble. Filtre par type et
  recherche par ID / titre.
- **Indicateurs d'en-tête** : nombre d'exigences par type, liens, exigences intermédiaires non
  raffinées, % d'exigences terminales couvertes.

## Critères d'acceptation

1. La vue s'ouvre depuis le panneau Analyse d'impact et l'onglet s'intitule « Constellation ».
2. Sur un projet à trois types (métier / fonctionnelle / technique), les trois anneaux apparaissent
   dans cet ordre du centre vers le bord.
3. Une exigence couverte par un test lié affiche un halo doré ; ses parents un halo partiel.
4. Le survol d'un nœud n'allume que sa lignée ; le clic ouvre la fiche, « Ouvrir » ouvre
   l'exigence.
5. Aucune donnée n'est écrite (lecture seule) et aucun indicateur n'est stocké (GH79).
