# GH195 — Champs : type `link` {libellé | URL} et obligation conditionnelle `requiredWhen`

> Lot **1/16** du milestone « D — Conformité et gestion du changement », épique #191
> (`specs/GH191.md` §2.2, §2.3, lot L1). Modèle d'ensemble : `specs/MODELE-OBJETS.md`.
> Cette spec détaille et peut amender la spec globale. Elle ne couvre **que** les extensions
> génériques de `SchemaField`. Les `runFields` / `stepFields` (lot L2, #196) les réutiliseront.

## Contexte

- Aujourd'hui, les preuves (rapport d'essai, capture, log) sont des liens OneDrive collés dans un
  `richtext` (SPEC-TESTS §7). Ces liens ne sont pas structurés : on ne peut pas en faire une
  colonne, un champ obligatoire ou un hyperlien d'export.
- `SchemaField.required` est une obligation inconditionnelle. Il n'existe pas d'obligation qui
  dépend de la valeur d'un autre champ (« rapport obligatoire si FAIL », « justification
  obligatoire si approuvé »).

État du code (`main` @ 08cd1a7) :

- `SchemaFieldType` (`packages/types/src/schema.ts`) : 11 types, pas de type lien.
- Les types de champ sont traités au cas par cas dans : `DynamicField`, `EditView`, `ExcelView`,
  `WordView`, `DiffValue`, `objectTypeEditor` (éditeur de schéma), `exportColumns` /
  `requirements.xlsx.ts` / exports gabarit, `update-validation.util.ts` et
  `bulk-import-validation.util.ts` (contrôles d'écriture, UI et MCP), `schema-mutation.tools.ts`
  (MCP), `history.ts` (GH77), `graph.ts` + `polenta.d.ts` (graphe #74), `suivi-columns.ts`
  (colonnes calculées), `merge-resolution.service.ts` / `RenderedObjectPane` (fusion GH37).
- Le contrôle `required` à l'écriture ne porte que sur les champs présents dans l'écriture
  (`update-validation.util.ts`, « champ requis vidé ») ; à la création, sur tous les champs
  (`bulk-import-validation.util.ts`).
- Ouverture d'URL : `HostContext.openExternal` (Electron : `shell.openExternal`), absent côté
  serveur web.

## 1. Type de champ `link`

### 1.1 Déclaration

```yaml
fields:
  - name: report
    label: Rapport d'essai
    type: link
    multiple: true          # facultatif ; absent = un seul lien
    required: false
```

- Nouveau `SchemaFieldType` : `link`.
- Nouvel attribut `multiple?: boolean`, **réservé au type `link`** dans ce lot (écrit seulement
  quand vrai). L'éditeur de schéma n'affiche la case « Multiple » que pour un champ `link`.
- Disponible pour tous les types d'objet (exigence, test, campagne). Les `runFields`,
  `stepFields`, champs de revue et de décision l'auront d'office en L2 / L5, sans travail
  supplémentaire sur le type lui-même.

### 1.2 Stockage

```yaml
fields:
  datasheet: { label: Fiche cellule, url: "https://ged.example.com/docs/CELL-18650" }   # multiple absent
  report:                                                                                # multiple: true
    - { label: RE-2026-118, url: "https://ged.example.com/docs/RE-2026-118" }
    - { url: "\\\\srv-labo\\essais\\2026\\RE-2026-118-photos" }
```

- Valeur : objet `{ label?, url }`. `label` est omis quand il est vide.
- `multiple: true` : liste d'objets, ordre conservé. Liste vide = champ absent.
- Champ vide = clé absente de `fields` (comme les autres types).
- **Tolérance à la lecture** (fichier édité à la main, schéma modifié) :
  - une chaîne seule est lue comme `{ url: <chaîne> }` ;
  - un objet seul sur un champ `multiple` est lu comme une liste d'un élément ;
  - une liste sur un champ non `multiple` : on affiche tous les liens et on marque le champ ⚠
    (« plusieurs liens pour un champ simple ») ; la prochaine écriture de ce champ par l'UI ne
    garde que ce que l'utilisateur laisse.
  - on ne réécrit jamais un fichier pour le normaliser hors d'une écriture du champ.

### 1.3 Schémas d'URL acceptés

| Forme | Exemple | Accepté |
|---|---|---|
| `http://`, `https://` | `https://ged.example.com/docs/42` | oui |
| `file://` | `file:///C:/essais/RE-118.pdf` | oui |
| Chemin réseau UNC | `\\srv-labo\essais\RE-118.pdf` | oui |
| Tout le reste (`javascript:`, `mailto:`, chemin local `C:\…`, texte libre) | | **refusé** |

- Le contrôle s'applique à **toute écriture** : UI, MCP, import. Un refus nomme le champ et la
  valeur fautive (« URL refusée pour 'report' : schéma non pris en charge »).
- Le libellé est du texte libre, sans `|` ni saut de ligne (voir §1.6).
- Polenta **ne vérifie pas** que le lien répond.

### 1.4 Ouverture

| Contexte | `http(s)` | `file://` et UNC |
|---|---|---|
| Desktop | ouverture directe dans l'application par défaut (`openExternal`) | **confirmation** (« Ouvrir `<url>` avec l'application du poste ? »), puis ouverture |
| Client web | lien cliquable, nouvel onglet (`target=_blank`, `rel=noopener noreferrer`) | non cliquable ; action **« Copier »** (presse-papiers) |

- L'ouverture passe par le main process, qui **revalide** le schéma d'URL avant d'ouvrir (on ne
  fait pas confiance au renderer).
- Échec d'ouverture (UNC hors Windows, partage inaccessible) : message d'erreur non bloquant.

### 1.5 Affichage et édition

| Endroit | Lecture | Édition |
|---|---|---|
| Vue Excel (cellule) | libellé(s) cliquable(s), URL en infobulle ; plusieurs liens séparés par un retour à la ligne | popover ancré sur la cellule (même principe que `multi_enum`, T126) : une ligne par lien (libellé, URL), ajouter / supprimer / réordonner (`multiple`) |
| Vue Word | idem, en ligne | même popover |
| Vue Édition (`EditView`), formulaires (`DynamicField`) | idem | liste de lignes (libellé, URL) éditable en place |
| Diff / historique (`DiffValue`) | `libellé (URL)` par lien, ajout / retrait mis en évidence | — |
| Fusion GH37 (`RenderedObjectPane`) | idem diff | choix « mien / leur » sur le champ entier |

- Libellé vide : on affiche l'URL.
- Une URL invalide saisie est signalée sur la ligne et **bloque l'enregistrement** du champ.
- Saisie rapide : coller `libellé | URL` ou une URL seule dans le champ URL d'une ligne remplit
  les deux champs.

### 1.6 Forme texte `libellé | URL`

Forme d'échange texte d'un lien, utilisée partout où un lien passe par du texte :

- un lien : `libellé | URL`, ou `URL` seule ;
- plusieurs liens : un lien par ligne ;
- le **dernier** `|` de la ligne sépare libellé et URL (une URL peut contenir `|` encodé `%7C`,
  jamais brut) ;
- espaces autour du `|` ignorés.

Utilisée par : le collage dans la cellule Excel et dans un champ URL, l'import MCP en chaîne
(§1.8), l'export texte / docx (§1.7), le classeur d'exécution GH36 (lot L2).

### 1.7 Exports

| Export | Rendu |
|---|---|
| xlsx (`requirements.xlsx.ts`, `query-result.xlsx.ts`, `campaign.xlsx.ts`, exports gabarit xlsx) | lien unique : **hyperlien natif** (texte = libellé, cible = URL) ; plusieurs liens : texte `libellé \| URL` un par ligne (Excel ne gère qu'un hyperlien par cellule) |
| docx (gabarits, `campaign.docx.ts`) et texte / markdown | `libellé (URL)` par lien — l'URL reste lisible une fois imprimé |
| Graphe de données (#74) | valeur brute : `{ label?, url }` ou liste (§1.9) |

### 1.8 MCP

- `schema-mutation.tools.ts` : `link` dans les types acceptés, `multiple` et `requiredWhen`
  dans les attributs de champ, avec les mêmes contrôles de cohérence que l'éditeur (§2.3).
- `bulk_import_*` / mises à jour : un champ `link` accepte l'objet / la liste YAML-JSON
  **ou** la forme texte `libellé | URL` (§1.6), convertie avant écriture. Contrôle des schémas
  d'URL (§1.3) et de `requiredWhen` (§2), en `dryRun` comme en écriture.
- Lecture : valeur brute stockée (§1.2).

### 1.9 Graphe de données, colonnes calculées, historique

- `graph.ts` / `polenta.d.ts` : `'link'` ajouté aux types de champ du graphe, valeur
  `GraphLink = { label?: string; url: string }` ou `GraphLink[]`. Évolution mineure du contrat
  (ajout), documentée dans `polenta.d.ts`.
- Colonnes calculées (`suivi-columns.ts`) : une colonne calculée ne peut **pas** être de type
  `link` dans ce lot (hors périmètre, §6) ; `link` est ajouté à l'exclusion comme `drawio`.
- Historique GH77 : `trackHistory: true` est autorisé sur un champ `link`. Les entrées stockent
  la valeur (liens petits, comparables) — pas en « événement seul » comme `richtext`.

## 2. Obligation conditionnelle `requiredWhen`

### 2.1 Déclaration

```yaml
fields:
  - name: rationale
    type: richtext
    requiredWhen: { status: [approved] }
  - name: datasheet
    type: link
    requiredWhen: { safety: [true] }
```

- Nouvel attribut générique `requiredWhen?: { [champ: string]: unknown[] }`, sur tout type de
  champ.
- Le champ est obligatoire quand **au moins une** des conditions est vraie (plusieurs clés =
  OU). Une condition est vraie quand le champ de référence a l'une des valeurs listées.
- `required: true` reste l'obligation inconditionnelle ; les deux peuvent coexister (`required`
  l'emporte).

### 2.2 Champs de référence admis

| Contexte | Références admises | Livré par |
|---|---|---|
| Champs d'un type d'objet (exigence, test, campagne) | le pseudo-champ `status` (noms de statut ; statuts fixes pour une campagne), un champ `enum`, `multi_enum` ou `boolean` du **même** type | **ce lot** |
| `runFields` / `stepFields` | pseudo-champ `result` (verdict global / d'étape) | L2 (#196) |
| Champs de décision | autre champ de décision (ex. `decision`) | L5 (#204) |

- `multi_enum` de référence : condition vraie si l'**intersection** avec les valeurs listées est
  non vide.
- `boolean` de référence : valeurs `[true]` ou `[false]`.
- Le mécanisme d'évaluation est écrit **une fois** (`packages/types`), paramétré par la
  fonction qui lit la valeur du champ de référence — L2 et L5 le réutilisent tel quel.

### 2.3 Cohérence du schéma

Contrôlée par l'éditeur de schéma (message sous le champ) et à `schema:save` / mutation MCP
(refus) :

- le champ de référence existe dans le même type et est d'un type admis (§2.2) ;
- pas d'auto-référence ;
- les valeurs listées appartiennent aux valeurs du champ de référence (enum, multi_enum,
  statuts) ; une valeur inconnue est refusée ;
- liste de valeurs non vide.

Évolution ultérieure du schéma (valeur d'enum ou statut retiré, champ de référence supprimé) :
la condition devient inerte pour cette valeur / ce champ, et l'éditeur de schéma l'affiche ⚠.
Rien n'est bloqué à l'écriture des objets.

### 2.4 Contrôle à l'écriture

- **Création** (formulaire, MCP `bulk_import_*`) : toutes les conditions sont évaluées sur
  l'objet créé ; un champ obligatoire vide bloque.
- **Mise à jour** (UI, MCP) : le contrôle porte sur l'**état résultant** de l'objet, mais seulement
  pour les champs `requiredWhen` dont **le champ lui-même ou un champ de référence** fait partie de
  l'écriture. Un objet ancien qui ne respecte pas une règle ajoutée après coup reste modifiable
  sur ses autres champs (même logique que `required` aujourd'hui).
- Changement de statut (y compris depuis la liste, le menu contextuel, la vue Excel) : c'est une
  écriture du pseudo-champ `status`, donc les champs `requiredWhen: { status: […] }` sont
  contrôlés.
- Refus : l'enregistrement est bloqué, le message **nomme le champ** (libellé) et la condition
  (« « Justification » est obligatoire quand Statut = Approuvé »).
- Affichage : quand la condition est vraie dans l'état courant de l'éditeur, le champ porte
  l'astérisque `*` comme un champ `required`, mis à jour en direct quand le champ de référence
  change.
- Fusion GH37 : un `requiredWhen` non satisfait après fusion est un **avertissement**
  (`requiredEmpty`, comme `required`), pas un refus.

## 3. Cas d'usage

| # | Situation | Résultat attendu |
|---|---|---|
| U1 | Ajouter un champ `link` « Fiche technique » à un type d'exigence dans l'éditeur de schéma | le champ apparaît dans les vues Excel / Word / Édition ; schéma sauvé avec `type: link` |
| U2 | Saisir un lien `https://…` avec libellé dans la vue Excel | la cellule affiche le libellé cliquable ; YAML `{label, url}` |
| U3 | Saisir `C:\docs\a.pdf` | refusé, message sur la ligne, rien n'est écrit |
| U4 | Cliquer un lien `\\srv\partage\x.pdf` sur desktop | confirmation, puis ouverture par le poste |
| U5 | Même lien sur client web | pas de lien cliquable, bouton « Copier » |
| U6 | Champ `multiple`, coller trois lignes `libellé \| URL` | trois liens créés dans l'ordre |
| U7 | Export xlsx d'exigences avec un lien simple et un champ à deux liens | hyperlien natif ; cellule texte deux lignes `libellé \| URL` |
| U8 | `rationale` `requiredWhen: { status: [approved] }`, passer en Approuvé sans justification | refus, message nommant le champ ; l'objet reste dans son statut |
| U9 | Même objet ancien déjà Approuvé sans justification, modifier son titre | autorisé (ni `rationale` ni `status` dans l'écriture) |
| U10 | MCP `bulk_import_requirements` avec `report: "RE-118 \| https://…"` | converti en `{label, url}` ; refusé si URL invalide |
| U11 | Déclarer `requiredWhen: { priority: [urgent] }` alors que `urgent` n'est pas une valeur de `priority` | refus à la sauvegarde du schéma |
| U12 | Script de la vue Suivi lit un champ `link` dans le graphe | reçoit `{label, url}` / liste, typé dans `polenta.d.ts` |

## 4. Critères d'acceptation

- [ ] `link` (+ `multiple`) déclarable dans l'éditeur de schéma, via MCP, et dans `schema.yaml`.
- [ ] Rendu lecture + édition d'un champ `link` simple et `multiple` dans les vues Excel, Word,
      Édition et les formulaires, desktop et client web.
- [ ] Les quatre formes d'URL acceptées sont enregistrées ; toute autre est refusée à la saisie UI,
      au MCP, avec message nommant le champ.
- [ ] Ouverture : directe en `http(s)`, confirmation pour `file://`/UNC (desktop), « Copier » hors
      `http(s)` (web) ; schéma revalidé par le main process.
- [ ] Forme texte `libellé | URL` acceptée au collage et au MCP, produite dans les exports texte /
      docx.
- [ ] Export xlsx : hyperlien natif pour un lien unique.
- [ ] Diff, historique GH77 et fusion GH37 affichent les liens lisiblement.
- [ ] `GraphLink` exposé au graphe et documenté dans `polenta.d.ts`.
- [ ] `requiredWhen` déclarable (éditeur de schéma, MCP), cohérence contrôlée (§2.3).
- [ ] `requiredWhen` contrôlé à la création et à la mise à jour selon §2.4 (UI, MCP), message
      nommant le champ et la condition ; astérisque dynamique dans les éditeurs.
- [ ] Le moteur `requiredWhen` est une fonction de `packages/types` réutilisable par L2/L5, avec
      tests unitaires (enum, multi_enum, boolean, status, plusieurs clés, référence absente).
- [ ] SPEC-REQ §3.1/§3.2, SPEC-TESTS §7, SPEC-MCP-SERVER, SPEC-DASHBOARDS (contrat graphe) mis à
      jour ; doc utilisateur : pérennité des URL dans la GED du client.

## 5. Indicateurs (GH79)

Aucun indicateur introduit. `requiredWhen` est une règle de saisie qui sert une fonction de
Polenta (contrôle à l'écriture) : il est calculé dans Polenta.

## 6. Hors périmètre

- `runFields` / `stepFields` et pseudo-champ `result` : L2 (#196). Classeur GH36 : L2.
- Champs de revue / décision : L5 (#204).
- Colonnes calculées de type `link` (vue Suivi) : évolution possible.
- Vérification que le lien répond, aperçu, miniature, stockage de fichiers.
- `requiredWhen` avec opérateurs (≠, comparaison numérique, ET entre conditions).
- Normalisation en masse des fichiers existants.
- Multi-hyperliens dans une cellule xlsx (limite d'Excel).
