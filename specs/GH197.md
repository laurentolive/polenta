# GH197 — Grille d'historique des exécutions (onglets du test et de l'exigence)

> Lot **3/16** du milestone « D — Conformité et gestion du changement », épique #191
> (`specs/GH191.md` §4, lot L3). Dépend de #196 (champs d'exécution, intégré dans `milestone-D`).
> **Besoin le plus immédiat de la qualité** : voir, au même endroit, toutes les exécutions d'un test ou
> d'une exigence, avec leurs verdicts, commentaires et champs.

## Contexte

Aujourd'hui, un run ne se consulte que depuis l'entrée de campagne qui l'a produit
(`campaign.$campaignId_.run.$testId`) : impossible de voir l'historique complet d'un test (toutes
campagnes, retests, reports GH64, instances T179), encore moins celui d'une exigence.

État du code (`milestone-D` @ 35cc92d) :

- Runs : `test-runs/<TEST>/<RUN>.yaml` (immuables), lus par `TestsService.findRuns` ; depuis #196 ils
  portent `fields` et `stepResults[].fields`.
- Campagnes : entrées `runs[]` (`entryId`, `testCaseId`, `requirementId`, `status`, `runId`,
  `testSnapshot`, `paramValues` / `resolvedParams`, `carriedFrom`) et entrées retirées `removedRuns[]`
  (GH73).
- Couverture exigence ↔ test : `matchCoverageLink` (`traceability.service.ts`), sens du lien
  indifférent ; règle T179 : un run avec `requirementId` ne compte que pour cette exigence.
- Éditeurs : la vue Édition (`EditView`) et les pages de détail (`req.$reqId`, `test.$testId`)
  empilent des **sections** (champs, liens, historique GH77) ; il n'y a pas d'onglets.
- Colonnes : panneau ⚙️ `FieldConfigModal`, préférence personnelle `fieldVisibility[<type>]` par vue ;
  défaut porté par le schéma (`defaultVisible`, #139) — `polenta-config` n'est plus lu.

## 1. Lignes

| Grille de… | Lignes |
|---|---|
| **un test** | tous ses runs (campagne ou exécution isolée), plus les entrées de campagne `pending` sans run (verdict « En attente ») |
| **une exigence** | les runs des tests qui la couvrent (lien de couverture, sens indifférent), règle T179 : run avec `requirementId` → seulement pour cette exigence, sans → pour toutes les exigences liées ; plus les entrées `pending` de ces tests (même règle sur l'instance) |

- Une ligne dont l'entrée de campagne a été **retirée** (GH73) est conservée et marquée
  « entrée retirée ».
- Run dont la campagne n'existe plus (supprimée, autre repo) : ligne conservée, colonnes de campagne
  vides, marquée « campagne introuvable ».
- Test d'un composant : runs lus dans le repo du composant (même règle que la traçabilité).
- Ordre par défaut (Q6) : entrées en attente en tête, puis `executedAt` décroissant. Tri par colonne
  (clic sur l'en-tête).

## 2. Colonnes (⚙️)

| Groupe | Colonnes |
|---|---|
| **Exécution** | verdict, date, testeur, durée, origine (saisie / import Excel), notes, équipement, **champs d'exécution** (`runFields`, union des types présents) |
| **Campagne** | ID, titre, statut, baseline, champs de la campagne |
| **Entrée** | `entryId`, exigence de l'instance, paramètres (saisis et résolus), version du test exécutée (`testSnapshot.version`), report (`carriedFrom`) |
| **Test** (grille d'exigence) | ID, titre du test |
| **Étapes** | une sous-ligne dépliable par étape : verdict, commentaire, **champs d'étape** (`stepFields`) |

- Choix dans le panneau ⚙️ existant (`FieldConfigModal`), un onglet « Exécutions ».
- Préférence personnelle : clé `executions` dans `fieldVisibility[<type>]` — type du **test** pour la
  grille d'un test, type de l'**exigence** pour la grille d'une exigence.
- **Défaut (Q2)** : verdict, date, testeur, campagne (ID + titre), `entryId` ; plus les champs
  d'exécution marqués `defaultVisible: true` dans le schéma (#139) — pas de `polenta-config`.
- « Réinitialiser » retire la clé `executions` (comme #139).

Colonnes **reportées** aux lots qui fournissent les données (Q3) : « Configuration testée » (L2b, #202)
et « Change » (#193). La grille est écrite pour qu'un groupe de colonnes s'ajoute sans la reprendre.

## 3. Interactions

- Valeurs : liens cliquables (`LinkList`), booléen Oui / Non, richtext rendu, valeur « hors schéma »
  marquée, ⚠ valeur d'enum inconnue (même rendu que la consultation d'un run, #196).
- Chevron sur une ligne : déplie les étapes (sous-lignes).
- **Ouvrir** (Q5) : une ligne de campagne ouvre la page de consultation du run (ou la page
  d'exécution pour une entrée en attente) ; une exécution isolée se consulte par le dépliage.
- Chargement à l'ouverture de la section (Q7), pas au montage de l'éditeur.

## 4. Emplacement (Q1)

Section repliable **« Exécutions (N) »** dans :
- la vue Édition (`EditView`) d'un test et d'une exigence, entre « Liens » et « Historique » ;
- les pages de détail `test.$testId` et `req.$reqId`.

Composant réutilisable `ExecutionHistoryGrid`, repris par la vue Conformité (L6, #205).

## 5. Données (main)

Nouveau canal `executions:history(repoPath, target, workspaceDir)` — `target` : `{ testId }` ou
`{ requirementId }` — qui renvoie des lignes assemblées côté main (runs + campagnes + entrées +
entrées retirées + type du test, couverture T179) ; lecture seule, aucune écriture.

## 6. Cas d'usage

| # | Situation | Résultat attendu |
|---|---|---|
| U1 | Test exécuté dans deux campagnes, un retest et un report | 4 lignes, date décroissante, campagne et entrée renseignées |
| U2 | Entrée `pending` dans une campagne en cours | ligne « En attente » en tête, ouvre la page d'exécution |
| U3 | Entrée retirée après exécution | ligne conservée, marquée « entrée retirée » |
| U4 | Exigence couverte par un test itérant (T179) et un test simple | runs de l'instance de cette exigence + tous les runs du test simple ; pas les runs des autres instances |
| U5 | ⚙️ : cocher « Température » (champ d'exécution) et « Rapport » (lien) | colonnes affichées, lien cliquable ; préférence retrouvée à la réouverture |
| U6 | Déplier une ligne | étapes : verdict, commentaire, valeur mesurée |
| U7 | Champ d'exécution retiré du schéma | valeur des anciens runs affichée « hors schéma » si la colonne est choisie |
