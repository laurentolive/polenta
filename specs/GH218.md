# GH218 — Passer Electron à une version maintenue (31.7.7 bloqué par macOS)

Issue : #218. Traité selon le Workflow Bug (montée de version, pas de nouvelle fonctionnalité).

## Root cause

`apps/desktop` dépendait d'`electron@^31` (31.7.7 installé). Electron 31 n'est plus maintenu
(hors des 3 dernières majeures : 43, 44, 45 au 29/10/2026) et macOS récent refuse son binaire
(`spctl` : « notarization indicates this code has been revoked ») : `Electron.app` est placé dans la
corbeille au lancement de `pnpm --filter @polenta/desktop dev`. Le binaire n'est pas altéré (SHA-256
conforme à la release officielle) : c'est la build Electron 31 qui est révoquée, pas Polenta.

## Correctif

- `electron` : `^31.0.0` → `^45.1.0` (dernière majeure stable ; Chromium 156, Node 24.22).
- `electron-vite` reste en `^2.3` : il déduit les cibles de build de la version d'Electron et, pour
  une majeure qu'il ne connaît pas, retombe sur celles d'Electron 31 (`node20.14` / `chrome126`) —
  bundles plus conservateurs que nécessaire, mais valides sous Electron 45. Le monter (3+) imposerait
  Vite 6+, donc aussi Vitest et le build du client web : hors périmètre.
- `electron-builder` reste en `^24` : il package Electron 45 sans changement de configuration
  (installeur NSIS vérifié). Pas de raison suffisante de le monter dans ce ticket.
- Aucun changement de code. Revue des changements cassants Electron 32 → 45 sur `src/main` et
  `src/preload` : pas d'usage de `File.path` (retiré en 32), de `session.setPreloads` (déprécié en
  35), de `BrowserView`, des `protocol.register*Protocol` ni de `ipcRenderer.sendTo`. Fenêtres déjà
  en `contextIsolation: true` / `nodeIntegration: false`, preload limité à `contextBridge` +
  `ipcRenderer` (compatible sandbox). `keytar` est un module N-API : pas de recompilation par ABI.
- Le script d'installation d'`electron@45` déclare `node >= 22.12`, mais fonctionne sous Node 20.20
  (vérifié : téléchargement du binaire OK) ; la CI release (Node 20) n'est donc pas bloquée.

Note poste Windows : sans le mode développeur, electron-builder 24 échoue à extraire son cache
`winCodeSign` (liens symboliques macOS). Problème d'environnement, indépendant de ce ticket
(contournement : extraire l'archive dans `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0`).

## Comment vérifier (à faire sur macOS Apple Silicon — non vérifiable depuis Windows)

1. `pnpm install` (télécharge Electron 45), puis `pnpm --filter @polenta/desktop dev` : l'app
   démarre, sans alerte « Logiciel malveillant bloqué ».
2. `spctl -a -vv node_modules/electron/dist/Electron.app` : plus de « revoked ».
3. `pnpm --filter @polenta/desktop package` puis lancer l'app produite (non signée : premier
   lancement par clic droit → Ouvrir).
4. Avec la forge de test : `POLENTA_E2E_SSH=… pnpm --filter @polenta/desktop test:e2e:desktop`.
