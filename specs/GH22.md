# GH22 — Matrice de conformité vide pour une interface en repo séparé

Issue : #22.

## Root cause

`InterfaceComplianceService.buildMatrix` comparait `impl.interface` au nom du nœud d'interface. Pour une
interface en repo séparé, ce nœud s'appelle `root`, alors que `ImplementsDeclaration.interface` contient
le **nom de montage** du repo. Aucun implémenteur ne correspondait : la matrice avait ses exigences et
aucune colonne. Les interfaces locales, dont le nom de nœud est le nom déclaré, fonctionnaient.

## Correctif

`interface-compliance.service.ts` : `ComponentRef.interfaceName`, nom de montage du repo pour `root`, nom
du nœud pour un composant local. La comparaison porte sur ce nom. Autre effet : une déclaration
`interface: root` ne peut plus associer un composant à la racine de n'importe quel repo.

Recensement : c'est la seule comparaison de ce type côté main. Celles du renderer (`workspaceActions.ts`,
`StructureTab.tsx`) comparent déjà au nom de montage d'une dépendance.

## Comment vérifier

- `interface-compliance.gh22.test.ts` : interface en repo séparé (vu en échec sans le correctif),
  interface locale, autre repo d'interface sans implémenteur emprunté.
- `e2e-web/gh22-compliance-matrix.spec.ts`, sur les données de démo : `if-bus-interne` a ses colonnes
  `comp-moteur`, `comp-module-wifi` et le composant local `carte-commande`, `bus-ihm` reste correcte.

À la main : `demo-lave-linge`, écran de conformité, matrice `if-bus-interne`.
