# GH229 — Liens de navigation sur les ID d'élément (+ #236)

Issue : #229 — milestone C « Fonctionnalités client ». Absorbe #236 (« ID Link bugged ») : ses
deux symptômes sont couverts par les critères §8.10 et §8.11 et #236 est fermée avec #229.

## 1. Objet

Partout où l'interface affiche l'ID d'un autre élément (exigence, test, campagne…), cet ID est
un **lien** :

- un **clic** ouvre l'élément dans la vue système, dans le dernier type de vue utilisé, élément
  ciblé et sélectionné comme si on l'avait choisi dans la barre latérale ;
- un **survol prolongé** affiche une **popup d'aperçu** en affichage dense, dont les champs se
  configurent dans le panneau ⚙️ de la vue de l'élément (nouvel onglet « Popup ») ;
- le texte du lien est l'**ID affiché** du type d'objet : l'ID Polenta par défaut, ou un champ
  choisi dans le modèle de données (ID client, titre…).

## 2. Ce qui est un lien

### 2.1 Règle

Est un lien tout ID qui **référence un autre élément** :

- vue système : colonnes de liens du Tableau, sections de liens du Document, liens de la fiche
  Édition (`LinkCombobox`) ;
- campagnes : liste des campagnes, tests d'une campagne, exécution / saisie d'un test (ID du
  test et des exigences liées) ;
- Vue Recherche et panneau Recherche, résultats de requêtes et dashboards de la vue Suivi,
  analyse d'impact, matrice de traçabilité / conformité, constellation, comparaisons (diff du
  répertoire de travail, diff de commit, baselines), résolution de merge, historique d'un
  élément ;
- **ID écrits dans le texte** : voir §2.2.

Ne sont **pas** des liens :

- l'ID de l'élément lui-même là où il est affiché comme sa propre donnée : colonne ID de sa
  ligne dans le Tableau, en-tête de sa section dans le Document, en-tête de sa fiche Édition ;
- les impressions et exports (routes `/print/*`, PDF, Excel, ReqIF…) ;
- un ID dont l'élément est **introuvable** (supprimé, autre branche, repo absent du workspace) :
  affiché en texte simple, avec le marqueur « introuvable » là où il existe déjà (`LinkCombobox`),
  sans popup.

Le design recense exhaustivement les composants qui affichent un ID référencé et les fait tous
passer par un **composant unique** (lien + popup) — le comportement est identique partout.

### 2.2 ID dans le texte

Dans les champs `richtext` et texte **en lecture** (Document, cellules du Tableau hors édition,
fiche Édition hors saisie, aperçu de test dans une campagne, popup d'aperçu elle-même), une
séquence qui est l'**ID Polenta exact d'un élément existant** du workspace devient un lien :

- reconnaissance : préfixe d'un type du workspace + `-` + chiffres, délimité (pas de lettre ni
  de chiffre collé avant ou après), et l'élément existe — `SYS-0001` dans « voir SYS-0001. »
  est un lien, `SYS-0001A` ou un `SYS-9999` inexistant ne l'est pas ;
- le texte n'est **jamais modifié** : le lien affiche ce qui est écrit (l'ID Polenta), pas
  l'ID affiché du §4 ;
- pas de reconnaissance dans un bloc de code, un lien Markdown existant, un bloc `drawio` ou
  pendant la saisie (le champ en cours d'édition reste du texte brut) ;
- les valeurs d'**ID affiché** personnalisé (§4) ne sont pas reconnues dans le texte (non
  uniques, pas de motif fiable).

## 3. Clic

### 3.1 Clic simple — page cible

Le clic est une navigation dans l'onglet courant : nouvelle entrée de l'historique de l'onglet
(GH228), Précédent revient à la page d'origine.

| Élément cible | Page ouverte |
|---|---|
| Exigence, test (tout objet d'un type `requirement` / `test`) | vue système, repo / composant / type de l'élément (GH105 : bascule de repo si besoin ; l'onglet Exigences / Tests suit la catégorie) |
| Campagne | fiche campagne `/campaign/<id>` |

**Type de vue** de la vue système :
1. si l'onglet courant est déjà sur la vue système : son mode courant — Tableau, Document ou
   **Édition** (suivre un lien depuis la fiche Édition d'un objet ouvre la fiche Édition de la
   cible) ;
2. sinon (lien suivi depuis une campagne, la recherche, l'analyse d'impact…) : le dernier mode
   Tableau / Document mémorisé pour le repo de la cible (même mémoire que l'ouverture de la vue
   système, repli Tableau).

Changement de comportement : aujourd'hui un clic depuis le Tableau ouvre toujours l'Édition ;
désormais il reste en Tableau.

**Élément affiché et sélectionné** — comme un clic simple sur l'élément dans la barre latérale :
- Tableau / Document : « goto » de l'élément (défilement + contour, T164), ligne sélectionnée
  dans le Tableau, élément sélectionné dans l'arbre de la barre latérale (dossiers parents
  dépliés) ;
- Édition : fiche de la cible, élément sélectionné dans l'arbre ;
- si l'élément est masqué par un filtre actif de la vue cible, le filtre est conservé et
  l'élément reste introuvable à l'écran : un message non bloquant l'indique (« SYS-0012 est
  masqué par le filtre ») — on ne retire pas le filtre de l'utilisateur.

### 3.2 Ctrl+clic, Cmd+clic, clic du milieu

Ouvre la **même page cible** (§3.1, mêmes règles de type de vue évaluées depuis l'onglet
source) dans un **nouvel onglet**, activé. L'onglet source **ne change pas** : ni URL, ni
sélection, ni historique (#236). Les fiches autonomes `/req/<id>` et `/test/<id>` ne sont plus
la cible des liens.

### 3.3 Interaction avec le geste du conteneur

Le clic sur un lien ne déclenche pas le geste de son conteneur : pas de sélection de ligne ou de
cellule, pas d'entrée en édition de la cellule, pas de sélection multiple (Ctrl) dans le
Tableau. Le reste de la cellule garde ses gestes (clic = sélection, double-clic = édition des
liens, GH169). Un appui sur le lien suivi d'un glisser n'est pas un clic.

## 4. ID affiché (modèle de données)

Nouvel attribut optionnel d'un type d'objet dans `.polenta/schema.yaml` :

```yaml
objectTypes:
  - name: exigence-systeme
    prefix: SYS
    displayIdField: clientRef   # nom d'un champ du type, ou `title` ; absent = ID Polenta
```

- valeurs admises : `title` ou le nom d'un champ du type de type `text`, `number` ou `enum` ;
  refusé à l'enregistrement du schéma sinon (champ inconnu, `textarea`, `richtext`,
  `multi_enum`…) ;
- éditeur de schéma : liste « ID affiché » dans l'éditeur du type, valeur par défaut « ID
  Polenta » ;
- un élément dont le champ est vide affiche son **ID Polenta** (repli) ;
- s'applique au **texte des liens** (§2.1) uniquement. L'ID Polenta reste affiché dans la
  colonne ID, les en-têtes Document et Édition, les fichiers, exports et impressions, les ID
  du texte (§2.2), et en tête de la popup ;
- infobulle native du lien quand l'ID affiché diffère de l'ID Polenta : l'ID Polenta ;
- un titre long est tronqué (ellipse) dans les listes de liens, complet dans la popup ;
- l'unicité n'est pas exigée : la navigation et les liens (`links.yaml`) utilisent toujours
  l'ID Polenta ;
- composant d'un autre repo : l'attribut du schéma **de ce repo** fait foi ;
- serveur MCP : l'attribut est lu, écrit et validé par les tools de mutation du schéma comme
  les autres attributs du type ; `AGENTS.md` généré le documente.

## 5. Popup d'aperçu

### 5.1 Ouverture et fermeture

- s'ouvre après **500 ms** d'immobilité du pointeur sur le lien ; quitter le lien avant annule ;
- reste ouverte tant que le pointeur est sur le lien ou sur la popup (délai de grâce de
  **200 ms** pour passer de l'un à l'autre) ; se ferme sinon, sur Échap, au clic sur le lien
  (navigation), au défilement de la page sous-jacente ;
- une seule popup à la fois ; positionnée sous le lien, retournée au-dessus ou décalée pour
  rester dans la fenêtre ; hauteur maximale ~50 % de la fenêtre, défilement interne ;
- non ouverte sur un appareil sans survol (client web tactile) ni pendant un glisser.

### 5.2 Contenu

- en-tête : ID Polenta, ID affiché s'il diffère, pastille du type (libellé + couleur), statut,
  repo si différent du repo courant, ⚠ « Impact à vérifier » si `needsRevalidation` ;
- titre ;
- puis les champs configurés (§5.3), en **lecture seule et affichage dense** : libellé du champ
  en petit, valeur juste en dessous ; richtext rendu (Markdown, images, `drawio` en
  miniature) ; un champ vide n'est pas affiché ;
- les ID présents dans la popup (champs de liens, ID dans le texte) sont des liens cliquables
  (§3) mais **n'ouvrent pas de popup imbriquée** ;
- texte sélectionnable / copiable ;
- pendant le chargement : squelette ; élément devenu introuvable : message « introuvable ».

Campagne : en-tête (ID, titre, statut de la campagne) et nombre de tests ; pas de configuration
de champs (hors scope).

### 5.3 Configuration — onglet « Popup » du panneau ⚙️

- troisième onglet du panneau ⚙️ de la vue système, à côté de « Tableau » et « Document » :
  liste des champs du type (champs système et personnalisés, colonnes de liens, couverture)
  avec cases à cocher, comme les autres onglets ; ordre d'affichage = ordre du panneau ;
- par **type d'objet et par utilisateur**, stocké avec les autres préférences de champs
  visibles (même mécanisme, nouvelle clé `popup`) ;
- **défaut** (aucune préférence enregistrée) : aucun champ coché — la popup n'affiche que
  l'en-tête et le titre ;
- la popup d'un élément utilise la configuration du type **de cet élément**, quel que soit
  l'écran où le lien est affiché.

## 6. Cas limites

- Lien vers un objet d'un autre repo du workspace : bascule de repo (GH105), popup lue dans ce
  repo ; repo de l'objet en lecture seule : sans effet sur la navigation.
- Lien suivi alors que la page courante a une saisie non enregistrée : comportement inchangé
  (hors scope GH228 §5), sauf le champ focalisé qui est quitté (`blur`) donc enregistré.
- Lien vers l'élément déjà affiché (même page) : re-goto sans nouvelle entrée d'historique.
- Lien vers un type que l'utilisateur n'a encore jamais ouvert : pas de préférence de vue →
  Tableau, colonnes par défaut.

## 7. Indicateur

Aucun indicateur introduit (navigation et affichage de données brutes) — principe GH79 sans
objet.

## 8. Critères d'acceptation

1. Dans le Tableau des tests, un clic sur `SYS-0003` de la colonne « vérifie » affiche la vue
   système, onglet Exigences, composant / type de SYS-0003, **en Tableau**, ligne SYS-0003
   sélectionnée et contourée, SYS-0003 sélectionné dans l'arbre ; Précédent revient au Tableau
   des tests.
2. Depuis le Document, même clic → Document positionné sur SYS-0003.
3. Depuis la fiche Édition d'un test, clic sur un lien → fiche Édition de l'exigence cible.
4. Depuis une campagne, clic sur l'ID d'un test → vue système dans le dernier mode Tableau /
   Document mémorisé du repo, test sélectionné ; clic sur l'ID d'une campagne dans la recherche →
   fiche campagne.
5. Survol immobile 500 ms d'un ID : la popup s'ouvre ; pointeur sorti du lien et de la popup :
   fermée en ≤ 200 ms ; survol de < 500 ms : pas de popup.
6. Sans configuration, la popup ne montre que l'en-tête et le titre ; après avoir coché
   « Énoncé » et « Priorité » dans l'onglet « Popup » du ⚙️ des exigences système, la popup de
   toute exigence de ce type les affiche, dans l'ordre choisi, partout dans l'application ; un
   autre utilisateur garde sa propre configuration.
7. `displayIdField: clientRef` sur un type : ses liens affichent la valeur de `clientRef`
   (infobulle = ID Polenta), un élément sans `clientRef` affiche son ID Polenta ; la colonne ID,
   les en-têtes et les exports affichent toujours l'ID Polenta. Un `displayIdField` vers un
   champ richtext est refusé à l'enregistrement du schéma.
8. Un richtext contenant « voir SYS-0001 et SYS-9999. » (SYS-9999 inexistant) affiche
   SYS-0001 comme lien avec popup et SYS-9999 en texte ; en saisie, le texte reste brut.
9. L'ID de l'élément dans sa propre ligne / son en-tête n'est pas un lien ; un ID introuvable
   n'est ni un lien ni une popup.
10. (#236) Clic sur un ID de la colonne « vérifie » : jamais de page invalide ou vide, quel que
    soit le mode de départ et le repo de la cible.
11. (#236) Ctrl+clic (Cmd+clic, clic du milieu) sur un ID : nouvel onglet sur la page cible ;
    revenu sur l'onglet source, son URL, sa sélection et son historique sont inchangés.
12. Le clic sur un ID dans une cellule ne sélectionne pas la ligne ni n'entre en édition ;
    Ctrl+clic sur un ID n'ajoute pas la ligne à la sélection multiple.

## 9. Hors scope

- Reconnaissance des ID affichés personnalisés dans le texte (§2.2) et transformation
  automatique du texte saisi.
- Liens dans les impressions / exports.
- Configuration de champs dans la popup d'une campagne ; popup sur les entrées / runs de
  campagne en tant que tels.
- Fiches autonomes `/req/<id>` et `/test/<id>` : conservées (accès direct existant), mais plus
  utilisées par les liens.
- Popup au survol des éléments de l'arbre de la barre latérale (titres, pas des ID).
- Navigation au clavier vers un lien / ouverture de la popup au clavier.
