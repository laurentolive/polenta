# GH23 — Serveur MCP : logs des index écrits sur stdout (corrompt le JSON-RPC stdio)

Type : bug — issue #23

## Root cause

En transport stdio, stdout est réservé aux messages JSON-RPC. Le point d'entrée
`apps/desktop/src/mcp-server/index.ts` respectait cette règle pour ses propres messages
(`console.error`), mais le conteneur MCP réutilise tels quels les services du process principal,
qui journalisent via `console.log` — donc sur stdout :

- `RequirementsIndexService` / `TestsIndexService` (construction / invalidation des index) ;
- et, sur d'autres chemins, `WorkspaceService` (« using cached tree… », régénération) et
  `SchemaService` (init d'un repo composant).

Un client MCP strict, qui parse chaque ligne de stdout, échoue alors avec
`Unexpected token 'R', "[Requiremen"... is not valid JSON` dès le premier appel qui construit
un index (`list_requirements`, `run_query`…).

## Correctif

Nouveau module `apps/desktop/src/mcp-server/stdout-guard.ts`, importé **en premier** dans
`index.ts` : il redirige `console.log`, `console.info` et `console.debug` vers `console.error`
(stderr) pour tout le process MCP. Le transport stdio du SDK écrit via `process.stdout.write`
et n'est pas affecté.

Choix d'une redirection globale côté serveur MCP plutôt que de passer chaque log des services en
`console.error` : couvre tous les services partagés (actuels et futurs) sans modifier les logs de
l'app Electron, où stdout reste le canal normal.

Fichiers : `apps/desktop/src/mcp-server/stdout-guard.ts` (nouveau),
`apps/desktop/src/mcp-server/index.ts` (import).

## Comment vérifier

1. `pnpm --filter desktop run build:mcp-server`
2. Lancer un client strict qui envoie `initialize`, `notifications/initialized`, puis
   `tools/call list_requirements` et `list_tests` sur un repo réel, et qui tente un `JSON.parse`
   sur chaque ligne de stdout.
3. Attendu : toutes les lignes de stdout sont du JSON ; les lignes `[RequirementsIndex] …` /
   `[TestsIndex] …` apparaissent sur stderr.

Vérifié sur `handstickProduct` (230 tests) : bundle avant correctif → 4 lignes non-JSON sur
stdout ; après correctif → 0, 3 réponses JSON-RPC, logs des index sur stderr.
`pnpm --filter desktop run typecheck` : 0 erreur.
