# GH230 — Conserver l'élément affiché au changement de type de vue

## Contexte

Vue système (`/product`, `/components`), exigences et tests : la barre d'en-tête propose deux
boutons de mode, **Tableau** (Excel) et **Document** (Word). Aujourd'hui, un clic sur l'un d'eux
(`showView(mode)`) ouvre une nouvelle page **sans `item`** : la nouvelle vue se monte en haut de
liste. L'utilisateur qui lisait l'exigence SYS-0042 au milieu du document se retrouve sur
SYS-0001 et doit la rechercher. Seul cas qui « marche » par accident : un élément ciblé par un
clic dans l'arbre (goto T164) dont la cible locale survit à la bascule — mais l'`item` disparaît
de l'URL, donc Précédent / Suivant le perd.

Objectif : la bascule Tableau ↔ Document montre **le même élément** dans la nouvelle vue.

## Élément de référence

Au clic sur un bouton de mode différent du mode courant, l'élément de référence est, par ordre
de priorité :

1. **L'élément sélectionné** :
   a. en Tableau, la ligne sélectionnée dans la grille (clic sur une ligne) ; sélection multiple
      → la première ligne sélectionnée dans l'ordre d'affichage ;
   b. sinon l'élément ciblé par un goto (clic simple / dépôt dans l'arbre, `item` de l'URL —
      contour persistant), item ou dossier ;
   c. depuis la Vue Édition (les boutons de mode y sont aussi affichés) : l'élément édité.
2. **Sinon, le premier élément affiché** : la première ligne (Tableau) ou la première carte /
   le premier titre de section (Document) visible en haut de la zone de défilement de la vue
   — un élément partiellement masqué en haut compte s'il en reste au moins la moitié visible,
   sinon c'est le suivant. L'en-tête de colonnes figé du Tableau n'est pas une zone visible.
   Seuls les éléments portant un objet comptent : un titre de dossier en haut de la vue cède la
   place au premier élément qui le suit (l'ancrage `top` est un objectId, stable dans l'URL).
3. Vue vide (aucun élément, ou tout filtré) : pas de référence, comportement actuel.

## Positionnement dans la nouvelle vue

| Référence | Nouvelle vue | URL (`item`) |
|-----------|--------------|--------------|
| Sélectionné (1a, 1b, 1c) | goto habituel : défilement jusqu'à l'élément + contour persistant | `item` = objectId de l'élément (nouvelle page PUSH, comme aujourd'hui pour la bascule) ; dossier : pas d'`item` (un dossier n'a pas d'objectId), cible locale seulement |
| Premier affiché (2) | l'élément est **aligné en haut** de la zone de défilement (la position de lecture est conservée), **sans contour** | pas d'`item` (ce n'est pas une sélection) : paramètre d'ancrage `top` = objectId de l'élément |

La sélection de lignes du Tableau n'est pas recréée en Document (Document n'a pas de sélection
de lignes) ; dans le sens Document → Tableau, la référence sélectionnée (1b) reste la cible goto
et aucune ligne n'est sélectionnée.

**Référence non rendue dans la vue** (s'applique aussi au goto d'un clic dans l'arbre, jusque-là
sans effet dans ce cas — T164) — chaque vue a ses propres dossiers repliés et sa
propre case « Afficher les titres des dossiers » :
- élément dans un dossier replié dans la vue → le titre du dossier replié qui le contient (sans
  contour : le contour reste sur l'élément visé) ;
- dossier dont les titres sont masqués dans la nouvelle vue → son premier descendant rendu ;
- rien de rendu (dossier vide, masqué) → l'élément rendu suivant dans l'ordre de l'arbre, sinon
  le précédent ; à défaut, haut de liste.

La bascule ne déplie jamais un dossier et ne change pas la configuration des champs.

## Navigation (GH228)

La bascule reste une **nouvelle page** de l'historique de l'onglet. Précédent / Suivant ramènent
à la position de l'élément (décision humaine du 2026-10-30) :
- la page quittée sans `item` reçoit d'abord (REPLACE) l'ancrage `top` = son premier élément
  affiché, puis la nouvelle page est poussée ; avec un `item`, elle le garde (goto au retour) ;
- une page dont l'URL porte `top` (sans `item`) s'ouvre l'élément aligné en haut, sans contour —
  au retour Précédent / Suivant comme à la bascule ;
- `top` est abandonné par toute autre navigation de la page (goto d'un clic dans l'arbre, clic
  dans le vide, changement de composant / type), comme `item`.

## Critères d'acceptation

1. Tableau, aucune sélection, défilé jusqu'à SYS-0042 en haut de la grille → Document : la carte
   SYS-0042 est en haut de la zone visible, sans contour ; l'URL n'a pas d'`item`.
2. Même chose Document → Tableau : la ligne SYS-0042 est la première ligne visible sous l'en-tête.
3. Clic simple sur SYS-0042 dans l'arbre, puis défilement de la vue ailleurs → bascule : la nouvelle
   vue défile jusqu'à SYS-0042 avec contour ; l'URL porte `item=SYS-0042`.
4. Tableau, clic sur la ligne SYS-0042 (sans passer par l'arbre) → Document : SYS-0042 affichée avec
   contour, `item=SYS-0042`.
5. Vue Édition de SYS-0042 → bouton Document : Document positionné sur SYS-0042 avec contour.
6. Référence dans un dossier replié dans la vue cible → la vue cible montre le titre de ce dossier.
7. Re-clic sur le bouton du mode déjà actif : aucun effet (pas de nouvelle page).
8. Vue vide / tout filtré : bascule sans erreur, haut de liste.
9. Précédent après la bascule (scénario 1) : retour au Tableau, SYS-0042 en haut de la grille ;
   Suivant : Document, SYS-0042 en haut.

## Hors scope

- Bascule depuis/vers la Vue Recherche, la vue Campagnes (pas de boutons de mode) et le sélecteur
  de tests de campagne.
- Changement de composant / type dans la combobox (autre contenu : la position repart du haut).
- Mémoriser la position de défilement au départ de la page par une autre navigation que la
  bascule de mode (lien interne, combobox, onglet d'activité).
- Synchroniser en continu la sélection de lignes du Tableau avec l'arbre.
