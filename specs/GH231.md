# GH231 — Vue graphe : le menu « Merger … dans » reste sur le choix de branche

Issue : #231 · Type : bug · Corrigé dans la branche de #222 (décision du 2026-10-29).

## Constat

Vue graphe → menu d'une branche → « Merger branche dans… » → clic sur la branche de destination :
le menu de choix de branche restait affiché. Il fallait cliquer « Retour » pour voir le résultat,
d'où l'impression que « Retour » lançait le merge.

## Root cause

`routes/graph.tsx`, `mergeIntoMut` : le merge partait bien au clic. En cas d'échec (erreur, ou
conflit), le message et le bouton « Résoudre les conflits » ne sont rendus que par le **menu
principal**, mais `selectorMode` restait à `'merge'` : le menu continuait d'afficher le sélecteur
de branche, sans retour visible. « Retour » remettait `selectorMode` à `null` et révélait le
résultat. (En cas de succès, le menu se fermait déjà.)

## Correctif

`mergeIntoMut` remet `selectorMode` à `null` en cas de conflit (`onSuccess` avec
`success: false`) et en cas d'erreur (`onError`) : le menu principal s'affiche avec le message et
« Résoudre les conflits ».

## Comment vérifier

- e2e `e2e-web/gh231-graph-merge-into.spec.ts` : merge en conflit depuis le graphe → le menu montre
  « Conflits de merge : … » et « Résoudre les conflits », le titre « Merger « … » dans… » a disparu.
- À la main : vue graphe, clic droit sur une branche, « Merger branche dans… », choisir une
  destination. Sans conflit : le menu se ferme et le graphe montre le commit de merge. Avec
  conflit : le message et « Résoudre les conflits » apparaissent aussitôt.
