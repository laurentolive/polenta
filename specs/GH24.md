# GH24 — Colonnes figées et repli des dossiers non mémorisés au changement de vue

Type : bug — issue #24

## Root cause

Le nombre de colonnes figées (`freezeColCount`, T151) et l'ensemble des dossiers repliés
(`collapsedFolders`) étaient des `useState` locaux d'`ExcelView` / `WordView`. Ces composants
sont démontés dès qu'on quitte la vue (bascule Tableau ↔ Document, passage en Édition, autre
type d'objet) : à leur remontage, l'état repartait de zéro. En plus, `ExcelView` remettait
explicitement `freezeColCount` à 0 à chaque changement de type.

Les autres réglages de vue (colonnes visibles, titres de dossiers — T162) sont, eux, détenus par
`SystemView` et persistés dans la pref utilisateur par type (`fieldVisibility[typeKey]` du
fichier `.{user}.pref`).

## Correctif

Les deux états rejoignent ce même objet de pref (`FieldVisibilityPref`) :

| Champ                    | Vue       | Absent ⇒ |
|--------------------------|-----------|----------|
| `collapsedFoldersExcel`  | Tableau   | `[]`     |
| `collapsedFoldersWord`   | Document  | `[]`     |
| `freezeColCountExcel`    | Tableau   | `0`      |

- `SystemView` charge ces valeurs avec les autres prefs du type, les détient en état et les
  enregistre via `persistPrefs` (objet complet, cf. T162).
- `ExcelView` / `WordView` deviennent contrôlés pour ces états (`collapsedFolders` +
  `onCollapsedFoldersChange`, `freezeColCount` + `onFreezeColCountChange`).
- `ExcelView` borne le nombre de colonnes figées au nombre de colonnes affichées au rendu
  (`Math.min`), sans réécrire la valeur stockée ; la remise à 0 au changement de type est
  supprimée (chaque type a désormais sa propre valeur).
- `toggleFolder` reste une callback stable (via ref) pour ne pas invalider les lignes mémoïsées.

Le repli est mémorisé **par type d'objet et par vue** (Tableau et Document indépendants, comme
`showFoldersExcel` / `showFoldersWord`), **par utilisateur**, et survit au redémarrage de l'app.

Fichiers : `packages/api-client/src/types.ts`, `apps/desktop/src/main/ipc/pref.handlers.ts`
(type du payload), `apps/desktop/src/renderer/components/system/{SystemView,ExcelView,WordView}.tsx`.

Hors périmètre (inchangés, toujours éphémères) : largeurs de colonnes, filtres de colonnes.
Les ids de dossiers supprimés restent dans la liste persistée ; sans effet visible.

## Comment vérifier

1. Vue Tableau d'un type : figer 2 colonnes, replier un dossier.
2. Passer en vue Document, replier un autre dossier ; revenir en Tableau → 2 colonnes figées,
   le premier dossier toujours replié.
3. Revenir en Document → le second dossier toujours replié.
4. Ouvrir un autre type, puis revenir → états conservés ; l'autre type a ses propres réglages.
5. Masquer une colonne figée pour n'en garder qu'une → le gel est borné ; la ré-afficher →
   le gel d'origine revient.
6. Redémarrer l'app → états conservés.
