# GH246 — Vue Tableau limitée à 50 lignes : boucle de rendu dans la barre du haut

Issue : #246.

## Root cause

`ModificationControl` (barre du haut, présent sur toutes les vues d'un projet ouvert) se re-rendait
sans fin, environ 2 500 à 5 800 commits par seconde, sur **tous les projets** :

1. `const { data: offRepos = [] } = useQuery(...)` : la requête est désactivée tant que la popup
   « Publier » est fermée, donc `data` vaut `undefined` et `[]` est un nouveau tableau à chaque rendu.
2. `offRepos` est une dépendance de l'effet qui, popup fermée, appelle `setMergeInitialized(false)`.
3. Cet appel relance un rendu, qui recrée le tableau, qui relance l'effet.

Les rendus de la boucle sont de priorité normale : ils passent toujours avant les transitions React.
`startTransition(() => setRenderAllRows(true))` (`ExcelView`) n'était donc jamais traité et le Tableau
restait à ses 50 premières lignes (`INITIAL_RENDERED_ROWS`). Sur un type de moins de 50 éléments, le
symptôme visible n'existait pas, mais la boucle tournait quand même.

Autres effets constatés ou attendus de la même cause :

- un cœur de processeur occupé en continu dès qu'un projet est ouvert ;
- la mise à jour `isTransitioning` du routeur restait en attente (voies React relevées) ;
- le rendu en tâche de fond des cellules (`useRenderWhenVisibleAtRest`, en transition) est soumis à la
  même famine ; ce point vient de la lecture du code, il n'a pas été mesuré à part.

L'analyse de l'issue (ExcelView re-rendue en boucle) était inexacte : `ExcelView` n'avait que 4 rendus
sur la mesure. Elle est restée exacte sur l'effet (transition jamais aboutie).

Origine : le motif (`offRepos = []` et l'effet) vient de GH133 (`d939e2c`, 2026-10-28), d'après
l'historique du fichier. La boucle n'a pas été mesurée sur un build antérieur.

### Comment la cause a été établie

Sur une copie de PH2, build de production, Electron piloté par Playwright :

| Mesure | Résultat avant correctif |
|---|---|
| `tr[data-node-id]` pendant 40 s | 51, sans évolution |
| Rendus de `ExcelView` avec `renderAllRows = true` | 0 |
| Voies de la racine React | transition en attente, intriquée avec celle du `Transitioner`, jamais suspendue |
| Écho `MessageChannel` sur 300 ms | 58 (rendu en tranches de 5 ms) |
| Profil CPU | `ModificationControl` : 52 % du temps en inclusif |
| Commits de `ModificationControl` | environ 2 500 par seconde (5 800 sur la démo) |
| Événements du cache de requêtes | options recalculées à chaque rendu, aucun résultat modifié dans la boucle |

## Correctif

`apps/desktop/src/renderer/components/layout/ModificationControl.tsx` : valeur par défaut stable
`NO_OFF_REPOS`, déclarée hors du composant. Le commentaire de `ExcelView` qui attribuait l'échec du
rendu complet aux re-rendus urgents « de la vue » est corrigé ; le rendu immédiat vers la ligne
ciblée (GH229) reste utile et n'est pas modifié.

| Mesure après correctif (copie de PH2) | Résultat |
|---|---|
| `tr[data-node-id]` | 196 |
| Profil CPU | 99,9 % au repos |
| Rendus de `ModificationControl` | 17 au total, stable sur 10 s |

### Recensement du même motif

Recherche des valeurs par défaut instables (`data: x = []`, `{}`, `new Map`, `x ?? []`) citées en
dépendance d'un effet qui modifie un état. Deux autres cas, sans boucle car gardés par une référence
qui rend l'effet à usage unique :

- `routes/query.tsx:214` (`savedQueries`, `history`) : `loadedRef` ;
- `components/sidebar/version/VersionCompareSelector.tsx:75` (`refs`) : `initializedRef`.

Ils ne sont pas modifiés. La recherche est textuelle : le test GH246-2 couvre le symptôme sur les vues
principales, quelle que soit la forme du code.

## Tests

`apps/desktop/e2e-web/gh246-render-loop.spec.ts` :

- **GH246-1** : avec 60 exigences de plus, le Tableau rend plus de 60 lignes. Sans le correctif : 51.
- **GH246-2** : le thread est au repos sur Suivi, Exigences, Tests, Campagnes, Paramètres et Version.
  Sans le correctif (vue Exigences, seule rejouée) : 58 échos pour un seuil de 200.

## Comment vérifier

1. Ouvrir PH2, Exigences, vue Tableau, sur un type de plus de 50 éléments : toutes les lignes sont là,
   la dernière est atteignable en défilant.
2. Gestionnaire des tâches, projet ouvert sans action : le processus de rendu de Polenta ne consomme
   plus un cœur en continu.
3. « Publier » avec une branche hors intégration (GH133) : la case « Fusionner » reprend le dernier
   choix mémorisé, comme avant.
