# GH256 — Client web : exécution refusée dès qu'une version existe, popup d'issue inutilisable

## Root cause

Les canaux `tested-config:*` (#202) et `issues:*` (#244) étaient masqués sur le web (`WEB_HIDDEN`), alors que `tests:execute` et les écrans qui en dépendent y restaient disponibles.

- **Exécution** : sans `tested-config:context`, l'écran ne montre pas le choix de version et n'envoie pas `testedVersion`. Le serveur refuse pourtant la saisie (`TESTED_VERSION_REQUIRED`) dès que le repo a une version sélectionnable. La page d'exécution produisait aussi une erreur 404 en console, cause de 5 échecs e2e.
- **Issues** : après un FAIL ou un BLOCKED, la popup s'ouvrait sans pouvoir lire ni créer d'issue. Le panneau Issues restait vide.
- **Classeur** : `web:execution-sheet-export` et `web:execution-sheet-preview` ne recevaient pas `workspaceDir`, contrairement au desktop. Les colonnes de composant manquaient donc à l'export, et l'aperçu d'un classeur desktop pouvait les signaler à tort comme non documentées.
- **`gh56`** attendait encore la barre d'activité sans le bouton « Issues ».

## Correctif

- Exposer `tested-config:context`, `tested-config:drift`, `issues:list`, `issues:get`, `issues:create`, `issues:update` et `issues:add-run`.
- `issues:add-decision` reste masqué : il ne sert qu'à la vue Validation, masquée sur le web (#252).
- Transmettre `workspaceDir` aux deux canaux du classeur web (handlers, pont du renderer, `ROOT_ARGS`).
- Mettre à jour `gh56` et SPEC-WEB §11.

Les canaux `versions:*` et `validations:*` restent masqués : ils relèvent de #252. Une version ne peut donc pas encore être créée depuis le web, mais elle peut y être choisie à l'exécution.

## Comment vérifier

- e2e : `pnpm build:web`, puis `npx playwright test e2e-web/gh256- e2e-web/gh56-activity-bar e2e-web/gh68-unapproved e2e-web/gh73-campaign-history e2e-web/gh80-execute-switch e2e-web/gh81-no-write-on-read e2e-web/gh81-verif e2e-web/s2-core`.
- Manuel, sur le client web, dans un repo avec une version créée depuis le desktop :
  1. Exécuter un test de campagne : le choix de version est présent et obligatoire.
  2. Saisir FAIL : la popup propose de créer une issue, et sa création aboutit.
  3. Ouvrir le panneau Issues : l'issue y figure.

## Non couvert

Le passage de `workspaceDir` au classeur n'a pas de test de comportement dédié : `ROOT_ARGS` et `s2-core` vérifient le canal, pas le contenu des colonnes de composant.
