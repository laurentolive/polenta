# GH265 — Liste Composant / Élément : deux types de même libellé donnent des lignes identiques

Issue : #265 — bug.

## Root cause

Les listes de choix d'un type d'objet affichent `type.label || type.name` sans regarder les autres
types de la même liste. Deux types d'un même composant et d'une même catégorie qui portent le même
libellé (cas `hmi-PH2` : `HMI_PH2_REQ` et `VE22D_SW_REQ`, tous deux « Exigence ») donnent donc deux
lignes identiques (« HMI VE22D / Exigence »), impossibles à distinguer.

## Correctif

Nouvelle fonction `typeChoiceLabel(type, siblings)` (`apps/desktop/src/renderer/lib/typeLabels.ts`) :
renvoie le libellé du type, ou son nom technique si un autre type de la même liste affiche le même
libellé. Un type de libellé unique garde son libellé ; un type sans libellé affiche son nom, comme
avant.

`siblings` = les types qui partagent le même préfixe d'affichage : même nœud et même catégorie
dans les listes préfixées par le composant ; tous les types de la liste dans les listes déroulantes
« Type », qui n'affichent pas le nœud. Appliquée partout
où une liste de choix énumère des types :

- `SystemViewContext` — liste « Composant / Élément » des panneaux Exigences / Tests / Campagnes
  (le cas de l'issue) ;
- `getObjectTypeRefs` (`useProjectSchema`) — choix du type dans la nouvelle campagne, le
  sélecteur de tests de campagne, la proposition d'issue, le sélecteur d'éléments d'une version ;
- les listes déroulantes « Type » de `req.new`, `test.new` et `test.$testId`.

Non modifiés : `RequirementsPanel` / `TestsPanel` (plus importés nulle part) et les affichages d'un
type isolé (en-têtes, structure du schéma), où aucune confusion n'est possible.

## Tests

- Unitaire : `apps/desktop/src/renderer/lib/typeLabels.gh265.test.ts`.
- e2e : `apps/desktop/e2e-web/gh265-type-choice-label.spec.ts` — ajoute un composant à trois types
  d'exigence (deux de même libellé, un unique) et vérifie les lignes de la liste Composant /
  Élément : `… / GH265_HMI`, `… / GH265_SW`, `… / GH265 Sécurité`.

## Comment vérifier

1. Ouvrir un projet dont un composant a deux types d'exigence de même libellé (ex. `hmi-PH2`, ou
   renommer dans le schéma deux types d'un même nœud avec le même libellé).
2. Panneau Exigences → liste Composant / Élément : les deux lignes affichent le nom technique
   (`HMI VE22D / HMI_PH2_REQ`, `HMI VE22D / VE22D_SW_REQ`) ; les autres lignes gardent leur libellé.
3. Nouvelle exigence depuis ce composant : la liste « Type » distingue aussi les deux types.
