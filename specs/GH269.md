# GH255 + GH269 — Élément de composant vu depuis le produit

Trouvés pendant #202 (#255) et à la revue du milestone D (#269), à la lecture du code.

## Décision (humain, 2026-11-05)

**Une campagne ne contient que les tests de son repo.** Un test de composant se teste dans une campagne de son composant.

Le cas « test de composant dans une campagne produit » n'était qu'à moitié pris en charge. Un test de type composant créé depuis le produit
est écrit dans le repo du composant, mais il n'est indexé qu'en mémoire côté produit : après un redémarrage, le produit ne le voit plus, et
son exécution depuis la campagne échoue.

## Correctifs

| Point | Correctif |
|---|---|
| #255, test de composant en campagne produit | Création et ajout refusés : `TEST_OTHER_REPO`, avec les ID. Repo du test lu à son type, comme à sa création |
| #269.1, fausse « non couverte » dans les tests à exécuter | Couverture jugée sur tous les tests du workspace. Seuls les tests du repo de la version restent proposés |

## Sans objet après la décision

- **#269.2, popup d'issue évaluée sur le repo de la campagne :** le test est toujours de ce repo.
- **#269.3, grille d'historique « campagne introuvable » :** un run désigne toujours une campagne de son repo.
- **GH202 critère 7 :** barré dans `GH202.md`. `SPEC-TESTS` est corrigé.

## Conservé, avec motif

- **#269.4, historique des exécutions d'un test d'un autre repo :** limité au repo ouvert. La vue Validation l'affiche « autre composant », avec un lien vers le test. Un test se valide dans la validation de son composant.
- **Campagnes existantes qui contiendraient déjà un test de composant :** non migrées. Le refus porte seulement sur l'ajout.

## Doutes vérifiés

- **Contournement de `NOT_OWN_ELEMENT` sans `workspaceDir`** (`ipc/index.ts:440`) : c'est l'ancien chemin d'un projet sans workspace. Les écrans du milestone passent `workspaceDir` quand un projet est ouvert. Non modifié.
- **`issue-impact` absent du schéma** et **vues d'équipe sur un nœud local `readonly`** : non reproduits, non modifiés. À rouvrir s'ils sont constatés.

## Comment vérifier

- Tests : `npx vitest run src/main/services/campaigns.service.gh255 src/main/services/versions.gh245`.
- Manuel :
  1. Depuis le produit, ajouter un test de composant à une campagne : refus nommant le test.
  2. Version produit dont un composant change une exigence couverte par un test du composant : la liste « non couvertes » des tests à exécuter ne la cite pas.
