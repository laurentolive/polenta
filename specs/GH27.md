# GH27 — Accueil : page de chargement en boutons + projet de démonstration Lave-linge LL800

## Contexte

Un workspace de démonstration public, « Lave-linge LL800 », illustre l'ensemble des fonctionnalités
de Polenta : multi-repo, composants locaux imbriqués, interfaces, paramètres, campagnes,
baselines, Suivi… Il est généré par `scripts/demo-lave-linge/generate.mjs` et publié sur GitHub :

- repo racine : `https://github.com/laurentolive/demo-ll800-produit.git` ;
- dépendances déclarées dans son `polenta-repo.yaml` : `demo-ll800-comp-moteur`,
  `demo-ll800-comp-pompe-vidange`, `demo-ll800-comp-module-wifi`, `demo-ll800-if-bus-interne`.

La page de chargement de projet (`/`) affiche aujourd'hui trois formulaires empilés, avec leurs
champs toujours visibles. La page est chargée visuellement et ouvrir un projet demande plusieurs
clics : remplir un champ, ouvrir le sélecteur, valider. Rien n'oriente non plus un nouvel
utilisateur vers un projet pour découvrir l'outil.

## Objectif

1. Proposer le projet de démonstration directement sur la page.
2. Refondre la page en **boutons d'action** qui donnent une sensation de facilité, en
   **minimisant le nombre de clics** : seuls les champs réellement nécessaires sont demandés, au
   moment où ils le sont.

## Description fonctionnelle

La page `/` n'affiche plus de formulaires. Elle présente quatre gros boutons d'action en colonne
centrée, chacun avec un libellé, une icône et une ligne d'explication :

```
                ┌──────────────────────────────────────────┐
                │ ▶  Découvrir Polenta avec le projet de   │
                │    démonstration                         │
                │    Lave-linge LL800 — toutes les         │
                │    fonctionnalités sur un projet complet │
                └──────────────────────────────────────────┘
                ┌──────────────────────────────────────────┐
                │ 📂 Ouvrir un projet existant              │
                └──────────────────────────────────────────┘
                ┌──────────────────────────────────────────┐
                │ ⬇  Ouvrir un projet depuis un repo        │
                │    existant                              │
                └──────────────────────────────────────────┘
                ┌──────────────────────────────────────────┐
                │ ＋ Créer un nouveau projet                │
                └──────────────────────────────────────────┘
```

Le bouton de démonstration est mis en avant (premier, style principal). Les trois autres ont un
style secondaire.

**Principe de saisie** : on ne demande que les informations nécessaires, au moment où elles le
sont.
- Un **dossier** se choisit par le sélecteur natif de l'OS (`dialog:pick-folder`, existant). Il n'y
  a pas de dossier par défaut : l'utilisateur choisit son chemin, comme aujourd'hui.
- Une **information textuelle** (URL Git, nom de projet) se saisit dans un **popup**. Le champ a le
  focus à l'ouverture et `Entrée` valide.
- Un seul nouveau canal IPC, `workspace:is-empty-dir`, pour le cas D3.

### Parcours par bouton

| Bouton | Enchaînement | Clics minimum |
|--------|--------------|---------------|
| **Découvrir… (démo)** | Clic → sélecteur natif « Dossier du projet » → chargement → ouverture du projet | 1 clic + choix du dossier |
| **Ouvrir un projet existant** | Clic → sélecteur natif « Dossier du projet » → ouverture | 1 clic + choix du dossier |
| **Ouvrir un projet depuis un repo existant** | Clic → popup « URL du repo Git » (champ avec focus, coller puis `Entrée`) → sélecteur natif « Dossier du projet » → clone → ouverture | 1 clic + collage + `Entrée` + choix du dossier |
| **Créer un nouveau projet** | Clic → popup « Nom du projet » (champ avec focus, saisie puis `Entrée`) → sélecteur natif « Dossier du projet » → création → ouverture | 1 clic + saisie + `Entrée` + choix du dossier |

- **Annulation** : `Échap` ou « Annuler » dans le popup, ou annulation du sélecteur natif, ramène à
  la page sans rien faire et sans message d'erreur.
- **Validation du popup** : impossible tant que le champ est vide (bouton désactivé, `Entrée`
  sans effet).
- **Pendant l'opération** (clone, création, ouverture) : un état de chargement visible remplace
  l'ancien libellé du bouton (« Chargement… », « Clonage… », « Création… »). Les autres boutons
  sont désactivés pour éviter les doubles lancements.
- **Erreur** : message affiché sous le bouton concerné, même présentation qu'aujourd'hui. Il est
  effacé au lancement suivant.
- **Succès** : même navigation qu'aujourd'hui (`markRecent` puis `/schema`).

### Projet de démonstration — cas particuliers

L'URL du repo racine de la démo est fixe et codée en dur. Le dossier choisi est le **dossier du
projet** : il contiendra `.polenta/workspace.yaml`, le repo racine et les dépendances clonées.
C'est le même rôle que le dossier de « Ouvrir un projet depuis un repo existant ».

| # | Dossier choisi | Comportement |
|---|----------------|--------------|
| D1 | Vide | Clone du repo racine, puis ouverture du workspace, qui clone les 4 dépendances aux pins déclarés. Navigation vers le projet. |
| D2 | Contient déjà un projet Polenta (`.polenta/workspace.yaml`), par exemple une démo déjà chargée | **Pas de nouveau clone** : le projet existant est ouvert (comme « Ouvrir un projet existant »). |
| D3 | Non vide, mais pas un projet Polenta | Message d'erreur : choisir un dossier vide ou un projet existant. Rien n'est écrit. |
| D4 | Échec réseau ou dépôt inaccessible | Message d'erreur. L'utilisateur peut relancer. |

Le sélecteur natif permet de créer un nouveau dossier (option `createDirectory` déjà active) : on
obtient un dossier vide sans quitter le sélecteur.

## Comportements conservés

- Le flux de démarrage (§16.1) est inchangé : vérification du compte, puis ouverture directe du
  dernier projet s'il existe. Sinon, la page `/` s'affiche.
- Les opérations derrière chaque bouton sont celles d'aujourd'hui : `openProject` (avec le message
  « pas un projet Polenta » en cas de `not-a-workspace`), `createFromClone`, `createNew`.
- Le contrôle « dossier non vide / pas un projet » de la démo (D2/D3) s'appuie sur
  `workspace:detect` (existant) et sur un nouveau canal `workspace:is-empty-dir`. Ce canal est le
  seul ajout IPC, validé par l'humain en phase Design.

## Critères d'acceptation

1. La page `/` n'affiche que les quatre boutons, sans champ de saisie visible au repos. Le bouton
   démo est le premier et il est mis en avant.
2. « Ouvrir un projet existant » : un clic ouvre directement le sélecteur natif. Choisir un dossier
   de projet ouvre le projet sans autre clic.
3. « Découvrir… (démo) » : un clic ouvre directement le sélecteur natif. Avec un dossier vide, on
   obtient `.polenta/workspace.yaml`, `demo-ll800-produit/`, `comp-moteur/`, `comp-pompe-vidange/`,
   `comp-module-wifi/` et `if-bus-interne/`, puis le projet s'ouvre sur `/schema` et apparaît dans
   les Récents.
4. Démo sur un dossier qui la contient déjà : le projet s'ouvre sans clone réseau.
5. Démo sur un dossier non vide qui n'est pas un projet Polenta : message d'erreur, dossier non
   modifié.
6. « Ouvrir un projet depuis un repo existant » : popup avec le seul champ « URL du repo Git », qui
   a le focus. `Entrée` enchaîne sur le sélecteur natif, puis le clone et l'ouverture.
7. « Créer un nouveau projet » : popup avec le seul champ « Nom du projet », qui a le focus.
   `Entrée` enchaîne sur le sélecteur natif, puis la création et l'ouverture.
8. Annuler (`Échap` ou bouton dans le popup, annulation du sélecteur) ne produit ni action ni erreur.
9. Pendant une opération : état de chargement visible, autres boutons désactivés. En cas d'échec :
   message sous le bouton concerné.
10. Tous les textes sont traduits (FR et EN). Le seul canal IPC ajouté est `workspace:is-empty-dir`.

## Hors scope

- Charger la démo sans compte configuré : la page `/` reste derrière `auth:has-any-account` (§16.1).
- Mettre à jour (pull) ou réinitialiser une démo déjà chargée.
- Rendre l'URL de la démo configurable.
- Dossier par défaut ou mémorisation du dernier dossier choisi.
- Écran `/login` et sidebar Récents : inchangés.
- Corriger les défauts révélés par la démo (#21, #22, #23).
