# GH276 — Branche d'intégration : écarts restants de #106

Issue : #276, relevée par la revue du milestone C.

## 1. Le graphe créait une `int-*` sans la désigner

**Root cause** : « Créer branche depuis commit… » et « depuis un tag » appelaient `sync.createBranchAt`
quel que soit le nom. Une `int-*` créée ainsi héritait du `project.yaml` de son point de départ (cas
PH2), ce qui rompt la décision 2 de `GH103.md`.

**Correctif** :

- `graph.tsx` : un nom `int-*` passe par `integration:create`, depuis le commit ou le tag choisi, puis
  propage le pin comme un checkout. Avertissements de la désignation (push, branche par défaut)
  affichés dans la saisie.
- La désignation fait un checkout. Comme les checkouts de ce menu, elle n'est proposée que sans
  modification en attente ; sinon, la saisie l'explique.
- `IntegrationBranchService.createAndDesignate` : `from: { tag } | { commit }`. Avec #21, une baseline
  annotée est un point de départ valide.

## 2. La garde laissait supprimer la dernière `int-*` sur `origin`

**Root cause** : pour une suppression sur `origin`, `assertDeletable` comptait aussi les branches
locales. Une `int-*` seule sur `origin`, mais présente en local, pouvait être supprimée de la forge.

**Correctif** : sur `origin`, seules les `int-*` d'`origin` comptent. En local, rien ne change : la
branche d'`origin` reste récupérable.
