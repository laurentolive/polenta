# GH28 — Packaging NSIS local en échec : chemin du store pnpm > MAX_PATH

Type : bug — issue #28 (découvert pendant #26)

## Root cause

pnpm 9.0.0 nomme les dossiers de `node_modules/.pnpm` avec la liste complète des peer
dependencies, suivie d'un hash : pour `app-builder-lib`, le dossier fait ~120 caractères
(`app-builder-lib@24.13.3_dmg-builder@…_lrspnoputfiosacwyigcypdbdi`). L'include NSIS
`…\app-builder-lib\templates\nsis\include\allowOnlyOneInstallerInstance.nsh` atteignait alors
**260 caractères** depuis `C:\Dev\polenta_ws\polenta-official`, soit la limite `MAX_PATH`.
`makensis` (binaire 32 bits, sans prise en charge des chemins longs) ne peut pas ouvrir le
fichier → `pnpm package` échoue à l'étape NSIS.

## Correctif

- `package.json` : `packageManager` `pnpm@9.0.0` → `pnpm@9.15.9`. Le réglage
  `virtual-store-dir-max-length` n'existe qu'à partir de pnpm 9.1.
- `.npmrc` : `virtual-store-dir-max-length=60`. pnpm tronque les noms de dossiers de
  `node_modules/.pnpm` à 60 caractères et les complète d'un hash
  (`app-builder-lib@24.13.3_dmg-build_lrspnoputfiosacwyigcypdbdi`).

Aucun code applicatif n'est modifié. Commit : 3f86ba2.

## Vérification

Mesures faites après `pnpm install` :
- nom de dossier le plus long dans `node_modules/.pnpm` : 60 caractères ;
- chemin complet de `allowOnlyOneInstallerInstance.nsh` : **200 caractères** (contre 260) ;
- `pnpm package` en local : l'installateur NSIS est bien produit.

Manuel :
1. Vérifier `pnpm --version` ≥ 9.1 (9.15.9 attendu), puis supprimer `node_modules` et lancer
   `pnpm install`.
2. `ls node_modules/.pnpm`. Aucun nom ne doit dépasser 60 caractères.
3. `pnpm package` doit se terminer sans erreur `makensis` « Can't open … .nsh ».

Si on clone dans un répertoire plus profond, il reste ~60 caractères de marge avant MAX_PATH.
