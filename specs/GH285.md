# GH285 — e2e gh228-navigation E5 : popup « Quitter cette page ? » sans modification

Issue : #285 — branche `milestone-C`.

## Constat

`e2e-web/gh228-navigation.spec.ts` E5 échouait pendant la suite complète du merge de milestone-C
(2026-11-05) : sur une exigence ouverte sans rien modifier, `Alt+←` ouvrait « Quitter cette
page ? ».

## Root cause

`req.$reqId.tsx` et `test.$testId.tsx` calculaient `hasChanges` dès que l'objet était chargé,
alors que le formulaire (`title`, `fields`…) n'est copié depuis l'objet que dans un `useEffect`.
Pendant le rendu entre l'arrivée des données et cette copie, le formulaire vide était comparé à
l'objet chargé, la page se déclarait modifiée (`useRegisterTabDirty`) et la navigation était bloquée.

L'échec ne se reproduit pas sur `milestone-C` seul : E5 passe 25 fois sur 25 (`--repeat-each 5`
sur toute la spec) avant le correctif. Il devient systématique avec 1339363 (GH206 sprint 2,
milestone-D), qui ajoute du travail à ce rendu. L'échec relevé sur `main`/`milestone-C` vient
très probablement d'un passage simultané de la suite de milestone-D, qui partage les ports e2e
avec les autres worktrees. La même correction a été faite sur milestone-D (cc522ee, `[GH206]`).

## Correctif

`hasChanges = req && initialized ? … : false` (et `tc && initialized` pour un cas de test) : la
page n'est pas « modifiée » tant que le formulaire n'a pas copié l'objet. Le code est identique à
cc522ee, donc le merge des deux milestones dans `main` ne crée pas de conflit.

## Comment vérifier

- `npx playwright test e2e-web/gh228-navigation` (après `pnpm build:web`) : E5 vert.
- À la main : ouvrir une exigence ou un cas de test, ne rien modifier, `Alt+←` revient en
  arrière sans popup. Modifier le titre puis `Alt+←` ouvre bien la popup.
