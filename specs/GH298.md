# GH298 — Campagne : un ID de test inconnu du repo est accepté (entrée sans copie)

Issue : #298. Constaté pendant #278 (2026-11-05).

## Root cause

`CampaignsService.snapshotsFor` omet de sa map tout ID qu'il ne résout pas dans le repo de la campagne
(choix T49 : un test supprimé entre l'affichage du panneau et l'appel ne devait pas faire échouer un
ajout groupé). Le contrôle GH255 `assertOwnTests` ne parcourait que cette map : un ID introuvable
(test d'un composant en repo séparé, ou ID qui n'existe nulle part) n'était jamais contrôlé, et
`makeRun` créait l'entrée avec `testSnapshot: undefined`.

## Chemins recensés

| Chemin | Avant | Après |
|--------|-------|-------|
| `create` (IPC, MCP) | entrée sans copie | refus |
| `addTests` (IPC, MCP) | entrée sans copie | refus |
| `duplicateTest` | entrée sans copie, pas de contrôle GH255 | refus (mêmes contrôles) |
| Report depuis une autre campagne (`buildCarriedRuns`, GH64) | test introuvable ignoré | inchangé : sélection invalide ignorée par conception |
| Lecture (`effectiveTests`, `previewParams`) | ID ignoré | inchangé (pas d'écriture) |

## Correctif

`assertOwnTests(repoPath, requestedIds, snapshots, workspaceDir)` contrôle les ID **demandés**, plus
seulement ceux trouvés :

- trouvé dans le repo : contrôle GH255 inchangé (test d'un autre nœud sans fichier dans le repo →
  `TEST_OTHER_REPO`) ;
- introuvable, mais `tests/<ID>.yaml` existe dans le repo d'un composant du projet (nœuds du schéma
  hors `root`, résolus par `resolveComponentRepoPath`) → `TEST_OTHER_REPO: <ID> …` ;
- introuvable ailleurs → `TEST_NOT_FOUND: <ID> — test introuvable dans le repo de la campagne.`

Un ID qui n'est pas un simple identifiant (`[A-Za-z0-9_-]+`) n'est cherché dans aucun composant (il
sert de nom de fichier). Le refus intervient avant toute écriture : la campagne n'est ni créée ni
modifiée. Le sélecteur de l'interface ne liste que les tests du repo : seul un appel hors interface
(MCP, ou test supprimé entre l'affichage et la validation) rencontre ces erreurs.

Fichiers : `apps/desktop/src/main/services/campaigns.service.ts`,
`apps/desktop/src/main/services/campaigns.service.gh298.test.ts` (nouveau).

## Comment vérifier

- Unitaires : `npx vitest run src/main/services/campaigns.service.gh298` (4 tests : création avec un
  test de composant et avec un ID inexistant, ajout et duplication, ID non simple). Sans le correctif,
  les 4 échouent.
- Manuel (démo générée, `pnpm --filter @polenta/desktop demo:generate`) : par le serveur MCP, créer
  une campagne de `ll800-produit` (`objectTypeRef: root::campagne-produit`) avec `testCaseIds:
  ['TMOT-0003']` → erreur `TEST_OTHER_REPO: TMOT-0003` ; avec `['TOTO-0001']` → `TEST_NOT_FOUND:
  TOTO-0001` ; aucune campagne créée. Avec un test du produit : campagne créée, entrée avec sa copie.
