# GH307 — Version released : tag local parfois non créé (e2e gh252 U4 intermittent)

## Root cause

Le tag n'était pas « non créé » : il était créé **sous un autre nom**. Les dépôts de trois exécutions
en échec (GH306, `%TEMP%/polenta-e2e-web/1793977972930`, `…8318362`, `…8403009`) portent tous le tag
`demo-ll800-produit-9.9gh252-9.9`, dans `freeze.tag` de la version comme dans
`.git/polenta-pending-tags` — d'où le badge `version-tag-pending` affiché alors que
`git tag --list gh252-9.9` reste vide.

Dans `ReleaseVersionDialog`, le champ du tag est éditable dès l'ouverture, avant que le tag proposé
(`versions:release-preview`, `<projet>-<label>`) ne soit chargé, et sa valeur vaut
`typed ?? suggestedTag ?? ''`. Quand la réponse arrive **pendant** la saisie — pour Playwright entre la
sélection du contenu (vide) et l'insertion du texte de `fill` ; pour un utilisateur entre le clic dans
le champ vide et la frappe —, le tag proposé s'affiche sous le curseur, placé en fin de valeur, et le
texte saisi s'y ajoute. Le résultat est un nom de tag valide : les contrôles passent et la version
est released sous `<proposé><saisi>`. L'intermittence (~1/3 sous charge, 0/6 sur un poste au repos)
vient uniquement du temps de réponse du canal.

L'application est donc en cause (pas un délai d'attente trop court du test) : la création du tag
elle-même est synchrone et correcte.

## Correctif

`apps/desktop/src/renderer/components/versions/ReleaseVersionDialog.tsx` : le champ du tag est
`readOnly` tant que la prévisualisation initiale charge (`isLoading`). Une fois le tag proposé
affiché, il ne change plus (`typed` prend la main dès la première frappe) ; les contrôles suivants
(`checkedTag`, `placeholderData`) ne rendent pas le champ à nouveau non éditable.

## Test

`apps/desktop/e2e-web/gh252-versions.spec.ts` U4 : la réponse de `versions:release-preview` est
retenue (`page.route`) ; le champ doit être non éditable, puis éditable et pré-rempli une fois la
réponse livrée, avant le `fill('gh252-9.9')`.

- Avant correctif : 3/3 échecs déterministes (`not.toBeEditable` : champ éditable). En rejouant les
  étapes internes de `fill` (sélection, réponse livrée, insertion), la valeur obtenue est exactement
  `demo-ll800-produit-9.9gh252-9.9`. La spec d'origine, en boucle (`--repeat-each 6`), passait 6/6
  sur poste au repos : la course n'apparaît que sous charge.
- Après correctif : `--repeat-each 6` → 30/30.

## Comment vérifier

1. `cd apps/desktop && pnpm build:web && npx playwright test e2e-web/gh252-versions.spec.ts --repeat-each 6`.
2. À la main (client web ou desktop) : ouvrir une version en cours, « Passer released » ; tant que le
   tag proposé n'est pas affiché, le champ refuse la saisie ; ensuite, remplacer le tag proposé par un
   autre et confirmer : le tag créé (`git tag --list`) est exactement celui saisi.
