# GH312 — e2e : « Soumettre le résultat » ne quitte pas la page d'exécution

Issue : #312 (type:bug). Bug **dans les tests**, pas dans l'application.

## Root cause

Depuis GH202, une exécution de campagne exige la **version testée** dès que le repo déclare une
version sélectionnable (`TestedVersionPicker`, contrôle dans `submitExecution` de
`renderer/routes/campaign.$campaignId_.execute.$testId.tsx`, avant même la confirmation GH68 d'un
test non approuvé). La démo `demo-ll800-produit` déclare des versions depuis GH278 ; GH278 a adapté
certaines specs (gh196, gh197, `support/campaign.ts#recordResult`) mais pas celles qui soumettent
une **première** exécution par l'interface sur une campagne créée par le test (pas de pré-remplissage
possible) : le clic sur « Soumettre le résultat » affiche « La version testée est obligatoire. » et
la page ne bouge pas — `waitForURL` (gh73) ou le clic sur « Exécuter quand même » (gh68, gh81)
attend jusqu'au timeout.

Specs concernées : `gh73-campaign-history` 1.5/1.6, `gh68-unapproved` E1–E3,
`gh81-no-write-on-read` E1–E2, `gh81-verif` M1 + E2.

## Correctif

- `apps/desktop/e2e-web/support/campaign.ts` : helper `chooseTestedVersion(s)` — choisit dans
  `tested-version-select` la version en cours retenue par `testedVersionArg` (même règle que les
  exécutions par IPC) ; ne fait rien sur un repo sans version.
- Les quatre specs l'appellent juste avant « Soumettre le résultat ». Les scénarios suivants d'un même
  fichier (ex. gh68 E6) profitent du pré-remplissage de la dernière exécution.
- `gh81-verif` M3, masqué jusqu'ici (série : il ne s'exécutait pas après l'échec de M1), échouait
  ensuite pour la même cause : le classeur exporté porte maintenant les colonnes de version testée et
  les résultats déjà saisis pré-remplis (GH196) ; rabattu en « v1 » (ordre fixe des colonnes), ces
  lignes ne correspondaient plus à leur signature et passaient pour 3 saisies au lieu d'1. Un vrai
  classeur v1 n'a ni l'un ni l'autre : `fillAsTester(…, v1)` vide désormais le verdict des lignes
  hors des tests saisis.

Aucun code applicatif modifié : niveau 3 non requis au titre du correctif.

## Comment vérifier

```
cd apps/desktop && pnpm build:web
npx playwright test e2e-web/gh73-campaign-history e2e-web/gh68-unapproved e2e-web/gh81-no-write-on-read e2e-web/gh81-verif
```

Les quatre fichiers passent. À la main (client web, démo) : ouvrir une campagne neuve, exécuter un
test sans choisir de version → « La version testée est obligatoire. » (comportement voulu, GH202) ;
choisir la version puis soumettre → retour à la campagne.
