# GH32 — Vue Suivi : widgets limités au repo produit à l'ouverture sans cache d'arbre

Type : bug · Issue #32

## Root cause

À l'ouverture d'un projet, le renderer lance en parallèle `api.workspace.open` (qui, sans
`.polenta/tree.cache.yaml` valide, reconstruit l'arbre — parsing récursif, fetch/clone des
dépendances — puis écrit le cache) et les requêtes des widgets de la vue Suivi
(`api.queries.execute`). Côté main, `QueryEngineService.resolveRepos` lit le cache via
`WorkspaceTreeService.readCache` ; tant que la reconstruction n'a pas écrit le fichier, la
lecture renvoie `null` et le moteur retombe silencieusement sur le seul repo produit
(comportement mono-repo). Le résultat faux est ensuite gardé par react-query
(`['widget-query-result', …]`) : rien ne l'invalide quand l'arbre est prêt, d'où un dashboard
faux en changeant de vue et revenant, juste après un rechargement.

La même fenêtre existait pour `rebuildTree` (le cache est supprimé avant la reconstruction) et
pour tous les autres lecteurs du cache (traçabilité, revalidation, paramètres, schéma de
composant, conformité d'interface).

## Correctif

- `WorkspaceTreeService` tient une table des ouvertures/reconstructions en cours par
  `workspaceDir` (`trackBuild`). `readCache` attend la fin de celle en cours avant de lire le
  fichier — tous les lecteurs du cache sont donc corrigés d'un coup.
- `readCacheFile` : lecture sans attente, réservée au chemin d'ouverture lui-même
  (`isCacheValid`, court-circuit « cache valide » d'`openWorkspace`) — sinon l'ouverture
  attendrait sa propre promesse.
- `WorkspaceService.openWorkspace` et `rebuildTree` enregistrent leur travail via `trackBuild`
  (`rebuildTree` dès avant la suppression du cache). Corps d'ouverture déplacé dans
  `doOpenWorkspace`, appelé directement par `rebuildTree`.
- Aucun changement renderer : la requête du widget reste en attente pendant la reconstruction
  et renvoie d'emblée le résultat multi-composants, que react-query peut garder en cache.

## Vérification

1. handstickProduct : supprimer `.polenta/tree.cache.yaml`, ouvrir le workspace, aller dans
   Suivi → les widgets affichent les 6 composants (chargement un peu plus long le temps de la
   reconstruction).
2. Changer de vue et revenir → toujours 6 composants.
3. Structure : ajouter/renommer une dépendance (déclenche `rebuildTree`) puis aller dans Suivi
   ou Traçabilité → les données incluent bien tous les composants.
4. Ouverture avec cache valide : aucun ralentissement (pas de reconstruction, rien à attendre).

`tsc --noEmit` (apps/desktop) : 0 erreur. Pas de tests automatiques pour les services main du
desktop.
