# GH328 — e2e gh107-create C-11 dépend de la spec lancée avant

## Root cause

Le serveur web mémorise, pour l'utilisateur e2e, le dernier projet ouvert (`workspace:get-last-opened`) :
`/` le rouvre (onglet du projet) au lieu d'afficher l'accueil. Ce dernier projet est partagé par toutes
les specs d'une exécution Playwright.

`setupSession({ project: null })` démarrait sans projet mais n'oubliait pas celui de la spec précédente.
`gh107-create` C-11 (`goto('/')` puis « Créer un nouveau projet ») échouait donc quand une spec qui
ouvre un projet le précédait (`gh106-designate` par exemple). Dans l'ordre de la suite complète, c'est
`gh107-adopt`, placé juste avant et qui appelle lui-même `workspace:clear-last-opened`, qui masquait
le problème. `s2-core` S2-1 faisait de même à la main.

## Correctif

`e2e-web/support/session.ts` : sans projet (`project: null`), le `beforeAll` appelle
`workspace:clear-last-opened` — `/` mène à l'accueil quelle que soit la spec lancée avant. Corrigé à la
source pour toutes les specs sans projet (gh107-adopt, gh107-create, gh108-repo-settings,
gh302-update, gh305-web-update, gh63-admin, gh63-sensitive, s2-core), pas seulement C-11.

## Vérifications

- Reproduction de l'issue (`gh106-designate` puis `gh107-create`) : C-11 en échec avant, 5/5 après.
- `pnpm typecheck` OK.
- Specs sans projet + voisines (gh106-structure, gh107-adopt, gh107-create, gh108-repo-settings,
  gh302-update, gh305-web-update, gh63-admin, gh63-sensitive, s2-core) : 34 passés, 3 échecs sur une
  exécution perturbée (1,7 h, mise en veille du PC). Relancées seules : gh63-admin et gh63-sensitive
  passent, s2-core passe sauf S2-2.
- s2-core S2-2 échoue sur ce poste quel que soit le correctif : le proxy d'entreprise (`HTTPS_PROXY`)
  est utilisé même pour la forge locale `127.0.0.1` listée dans `NO_PROXY` → issue #347.
