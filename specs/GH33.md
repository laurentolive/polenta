# GH33 — Campagnes : sélection des tests à ajouter via une vue Excel filtrable

**Statut** : spec en validation
**Issue** : laurentolive/polenta#33

## 1. Contexte

On ajoute des tests à une campagne à deux endroits :
- le formulaire de création (`/campaign/new`, section « Cas de test ») ;
- le panneau « + Ajouter des tests » de la page d'une campagne (`/campaign/$campaignId`).

Dans les deux cas, on dispose d'une liste de cases à cocher de 192 px de haut, qui n'affiche que
l'ID et le titre. Le filtrage se limite au nœud/type à la création et à un champ texte (ID/titre)
dans le panneau d'ajout. La saisie des paramètres (`TestParamFields`) et le choix des exigences
d'un test itérant (`ReqInstancePicker`, T179) se déplient dans cette même liste. Au-delà d'une
vingtaine de tests, choisir un sous-ensemble devient laborieux.

GH33 remplace ces listes par un **sélecteur en modale à deux étapes**. L'étape 1 est une grille
de type Vue Excel, en lecture seule, avec les filtres par colonne existants (T51). L'étape 2
sert à saisir les paramètres des tests retenus.

Décisions validées en phase Spec :
- **un type de test affiché à la fois**, choisi dans un sélecteur ; la sélection est conservée
  quand on change de type ;
- **les colonnes reprennent la configuration Vue Excel de l'utilisateur** pour ce type (colonnes
  visibles et ordre), en lecture seule ;
- **les dossiers de l'arbre sont affichés**, et la case d'un dossier coche/décoche ses tests
  visibles ;
- **modale à deux étapes** : sélection, puis paramètres ;
- **filtres** : uniquement le filtre global et les filtres par colonne existants. Aucun filtre
  propre aux campagnes.

## 2. Description fonctionnelle

### 2.1 Points d'entrée

Le sélecteur s'ouvre :
- **à la création** : un bouton « Sélectionner des tests… » remplace la liste de cases à cocher
  du formulaire. Sous le bouton s'affiche un **récapitulatif** de la sélection courante (ID,
  titre, nombre d'instances et paramètres saisis par test) avec un bouton « Modifier » qui
  rouvre la modale. Les tests préremplis (T46, `testCaseIds` dans l'URL) sont présélectionnés ;
- **dans une campagne active** (`planned`/`in_progress`) : le bouton « + Ajouter des tests »
  ouvre la modale à la place du panneau en ligne. La validation de l'étape 2 ajoute directement
  les tests à la campagne (`addTests()` / `duplicateTest()`, mêmes règles qu'aujourd'hui).

### 2.2 Tests proposés (inchangé)

Le sélecteur ne modifie pas les règles qui décident quels tests sont proposés. Il les reprend
telles quelles :
- **création** : tous les tests du repo, sans restriction de statut (comportement actuel) ;
- **ajout à une campagne** : uniquement les tests approuvés (`isApproval`). Un test déjà présent
  n'est proposé que dans deux cas : s'il a des références à saisir (nouvelle instance, T97), ou
  s'il est itérant et qu'une de ses exigences liées n'a pas encore d'instance (T179).

Les tests non proposés n'apparaissent pas dans la grille. Les dossiers restent affichés même
s'ils ne contiennent aucun test proposé (comme pour le filtre, T51).

### 2.3 Étape 1 — grille de sélection

**Disposition** : modale grand format (quasi plein écran), avec de haut en bas :
1. un **sélecteur de type de test** : combobox des types de catégorie `test` du repo, avec le
   même libellé que dans la vue système ;
2. le **filtre global** : champ texte avec ses options casse / mot entier / regex, même
   comportement que dans la vue système (T166) ;
3. la **grille** ;
4. un **pied de modale** avec le compteur, puis « Annuler » et « Suivant » (ou « Ajouter » si
   l'étape 2 est sautée, §2.4).

**Type affiché par défaut** :
- le type du filtre composant/niveau de la campagne ou de la route, s'il est défini ;
- sinon le premier type de test du repo.

Changer de type remplace le contenu de la grille et réinitialise les filtres par colonne, comme
dans la vue système (T51). Cela **ne modifie pas la sélection**.

**Grille** : même rendu que la Vue Excel de la vue système pour ce type :
- colonnes visibles et ordre issus de la configuration Vue Excel de l'utilisateur pour ce type ;
- hauteur max des lignes et nombre de colonnes figées repris des réglages existants ;
- dossiers affichés et repliables.

La grille est **en lecture seule** :
- pas d'édition de cellule (double-clic, F2, frappe) ;
- pas d'édition des liens ;
- pas de glisser-déposer ;
- pas de menu de création ;
- pas d'ouverture en édition.

Ce qu'on modifie dans la modale (repli de dossiers, colonnes figées, filtres) **n'est pas
persisté** et ne touche pas aux préférences de la vue système.

**Filtres** : le filtre global et les filtres par colonne fonctionnent exactement comme dans la
Vue Excel (T51, T166) : popover par colonne, combinaison en ET, regex invalide sans effet.

**Colonne de sélection** : une colonne de cases à cocher est placée en tête, figée.
- **Ligne de test, case à cocher** : la case bascule la sélection de ce test sans toucher au
  reste. Maj+clic sur une case applique le nouvel état de la case cliquée (coché ou décoché) à
  toute la plage de lignes de test **visibles** comprise entre l'ancre et cette ligne.
- **Ligne de test, clic sur la ligne** (hors case et hors lien), comme dans la Vue Excel
  (T149) :
  - **clic simple** : seul ce test est sélectionné parmi les lignes visibles ;
  - **Ctrl+clic** (Cmd+clic sous macOS) : bascule ce test, le reste est inchangé ;
  - **Maj+clic** : les lignes visibles sélectionnées sont remplacées par la plage entre l'ancre
    et la ligne cliquée ;
  - **Ctrl+Maj+clic** : la plage est ajoutée à la sélection, sans rien retirer.
- **Ancre** : c'est la dernière ligne de test cliquée sans Maj, que ce soit sur la case ou sur
  la ligne. Sans ancre, ou si l'ancre n'est plus visible (filtre, repli, changement de type),
  Maj+clic se comporte comme un clic sans Maj.
- **Tests non affichés** : aucun clic ne retire de la sélection un test non affiché (masqué par
  un filtre, d'un autre type, ou dans un dossier replié). Le clic simple et le Maj+clic ne
  remplacent que la sélection des lignes visibles, pour qu'un clic distrait n'efface pas ce qui
  a été choisi ailleurs.
- **Ligne de dossier** : un clic sur la ligne ne fait que replier ou déplier le dossier, sans
  toucher à la sélection. La case est cochée si tous les tests proposés visibles du dossier (à
  toute profondeur) sont sélectionnés, partielle (indéterminée) si seulement certains le sont,
  et vide sinon. Un clic coche tous ces tests, ou les décoche s'ils étaient tous cochés. Un
  dossier sans aucun test proposé visible a une case désactivée.
- **En-tête** : case « tout sélectionner », même logique que pour un dossier, appliquée à toutes
  les lignes de test **visibles** de la grille, filtres compris.

Pour un dossier comme pour l'en-tête, « visible » signifie « qui passe les filtres actifs ». Un
test caché parce que son dossier est replié est inclus.

**Indicateur « déjà présente »** (ajout à une campagne uniquement) : un test déjà inclus dans la
campagne affiche à côté de son ID le nombre d'instances existantes, comme le fait le panneau
actuel.

**Compteur** (pied de modale) : « N tests sélectionnés ». Si une partie de la sélection n'est
pas visible, il ajoute « dont M non affichés ». Les tests non affichés sont ceux que masquent
les filtres, ceux d'un autre type, ou, à la création, ceux préremplis hors du filtre
composant/niveau. Un lien « Vider la sélection » remet la sélection à zéro.

**Cas vides** :
- aucun test proposé pour le type affiché : la grille affiche le message existant (« Aucun test
  approuvé disponible » pour l'ajout, « Aucun cas de test disponible » à la création), avec le
  sélecteur de type toujours utilisable ;
- le repo n'a aucun type de test : la modale affiche seulement ce message et « Annuler ».

### 2.4 Étape 2 — paramètres et exigences

L'étape 2 liste **uniquement les tests sélectionnés qui demandent une saisie**, avec les mêmes
composants qu'aujourd'hui :
- **test itérant** (T179) : `ReqInstancePicker`, avec exigences liées cochées par défaut et
  décochables, valeurs en lecture seule, références à saisir par instance, exigences déjà
  instanciées grisées ;
- **test avec références à saisir** (T97/T171) : `TestParamFields`, avec les références
  résolues en lecture seule et les références non résolues accompagnées de leur raison.

Les tests sélectionnés sans saisie requise apparaissent en une ligne récapitulative repliée
(« K tests sans paramètre »), pour information.

**Navigation** :
- **« Précédent »** revient à l'étape 1 en conservant la sélection et les valeurs saisies. Les
  valeurs d'un test désélectionné entre-temps sont oubliées ;
- le bouton principal reprend le libellé actuel avec le nombre d'instances qui seront créées
  (« Ajouter (N) » ; à la création, « Valider la sélection (N) »). Il reste désactivé tant
  qu'une référence à saisir est vide, ou pendant le chargement de la prévisualisation
  (`isAddComplete`, règle inchangée) ;
- **étape 2 sautée** : si aucun test sélectionné ne demande de saisie, le bouton de l'étape 1
  devient directement « Ajouter (N) » ou « Valider la sélection (N) ».

**Prévisualisation des paramètres** : la résolution (`campaigns:preview-params`, avec le
`baselineRef` de la campagne ou celui saisi dans le formulaire de création) est calculée pour
la sélection à l'entrée de l'étape 2, ou dès l'étape 1 si c'est plus simple : ce choix est
laissé au Design. Ses règles ne changent pas (T171, T179).

### 2.5 Validation et annulation

- **Création** : valider ferme la modale et met à jour la sélection du formulaire (tests,
  `paramValues`, `reqInstances`). La campagne n'est créée qu'à la validation du formulaire,
  comme aujourd'hui. Rouvrir la modale restitue la sélection et les valeurs saisies.
- **Ajout à une campagne** : valider lance l'ajout. La modale se ferme en cas de succès ; en cas
  d'échec, elle reste ouverte avec l'erreur affichée.
- **Annuler** (bouton, `Échap` hors popover, clic hors modale) : ferme sans rien modifier. À la
  création, la sélection d'avant l'ouverture est conservée. Dans une campagne, rien n'est
  ajouté. Si la sélection a changé, une confirmation « Abandonner la sélection ? » s'affiche.
- `Échap` dans un popover de filtre colonne garde son comportement T51 et ne ferme pas la
  modale.

## 3. Critères d'acceptation

1. À la création et dans une campagne active, la sélection des tests se fait dans une modale ;
   l'ancienne liste de cases à cocher a disparu des deux pages.
2. La grille affiche les tests du type choisi avec les colonnes visibles et l'ordre de la
   configuration Vue Excel de l'utilisateur pour ce type, ainsi que les dossiers de l'arbre.
3. Aucune cellule n'est éditable, aucun glisser-déposer n'est possible, et aucune modification
   faite dans la modale (repli, colonnes figées, filtres) n'affecte la vue système.
4. Les filtres par colonne et le filtre global se comportent comme dans la Vue Excel (T51/T166).
5. Avec un filtre colonne actif, la case d'en-tête ne sélectionne que les tests visibles. Le
   compteur affiche alors « N sélectionnés, dont M non affichés » dès qu'un test sélectionné est
   masqué.
6. La case d'un dossier sélectionne tous ses tests proposés visibles (sous-dossiers compris), et
   passe à l'état indéterminé quand seule une partie est sélectionnée.
6b. Ctrl+clic bascule un test sans toucher au reste. Maj+clic sélectionne la plage visible
    entre l'ancre et la ligne cliquée ; Ctrl+Maj+clic l'ajoute à la sélection. Un clic simple
    sur une ligne ne garde que ce test parmi les lignes visibles. Dans tous les cas, les tests
    sélectionnés non affichés restent sélectionnés.
7. Si on sélectionne des tests d'un type, qu'on passe à un autre type, qu'on en sélectionne
   d'autres, puis qu'on valide, les tests des deux types sont ajoutés.
8. Les tests proposés sont les mêmes qu'avant GH33 : approuvés et non dédoublonnés pour l'ajout,
   tous les tests à la création.
9. Un test itérant ou à références à saisir apparaît à l'étape 2 avec les mêmes contrôles et la
   même règle de complétude qu'avant GH33 ; l'étape 2 est sautée quand aucune saisie n'est
   requise.
10. Le nombre d'instances créées et le contenu des campagnes (`runs`, `paramValues`,
    `resolvedParams`, `requirementId`) sont identiques à ce que produisait l'ancienne UI pour la
    même sélection.
11. Le préremplissage T46 présélectionne les tests transmis, y compris ceux hors du filtre
    composant/niveau, qui sont comptés « non affichés ».
12. Annuler ne modifie ni la sélection du formulaire de création, ni la campagne.

## 4. Hors périmètre

- Filtres propres aux campagnes : exigence couverte et ses descendantes, `needsRevalidation`,
  résultat de la dernière campagne, tags dédiés… À traiter dans une issue séparée si le besoin
  se confirme.
- Affichage de tests de plusieurs types dans une même grille.
- Persistance des filtres, du repli ou des colonnes figées propres au sélecteur.
- Changement des règles d'éligibilité. En particulier, la création reste sans contrôle
  « approuvé » (écart existant avec l'ajout, non traité ici).
- Tests de repos composants : le sélecteur couvre les mêmes tests qu'aujourd'hui (repo de la
  campagne, `api.tests.list(repoPath)`).
- « Dupliquer » une instance depuis la liste des tests de la campagne : inchangé.
