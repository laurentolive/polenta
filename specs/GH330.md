### S2-8 — coupure réseau : deux courses

1. **Avant la coupure** : le test coupait « la dernière socket routée » dès que le handler de
   `routeWebSocket` l'avait vue, sans preuve que la socket était ouverte côté page. Le bridge
   (`connectEvents`) n'émet `web:events-reconnected` que si une connexion a déjà abouti
   (`hadConnection`, posé dans `onopen`) : coupée avant, la reconnexion passe pour une première
   connexion et l'attente de `reconnected` échoue.
2. **Après la reconnexion** : avec `connectToServer`, la socket s'ouvre côté page avant que le proxy
   de Playwright ait atteint le serveur, et le serveur n'inscrit la socket qu'après `await pool.get`.
   L'écriture faite aussitôt peut émettre `repo:file-changed` vers personne.

Correctif (test seul) : `expectEventsFlow` prouve que le flux est branché de bout en bout — une
écriture côté serveur est reçue par la page — en renouvelant l'écriture (titre numéroté) toutes les
2 s jusqu'à 30 s. Appelé avant la coupure (la socket est donc ouverte) et après la reconnexion.
Ce que vérifie le test est inchangé : la reconnexion est signalée, et les événements circulent ensuite.

Côté produit, l'intervalle (2) existe aussi sans proxy (`await pool.get` avant l'inscription), mais
la reconnexion déclenche `invalidateQueries()` : un événement perdu là ne laisse pas d'état périmé.

### Serveur arrêté en cours de suite

Playwright ne signale pas un `webServer` qui s'arrête après son démarrage. Le serveur de test est
désormais lancé par `e2e-web/support/run-server.mjs`, qui précharge `e2e-web/support/server-watch.cjs` :

- le préchargement journalise un signal reçu (SIGINT / SIGTERM) et, à la sortie, le code, la durée de
  vie et le pic de mémoire ; il envoie sa mémoire au lanceur toutes les 5 s (canal IPC, non retenu) ;
- le lanceur, si le serveur s'arrête avant lui, écrit le code de sortie ou le signal, la dernière
  mesure de mémoire et le pic mesuré. C'est le seul témoin d'un arrêt brutal (`taskkill /F`, plantage
  natif), qui n'exécute aucun gestionnaire dans le serveur.

Ces lignes sortent sur stderr, affiché `[WebServer] [e2e] serveur web …` dans la sortie de la suite.
En fin de suite normale, Playwright tue l'arbre (lanceur compris) : aucune ligne.

Piste à confirmer au prochain arrêt : le serveur sort **silencieusement avec le code 0** sur SIGINT
(`src/web-server/index.ts`). Un Ctrl+C de console diffusé à tous les processus d'une même console
(arrêt d'une autre suite lancée depuis la même session) donnerait exactement le symptôme observé ; la
ligne `signal SIGINT reçu` le montrera.
