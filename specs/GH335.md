# GH335 — Checkout bloqué par des fichiers qui ne diffèrent que par les fins de ligne

## Root cause

`core.autocrlf=true` dans la config **système** de Git for Windows (invisible d'isomorphic-git) : les
fichiers sortis par git sont en CRLF sur le disque, en LF dans git. `git status` et le statut Polenta
(GH296) les voient inchangés, mais `git.checkout` d'isomorphic-git compare le contenu brut : un tel
fichier qui diffère entre la branche courante et la cible lève `CheckoutConflictError` (« Your local
changes … would be overwritten by checkout »). Vérifié sur handstickProduct (`int-PH2` → `int-tmp`) :
`.local.migrated.pref`, `.polenta/trees/root/PRODUCT_REQ.yaml`, `dashboards/.seeded.yaml` en CRLF,
blobs LF, index = HEAD.

## Correctif

`checkoutKeepingEol` (`eol-status.util.ts`) : sur `CheckoutConflictError`, si tous les fichiers en
conflit ne diffèrent de HEAD que par les fins de ligne (non stagés), ils sont réécrits tels que dans
HEAD puis le checkout est relancé ; une vraie modification locale bloque toujours. Utilisé pour tous
les checkouts non forcés (Checkout branche, checkout de commit, resync, Publier, retour arrière de
branche d'intégration, pin des sous-repos).

## Comment vérifier

- `eol-checkout.gh335.test.ts` (blocage reproduit, checkout qui passe, vraie modification qui bloque).
- Manuel : PH2/handstickProduct sur `int-PH2`, « Checkout branche » `int-tmp` → aboutit.
