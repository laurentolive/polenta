# GH347 — Proxy : NO_PROXY ignoré

## Root cause

`resolveProxyDispatcher(url)` (`apps/desktop/src/main/services/net-proxy.ts`) choisit le dispatcher
undici de **toutes** les requêtes HTTP sortantes de Polenta vers une forge : client git HTTPS
(`git-http.ts` : clone, fetch, push) et API de la forge (`forge-http.ts`). Dès que `HTTPS_PROXY` /
`HTTP_PROXY` était défini, il renvoyait un `ProxyAgent` pour toute cible, sans jamais lire
`NO_PROXY`. Sur un poste derrière un proxy d'entreprise (constaté avec Zscaler,
`NO_PROXY=localhost,127.0.0.1`), une forge interne ou locale était donc demandée au proxy, qui
refusait : `Proxy response (403) !== 200 when HTTP Tunneling`.

Recensement des autres consommateurs (aucun autre à corriger) :
- git CLI (remotes SSH, `sync.service.ts`) : lit `NO_PROXY` lui-même ;
- `fetch` global de Node (images distantes des gabarits, OIDC du serveur web) : n'utilise aucun proxy ;
- sans variable d'environnement, le repli `session.resolveProxy` (Chromium) applique déjà les
  exclusions du proxy système.

## Correctif

- `matchesNoProxy(url, NO_PROXY)` : même lecture que curl / git — entrées séparées par virgules ou
  espaces, insensible à la casse, `*`, hôte et sous-domaines (avec ou sans `.` / `*.` en tête),
  `hôte:port`, IP telle quelle, IPv6 avec ou sans crochets. Plages CIDR non reconnues.
- `resolveProxyDispatcher` : cible exclue → connexion directe (`Agent`), sans consulter le proxy
  système à la place. `NO_PROXY` puis `no_proxy`.
- `SPEC-TECH-stack.md` §9 : ligne « Proxy (T152, GH347) ».

## Vérifications

- `net-proxy.gh347.test.ts` : 24 cas (21 `matchesNoProxy`, 3 `resolveProxyDispatcher`) ;
  `net-proxy.gh15.test.ts` inchangé, vert.
- `pnpm typecheck` OK ; `pnpm test` OK (desktop 1798/1798).
- e2e web `s2-core` sur ce poste derrière Zscaler (`HTTPS_PROXY` + `NO_PROXY=localhost,127.0.0.1`) :
  S2-2 (clone depuis l'URL de la forge locale) en échec avant, `s2-core` 10/10 après.

## Comment vérifier à la main

Sur un poste avec `HTTPS_PROXY` défini et une forge listée dans `NO_PROXY` (ou `127.0.0.1` pour une
forge locale) : « Ouvrir un projet depuis un repo existant » avec l'URL de cette forge → clone et
ouverture, sans erreur « Proxy response ». Un repo GitHub passe toujours par le proxy.
