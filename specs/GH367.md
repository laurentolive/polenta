# GH367 — Branches d'intégration seulement sur le serveur absentes du sélecteur

Issue : #367 (type:bug)

## Constat

Sur un composant, plusieurs `int-*` ont été créées et poussées (toutes présentes sur GitHub). Les
autres utilisateurs ne voient dans le sélecteur de branche que la branche d'intégration désignée.

## Root cause

Le sélecteur de branche (`BranchCombobox`, onglet Structure via `RepoBranchSelector` et panneau
Version via `VersionRepoFolder`, tous deux par `useBranchCheckout`) lit `sync:branches`, et
`SyncService.listBranches` ne renvoyait que les branches **locales**. Un clone ne crée en local que
la branche par défaut de la forge (= la branche désignée) ; les autres `int-*` sont bien rapatriées
par le fetch (`refs/remotes/origin/*`), mais ne sont listées nulle part.

Le push n'est pas en cause : toutes les `int-*` sont sur la forge (confirmé par l'humain).

## Correctif

- `SyncService.listBranches` : après les branches locales, les branches présentes seulement sur
  `origin` (triées, sans `HEAD`), marquées `remoteOnly: true` (`BranchInfo.remoteOnly`).
- `BranchCombobox` : une branche `remoteOnly` porte le libellé « serveur » (info-bulle : la choisir
  crée la branche locale qui la suit), n'a pas de bouton de suppression, et se checkoute par
  `origin/<nom>` — le mécanisme GH138 crée la branche locale de suivi et la checkoute.
- `useBranchCheckout` : le pin propagé aux parents après un checkout est la branche réellement
  checkoutée (`CheckoutBranchResult.branch`, soit `int-B`), jamais l'étiquette `origin/int-B`.

Effet de bord voulu : `publishWorkspace` (choix du nom de la branche `dev-*`) évite aussi les noms
déjà présents sur le serveur.

## Tests

- Unitaire `sync.service.gh367.test.ts` : liste locale + seulement-distante (tri, sans `HEAD`) ;
  après checkout de `origin/int-B`, `int-B` est locale et courante ; repo sans remote inchangé.
- E2E `e2e-web/gh367-remote-branches.spec.ts` : une `int-*` présente seulement en ref distante
  apparaît dans la combo de l'onglet Structure avec « serveur » ; la choisir la checkoute en
  branche locale.

## Comment vérifier (à la main)

1. Poste A : sur un composant, créer deux `int-*` (la seconde devient désignée) ; vérifier qu'elles
   sont sur la forge.
2. Poste B (ou autre workspace, autre compte) : ouvrir le workspace (clone neuf, ou attendre la
   synchro auto). Onglet Structure → combo du composant : les deux `int-*` sont listées, celle qui
   n'est pas en local avec « serveur ».
3. Choisir l'`int-*` « serveur » : elle est checkoutée, le libellé « serveur » disparaît, et le pin
   proposé au parent est `int-…` (pas `origin/int-…`).
4. Même contrôle dans le panneau Version (combo du repo).
