# GH372 — Import MCP : valeurs des champs non contrôlées

Issue #372 (type:bug).

## Symptôme

`bulk_import_requirements` et `bulk_import_tests` acceptaient sans erreur une enum hors liste
(`priority: "9"`, `dev_qualif: "X"`), une valeur inconnue dans un `multi_enum`, du texte dans un
`number` et un champ absent du schéma. Seul le statut était refusé.

## Root cause

Deux règles pour un même besoin :

- `bulk-import-validation.util.ts::validateEntry` ne contrôlait que les champs requis, la syntaxe EARS,
  le statut et (GH195) les liens / `requiredWhen` — aucune valeur de champ.
- `update-validation.util.ts::planUpdate` (GH150) contrôlait, dans sa propre boucle, la clé déclarée et
  les valeurs d'`enum` / `multi_enum`, mais pas `number`, `boolean` ni `date` ; et lisait toujours
  `field.values` pour le `multi_enum` `roles`, alors que ses options viennent du catalogue de rôles du
  schéma quand il existe (T110, `resolveMultiEnumOptions`).

## Correctif

Une seule règle, `apps/desktop/src/main/services/field-values.util.ts::fieldValuesError`, appelée par
les deux chemins (import : après le contrôle du statut ; modification : à la place de l'ancienne boucle).
Première erreur retournée, `{ field, reason }`, par entrée :

| Cas | Refusé |
|---|---|
| clé de `fields` | absente des champs du type (le message liste les champs du type) |
| `enum` | valeur hors `values` ; liste ou objet au lieu d'une valeur |
| `multi_enum` | élément hors `values` (catalogue de rôles pour `roles`), en liste ou en texte `a, b` |
| `number` | ni nombre fini, ni chaîne numérique — l'éditeur enregistre la saisie en chaîne (`"12.5"` admis) |
| `boolean` | autre chose que `true` / `false` (la chaîne `"true"` est refusée) |
| `date` | autre chose qu'une chaîne `AAAA-MM-JJ` de date réelle |

Non contrôlé : valeur vide (`null`, `""`, `[]` — l'obligation relève du contrôle `required`, `null`
retire le champ en modification) ; enum sans liste déclarée ; types texte, richtext, user, drawio,
datetime ; `link` reste contrôlé par `prepareFieldsWrite` (GH195).

Les campagnes importées avec un `objectTypeRef` passent par la même validation (`validateBulkEntries`).
Descriptions des outils `bulk_import_requirements` et `update_requirements` mises à jour ;
`SPEC-MCP-SERVER.md` §4.2.

Hors périmètre : `runFields` / `stepFields` (aucun outil MCP n'écrit de run), import de résultats JUnit
(n'écrit pas de `fields`).

## Vérification

- `apps/desktop/src/main/services/field-values.gh372.test.ts` : la règle cas par cas, les quatre cas
  du rapport refusés par `validateBulkEntries` (exigences et tests, une erreur par entrée, entrée
  conforme acceptée), `planUpdate` refusant désormais du texte dans un `number` et contrôlant `roles`
  contre le catalogue.
- Manuel (serveur MCP sur un projet) : `bulk_import_requirements` en `dryRun` avec
  `fields: { priority: "9" }` → `errors: [{ index: 0, field: "priority", reason: "valeur \"9\" hors liste…" }]` ;
  même chose avec un champ inconnu, `quantity: "abc"` sur un `number`, un élément inconnu de `multi_enum`.
