# GH381 — Renommer ou retirer un statut du type version ne migre pas les versions

Issue #381 (type:bug).

## Symptôme

Renommer ou retirer un statut **non marqué** du type version (ni `isApproval` / released, ni
`isTerminal` / abandonnée), dans l'éditeur de schéma de l'application comme via les outils MCP
`update_status` / `remove_status` (GH371) : les fichiers `versions/*.yaml` gardaient l'ancien statut,
qui n'existe plus dans le schéma. L'aperçu ne les comptait pas, et `remove_status` sans `replaceWith`
ne voyait pas qu'une version portait le statut.

## Root cause

`FieldRenameService` (GH77 / GH82, étendu aux issues GH244 et aux validations GH204) énumère les
exigences, tests, campagnes, issues et validations du type, **pas les versions** :
`renameValues`, `previewValueRenames`, `objectIdsWithStatus` (qui calcule `STATUS_IN_USE`) et
`renameFields` les ignoraient. Les statuts marqués étaient protégés à part
(`SchemaService.assertVersionTypeStable`), d'où un trou limité aux statuts non marqués.

## Correctif

- `VersionsService.rewriteObjects` / `renameFieldKeys` : réécriture brute des versions du type, dans
  la file d'écriture du repo, sur le modèle de `ValidationsService.rewriteObjects`.
- `FieldRenameService` reçoit `VersionsService` (conteneurs app et MCP) : les versions sont migrées
  (statut courant, `history.status`, valeurs d'enum, clés de champ), comptées dans l'aperçu et dans
  `STATUS_IN_USE`.
- Description de l'outil MCP `update_status` mise à jour.

**Version released / abandonnée** (point laissé ouvert par l'issue) : réécrite comme une validation
signée, car un renommage n'est pas une modification de la version. Son statut courant est marqué
donc gelé : seul son historique peut changer. Le `freeze` (tag, sha) n'est pas touché.

## Vérification

`src/main/services/schema-mutation.gh371.test.ts`, bloc « V — GH381 » (conteneur MCP réel) :
- V1 : renommage d'`en_cours` → version en cours migrée (statut + historique), version released :
  historique migré, statut et `freeze` inchangés ;
- V2 : `dryRun` compte la version, rien n'est écrit ;
- V3 : `remove_status` sans `replaceWith` → `STATUS_IN_USE (PV-0001)` ; avec → migration.

Manuel (app) : éditeur de schéma, type version avec une version en cours, ajouter un statut non marqué,
y passer la version, renommer ce statut → la version affiche le nouveau nom.
