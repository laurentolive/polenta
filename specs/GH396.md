# GH396 — Serveur web e2e arrêté en cours de suite (code 0xC0000409)

## Constat

Le serveur web de test s'arrête en cours de suite avec le code 3221226505 = `0xC0000409`, sans
aucun message sur stderr. Toute la suite derrière échoue en `ERR_CONNECTION_REFUSED`.

- 2026-11-17 : arrêt après 1263 s, rss 854 Mo (`../gh387-base-e2e.log`).
- 2026-11-18 (niveau 3 de GH389) : arrêt du worker w2 **après 17 s**, rss 291 Mo. Le même code
  apparaît le même jour dans `pnpm test` (processus vitest).

## Root cause

Arrêt natif de **Node 24.15.0 (libuv 1.51.0) sous Windows**, la version installée sur le poste de
dev. Ce n'est ni le code de Polenta, ni l'accumulation de projets ouverts.

Éléments :

- **Pas l'accumulation** (hypothèse initiale de l'issue) : l'occurrence du 18 survient après 17 s,
  à 291 Mo, sur un serveur qui n'a presque rien ouvert.
- **Pas de module natif de Polenta** : le serveur web n'en charge aucun (`node-pty` et `keytar`
  ne sont utilisés que par le desktop). vitest, qui exécute un code sans rapport avec le serveur,
  sort avec le même code.
- **Pas un `abort()` de Node** : `node -e "process.abort()"` sort en 134 avec une pile affichée ;
  aucune assertion ni pile n'apparaît avant l'arrêt. Il s'agit donc d'un `__fastfail` natif
  (contrôle de pile /GS) dans le binaire Node lui-même. Windows n'a enregistré aucun événement de
  plantage pour node.exe.
- **Bug connu ailleurs** : plusieurs projets signalent ce code sous Windows avec Node 24.15.0 /
  libuv 1.51.0, et le corrigent en passant à Node 24.21+ / 24.22.x. Issue amont
  nodejs/node#56645, correction nodejs/node#61999 (mergée sur `main` le 2026-07-24). La version 24.x
  qui l'embarque n'a pas été confirmée dans le changelog officiel : ce sont des signalements de
  projets tiers.
- **Périmètre** : le repo fixe Node 20 (`.nvmrc`, `apps/desktop/Dockerfile.web`, CI). Le serveur
  web déployé n'est donc pas concerné, et Electron embarque son propre Node.

## Correctif

- Poste de dev : passage de Node 24.15.0 à **Node 24.22.3** (dernière LTS 24, 2026-11-11), décidé
  par l'humain le 2026-11-18.
- Lanceur e2e `apps/desktop/e2e-web/support/run-server.mjs` : quand le serveur sort en
  `0xC0000409`, une ligne supplémentaire donne les versions de Node et libuv et renvoie à ce
  fichier, pour qu'une prochaine occurrence ne soit plus confondue avec un problème du serveur.
- Aucune modification du code applicatif.

## Comment vérifier

1. `node -v` → `v24.22.3` ; `node -p process.versions.uv` → libuv > 1.51.0.
2. Plusieurs suites e2e complètes (`pnpm --filter @polenta/desktop test:e2e:web`) et `pnpm test`
   lancés en parallèle : aucun arrêt `0xC0000409`.
3. Le crash étant intermittent, l'absence d'arrêt sur quelques passes est un indice, pas une preuve.
   Une nouvelle occurrence sous 24.22.3 rouvre l'enquête : la ligne ajoutée par le lanceur donne
   alors les versions en cause.

## Résultat (2026-11-18, après passage à Node 24.22.3 / libuv 1.52.1)

Deux suites e2e complètes, chacune avec `pnpm test` sur toute la monorepo en parallèle :

| Passe | e2e | unitaires |
|-------|-----|-----------|
| 1 | 397 passés, 2 échecs, 5 non lancés, 14 ignorés — aucun arrêt du serveur ; les 2 échecs, verts relancés seuls, sont des instabilités sans rapport (#401) | 3/3 paquets verts |
| 2 | 404 passés, 14 ignorés | 3/3 paquets verts |

Aucun arrêt `0xC0000409` (serveur ni vitest).
