# GH40 — Panneau Version : icône graphe par repo, densité, sections vides masquées — baselines : liste dans le panneau latéral, création intégrée à la vue

Issue : [#40](https://github.com/laurentolive/polenta/issues/40) — type:feature

## Contexte

- Le panneau Version (`VersionPanel` + `VersionRepoFolder`) affiche un arbre de repos (root,
  composants, interfaces), chacun avec son état git (stagés, modifications, push, checkout).
- Le graphe de versions (`/graph`) est déjà **par repo** : il affiche le repo sélectionné
  (`selectedRepoPath`, `SelectedRepoContext`). Mais la seule icône qui l'ouvre est dans le header
  du panneau, globale : il faut d'abord cliquer sur un repo pour le sélectionner, ce qui n'est pas visible.
- La page `/baseline` affiche dans la vue de droite la liste des baselines (filtre, items
  dépliables, suppression) ; la création passe par une popup `CreateBaselineModal`.

## 1. Panneau Version — icône graphe par repo

- Chaque ligne de repo de l'arbre (`VersionRepoFolder`, tous niveaux) porte une icône graphe
  (`History`, même icône que le header), toujours visible, à côté du bouton Rafraîchir.
- Clic : sélectionne ce repo (`selectRepo(repoPath)`) **et** ouvre `/graph` sur ce repo. Le clic
  ne replie/déplie pas le dossier (propagation stoppée).
- L'icône graphe du header du panneau est **conservée** : elle ouvre simplement la vue graphe
  (sur le repo actuellement sélectionné, comportement actuel inchangé).
- Infobulle : « Voir l'historique de <repo> ».

## 2. Panneau Version — densité

Objectif : plus de repos et de fichiers visibles sans défiler, sans perte de lisibilité.

- Ligne de repo : hauteur réduite (padding vertical ~4 px au lieu de ~6 px), indentation par
  niveau inchangée (16 px).
- Contenu d'un repo déplié : padding des sections réduit (≈ `px-2 py-1` au lieu de `px-3 py-2`),
  plus de bordure de séparation entre sections quand une seule est affichée ; espacement en-tête
  de section → liste réduit.
- Lignes de fichier : hauteur compacte (≈ 20 px), police inchangée (`text-xs`, mono).
- Ligne « N commit(s) à pousser » : même compacité.
- Header du panneau : padding vertical réduit (aligné sur les autres panneaux compacts).
- Les boutons d'action restent toujours visibles (règle §19.8 « pas de `opacity-0 group-hover` »).

## 3. Panneau Version — sections vides masquées

Dans un repo déplié :

| Stagés | Modifications | Affichage |
|--------|---------------|-----------|
| ≥ 1    | ≥ 1           | les deux sections |
| ≥ 1    | 0             | section Stagés seule |
| 0      | ≥ 1           | section Modifications seule |
| 0      | 0             | une ligne « Nothing to commit » (fr : « Rien à commiter »), italique, discrète |

- Les messages « Aucun fichier stagé » / « Aucune modification » disparaissent.
- La ligne « à pousser » (ahead > 0) et l'avertissement de propagation de pin après commit
  (`PinPropagationWarning`) restent affichés indépendamment des sections : l'avertissement de pin
  post-commit doit rester visible même si la section Stagés vient de disparaître (le commit l'a vidée).
- Un dossier replié n'affiche rien de plus qu'aujourd'hui (pastille de modifications en attente).

## 4. Baselines — liste dans le panneau latéral

- Navigation (pattern de la vue Comparer) : l'icône Baselines (`Tag`) du header ouvre `/baseline` ;
  tant que la route est `/baseline`, le panneau Version affiche **la liste des baselines** à la
  place de l'arbre des repos, avec le titre « Baselines ». Quitter la route (icône graphe du
  header ou d'un repo, retour, autre vue) ramène l'arbre.
- Contenu du panneau, repris de la vue actuelle :
  - champ de filtre (tag ou message) ;
  - liste des baselines, la plus récente en premier (ordre actuel de `baseline.list`) ;
  - chaque ligne : chevron, tag (mono), message tronqué, date ; clic = **déplier sur place** la
    liste des composants (nom → tag), comme aujourd'hui ;
  - suppression : icône corbeille au survol de la ligne → même confirmation
    (`DeleteBaselineModal`) qu'aujourd'hui ;
  - états vides : « Aucune baseline » / « Aucune baseline ne correspond au filtre ».
- Après création d'une baseline (§5), la liste du panneau se met à jour (invalidation
  `baseline:list`).

## 5. Baselines — création intégrée à la vue de droite

- La vue de droite `/baseline` **est** le formulaire de nouvelle baseline : plus de popup,
  plus de bouton « Nouvelle baseline » dans le header.
- Contenu, repris tel quel de `CreateBaselineModal` :
  1. État des repos (readiness par repo, bouton rafraîchir, raison bloquante, branche courante) ;
  2. Tag du repo principal (pré-rempli par `nextTag`), avertissements tag déjà utilisé / existant ;
  3. Message (optionnel) ;
  4. Erreur de création / avertissement de tags composants manquants ;
  5. Bouton « Créer la baseline » (mêmes conditions d'activation qu'aujourd'hui). Pas de bouton
     Annuler (rien à fermer).
- Raccourci : `Ctrl+Entrée` dans le formulaire = créer (si autorisé). Échap ne fait rien.
- Après succès : tag ré-initialisé à la valeur suivante, message vidé, un bandeau de succès
  « Baseline <tag> créée » s'affiche dans la vue ; la nouvelle baseline apparaît dans le panneau.
- Mise en page : colonne centrée de largeur limitée (~ `max-w-2xl`), sections empilées comme
  dans la popup.
- Le bouton retour du header (vers `/graph`) est conservé.

## Critères d'acceptation

1. Chaque repo de l'arbre Version a une icône graphe ; un clic ouvre `/graph` sur ce repo
   (vérifiable : le graphe affiché est celui du repo cliqué, le repo est surligné comme sélectionné)
   et ne replie/déplie pas le dossier.
2. L'icône graphe du header ouvre toujours `/graph` sans changer la sélection.
3. Repo sans stagé ni modification déplié : seule la ligne « Nothing to commit » est affichée.
4. Repo avec uniquement des modifications : pas de section Stagés, et inversement.
5. Après un commit qui vide les stagés d'un repo dépendant, l'avertissement de propagation de pin
   reste visible.
6. Densité : à contenu égal, la hauteur occupée par l'arbre est réduite (une ligne de repo
   ≤ 28 px, une ligne de fichier ≤ 20 px).
7. Sur `/baseline`, le panneau latéral liste les baselines (filtre, dépliage des composants,
   suppression avec confirmation) ; hors `/baseline`, il affiche l'arbre des repos.
8. Sur `/baseline`, la vue de droite affiche le formulaire de création sans popup ; créer une
   baseline la fait apparaître dans le panneau sans recharger, et le formulaire se ré-initialise.
9. Création bloquée (bouton désactivé, raison affichée) dès qu'un repo a des modifications en
   attente — comportement T79/T46 inchangé.
10. Libellés nouveaux présents en `en.json` et `fr.json`.

## Hors scope

- Pas de vue détail d'une baseline dans la vue de droite (dépliage sur place uniquement).
- Pas de consultation/navigation dans une baseline (§5.5) ni de comparaison entre baselines.
- Pas de changement des conditions de création (avertissements §5.2 non implémentés restent hors
  scope), ni du service `baseline.service.ts` / des channels IPC.
- Pas de refonte de la vue Comparer ni du graphe lui-même.
