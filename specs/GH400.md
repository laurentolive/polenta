# GH400 — Vue « Exécutions » : toutes les exécutions du repo (Tableau, Document)

Issue : #400. Ticket compagnon : #399 (popup d'aperçu d'une exécution), bloqué par celui-ci.

## Évolution du besoin

L'issue proposait une section repliable « Exécutions (N) » sur la page d'une campagne. Au cadrage
(2026-11-18), l'humain l'a remplacée par une **vue à part entière**, conçue comme les vues
Exigences et Tests. Elle sert à chercher de l'information dans **toutes** les exécutions du repo.
Comme dans la vue Tests, on y choisit un type de test à la fois. Elle a un mode Tableau, un mode
Document, des exports et un panneau ⚙️ avec un onglet Popup. On y
accède par des icônes en tête du panneau latéral des campagnes.

## Décisions de cadrage

| # | Question | Décision |
|---|----------|----------|
| Q1 | Emplacement | Une page à part, pas une section de la page campagne. Des icônes en tête du panneau latéral basculent entre **Campagnes** et **Exécutions**. |
| Q2 | Périmètre | **Toutes les exécutions du repo affiché** : exécutions de campagne, exécutions hors campagne, exécutions remplacées, entrées retirées. Choisir une campagne dans le panneau filtre la vue sur elle ; « Toutes » retire ce filtre. |
| Q3 | Types de test | **Un type de test à la fois**, comme dans la vue Tests : le sélecteur composant × type du panneau choisit le type de test, et la vue montre les exécutions des tests de ce type (voir la note ci-dessous). Le ⚙️ se règle **par type de test**, comme pour les éléments. |
| Q4 | Modes | **Tableau + Document**. Pas de mode Édition : une exécution ne se modifie pas après coup. Le double-clic ouvre la page d'exécution ou la relecture, comme aujourd'hui. |
| Q5 | Popup (#399) | La popup d'une exécution affiche les champs de l'onglet **Popup** du ⚙️ de cette vue, pour le **type de son test**. #400 livre le réglage ; #399 livre la popup qui s'en sert. |

**Note sur les types de test (Q3).** Un repo peut déclarer plusieurs types d'objet de catégorie
`test` dans `schema.yaml`, par exemple « Test système » et « Test firmware ». Chaque type déclare
ses propres `runFields` (champs d'exécution) et `stepFields` (champs d'étape) (GH196). Ces champs
ne sont donc pas communs au repo. Comme la vue montre un seul type à la fois, ses colonnes de
champs d'exécution et d'étape sont exactement celles de ce type, sans cellules vides dues à un
autre type. Pour voir les exécutions d'un autre type, on change de type dans le sélecteur, comme
dans la vue Tests.

## Description fonctionnelle

### 1. Accès : panneau latéral

- Le panneau latéral des campagnes (`SystemPanel`, catégorie `campaign`) gagne en tête deux icônes
  qui naviguent, sur le modèle du panneau Versions (GH201) : **Campagnes**, la page actuelle, et
  **Exécutions**, la nouvelle vue. L'icône de la page affichée est marquée active.
- En mode Exécutions, le panneau garde la liste des campagnes, avec en tête deux entrées :
  **Toutes les exécutions** (par défaut) et **Hors campagne**.
  - Un clic sur une campagne filtre la vue sur cette campagne, sans ouvrir sa fiche.
  - Le filtre choisi se lit dans l'URL : il survit à l'historique Précédent / Suivant et à
    l'ouverture dans un nouvel onglet.
- La fiche d'une campagne gagne un lien **« Voir les exécutions »**, qui ouvre la vue filtrée sur
  cette campagne.
- En mode Exécutions, le sélecteur composant × type du panneau propose les **types de test**,
  repo et composants locaux compris, comme dans la vue Tests. La vue montre les exécutions rangées
  dans le repo du composant choisi (`test-runs/`), restreintes aux tests du type choisi. Le type
  choisi se lit dans l'URL, comme le filtre.
- La liste des campagnes reste celle du repo choisi. Une campagne qui ne contient aucun test du
  type choisi donne une vue vide.

### 2. Données affichées (lecture seule, données brutes — GH79)

- **Une ligne par exécution** (`TestRun`) d'un test du type choisi :
  - exécutions de campagne ;
  - exécutions hors campagne, dites « isolées » ;
  - exécutions **remplacées**, avec le badge « remplacé » ;
  - exécutions d'une **entrée retirée**, avec le badge « retirée » ;
  - exécutions dont la campagne est introuvable, avec la mention actuelle.
- **Les entrées en attente** des campagnes ouvertes (`kind: pending`, verdict « En attente ») sont
  incluses, comme dans GH197.
- Une exécution antérieure à GH73, sans `campaignEntry`, est rattachée à sa campagne quand une
  entrée la désigne par `runId`. Sinon, elle apparaît comme isolée.
- Ordre : celui de GH197 (entrées en attente d'abord, puis les plus récentes). **Aucun tri** par
  colonne (GH389).
- Aucun calcul nouveau : les marqueurs `removed`, `superseded`, `campaignMissing` et l'écart de
  version testée (GH202) sont ceux de l'historique actuel.

### 3. Mode Tableau

- C'est la grille d'historique des exécutions (`ExecutionHistoryGrid`, GH197, briques communes
  GH389), avec toutes ses fonctions :
  - groupes de colonnes Exécution / Campagne / Entrée / Test ;
  - colonnes `run:<champ>` (les `runFields` du type choisi) et `campaign:<champ>` ;
  - étapes dépliables, avec les `stepFields` du type choisi ;
  - filtre par colonne, largeurs, gel et ordre des colonnes, hauteur des lignes ;
  - panneau 👁 et barre d'outils commune.
- **Colonne Test** toujours disponible : ID et titre, en lien d'élément (GH229).
- **Colonnes par défaut** : Test, Exigence de l'entrée, Campagne, Entrée, Verdict, Date, Testeur,
  Version testée, plus les `runFields` marqués `defaultVisible`.
- **Navigation** : celle de GH197 (Q5).
  - Entrée d'une campagne ouverte → page d'exécution.
  - Sinon → relecture.
  - Entrée retirée, exécution remplacée ou exécution isolée → pas de navigation.
  - Ctrl / Cmd / clic du milieu → nouvel onglet.
- **Export xlsx** : export générique des grilles (`table`), avec les colonnes affichées et les lignes
  filtrées.

### 4. Mode Document

- **Une fiche par exécution**, dans l'ordre et avec le filtre du Tableau (filtre du panneau et
  filtres de colonnes). Chaque fiche contient :
  - **En-tête** : test (ID et titre), campagne et entrée, verdict, date, testeur.
  - **Champs** : ceux de l'onglet **Document** du ⚙️, dans l'ordre du panneau.
  - **Notes**, en richtext, en lecture seule.
  - **Tableau des étapes** : n°, action, résultat attendu, verdict de l'étape, commentaire, et les
    `stepFields` du type. Il s'affiche si l'onglet Document coche « Étapes ».
- Les entrées en attente n'ont pas de fiche : il n'y a pas d'exécution à décrire.
- **Exports docx et PDF** du Document : même contenu que l'écran, avec les fiches affichées (filtres
  appliqués).

### 5. Panneau ⚙️ de la vue

- Il a trois onglets : **Tableau**, **Document** et **Popup**.
  - Chaque onglet liste les colonnes de la grille par groupe : Exécution, Campagne, Entrée, Test,
    champs d'exécution, champs de campagne.
  - « Réinitialiser » rend les colonnes par défaut.
- Dans l'onglet **Tableau**, les colonnes visibles et leur ordre sont les mêmes que dans le panneau
  👁 de la grille : il n'y a qu'un réglage.
- L'onglet **Popup** ne propose pas les champs déjà présents dans l'en-tête de la popup (défini par
  #399). Son défaut est vide, comme pour les éléments (GH229).
- **Stockage** : `.pref` du repo affiché, par utilisateur et **par type de test**, sous la clé du
  type (`fieldVisibility["<nœud>::<type de test>"]`), dans trois nouvelles vues à nommer au design
  (par exemple `runExcel` / `runWord` / `runPopup`). Ce réglage est **distinct** de celui de la
  section Exécutions de l'éditeur (`fieldVisibility[<type>].executions`), qui ne change pas, et des
  réglages `excel` / `word` / `popup` des tests eux-mêmes.
- **Hors scope** de #400 : les vues enregistrées d'équipe (GH203).

### 6. Ce qui ne change pas

- La section « Exécutions » de l'éditeur d'un test ou d'une exigence (GH197).
- La grille des entrées de la page campagne.
- La page d'exécution et la relecture.
- Le format des fichiers : aucun champ nouveau dans les YAML.

### 7. Client web

Même comportement. Le canal de lecture reste exposé au serveur web, avec la vérification des
racines actuelle.

## Critères d'acceptation

1. Depuis le panneau Campagnes, l'icône Exécutions ouvre la vue, et l'icône Campagnes ramène à la
   page des campagnes. L'icône active correspond à la page affichée.
2. Dans un repo avec plusieurs types de test, le sélecteur du panneau propose chaque type de test.
   La vue ne liste que les exécutions des tests du type choisi, et ne propose que les colonnes
   `run:<champ>` de ce type. Changer de type change les lignes, les colonnes et le réglage ⚙️.
3. La vue liste les exécutions isolées, remplacées (badge), retirées (badge) et en attente.
4. Un clic sur une campagne du panneau filtre la vue sur ses exécutions, y compris remplacées et
   retirées. « Hors campagne » ne garde que les exécutions isolées. « Toutes » retire le filtre.
   Le filtre survit à Précédent / Suivant.
5. Le lien « Voir les exécutions » de la fiche campagne ouvre la vue filtrée sur elle.
6. Le Tableau navigue comme GH197 : page d'exécution, relecture, pas de navigation, nouvel onglet.
7. Le Document affiche une fiche par exécution filtrée, avec les champs de l'onglet Document et les
   étapes. Les exports docx et PDF reprennent ce contenu.
8. L'export xlsx du Tableau reprend les colonnes affichées et les lignes filtrées.
9. Les réglages Tableau, Document et Popup du ⚙️ sont persistés par utilisateur et par type de test
   dans le `.pref` du repo. Ils sont indépendants du réglage `executions` de l'éditeur et des
   réglages des tests. « Réinitialiser » rend le défaut.
10. Le même scénario fonctionne dans le client web.

## Hors scope

- La popup d'aperçu d'une exécution et la conversion des liens d'exécution : #399.
- Les vues enregistrées d'équipe pour cette vue (GH203).
- Le mode Édition, et toute modification d'une exécution depuis la vue.
- Les exécutions des tests de composants vues depuis le produit : la vue montre les exécutions du
  repo affiché (GH269).
- Tout indicateur calculé, comme l'état de la campagne à une date ou le dernier résultat : côté
  projet (GH79, #73, #74).

## Points ouverts pour le design

- **Canal** : étendre `executions:history` avec une cible « type de test » (`{ objectTypeRef }`,
  filtre `campaignId` facultatif), plutôt que d'ouvrir un nouveau canal. Le coût dépend de l'écart de
  version GH202 calculé pour chaque exécution (déjà mis en cache) : il faut le mesurer sur un repo
  de plusieurs centaines d'exécutions.
- **Document et exports** : un nouveau `ExportKind` (`executions`, docx et pdf) et une route
  d'impression `/print/executions`.
- **Panneau ⚙️** : réutiliser `FieldConfigModal` avec une liste de colonnes `GridColumn` plutôt que
  les champs du schéma, ou dériver un panneau des briques `ColumnChecklist` (GH389).
- **Découpage probable en sprints** :
  1. Vue, Tableau et panneau ;
  2. Document et exports ;
  3. ⚙️ Popup et mise à jour des SPEC.
