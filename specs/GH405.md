# GH405 — Navigation entre onglets au clavier : Ctrl+Tab et Ctrl+PageUp/PageDown

Issue : #405 — `type:feature`

## Description fonctionnelle

Dans l'application desktop, l'utilisateur passe d'un onglet de la barre d'onglets (§19.1, `TabBar`)
à l'onglet voisin sans la souris, avec les raccourcis de Chrome, Firefox et VS Code :

| Raccourci | Action |
|---|---|
| `Ctrl+Tab` | onglet suivant |
| `Ctrl+Shift+Tab` | onglet précédent |
| `Ctrl+PageDown` | onglet suivant |
| `Ctrl+PageUp` | onglet précédent |

`Ctrl` sur toutes les plateformes, macOS compris (convention des navigateurs sur Mac : `Ctrl+Tab`,
pas `Cmd+Tab` qui appartient au système).

Le changement d'onglet passe par le même chemin que le clic sur un onglet. Ce chemin reçoit une
**garde contre la perte de saisie** : aujourd'hui, seule la page de l'onglet actif est montée et
`activateTab` n'a aucune garde, donc quitter un onglet dont la saisie n'est pas enregistrée la
perd sans prévenir (constaté dans le code : `TabsContext.activateTab`, `useRegisterTabDirty` qui
se désinscrit au démontage). La garde est celle de Précédent / Suivant (GH228) et s'applique au
raccourci **et** au clic.

## Comportements attendus

### Ordre et bouclage

- Ordre **visuel** de la barre (gauche → droite), celui que l'utilisateur voit après un éventuel
  réordonnancement par glisser (GH343).
- **Bouclage** : « suivant » sur le dernier onglet active le premier ; « précédent » sur le premier
  active le dernier.
- Un seul onglet ouvert : rien ne se passe (pas de navigation, pas de popup).
- La touche maintenue (répétition automatique) fait avancer d'un onglet par répétition, tant
  qu'aucune popup ne s'ouvre.
- L'onglet activé devient visible dans la barre si elle défile (même comportement qu'une
  activation par le menu ▾).

### Où le raccourci agit

- **Partout dans la fenêtre**, y compris quand le focus est dans un champ de saisie, un éditeur
  richtext, une cellule de la grille (`DataGrid`, Vue Excel), un éditeur CodeMirror (diff Raw) ou le
  terminal Git Bash (GH238).
- Le raccourci est consommé : aucune tabulation insérée, pas de déplacement de cellule dans la
  grille, rien envoyé au terminal.
- **Ignoré** quand une modale ou un menu est ouvert (même critère que Précédent / Suivant), ou
  quand une confirmation de fermeture / de départ est déjà affichée.

### Garde contre la perte de saisie (raccourci, clic sur un onglet, menu ▾)

Avant d'activer l'onglet cible, dans cet ordre :

1. `blur()` du champ actif : les saisies à enregistrement automatique (vue Édition, cellules) sont
   enregistrées, comme avant Précédent / Suivant et Ctrl+W.
2. Si l'onglet actif est **modifié** (`useRegisterTabDirty` : exigence, test, champs d'une
   campagne, Schéma, éditeur de fichier d'un diff) → popup **« Quitter cette page ? »**
   (`ConfirmLeavePageModal`, la même que Précédent / Suivant) :
   - **Rester** : aucun changement d'onglet, la saisie est intacte ;
   - **Quitter sans enregistrer** : l'onglet cible est activé, la saisie est abandonnée.
3. Sinon, l'onglet cible est activé directement.

Points d'entrée gardés : `Ctrl+Tab` / `Ctrl+Shift+Tab` / `Ctrl+PageUp` / `Ctrl+PageDown`, clic
sur un onglet de la barre, choix d'un onglet ouvert dans le menu ▾, et aussi `+` / Ctrl+T et
« Récemment fermés » : ils quittent eux aussi la page de l'onglet actif et perdent sa saisie de la
même façon. Inchangés : fermeture d'un onglet (déjà gardée), glisser d'un onglet vers une autre
fenêtre (la saisie suit l'onglet, GH343).

### Client web

- **Pas de raccourci** : le navigateur garde `Ctrl+Tab` et `Ctrl+PageUp/PageDown` pour ses propres
  onglets (la page ne les reçoit pas). Aucune combinaison de remplacement.
- La **garde** (clic, menu ▾, `+`, Récemment fermés) s'applique aussi au web : elle vit dans
  `TabsContext`, commun aux deux clients.

## Critères d'acceptation

1. Desktop, 3 onglets A B C, A actif : `Ctrl+Tab` → B, `Ctrl+Tab` → C, `Ctrl+Tab` → A ;
   `Ctrl+Shift+Tab` depuis A → C. Idem avec `Ctrl+PageDown` / `Ctrl+PageUp`.
2. Après avoir glissé C entre A et B (ordre A C B), `Ctrl+Tab` depuis A active C.
3. Un seul onglet : le raccourci ne change rien et n'ouvre aucune popup.
4. Focus dans un champ texte, un richtext, une cellule de grille en édition, le diff Raw et le
   terminal : le raccourci change d'onglet, et le contenu du champ / de la cellule / du terminal
   est inchangé (aucune tabulation insérée, pas de déplacement de cellule).
5. Champ de la vue Édition en cours de saisie, puis `Ctrl+Tab` : la valeur est enregistrée (visible
   en revenant sur l'onglet), pas de popup.
6. Exigence modifiée non enregistrée, puis `Ctrl+Tab` **ou** clic sur un autre onglet **ou** choix
   dans le menu ▾ : popup « Quitter cette page ? ». Rester → même onglet, saisie intacte, point
   « modifié » toujours affiché. Quitter sans enregistrer → onglet suivant affiché ; en revenant,
   l'exigence est dans son état enregistré.
7. Même scénario que 6 pour `+` / Ctrl+T et « Récemment fermés ».
8. Modale ou menu ouvert (ex. ⚙️, menu ▾, popup de confirmation) : le raccourci ne fait rien.
9. Client web : `Ctrl+Tab` n'est pas intercepté par l'application ; le clic sur un autre onglet
   depuis une exigence modifiée ouvre la popup (critère 6).
10. Aucune régression : Ctrl+T, Ctrl+W, Ctrl+Shift+N, Précédent / Suivant, Ctrl+B, zoom, `Tab` /
    `Shift+Tab` seuls dans la grille et les formulaires.

## Hors scope

- Ordre « dernier utilisé » (MRU) et sélecteur d'onglets tant que Ctrl est maintenu.
- Raccourci de remplacement dans le client web.
- Conserver la saisie d'un onglet quand on le quitte (stockage par onglet) : écarté au profit de la
  confirmation.
- `Ctrl+1…9` (aller à l'onglet n), `Cmd+Option+←/→` ou `Cmd+Shift+[ ]` sur macOS.
- Déplacement d'onglet au clavier (`Ctrl+Shift+PageUp/PageDown`).
