# GH41 — « ↑N commits à pousser » compte tout l'historique sur une branche jamais poussée

Issue : #41 (type:bug).

## Root cause

`SyncService.status()` calcule `ahead` contre `refs/remotes/origin/<branche courante>`. Quand cette
ref n'existe pas (branche jamais poussée — `dev-resync` créée par Resynchroniser (GH39), ou toute
branche `dev-*` créée à la main), le repli T89 comptait **tout** l'historique de la branche
(`git.log` profondeur 100) dès qu'un remote était configuré. Le panneau Version affichait donc
« ↑13 commits à pousser » pour un seul commit réellement absent du serveur.

## Correctif

`apps/desktop/src/main/services/sync.service.ts` — dans ce repli seulement, `ahead` = commits de
la branche absents de **toutes** les branches `origin/*` connues (équivalent
`git log <branche> --not --remotes`, même fenêtre de 100 commits), via la nouvelle fonction
`countNotOnRemote`. Inchangé : branche suivie (comparaison à `origin/<branche>`), repo sans remote
(0, T89), remote sans aucune branche poussée (tout l'historique est bien à pousser).

## Vérification

Scénarios sur de vrais repos git (bare local + clone), contre `SyncService.status()` :

| Cas | `ahead` attendu | Obtenu |
|---|---|---|
| Remote configuré, rien poussé, 2 commits | 2 | 2 |
| Branche suivie, 1 commit non poussé | 1 | 1 |
| `dev-x` jamais poussée, créée depuis `main` poussé + 1 commit | 1 | 1 |
| Pas de remote | 0 | 0 |

`pnpm typecheck` : 0 erreur.

Manuellement : sur un projet avec remote, créer une branche depuis le panneau Version (combobox →
Nouvelle branche), y publier/committer une modification → la ligne affiche « ↑1 commit à
pousser » (et non tout l'historique).
