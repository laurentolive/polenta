# GH420 — E2E web : échecs après merge de GH337

Type : bug (test). Issue #420. Base : `origin/main` 70b896a.

## Root cause

Trois causes distinctes, toutes côté test (aucun changement de comportement produit).

1. **`gh252-versions` U4/U5 — remote `file://` refusé.** Le test remplace `origin` par un dépôt nu
   local (chemin disque) et pousse dessus. Le serveur web refuse désormais tout remote hors
   `https`/`http` des hôtes autorisés (`gitRemoteGuard`, `src/web-server/hardening.ts`, garde GH337).
   Le refus est voulu ; le test demandait un comportement interdit en production.

2. **`parity` P-4 — commit de merge suivi d'un commit parasite.** `outsideClone()` (`support/forge.ts`)
   clone avec la config système de Git for Windows (`core.autocrlf=true`) et ne passe `autocrlf=false`
   qu'*après* le clone. Le clone écrit donc les fichiers en CRLF, et `commitAndPush()` (`add -A`)
   committe cette version : le commit « autre poste » (35c3253) réécrit **175 fichiers** en CRLF.
   Le merge du web reprend ces CRLF, puis la publication réécrit `.e2e.pref` (fichier de préférences
   de l'utilisateur, publié avec le repo) en LF : un commit « web : titre PRD-0001 » parasite
   (9645572) se pose après le commit de merge, et le test attend que la tête soit le merge.
   Vérifié : `git diff --stat 95b3948 9645572` ne touche que `.e2e.pref` ; `git show --stat 35c3253`
   touche 175 fichiers ; le reflog de l'espace de travail web montre le commit parasite sur `main`
   juste après la finalisation.

3. **`gh252-versions` U4/U5 — marqueur « tag pas encore poussé » lu périmé sous charge.** Le push
   part par `sync:push` (hors UI, aucune invalidation de la requête de la page). Le serveur est à jour
   (`versions:get` → `tagPending: false`), mais la page affichait encore le marqueur après une
   réouverture par `pushState` (le composant reste monté, la requête reste en cache). Non reproduit
   seul ; apparu avec 4 workers.

## Correctif appliqué (tests seulement)

- `apps/desktop/e2e-web/gh252-versions.spec.ts` : le dépôt nu est créé dans `E2E.remotesDir`
  (servi par la forge de test, `http://127.0.0.1`, `http.receivepack true`), `origin` pointe sur
  `${E2E.gitBaseUrl}/<nom>.git`. Le test vérifie `versions:get` côté serveur, puis recharge la page
  (`goto`) avant de lire le marqueur.
- `apps/desktop/e2e-web/support/forge.ts` : `outsideClone()` clone avec `-c core.autocrlf=false`.

La garde de production n'est pas modifiée.
