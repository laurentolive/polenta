# GH425 — Vue Validation : même validation, même position au retour

Type : bug. Issue : #425. Refs SPEC : aucune (bug de navigation et de mémoire de défilement).

## Symptôme

Dans la vue Validation, l'utilisateur quitte une validation puis revient : il ne retrouve ni la
même validation chargée, ni la même position dans la grille des décisions.

## Root cause

Deux mécanismes distincts, dont un seul est cassé :

- **Route perdue (barre d'activité).** `AppLayout.tsx`, `handleSelectPanel`, `case 'validation'`,
  redirige toujours vers `/validations` (accueil vide). Les panneaux Version, Suivi et Campagnes
  mémorisent leur dernière route (`lastVersionRoute`, `lastDashboardRoute`, `lastCampaignsRoute`) ;
  le panneau Validation n'en avait pas. Le clic sur l'icône « Validation » perd donc la validation
  quittée.
- **Position de grille (onglet, Précédent, arbre) : fonctionnelle.** La grille (`DataGrid`) reprend la
  mémoire de défilement GH300 (`useViewScrollMemory`, clé onglet + page via `useGridScrollKey`). Dès
  que l'URL revient à la même validation, la position est rétablie. Vérifié sur le build non corrigé :
  les scénarios G2 (onglet), G3 (Précédent) et G4 (arbre) passent déjà.

## Correctif appliqué

`apps/desktop/src/renderer/components/layout/AppLayout.tsx` (même patron que `lastVersionRoute`) :

- état `lastValidationRoute`, mis à jour à chaque affichage d'une page du panneau Validation
  (`routePanel === 'validation'`) ;
- remis à zéro au changement de projet, avant la mise à jour du nouveau projet (ordre des effets) ;
- `case 'validation'` : `router.history.push` vers la dernière route mémorisée (même URL, donc même
  clé de position GH300) ; sans route mémorisée, l'accueil comme avant.

Aucun changement de la mémoire de défilement ni de `DataGrid`.

## Comment vérifier

Test e2e `apps/desktop/e2e-web/gh425-validation-state.spec.ts` (viewport 1000×420) :

- **G1** — barre d'activité : Validation → Exigences → Validation ramène la même validation, à la même
  position, sans à-coup (échantillonnage de chaque frame pendant le retour).
- **G2** — onglet : retour sur l'onglet, même validation et même position.
- **G3** — Précédent : même validation et même position.
- **G4** — arbre du panneau : après une autre vue, ouverture par le panneau, même validation et même position.

Vérification manuelle : ouvrir une validation longue, défiler, passer sur Exigences, revenir par
l'icône « Validation » de la barre d'activité : la même validation doit s'afficher à la même hauteur.

## Résultats de vérification

- Avant correctif : G1 échoue (retour sur `/validations`, validation perdue) ; G2, G3, G4 passent déjà.
- Après correctif : G1 à G4 passent (4/4). G1 échantillonne chaque frame pendant le retour : aucune hors position.
- GH252 (panneau Validation, création et signature par la barre d'activité) : 5/5.
- `pnpm test` (apps/desktop) : deux échecs de temporisation au premier passage
  (`sync.service.gh414` R7, `repo-adoption.gh107` A-07), qui passent seuls et au second passage complet
  (234/234 fichiers). Cause non identifiée ; code du processus principal non touché par ce ticket. Non vérifié sur `main`.
- Typecheck (`tsc --noEmit`) : 0 erreur. ESLint sur les deux fichiers modifiés : rien.
- Niveau 3 (suite e2e complète) : non lancé, il attend le « Validé » (AppLayout est un composant commun du renderer).

## Hors scope

- Au changement de projet, la dernière validation mémorisée est oubliée (comme Version et Suivi) : pas de
  retour sur une validation d'un autre projet. Ce cas n'est pas couvert par un test e2e automatique.
- La sélection de cellule et la hauteur de l'en-tête replié ne sont pas mémorisées par ce correctif.
