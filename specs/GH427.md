# GH427 — e2e instable : `gh106-designate` GH106-1 (branche `int-e2e106` absente de la forge)

## Root cause

Le test lit la branche distante (`remoteLog`, sur le repo nu de la forge locale) dès que le bandeau
« Désigner » a disparu. Or la désignation (`designate`, `integration-branch.service.ts`) fait trois
choses dans cet ordre :

1. écrit `config/project.yaml` dans la copie de travail (ligne 88) ;
2. pousse la branche (ligne 94) ;
3. aligne la branche par défaut de la forge.

L'état d'intégration (`integration:state`) lit la copie de travail, et le bandeau en dépend. Il est
relu toutes les 10 s (`IntegrationBranchIndicator.tsx`, `refetchInterval: 10_000`). Si cette relecture
tombe entre l'étape 1 et la fin de l'étape 2 (push lent sous charge, suite complète), le bandeau
disparaît avant que la branche n'existe sur la forge : le test lit alors un repo nu sans `int-e2e106`
et échoue (`ambiguous argument 'int-e2e106'`).

Ce n'est pas une absence de push : le push part bien, il est simplement pas encore terminé quand le
test regarde. Observé seul, le test passe (18 s) ; le défaut n'a pas été reproduit en isolation.

## Correctif appliqué

Test seulement, pas de changement de produit :

- `e2e-web/support/forge.ts` : `remoteHasBranch(branch)` (`git rev-parse --verify` sur le repo nu).
- `e2e-web/gh106-designate.spec.ts` : avant de lire la branche distante, `expect.poll` jusqu'à ce
  qu'elle existe sur la forge (15 s au plus). Si le push échoue vraiment, le test échoue avec la
  même erreur, sans fausse réussite.

## Comment vérifier

- `npx playwright test e2e-web/gh106-designate` : 1 test vert (18,9 s).
- Non vérifié : le défaut lui-même (suite complète relancée plusieurs fois). À surveiller dans les
  suites complètes suivantes : si `gh106-designate` échoue encore, lire le message avant de conclure.
