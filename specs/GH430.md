# GH430 — Validation : entrées en attente d'une campagne ouverte sous leur test

Issue #430 (`type:bug`).

## Symptôme

Campagne ouverte (`planned`) avec des tests non exécutés. Sur une exigence liée, la section Exécutions
de l'exigence affiche les entrées « En attente » ; la vue Validation de la version qui contient cette
exigence n'affiche rien : sous chaque test, « Aucune exécution ».

## Root cause

`apps/desktop/src/renderer/components/validation/ValidationRuns.tsx` lisait l'historique des exécutions
de l'exigence (`api.executions.history`, même service que la grille des exécutions) et gardait
seulement les lignes `kind === 'run'`. Les lignes `kind === 'pending'` (entrées des campagnes ouvertes,
`execution-history.service.ts`, GH197 §1) étaient ignorées. Le filtre est présent depuis le commit
initial de la vue ; il n'y a pas de régression.

## Correctif

Décision validée (option A) : les entrées en attente s'affichent sous leur test, sans entrer dans les
runs.

- `validationRunGroups.ts` (nouveau) : `groupExecutionsByTest` range les lignes par test, dans deux
  listes distinctes : `runs` (kind `run`) et `pending` (kind `pending`). Logique de validation figée
  (GH267) inchangée.
- `ValidationRuns.tsx` :
  - la « dernière exécution » (colonne et registre, `signatureCopy`) ne lit que `runs` : une attente ne
    devient jamais une dernière exécution, la couverture et le registre signé restent identiques ;
  - le chevron d'un test s'ouvre dès qu'il a un run **ou** une attente ;
  - une attente s'affiche avec son identifiant d'entrée (bouton ouvrant la page d'exécution de l'entrée,
    comme la grille des exécutions), sa campagne et le verdict « En attente ».
- Cellule résumé inchangée : sans run, elle dit toujours « Aucune exécution ». Une attente se voit en
  dépliant le test.

Le registre signé (`signatureCopy`) filtre déjà sur `kind === 'run'` : aucun changement.

## Comment vérifier

1. Unitaire : `npx vitest run src/renderer/components/validation` (dans `apps/desktop`) : regroupement
   run / attente, test sans ligne, test seulement en attente, validation figée, test non lié.
2. e2e web : `e2e-web/gh430-validation-pending.spec.ts` (après `pnpm build:web`) : sur la page Validation,
   dépliage souris de l'exigence puis du test ; l'attente est visible avec sa campagne et « En attente » ;
   aucune ligne d'exécution ; le clic sur l'identifiant ouvre `/campaign/<campagne>/execute/<entrée>`.
3. Manuel, projet `ver-washer` : campagne `CAMP-0001`, validation `WASHER_VAL-0001`, exigence
   `WASHER_REQ-0062` : dérouler le test `WASHER_TEST-0062` et voir l'entrée `WASHER_TEST-0062-1`.
