# GH448 — Publier : git ne peut pas lancer askpass.sh (GIT_ASKPASS cité)

## Symptôme
Toute opération réseau HTTPS qui demande un identifiant (fetch, pull, push : « Publier », synchronisation) échoue :

```
error: cannot spawn "C:\…\askpass\askpass.sh": Permission denied
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

## Root cause
La revue de GH337 (`1008831`) a mis `GIT_ASKPASS` entre guillemets (`shellQuote`) en supposant que git le lance
via `sh -c`. Git l'exécute directement, sans shell (comme ssh pour `SSH_ASKPASS`) : les guillemets font partie du
nom de fichier, le shim n'est pas trouvé, git se rabat sur l'invite terminal, désactivée. Le test de GH337 lançait
lui-même le shim avec `sh -c` au lieu de passer par git : il validait l'hypothèse fausse.

## Correctif
- `askpass.ts` : `GIT_ASKPASS` = chemin brut du shim (un chemin avec espace passe tel quel) ; `shellQuote` supprimé.
- Test `askpass-spawn.gh448.test.ts` : le git embarqué (`git credential fill`, sans helper) obtient identifiant et
  mot de passe par le shim de la session, et depuis un dossier « Jean Dupont ». Il échoue avec l'ancien code
  (`cannot spawn`). Remplace `askpass-quoting.gh337.test.ts`.
- `.gitattributes` : `*.sh text eol=lf` (le shim reste en LF dans les arbres Windows en autocrlf).

## Comment vérifier
Relancer l'appli depuis le dossier principal, puis « Publier » (ou synchroniser) un dépôt HTTPS qui demande un
identifiant, par ex. PH2 / HMI VE22D : plus d'erreur `cannot spawn`. Dans le terminal intégré, un `git fetch`
sur ce dépôt passe aussi.
