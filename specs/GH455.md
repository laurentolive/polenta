# GH455 — Diff d'un fichier modifié non rafraîchi pendant ~1 minute

## Root cause

Le diff du répertoire de travail (`['sync:diff', repoPath, filepath]`, `routes/diff.tsx`) et le diff
d'élément vers le disque (`['sync:diff-element', …]` sans `toSha`) sont des requêtes React Query
sans option propre : elles héritent du `staleTime` global de 60 s (`main.tsx`). Aucune écriture
ne les invalide, et le statut de synchro (relu toutes les 3 s) n'entraîne aucune invalidation du
diff. Un diff déjà consulté reste donc servi depuis le cache pendant une minute.

## Correctif appliqué

`routes/diff.tsx` : une constante `WORKING_TREE_DIFF = { staleTime: 0, refetchInterval: 3000 }`
appliquée aux deux requêtes qui lisent le disque. Le diff se relit à la cadence du statut ; un diff
ouvert à nouveau repart d'une lecture fraîche. Les diffs de commit (`sync:commit-diff`, diff
d'élément entre deux commits) sont figés et gardent leur cache.

Hors correctif : le bouton « Rafraîchir » demandé dans l'issue n'est pas ajouté. Le relecture à
3 s le rend inutile pour le cas signalé ; à décider si l'humain le veut malgré tout.

## Comment vérifier

- Test e2e `e2e-web/gh455-diff-refresh.spec.ts` : le diff est ouvert en mode Raw sur un fichier
  modifié (`marker: v2`), le fichier est réécrit hors application (`marker: v3`), le nouveau
  contenu doit apparaître en 10 s au plus. Résultat : 1 test vert (19,6 s).
- À la main : ouvrir le diff de `polenta-repo.yaml`, changer la branche d'un composant dans la
  combo : le diff affiche le nouveau pin en quelques secondes, sans attendre une minute.
