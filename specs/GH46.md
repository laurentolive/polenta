# GH46 — Édition des diagrammes drawio dans le client web

Issue : #46 (feature). Dépend de #44 (livré). Lié à #88 (CSP) : `frame-src` devra autoriser l'éditeur.

## Constat

Dans le client web, un diagramme `.drawio` s'affiche (visionneuse `drawio-viewer.min.js`, lecture
seule) et peut être remplacé par un fichier envoyé (`web:drawio-import`). Il ne peut pas être édité.
L'action « Ouvrir dans draw.io » est masquée sur le web (`capabilities.externalDrawioEditor = false`,
`specs/SPEC-WEB.md` §7) : sur le desktop, elle lance l'application draw.io locale
(`drawio:open-external` → `shell.openPath`), qui modifie le fichier sur disque.

## Besoin

Éditer un diagramme du repo dans le navigateur, avec l'éditeur draw.io, sans dépendre d'un service
externe (on-premise : aucun appel à `app.diagrams.net`).

## Description fonctionnelle

- **Ouverture** : depuis un bloc diagramme (menu contextuel, entrée « Modifier le diagramme ») et depuis
  le champ fichier de l'éditeur de diagramme (`EditView`), un bouton « Modifier » ouvre l'éditeur.
- **Éditeur** : la webapp draw.io, en mode embarqué (`embed=1&proto=json`), est servie par le serveur
  web (image `polenta-web`). Elle est chargée dans un `<iframe>` plein écran, dans une fenêtre modale.
- **Échange** : Polenta envoie le XML du fichier (`load`), l'éditeur renvoie les modifications
  (`save`, `exit`) par `postMessage`. Seule l'origine de l'iframe servie par Polenta est acceptée.
- **Enregistrement** : le bouton « Enregistrer » envoie le XML au serveur par un nouveau channel
  `web:drawio-save(repoPath, relativePath, xml, baseSha)`. Le serveur écrit le fichier dans le repo
  (dossier `diagrams/`, chemin validé), comme le fait l'éditeur externe du desktop : le fichier change
  dans l'arbre de travail, sans commit automatique.
- **Fermeture** : « Fermer » sans enregistrer laisse le fichier intact. Une modification non
  enregistrée demande confirmation.
- **Pages** : un fichier multi-pages garde toutes ses pages ; l'éditeur ouvre la page choisie
  (« Changer de page » reste disponible).
- **Droits** : le bouton est désactivé quand le nœud est en lecture seule (`readonly: true`).

## Comportements attendus par cas d'usage

| Cas | Comportement |
|---|---|
| Diagramme d'une exigence, éditeur ouvert, modifié, « Enregistrer » | Fichier `.drawio` réécrit ; le bloc affiche la version modifiée à la fermeture |
| Modifié, « Fermer » sans enregistrer | Fichier inchangé (octets identiques) |
| Modifié, fermeture de l'onglet ou du navigateur | Avertissement du navigateur (`beforeunload`, comme GH342) |
| Fichier modifié par un tiers pendant l'édition (`baseSha` différent) | Enregistrement refusé, message « Le diagramme a changé depuis son ouverture », rien d'écrasé ; proposition de recharger |
| Fichier absent ou chemin hors `diagrams/` | Refus serveur, message d'erreur ; aucune écriture |
| Nœud en lecture seule (composant `readonly`) | Bouton absent ou désactivé, édition impossible |
| Diagramme multi-pages | Toutes les pages conservées après enregistrement |
| Desktop | Inchangé : « Ouvrir dans draw.io » reste l'éditeur externe |

## Critères d'acceptation mesurables

- [ ] **AC1** — Sur le web, un diagramme du repo s'ouvre dans l'éditeur ; le bouton est absent sur un nœud `readonly`.
- [ ] **AC2** — Pendant toute l'édition, aucune requête n'est émise vers `diagrams.net`, `app.diagrams.net`
      ou `embed.diagrams.net` (vérifié en e2e par interception réseau de la page).
- [ ] **AC3** — Modifier puis « Enregistrer » : le fichier `.drawio` sur disque contient la modification
      (relecture par `drawio:read`), et la vue du bloc l'affiche.
- [ ] **AC4** — « Fermer » sans enregistrer : hash SHA-256 du fichier identique avant et après.
- [ ] **AC5** — Une modification non enregistrée déclenche `beforeunload` ; une fois enregistrée, non.
- [ ] **AC6** — Fichier à deux pages : après enregistrement, les deux pages sont lisibles par `drawio:read`.
- [ ] **AC7** — Fichier modifié hors Polenta pendant l'édition : `web:drawio-save` renvoie une erreur de
      conflit, le fichier reste celui du tiers.
- [ ] **AC8** — `web:drawio-save` refuse un chemin hors `diagrams/` et un chemin qui sort du repo (test unitaire).
- [ ] **AC9** — Desktop : `drawio:open-external` et « Ouvrir dans Draw.io » inchangés ; tests existants verts.
- [ ] **AC10** — La taille du bundle éditeur ajouté à l'image est mesurée et indiquée dans `GH46-design.md`.
- [ ] **AC11** — Le bundle est listé dans les notices tierces (`generate-third-party-notices`) avec sa licence.

## Décisions à valider (recommandation en premier)

- **D1 — Éditeur** : bundle de la webapp jgraph/drawio (licence Apache-2.0, même source que la
  visionneuse déjà vendorisée), servi par `polenta-web`, sans appel externe. Alternative : aucune
  (pas d'autre éditeur à considérer).
- **D2 — Où on édite** : fenêtre modale plein écran, ouverte depuis le bloc ou le champ fichier.
  Alternative : édition en place dans le bloc (beaucoup plus complexe, reportée).
- **D3 — Desktop** : inchangé en V1 (draw.io desktop externe). L'étendre au desktop est hors ticket.
- **D4 — Sauvegarde** : écriture dans l'arbre de travail, sans commit, comme l'éditeur externe du
  desktop. Alternative : commit automatique (refusé : crée des commits que l'utilisateur n'a pas faits).
- **D5 — Conflit** : refus avec proposition de recharger (AC7). Alternative : fusion (hors périmètre).
