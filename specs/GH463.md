# GH463 — « + Nouvel élément » en tête d'arbre, et sélection dans la vue de droite

Issue : #463 · Branche `GH463` (depuis `main`) · Type : évolution

## Demande

Issue #463 : « La création d'exigence n'est pas assez intuitive » — il manque un bouton de création
visible, pour toutes les catégories d'objet.

Proposition de l'humain :

1. Remonter **« + Nouvel élément »** en haut de la liste (aujourd'hui en fin d'arbre).
2. Après création, l'élément doit être **ajouté et sélectionné dans la vue de droite tout de suite**.
   Le titre passe déjà en édition dans l'arbre : ce comportement est conservé.

## Constat (code, `main` à `fe986eeb`)

- **Bouton du bas** : `apps/desktop/src/renderer/components/system/ElementTree.tsx:1063-1073`. Il ouvre
  le menu Élément / Dossier / Coller (`openAddMenuNear`, ligne 721), sans création directe.
- **Création de l'arbre** : `ElementTree.tsx:571-581` (`createItem`). Le nœud est inséré, sélectionné
  **dans l'arbre seulement** (`onSelect([id])`), son titre passe en édition 50 ms plus tard, puis
  `onItemNodeAdded` est appelé.
- **Création de l'objet** : `apps/desktop/src/renderer/contexts/SystemViewContext.tsx:912-996`
  (`createItemObject`). L'objet est créé via l'API, son `objectId` est posé sur le nœud
  (`treeUpdateObjectId`), puis les requêtes sont invalidées. **Il n'appelle pas `requestGoto`** : la
  vue de droite (Tableau `ExcelView`, Document `WordView`) ne reçoit aucune cible et ne sélectionne rien.
- **Mécanisme existant** : `requestGoto` (`SystemViewContext.tsx:807`) → `gotoNodeId` / `gotoSeq` →
  sélection dans `ExcelView.tsx:1405-1411`, défilement dans `ExcelView.tsx:1972` ; `WordView` reçoit le
  même couple de props. Un clic dans l'arbre l'utilise déjà. Il suffit de l'appeler à la création.
- **Piège** : `requestGoto` lit l'`objectId` dans `rootRef.current`, mis à jour par un `useEffect` après
  rendu (`SystemViewContext.tsx:622-623`). Juste après `setRoot`, la valeur est périmée : l'`objectId`
  doit être passé en argument.
- **Position** : `insertAfter` (`apps/desktop/src/renderer/hooks/useTreeState.ts:137`) ajoute en fin de
  liste quand `afterId` vaut `null`. Avec le bouton en tête et ce comportement, l'élément créé tomberait
  en bas d'une liste longue, hors de vue.

## Comportement attendu

- **Bouton** : WHERE l'arbre est modifiable, « + Nouvel élément » est affiché **en tête de l'arbre**,
  avant le premier nœud, toujours visible (sans survol). Il est retiré de la fin de l'arbre.
- **Menu** : le clic ouvre toujours le menu Élément / Dossier / Coller, comme aujourd'hui.
- **Création** : l'élément est inséré selon la décision 2 ; son titre passe en édition dans l'arbre
  comme aujourd'hui.
- **Sélection** : WHEN l'objet est créé, l'élément est sélectionné et amené à l'écran dans la **vue de
  droite courante** (Tableau ou Document), par le mécanisme de cible existant. La navigation est un
  remplacement d'historique, comme un clic dans l'arbre : « Précédent » ne reçoit pas d'entrée en plus.
- **Focus** : le champ de titre de l'arbre garde le focus ; la sélection dans la vue de droite ne doit
  pas le voler.
- **Vue Édition** : comportement actuel conservé (l'objet créé s'ouvre).
- **Échec de création** : rien n'est sélectionné dans la vue de droite ; aucune gestion d'erreur ajoutée
  (le nœud reste sans objet, comme aujourd'hui).

## Décisions à valider

1. **Bouton** : en tête de l'arbre pour exigences, tests et issues. Libellé inchangé « Nouvel élément »
   (un libellé par catégorie, « Nouvelle exigence »…, n'est pas demandé ici).
2. **Position du nouvel élément** :
   - **A — en tête de liste** (recommandé) : cohérent avec le bouton, visible sans défiler. Utilise
     `treeInsertAtBeginning`, déjà présent dans `useTreeState.ts:104`.
   - B — en fin de liste (comportement actuel) : la sélection fait défiler jusqu'à lui, mais il reste
     loin du bouton dans une liste longue.
3. **Filtre actif qui masque le nouvel élément** — **validé : effacer le filtre**. Le filtre global est
   effacé ; le filtre de colonne du Tableau aussi, sinon la nouvelle ligne resterait masquée. Les autres
   points d'entrée (clic droit, interstice, coller) ne changent pas.

## Hors périmètre

- Gestion d'erreur de création (échec silencieux inchangé).
- Bouton de l'état vide (« Créer le premier élément ») : inchangé.
