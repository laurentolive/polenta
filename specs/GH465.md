# GH465 — Popup « Champs visibles » : barres de défilement de la vue principale

Issue : #465 · Milestone V0.8.0 · Branche `GH465` (depuis `milestone-v0.8.0`) · Type : bug

## Symptôme

Popup « Champs visibles » ouverte (⚙ de la vue Tableau / Excel, ou 👁 Colonnes d'une grille, ⚙ des
Exécutions) : cliquer sur une barre de défilement de la vue principale ferme la popup. La molette ne
fait pas défiler la vue non plus.

## Root cause

Les trois panneaux partagent la même coque, qui recouvre toute la fenêtre :

- `components/system/FieldConfigModal.tsx` (« Champs visibles », demandé),
- `components/grid/ColumnPickerPanel.tsx` (👁 Colonnes),
- `components/executions/ExecutionConfigPanel.tsx` (⚙ Exécutions),

chacun avec `<div className="fixed inset-0 …" {...backdropDismiss(onClose)}>`.

Le fond occupe toute la fenêtre, donc il reçoit le clic destiné à la barre de défilement de la vue
située dessous. `backdropDismiss` ferme la popup quand appui et relâchement ont lieu sur le fond. La
molette n'atteint pas non plus la vue : le fond n'a pas de conteneur défilant.

## Correctif

Un panneau de colonnes devient **non modal** : il ne recouvre plus la vue.

1. Le fond plein écran disparaît : le conteneur du panneau reçoit `pointer-events-none`, la carte
   `pointer-events-auto`. Barres de défilement et molette atteignent la vue.
2. Nouveau hook `renderer/lib/nonModalPanel.ts` (`useNonModalDismiss`), appliqué aux trois panneaux :
   écouteurs `mousedown` / `mouseup` / `click` en phase de capture sur `window` qui reproduisent la règle
   de `backdropDismiss` hors de la carte :
   - appui hors carte, bouton principal, hors barre de défilement : l'appui n'atteint pas la vue ;
   - fermeture si l'appui et le relâchement sont hors carte (le clic qui suit est arrêté) ;
   - un geste commencé dans la carte ou relâché dans la carte ne ferme pas (GH352) ;
   - un appui sur une barre de défilement (`isScrollbarPress`) est laissé à la vue.
3. `backdropDismiss` n'est pas modifié : les autres popups gardent leur fond.

Effet de bord voulu : la molette fait défiler la vue quand une de ces popups est ouverte.

## Périmètre

- Dans le périmètre : les trois panneaux de colonnes ci-dessus (même coque, même symptôme).
- Hors périmètre : les autres menus à fond `fixed inset-0 z-40` (`RowMaxHeightButton`, `SavedViewsMenu`,
  `ExportButton`, …) ont le même mécanisme. Non traités ici : à décider séparément.

## Comment vérifier

Test e2e `apps/desktop/e2e-web/gh465-champs-visibles-scroll.spec.ts` (barres visibles en headless) :

- clic sur la piste de la barre verticale, puis de la barre horizontale : popup ouverte, vue défilée ;
- glissement du pouce : popup ouverte à chaque étape du geste ;
- molette sur la vue : popup ouverte, vue défilée ;
- clic franc sur la vue : popup fermée ;
- appui dans la popup, relâché sur la vue : popup ouverte (GH352).

Manuel : ouvrir la Vue tableau d'une grande liste, ouvrir ⚙ Champs visibles, faire défiler la vue par
la barre verticale, la barre horizontale et la molette ; la popup reste ouverte. Un clic sur une
cellule de la vue ferme la popup sans rien sélectionner.

## Tests existants adaptés

Ces tests fermaient le panneau en cliquant son conteneur plein écran (`.fixed.inset-0.z-50`,
`getByTestId('field-config-panel')`). Le conteneur ne reçoit plus les clics : ils cliquent maintenant la
vue à `(5, 5)` (`s.page.mouse.click(5, 5)`), ce qui ferme le panneau de la même façon.

- `gh126-split-column` (5 sites), `gh169-excel-link-navigate`, `gh235-column-order`,
  `gh250-cell-tooltips`, `gh421-link-picker`, `gh70-computed-column` (2 sites),
  `gh203-saved-views`, `gh229-element-links` (2 sites), `gh176-picker-columns` (2 sites).
