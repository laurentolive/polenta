# GH54 — Gabarits d'export ajoutables depuis le client web

Issue : #54 (feature). Suite de #44 (client web). Lié à #45 (forge, bibliothèque partagée à étudier).

## Constat

Dans le client web, la bibliothèque de gabarits d'export de chaque utilisateur est
`<data>/users/<login>/userData/export-templates/` (`user-pool.ts`, GH34). Elle ne reçoit que les
exemples livrés (« Installer les exemples », `export-templates:install-examples`, qui ne réécrit jamais un
fichier existant). Le choix d'un dossier local est masqué sur le web (`capabilities.localFilesystem = false`),
et rien ne permet d'envoyer un fichier. Un client qui a ses propres gabarits Word ou Excel ne peut donc pas
les utiliser dans le navigateur.

La limite est documentée : `specs/SPEC-TEMPLATES.md` (note « Client web (GH44) ») et
`specs/GH44-design.md` §10.3 (tableau, ligne « Gabarits du client »).

## Besoin

Ajouter, remplacer et supprimer des gabarits `.docx` / `.xlsx` **dans sa bibliothèque**, depuis le navigateur.
Le mécanisme d'envoi existe déjà : `POST /upload` puis un canal `web:*` qui lit le fichier envoyé
(`web:drawio-import`, `web:image-import`).

## Hors scope

- **Bibliothèque partagée par l'équipe** (gabarits versionnés dans le repo de configuration de la forge,
  #45) : le ticket la marque « à étudier ». Elle change le modèle (droits, versionnement, conflits entre
  membres). Voir D1.
- Édition d'un gabarit dans le navigateur ; aperçu du rendu ; formats autres que `docx` et `xlsx`.
- Choix d'un sous-dossier à l'envoi (V1 : racine de la bibliothèque, voir D6).
- Gabarits par défaut déclarés dans `schema.yaml` (`exportTemplates`) : leur absence est une cause du
  constat, mais le besoin ne le demande pas. À traiter si D8 est validé.
- Bibliothèque desktop (dossier local, inchangée).

## Description fonctionnelle

- **Préférences → Bibliothèque de gabarits** (web uniquement) : la liste existante (`export-templates:list`)
  gagne trois actions : **Ajouter un gabarit** (sélecteur de fichier), **Remplacer** et **Supprimer** par
  gabarit.
- **Ajouter** : le fichier est envoyé (`POST /upload`), contrôlé par le serveur, puis copié à la racine de
  `export-templates/` sous son nom d'origine.
- **Nom déjà présent** : refus par défaut ; le remplacement n'a lieu que sur confirmation (D3).
- **Supprimer** : confirmation ; le nom du gabarit est affiché et, s'il est la préférence du projet, le
  message le signale (D4).
- Les gabarits ajoutés apparaissent sans recharger la page dans les listes d'export (`ExportButton`,
  préférences) : ces listes sont relues après chaque action.
- Export d'un gabarit ajouté : la sortie utilise le fichier de la bibliothèque (chemin validé côté serveur,
  `ExportTemplateLibrary.resolve`).

## Décisions à valider (recommandation en premier)

- **D1 — Périmètre** : bibliothèque **personnelle** de l'utilisateur. La bibliothèque partagée reste hors
  de ce ticket ; si elle est voulue, elle ouvre un nouveau ticket. *Alternative* : tout faire dans ce
  ticket (non recommandé : le ticket marque la partie partagée « à étudier »).
- **D2 — Formats** : `.docx` et `.xlsx` seulement (`TemplateExportFormat`). *Alternative* : aucune.
- **D3 — Nom déjà présent** : refus, remplacement seulement sur confirmation explicite. Le chemin relatif
  reste le même, donc les préférences du projet restent valables. *Alternative* : écrasement direct (non
  recommandé).
- **D4 — Suppression** : confirmation, avec le nom du gabarit et l'avertissement si la préférence du projet
  le référence. *Alternative* : suppression directe (non recommandée : un export casse sans prévenir).
- **D5 — Contenu** : le fichier doit être une archive ZIP contenant la partie principale du format
  (`word/document.xml` pour `.docx`, `xl/workbook.xml` pour `.xlsx`). Sinon refus, rien n'est écrit.
  *Alternative* : extension seule (un fichier corrompu se voit à l'export, pas à l'envoi).
- **D6 — Emplacement** : racine de la bibliothèque, à plat. Les gabarits déjà dans des sous-dossiers restent
  lisibles. *Alternative* : choix de sous-dossier à l'envoi (plus tard, si besoin).
- **D7 — Taille** : la limite existante `POLENTA_WEB_MAX_UPLOAD_MB` (20 Mo) s'applique, sans nouvelle
  variable. Un fichier trop gros reçoit le message existant.
- **D8 — Gabarit par défaut absent** (constat) : afficher, à l'export, le nom attendu du gabarit du projet
  absent de la bibliothèque. *Alternative* : hors ticket (recommandé si D1 à D7 sont validés, pour rester
  étroit).

## Critères d'acceptation mesurables

- [ ] **AC1** — Web, Préférences → Bibliothèque : « Ajouter un gabarit » envoie un `.docx` ; il figure dans
      la liste des gabarits Word sans rechargement de la page.
- [ ] **AC2** — Le fichier est écrit à `<data>/users/<login>/userData/export-templates/<nom>` ; son contenu
      est identique à l'envoi (SHA-256).
- [ ] **AC3** — Un nom déjà présent est refusé sans rien écrire (SHA-256 du fichier existant inchangé) ;
      après confirmation de « Remplacer », le contenu est celui de l'envoi.
- [ ] **AC4** — « Supprimer » demande confirmation, affiche le nom, puis retire le fichier du disque et de la
      liste. Si le gabarit est la préférence du projet, le message le dit.
- [ ] **AC5** — Un fichier d'extension `.docx`/`.xlsx` qui n'est pas une archive, ou dont la partie principale
      manque, est refusé avec un message, sans écriture.
- [ ] **AC6** — Un fichier de plus de `POLENTA_WEB_MAX_UPLOAD_MB` est refusé avec le message « Fichier trop
      volumineux (max 20 Mo). ».
- [ ] **AC7** — Un nom contenant `..`, un chemin absolu ou une autre extension est refusé (test unitaire
      sur le service de bibliothèque, qui refuse tout chemin sortant).
- [ ] **AC8** — Un gabarit ajouté est utilisé par l'export Word (le téléchargement produit le fichier).
- [ ] **AC9** — « Installer les exemples » ne réécrit jamais un fichier existant (test existant inchangé et vert).
- [ ] **AC10** — Desktop : aucune action d'ajout / suppression n'apparaît ; les canaux desktop
      (`export-templates:*`) sont inchangés.
