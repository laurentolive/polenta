# GH58 — Client web : bouton « projet de démonstration » absent

Issue : #58 (type:bug). Lié à #27 (bouton démo), #44 (client web), #45 (kit de déploiement).

## Root cause

La page d'accueil (`apps/desktop/src/renderer/routes/index.tsx`) n'affiche le bouton démo que si
`getMachineConfig()` renvoie `demoProjectUrl`, ou à défaut si GitHub n'est pas masqué (démo publique
GitHub). Côté web, `webMachineConfig` (`apps/desktop/src/web-server/config.ts`) masque GitHub dès que
la forge par défaut n'est pas github.com et ne renseigne `demoProjectUrl` que depuis
`POLENTA_WEB_DEMO_PROJECT_URL`.

Or `render_web_env` (`deploy/polenta-host.sh`) n'écrivait jamais cette variable, alors que
`instance add` crée le miroir `<org>/demo-ll800-produit` sur la forge et que la configuration
desktop (`write_polenta_config`) le déclare bien. Résultat : sur toute instance déployée par le kit,
le client web n'a ni démo GitHub (masquée, et hôte non autorisé par `POLENTA_WEB_GIT_HOSTS`) ni démo
de la forge.

## Correctif

`render_web_env` interroge la forge de l'instance (`GET /repos/<org>/demo-ll800-produit`, même test
que `instance sync`) et, si le miroir existe, ajoute
`POLENTA_WEB_DEMO_PROJECT_URL=https://<forge>/<org>/demo-ll800-produit.git` à `web.env`. Instance
créée avec `--no-demo` : pas de variable, pas de bouton (comportement du desktop).

RUNBOOK §client web : mention de la démo dans le contenu de `web.env`.

Aucun changement applicatif : l'hôte du miroir est la forge, déjà dans `POLENTA_WEB_GIT_HOSTS`.

## Vérifier

1. Sur le VPS, déployer le script puis rejouer `sudo polenta-host instance web enable <instance>`.
2. `web.env` de l'instance contient la ligne `POLENTA_WEB_DEMO_PROJECT_URL=…/demo-ll800-produit.git`
   (le conteneur est recréé car le fichier a changé).
3. Page d'ouverture du client web : le bouton « Discover Polenta with the demo project » apparaît en
   tête ; un clic clone la démo dans « Mes projets » et l'ouvre.
4. Instance sans démo (`--no-demo`) : pas de ligne dans `web.env`, pas de bouton.
