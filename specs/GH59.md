# GH59 — Démo : la vue Campagnes affiche 0 campagne

## Root cause

`CampaignsService.list(repoPath, component, level)` écartait toute campagne dont
`campaign.level !== level`. Le panneau Campagnes passe `level = <type de campagne>`
(ex. `campagne-produit`) ; les campagnes écrites par `scripts/demo-lave-linge/generate.mjs`
n'ont pas de champ `level` (optionnel dans `TestCampaign`) → toutes filtrées.

## Correctif

- `apps/desktop/src/main/services/campaigns.service.ts` — `list()` : le niveau effectif d'une
  campagne est `level`, à défaut le type lu dans `objectTypeRef` (`<nœud>::<type>`). Une campagne
  sans l'un ni l'autre n'est plus filtrée. Les campagnes d'un autre type restent exclues.
- `scripts/demo-lave-linge/generate.mjs` — écrit `level: campagne-produit`, comme l'app.
- Test : `apps/desktop/src/main/services/campaigns.service.list.test.ts`.

Le correctif côté app suffit à rendre visibles les campagnes des dépôts de démo déjà publiés ;
régénérer/republier `laurentolive/demo-ll800-produit` n'est pas nécessaire (optionnel, pour
aligner les fichiers sur le format de l'app).

## Vérifier

1. `node scripts/demo-lave-linge/generate.mjs --force` (ou un dépôt de démo publié avant le correctif).
2. Ouvrir le workspace → vue Campagnes : CAMP-0001 à CAMP-0005 sont listées.
3. `pnpm --filter @polenta/desktop exec vitest run src/main/services/campaigns.service`
