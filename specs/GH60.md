# GH60 — AGENTS.md généré : format d'objet périmé

Issue : #60 (type:bug)

## Root cause

Le gabarit `apps/desktop/src/main/services/agents-md.template.ts` (`buildAgentsMdTemplate`)
décrivait encore le format d'objet d'origine — fichier `.md` avec frontmatter YAML et corps
Markdown libre, champs système limités à `id`/`objectTypeRef`/`status`. Le format a depuis
évolué (YAML pur, `requirements/<ID>.yaml`, champs système complets) sans que le gabarit
suive. Un agent IA qui édite les fichiers à la main en suivant `AGENTS.md` produisait donc
des fichiers illisibles par Polenta.

## Correctif

Gabarit `AGENTS.md` (§ « Format d'un objet ») réécrit :

- objet = fichier **YAML pur** nommé d'après son ID, sans `---` ni corps Markdown ; texte long
  dans des champs `richtext` (Markdown) ;
- table des emplacements : `requirements/`, `tests/`, `campaigns/`, `test-runs/<test>/<run>.yaml`,
  `links/links.yaml` ;
- exemples complets d'exigence (`SYS-0001`) et de cas de test (`TEST-0001`, avec `equipment`,
  `steps`) ;
- champs système : `id`, `projectId`, `branchId`, `objectTypeRef`, `title`, `status`, `version`,
  `jiraLinks` ; champs de structure du test ; `needsRevalidation`/`history` posés par
  l'application seule ; champs d'audit dérivés de git, non stockés ;
- campagnes et runs : à créer via l'application ou MCP, pas à la main.

Corrections voisines dans le même gabarit (même défaut : contenu périmé qui ferait produire un
mauvais fichier à un agent) :

- invariant `tree.yaml` / `.polenta/tree.cache.yaml` → `.polenta/trees/<nœud>/<type>.yaml` ;
- règle d'ID : pas de compteur, numéro suivant déduit des fichiers **et** des pierres tombales
  `.polenta/tombstones/` (GH20) — ne pas les supprimer, ne pas supprimer un objet à la main ;
- ligne `needs_revalidation` de la table de couverture : portée par l'exigence ou un test lié
  (T172), plus par un lien.

`AGENTS_MD_TEMPLATE_VERSION` 4 → 5 : les projets existants régénèrent `AGENTS.md` à l'ouverture
(`WorkspaceService.ensureAgentFiles()`). Mise à jour de `SPEC-MCP-SERVER.md` §5 (historique des
versions) et de la colonne MAJ de `SPEC-INDEX.md`.

## Vérification

- `tsc --noEmit` (apps/desktop) : 0 erreur ; `vitest run` : 435/435.
- Rendu du gabarit contrôlé (sortie de `buildAgentsMdTemplate`) : Markdown et blocs YAML valides.
- Manuel : ouvrir un projet existant dans l'app → `AGENTS.md` à la racine réécrit, première ligne
  `<!-- polenta:agents-md-version:5 -->`, section « Format d'un objet » en YAML pur ; rouvrir le
  projet → fichier inchangé (pas de réécriture à version égale).
