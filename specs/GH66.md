# GH66 — Campagne : entryId en doublon après retrait puis nouvel ajout du même test

## Root cause

`CampaignsService` numérotait l'`entryId` d'une nouvelle instance (`${testCaseId}-${n}`) avec
`n` = **nombre** d'instances de ce test présentes + 1 (`counts` construit dans `buildNewRuns` et
`buildCarriedRuns`, consommé par `makeRun`). Après `removeEntries`, ce nombre baisse alors que les
suffixes restants ne changent pas : `TEST-0002-1` et `-2`, retrait de `-1`, compte = 1 → la
nouvelle instance reçoit `TEST-0002-2`, déjà porté.

## Correctif

`apps/desktop/src/main/services/campaigns.service.ts` : nouvelle fonction `lastEntrySuffixes(runs)`
qui renvoie, par test, le **plus grand suffixe** numérique des `entryId` existants ; elle remplace le
comptage dans `buildNewRuns` et `buildCarriedRuns`. `makeRun` reste inchangé (suffixe + 1, map mise
à jour). Un `entryId` hors format compte comme sa position parmi les instances du test (schéma du
backfill `ensureEntryIds`, conservé tel quel pour les campagnes pré-T97).

Couvre les trois chemins d'ajout : « Dupliquer » (`duplicateTest`), ajout groupé (`addTests`, dont
tests itérants T179) et report GH64. Prépare #73 : tant que les entrées retirées resteront dans
`runs[]` (`removedAt`), leur suffixe sera compté et un `entryId` ne sera jamais réutilisé.

## Vérification

- Tests de non-régression : `campaigns.service.carry.test.ts`, bloc « entryId après retrait (GH66) »
  (duplicata, ajout groupé d'un test itérant, report) — échouent sans le correctif, passent avec.
- Manuel : campagne active avec deux instances d'un test paramétré (`…-1`, `…-2`), retirer `…-1`,
  « Dupliquer » l'instance restante → la nouvelle instance est `…-3` dans `campaigns/CAMP-xxxx.yaml`.
