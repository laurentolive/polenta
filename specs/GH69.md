# GH69 — Requêtes : widget matrice — résultat de chaque test par campagne

Issue : #69 — type `feature`.

## Description fonctionnelle

Dans la vue **Suivi** (dashboards), pouvoir afficher **pour chaque test son résultat dans chaque
campagne** : un tableau croisé avec les tests en lignes, les campagnes en colonnes et le statut
d'exécution dans chaque cellule.

Le besoin est couvert par un **nouveau type de widget générique « Matrice »** (tableau croisé /
pivot) : sur n'importe quelle requête sauvegardée, l'utilisateur choisit le champ des **lignes**,
celui des **colonnes** et celui de la **valeur**. Quand les valeurs sont des statuts d'exécution de
test, la cellule est **colorée** et agrège les entrées multiples au **pire statut**. Le cas d'usage
principal (test × campagne) s'appuie sur la table `campaign_entries` (GH65) ; le widget reste
utilisable pour d'autres croisements (exigence × campagne, test × baseline, composant × statut…).

Pourquoi un widget et pas des colonnes dans la Vue Excel des tests : le nombre de campagnes n'est
pas borné, une cellule agrège plusieurs entrées (instances itérantes T97/T179, reports GH64), et il
s'agit d'analyse en lecture seule. La colonne « Dernier résultat » côté Vue Excel est traitée à part
(#70).

**Décisions de cadrage** (validées) :
- Cellule à entrées multiples : **pire statut + compteur**.
- Granularité des lignes : **libre** (champ choisi dans le widget) ; une ligne par test par défaut
  dans l'exemple, instances agrégées.
- **Widget générique** (pas un widget dédié test × campagne).
- Colonnes dans l'**ordre du résultat** de la requête ; nouvelle colonne `campaignCreatedAt` dans
  `campaign_entries` pour permettre l'ordre chronologique. **Pas de modification du seed**
  « Campagnes ».

## Comportements attendus

### 1. Nouvelle colonne `campaignCreatedAt` dans `campaign_entries`

- Source : `TestCampaign.createdAt` (ISO), identique sur toutes les entrées d'une même campagne.
- Ajoutée à `CAMPAIGN_ENTRY_FIELDS` : interrogeable en SQL et proposée dans le builder (comme
  `executedAt`).
- Permet `ORDER BY campaignCreatedAt` pour obtenir des colonnes chronologiques dans la matrice.

### 2. Type de widget « Matrice »

Nouveau `WidgetType` (`matrix`), proposé dans la popup « Ajouter / Modifier un widget » à côté de
barres, camembert, courbe, KPI, table. Comme pour les autres types, il n'est **jamais contraint**
par la forme du résultat ; l'aperçu live montre le rendu.

**Mapping** (rôles affichés dans la popup, listes = colonnes du résultat) :

| Rôle | Obligatoire | Exemple test × campagne |
|---|---|---|
| Lignes | oui | `testCaseId` |
| Libellé de ligne | non — colonne affichée à côté de la valeur de ligne | `testTitle` |
| Colonnes | oui | `campaignId` (ou `campaignTitle`) |
| Valeur | oui | `status` |

Mapping incomplet → état vide « Choisissez les lignes, les colonnes et la valeur » (jamais un rendu
cassé). Résultat vide → état vide « Aucune donnée » existant.

### 3. Construction du tableau croisé

- **Colonnes** : une par valeur distincte du champ Colonnes, dans l'**ordre de première
  apparition** dans le résultat (l'utilisateur maîtrise l'ordre par `ORDER BY` dans sa requête).
- **Lignes** : une par valeur distincte du champ Lignes, **triées par libellé en ordre naturel**
  croissant (`TEST-0002` avant `TEST-0010`) — l'ordre du résultat ne peut pas servir à la fois aux
  lignes et aux colonnes. Libellé de ligne : valeur de la **dernière** ligne du résultat portant cette
  valeur de ligne (requête triée chronologiquement → titre le plus récent, `testTitle` étant un
  snapshot par entrée).
- Valeurs `null`/vides de Lignes ou Colonnes : regroupées sous le libellé « — » (même règle que les
  autres widgets).
- **Cellule** = toutes les lignes du résultat portant ce couple (ligne, colonne) :
  - **aucune ligne** → cellule vide neutre (« · »), visuellement distincte d'un statut `pending`
    (le test n'est pas dans la campagne ≠ le test n'est pas encore exécuté) ;
  - **toutes les valeurs sont des statuts d'exécution** (`pending`, `PASS`, `FAIL`, `BLOCKED`,
    `INCOMPLETE` — `TestRunStatus`) → **pire statut** selon l'ordre
    `FAIL > BLOCKED > INCOMPLETE > pending > PASS`, cellule colorée avec les couleurs de statut
    déjà utilisées dans la page campagne ; si la cellule agrège **plus d'une** ligne, suffixe
    compteur `×n` et infobulle détaillant la répartition (ex. « 2 PASS, 1 FAIL ») ;
  - **sinon, toutes numériques** → somme (permet une requête pré-agrégée `COUNT(*) … GROUP BY`) ;
  - **sinon** → valeurs distinctes jointes par « , » (infobulle avec le texte complet si tronqué).
- Pas de ligne ni de colonne de total.

### 4. Affichage

- Tableau défilant dans les deux sens à l'intérieur du widget, **en-tête de colonnes et première
  colonne (ligne + libellé) figés**.
- En-têtes de colonnes : libellé de la valeur (tronqué, texte complet en infobulle).
- Mode impression (`printMode`) : rendu statique, sans interaction (comme les autres widgets).

### 5. Navigation (même mécanique que GH65)

- **Clic sur une cellule non vide** → popup « Détail » (`DrillDownModal`) listant les lignes
  sources de la cellule : drill-down avec les valeurs **brutes** `{ [Lignes]: v, [Colonnes]: w }`
  (§2.2 de SPEC-DASHBOARDS : mode `source` si la requête est réécrivable, sinon repli `result`).
  Depuis la popup, clic sur une ligne → ouverture de l'objet (résultat d'exécution d'une entrée de
  campagne, etc.), inchangé.
- **Clic sur un en-tête de ligne ou de colonne** dont la valeur a la forme d'un ID d'objet
  (`PREFIXE-123`, `REQ-MC-SW-001`) → ouverture, dans un nouvel onglet, de l'objet (test, exigence
  ou campagne — résolution existante par `id`). ID bien formé mais inexistant → mention « objet
  introuvable » sous la table. Les autres valeurs (titre, statut, date, colonne concaténée) ne sont
  pas cliquables.
- Rien de cliquable dans l'aperçu de la popup de configuration ni en impression.

### 6. Serveur MCP

- `add_widget` / `update_widget` acceptent le type `matrix` et son mapping ; documentation des tools
  mise à jour (y compris un exemple de requête test × campagne).

### Exemple de requête (documenté dans la spec du module)

```sql
SELECT testCaseId, testTitle, campaignId, campaignCreatedAt, status
FROM campaign_entries
ORDER BY campaignCreatedAt
```
Widget Matrice : Lignes `testCaseId`, Libellé `testTitle`, Colonnes `campaignId`, Valeur `status`.
Variante « une ligne par instance » : ajouter en SQL une colonne concaténée
(`testCaseId + ' / ' + requirementId AS instance`) et la choisir comme Lignes.

## Critères d'acceptation

1. `campaign_entries` expose `campaignCreatedAt` (= `createdAt` de la campagne) ; la colonne est
   proposée dans le builder.
2. Le type « Matrice » est proposé dans la popup de widget ; le bouton Enregistrer reste désactivé
   tant que Lignes, Colonnes et Valeur ne sont pas choisis.
3. Avec l'exemple ci-dessus sur un projet de 3 campagnes, chaque test apparaît sur une ligne, chaque
   campagne sur une colonne, dans l'ordre de création des campagnes.
4. Un test présent deux fois dans une campagne avec `PASS` et `FAIL` affiche `FAIL ×2`, infobulle
   « 1 PASS, 1 FAIL ».
5. Un test absent d'une campagne affiche une cellule vide « · », différente d'une cellule `pending`.
6. Lignes triées en ordre naturel (`TEST-0002` avant `TEST-0010`).
7. Valeur numérique : deux lignes `3` et `4` dans une cellule → `7`. Valeur texte non statut :
   valeurs distinctes jointes par « , ».
8. Clic sur une cellule → popup Détail avec exactement les entrées de ce test dans cette campagne ;
   clic sur une entrée exécutée → résultat d'exécution ouvert.
9. Clic sur l'en-tête `TEST-xxxx` → fiche du test ; sur `CAMP-xxxx` → page campagne ; un en-tête
   qui n'a pas la forme d'un ID (titre, statut, date) n'est pas cliquable.
10. En-têtes et première colonne restent visibles en défilant une matrice de 200 lignes × 30
    colonnes ; rendu fluide (pas de gel perceptible) pour 1 000 lignes de résultat.
11. Mapping incomplet ou résultat vide → état vide dédié, jamais d'erreur.
12. Widget `matrix` créable et modifiable via MCP (`add_widget` / `update_widget`).
13. Le widget fonctionne dans un dashboard privé comme partagé (règles de scope §3.1 inchangées).

## Hors scope

- Colonne « Dernier résultat » dans la Vue Excel des tests (#70).
- Ajout d'un widget matrice au seed « Campagnes » (le seed n'est jamais rejoué chez un utilisateur
  existant).
- Tri interactif par clic sur les en-têtes, filtres dans le widget, totaux de ligne/colonne.
- Historique des ré-exécutions d'une entrée (la table ne porte que le dernier état, GH65).
- Choix d'une autre règle d'agrégation que celles décrites (pas de réglage « dernier statut »).
- Export Excel du widget / du dashboard.
- Édition des résultats depuis la matrice.
