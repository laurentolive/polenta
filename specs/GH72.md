# GH72 — Campagne ouverte : en-tête du panneau latéral et combobox basculent sur « Exigences »

## Root cause

`SystemViewContext` déduit l'onglet actif (`urlCategory`) uniquement du paramètre `?category=`,
avec `requirement` par défaut. Les routes de document (`/campaign/$campaignId`, `/test/$testId`,
`/req/$reqId`) ne déclarent pas ce paramètre dans leur `validateSearch` : en ouvrant une campagne,
il disparaît de l'URL. Le panneau latéral reste « Campagnes » (`deducePanel` se base sur le
chemin), mais le contexte retombe sur `requirement` → titre « Exigences » (`CATEGORY_TITLE_KEY`)
et combobox filtrée sur les types d'exigence.

## Correctif

`apps/desktop/src/renderer/contexts/SystemViewContext.tsx` : à défaut de `?category=`, la
catégorie est déduite du chemin — `/campaign/…` → `campaign`, `/test/…` → `test`, sinon
`requirement`. Même logique que `deducePanel` (AppLayout) pour les routes de document.
Couvre aussi l'ouverture d'un test (même défaut).

## Vérification

1. Onglet Campagnes → cliquer une campagne : l'en-tête reste « Campagnes », la combobox reste
   sur le type campagne sélectionné.
2. Idem depuis une campagne → exécuter un test (`/campaign/…/run/…`) : toujours « Campagnes ».
3. Onglet Tests → ouvrir un test : en-tête « Tests ».
4. Onglet Exigences → ouvrir une exigence : en-tête « Exigences » (inchangé).

Typecheck OK, tests unitaires renderer OK (53/53).
