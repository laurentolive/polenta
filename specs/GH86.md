# GH86 — Éditeur de schéma : enregistrer un type supprime le validator (EARS) de ses champs

Type : bug · Issue #86 (relevé pendant GH77 sprint 2)

## Root cause

L'éditeur de type (onglet Structure, `ElementConfigModal`) travaille sur un état éditable
(`objectTypeEditor.tsx`). Il reconstruit le champ, le statut et le type à l'enregistrement, avec les
seules clés qu'il affiche :
- `fieldToEditable` / `editableToField` : `name`, `label`, `type`, `values`, `required`, `default`,
  `placeholder`, `trackHistory` ;
- `statusToEditable` / `editableToStatus` : `name`, `label`, `color`, `isApproval`, `isTerminal` ;
- `objTypeToEditable` / `editableToObjType` : `name`, `label`, `color`, `prefix`, `category`, `fields`,
  `statuses`, `trackStatusHistory`.

Toute autre clé disparaissait à l'enregistrement, y compris pour une simple modification du libellé.
Concrètement, il s'agit de `validator` (`EARS`, `regex:…`), ou d'une clé ajoutée à la main ou par une
version plus récente. Or la règle EARS sert à la maturité, à l'import en masse MCP (contrôle strict,
T122) et au contrôle avant review.

## Correctif

Correctif minimal, sans changement d'UI : les clés que l'éditeur n'affiche pas sont mises de côté au
chargement (`extra` sur `EditableField`, `EditableStatus` et `EditableObjectType`), puis réécrites
telles quelles à l'enregistrement, **après** les clés de l'éditeur. L'ordre des clés dans
`schema.yaml` reste donc stable. Les clés éditées gardent la main : vider un libellé le retire
toujours.

Un champ renommé garde ses clés mises de côté. Un champ ajouté dans l'éditeur n'en a aucune.

Fichier modifié : `apps/desktop/src/renderer/components/schema/objectTypeEditor.tsx`.
Test : `objectTypeEditor.gh86.test.ts`, 5 scénarios :
- aller-retour identique ;
- libellé modifié, `validator` et clés inconnues conservés ;
- libellé vidé ;
- champ renommé ;
- nouveau champ.

Hors correctif, à traiter dans une issue à part si utile :
- l'éditeur ne permet toujours pas de **saisir** un `validator` ;
- `default` est relu en texte, donc une valeur par défaut numérique est réécrite en chaîne.

## Comment vérifier

1. Dans `schema.yaml`, donner `validator: EARS` à un champ `statement`.
2. Projet → Modèle de données → onglet Structure → ouvrir le type, changer son libellé, Enregistrer.
3. `schema.yaml` : `validator: EARS` est toujours présent, et seul le libellé a changé dans le diff
   (Version).

Résultats : `tsc` sans erreur ; `pnpm test` 430 tests desktop + 38 merge-core, tous verts.
