# GH95 — Onglet Liens : types des composants en repo séparé absents

## Root cause
`getAllRefs` (`apps/desktop/src/renderer/routes/schema.tsx`) construisait la liste des refs
proposées (Sources / Cibles d'un type de lien) uniquement depuis `schema.nodes` du repo courant.
Un composant monté depuis son propre repo (dépendance `polenta-repo.yaml`) ne déclare pas
d'`objectTypes` dans ce schéma — le schéma du composant fait foi — donc ses types n'étaient
jamais proposés. De plus `RefChips` n'affichait que les refs de cette liste : une ref déjà
enregistrée vers un type de sous-repo devenait invisible.

## Correctif
- `SchemaEditorPage` récupère les schémas de tous les repos du workspace via
  `useWorkspaceStructure` (même primitive et même cache react-query que l'onglet Structure).
- `getAllRefs` ajoute les types de tous ces schémas, en `<nœud>::<type>` tel qu'écrit dans le
  schéma du repo — la chaîne que portent les objets dans `objectTypeRef`, comparée par
  `linkUtils.matchesRefs`. Dédoublonné.
- `RefChips` affiche aussi, sélectionnée, toute ref enregistrée absente de la liste (repo non
  chargé/inaccessible, type renommé), pour qu'elle reste visible et retirable.

## Vérification
1. Ouvrir le workspace démo lave-linge (`ll800-produit`).
2. Modèle de données → Liens : les puces incluent `root::exigence-moteur`,
   `root::test-moteur`, `firmware-moteur::exigence-fw-moteur`, `root::exigence-pompe`,
   `root::exigence-wifi`, `root::exigence-bus`…
3. Sélectionner une de ces refs, Enregistrer, recharger : la puce reste sélectionnée.
4. Ouvrir un repo seul (pas de workspace) : comportement inchangé.
