# GH97 — Impossible d'ajouter un 2e type d'exigence/test/campagne à un repo

## Root cause
`handleAddElement` (`StructureTab.tsx`) crée le nouveau type via `emptyObjType`, qui propose
`<COMPOSANT>_<SUFFIXE>` pour le nom **et** le préfixe, puis enregistre le schéma aussitôt.
Quand le repo/nœud a déjà un type de cette catégorie (son type par défaut), la proposition est
identique au type existant : `SchemaService.assertUniquePrefixes` refuse l'enregistrement
(`PREFIX_TAKEN`), l'éditeur du nouveau type ne s'ouvre jamais, et l'utilisateur n'a aucun moyen de
choisir un autre nom.

## Correctif
- `emptyObjType` accepte un ensemble `taken` (optionnel) et prend le premier suffixe libre
  (`_2`, `_3`…) si la proposition est déjà prise.
- `handleAddElement` lui passe les noms des types du nœud et les préfixes de tout le workspace
  (`allPrefixes`). Le type est créé, l'éditeur s'ouvre, l'utilisateur renomme nom/préfixe.
- Test : `objectTypeEditor.gh97.test.ts`.

## Vérification
1. Workspace avec un repo qui a déjà un type d'exigence (ex. PH2 → `hmi-PH2`, `HMI_PH2_REQ`).
2. Structure → « + » sur la ligne du repo → « + Exigence » : un type `HMI_PH2_REQ_2` est créé et
   son éditeur s'ouvre ; aucun message d'erreur.
3. Le renommer (nom + préfixe), enregistrer : le schéma est sauvé.
