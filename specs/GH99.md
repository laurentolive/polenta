# GH99 — L'onglet Liens n'édite que les types de lien du repo racine

## Root cause
`SchemaEditorPage` (`apps/desktop/src/renderer/routes/schema.tsx`) chargeait et enregistrait les
`linkTypes` du seul `repoPath` ouvert (repo racine). Or, quand on édite un objet, les types de
lien proposés viennent du schéma **du repo de cet objet** (`SystemViewContext`). Un composant en
repo séparé dont le schéma a `linkTypes: []` ne pouvait donc avoir aucun lien, sans recours dans
l'UI.

## Correctif
- Sélecteur « Types de lien du repo » en tête de l'onglet Liens (affiché quand le workspace a
  plusieurs repos) : liste les repos de `useWorkspaceStructure().flatNodes`, libellés comme dans
  Structure (label du nœud `root`).
- L'état d'édition est chargé depuis le schéma du repo choisi et l'enregistrement écrit dans le
  `schema.yaml` de ce repo (`nodes`/`preferences`/`roles`/`implements` de ce repo repassés tels
  quels, comme pour le repo racine).
- Le sélecteur est désactivé tant qu'il y a des modifications non enregistrées (sinon elles
  seraient perdues ou écrites dans le mauvais repo).
- Dépend de GH95 (#96) : refs proposées issues de tous les repos du workspace.

   cible `root::VE22D_SW_REQ` → Enregistrer : `hmi-PH2/.polenta/schema.yaml` contient le type.
4. Modifier sans enregistrer : le sélecteur est grisé.
5. Ouvrir une exigence de `hmi-PH2` : le type `implements` est proposé dans ses liens.
