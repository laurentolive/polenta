# T100 — bug : accents mal affichés dans la vue édition de campagne

## Root cause

Le fichier source `apps/desktop/src/renderer/routes/campaign.$campaignId.tsx` contenait
des chaînes de caractères corrompues par un mojibake UTF-8 → Latin-1/Windows-1252 : à un
moment donné, du texte UTF-8 correctement encodé a été réinterprété puis resauvegardé comme
Latin-1/Windows-1252, ce qui a converti chaque caractère accentué codé sur 2 octets UTF-8 en
deux caractères Unicode distincts (ex: `é` → `Ã©`, `…` → `â€¦`, `─` → `â”€`). Le fichier se
retrouve alors valide comme UTF-8, mais son contenu textuel est faux — ce n'est pas un bug de
rendu runtime (charset HTML, police, etc.), le texte source lui-même est corrompu à la racine.

Seul ce fichier était touché (vérifié par recherche du motif de mojibake dans
`apps/desktop/src`) : les libellés de statut d'exécution (`Passé`/`Echoué`/`Bloqué`), les
messages d'état (`Chargement…`, `Paramètre … manquant`), les titres de boutons (`Exécuter`,
`Consulter le résultat`, `Modifier les valeurs des paramètres`), le texte du panneau d'ajout
de tests (`Filtrer…`, `Aucun résultat`, `Tous les tests sont déjà dans la campagne`,
`Ajout…`) et la boîte de dialogue de suppression (`sera supprimée définitivement`,
`irréversible`). Le reste du fichier contenait déjà des accents correctement encodés,
signe que la corruption provient d'une édition ponctuelle antérieure et non d'un problème
systémique d'encodage de l'éditeur/du dépôt.

## Correctif appliqué

Remplacement de chaque séquence mojibake par le caractère Unicode correct
(`Ã©`→`é`, `Ã¨`→`è`, `Ã `+` `→`à`, `Ã§`→`ç`, `â€¦`→`…`, `â”€`→`─`, etc.), fichier
réenregistré en UTF-8. Aucun changement de logique, uniquement du texte affiché.

**Fichier modifié** : `apps/desktop/src/renderer/routes/campaign.$campaignId.tsx`
(19 lignes touchées, uniquement du texte).

## Comment vérifier

1. Ouvrir une campagne (active ou non) dans la vue édition de campagne.
2. Vérifier que les libellés de statut ("Passé", "Echoué", "Bloqué") s'affichent avec
   accents corrects, sans séquences `Ã©`/`â€¦` etc.
3. Ouvrir le panneau "Ajouter des tests" → vérifier "Filtrer…", "Aucun résultat",
   "Tous les tests sont déjà dans la campagne".
4. Cliquer sur "Supprimer la campagne" → vérifier le texte de la boîte de dialogue
   ("sera supprimée définitivement", "irréversible").
5. Survoler les boutons d'action (icône Exécuter, icône Voir, icône crayon) → vérifier les
   info-bulles ("Exécuter ce test", "Consulter le résultat", "Modifier les valeurs des
   paramètres").
6. `pnpm --filter @polenta/desktop typecheck` propre (l'échec de `@polenta/api` sur
   `schema.service.ts` est préexistant, sans rapport avec ce ticket).
