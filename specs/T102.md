## Description

Au démarrage de l'application, la route `/` doit appliquer un ordre de priorité strict
pour décider de l'écran affiché :

1. **Écran de connexion** (`/login`) si aucun compte git n'est configuré.
2. **Page de chargement de projet** (écran actuel de `/` : Récents / Ouvrir un projet
   existant / Ouvrir depuis un repo distant / Créer un nouveau projet) si un compte
   existe mais qu'aucun projet n'est actuellement chargé (`lastOpenedId` absent).
3. **Page Suivi/Dashboard** (`/dashboard`) si un compte existe **et** qu'un projet était
   déjà chargé au moment de la fermeture précédente (`lastOpenedId` présent).

## État actuel (avant correctif)

Le point 1 et le point 2 sont déjà implémentés dans `apps/desktop/src/renderer/routes/index.tsx`
(`useEffect` d'init : `hasAnyAccount()` → `/login` sinon ; `getLastOpened()` → si absent,
affiche la page de chargement de projet).

Le point 3 est **incorrect** : quand `getLastOpened()` renvoie un projet, le code navigue
vers `/schema` (page d'atterrissage du projet depuis T86) au lieu de `/dashboard`.

```typescript
// index.tsx, useEffect init() — comportement actuel
const lastOpened = await api.workspace.getLastOpened()
if (lastOpened) {
  await navigate({ to: '/schema', search: { repoPath: '', projectId: encodeProjectId(lastOpened.workspaceDir) } })
  return
}
```

## Comportement attendu (après correctif)

Remplacer la navigation vers `/schema` par une navigation vers `/dashboard` avec le
`projectId` encodé, sans `dashboardId` :

```typescript
await navigate({ to: '/dashboard', search: { projectId: encodeProjectId(lastOpened.workspaceDir) } })
```

`/dashboard` gère déjà nativement l'absence de `dashboardId` (cf. docstring de
`routes/dashboard.tsx` — invite l'utilisateur à choisir un dashboard depuis le panneau
latéral). Le fait d'y afficher automatiquement le *premier* dashboard par défaut est le
périmètre du ticket **T109** (hors scope ici).

## Hors scope

- Le choix automatique du premier dashboard à afficher dans `/dashboard` quand
  `dashboardId` est absent → **T109**.
- La navigation déclenchée par un clic manuel sur un projet dans "Récents" (fonction
  `goToProject` / `<Link>` de la page de chargement de projet) : action utilisateur
  explicite, distincte du flux "démarrage app", elle continue de pointer vers `/schema`
  (comportement issu de T86, non remis en cause par ce ticket).
- Les channels `menu:open-workspace` / `menu:close-project` (déclenchent tous deux
  `markLastOpened(null)` + navigation vers `/`) : après leur passage, `lastOpenedId` est
  toujours `null`, donc `/` retombe systématiquement sur la page de chargement de projet
  (point 2), jamais sur `/dashboard` — comportement inchangé et correct.
- Le flux de connexion (`login.tsx`, PAT ou Device Flow) : navigue déjà vers `/` après
  succès, qui ré-applique la même logique de priorité — inchangé.

## Critères d'acceptation

- [ ] App relancée avec un compte configuré et **aucun** projet précédemment chargé
      (`lastOpenedId` vide) → affiche la page de chargement de projet (Récents/Ouvrir/Créer).
- [ ] App relancée avec un compte configuré et un projet précédemment chargé
      (`lastOpenedId` renseigné) → affiche `/dashboard?projectId=<id>` (et non `/schema`).
- [ ] App relancée sans aucun compte configuré → affiche `/login`, quel que soit l'état
      de `lastOpenedId`.
- [ ] Connexion réussie (PAT ou Device Flow) → retombe sur `/` puis applique la même
      priorité (project chargé → dashboard ; sinon → page de chargement de projet).
- [ ] Clic manuel sur un projet dans "Récents" (page de chargement de projet) → continue
      de naviguer vers `/schema`, inchangé.
