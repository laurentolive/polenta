# T107 — Vue Recherche : page vide dédiée au lieu de laisser la page précédente affichée

## Root cause

`SIDEBAR_ONLY_PANELS` dans `AppLayout.tsx` incluait `'search'` au même titre que
`'account'` : cliquer sur l'icône Recherche de la barre d'activité ne faisait que
basculer un overlay de sidebar (`sidebarOverride`), sans jamais appeler `navigate()`.
La zone de contenu principale (`<Outlet/>`) continuait donc d'afficher la page/route
précédente (dashboard, exigence, requêtes…) derrière le panneau de recherche.

Confirmé en reproduisant en direct (app desktop lancée en `dev`, pilotée via CDP/
Playwright) : sur trois vues différentes avec du contenu réel (dashboard avec
widgets, vue Système, vue Requêtes), cliquer sur Recherche laissait le contenu
principal strictement inchangé, y compris à 0 ms de délai (pas de flash transitoire).

Le comportement voulu (confirmé avec l'utilisateur) : la vue Recherche doit avoir sa
propre page de contenu principal, vide par défaut (avec un message invitant à
rechercher), plutôt que de laisser transparaître la page précédente.

## Correctif appliqué

- Nouvelle route `apps/desktop/src/renderer/routes/search.tsx` : page de contenu
  principal dédiée à `/search?projectId=…`, affichant un état vide (icône + message
  « Utilisez le panneau de recherche à gauche… »). Le panneau de recherche
  (query/filtres/remplacement/résultats) reste inchangé, toujours dans la sidebar
  (`SearchPanel.tsx`, non modifié).
- `AppLayout.tsx` :
  - retrait de `'search'` de `SIDEBAR_ONLY_PANELS` (seul `'account'` y reste — la
    vue Compte n'a pas de contenu principal dédié, comportement inchangé pour elle) ;
  - `deducePanel()` reconnaît désormais `/search` ;
  - `handleSelectPanel()` : nouveau `case 'search'` qui navigue vers `/search` avec
    `projectId`, symétrique aux autres panneaux (`system`, `dashboard`, `version`…).

### Bug de config annexe découvert et corrigé (bloquant pour tester le correctif)

`electron.vite.config.ts` déclarait `routesDirectory: './src/renderer/routes'` et
`generatedRouteTree: './src/renderer/routeTree.gen.ts'` alors que le plugin
TanStack Router les résout déjà relativement à `root: './src/renderer'` — le chemin
effectif doublait `src/renderer` (`src/renderer/src/renderer/routes`, `ENOENT`).
Résultat : la génération automatique de `routeTree.gen.ts` en mode `dev` échouait
silencieusement depuis un moment (log `Error: ENOENT… scandir
'…\src\renderer\src\renderer\routes'` visible dès le tout premier lancement, avant
toute modification liée à T107) — le fichier généré existant datait d'un run
antérieur et n'était simplement plus régénéré. Sans ce correctif, `search.tsx`
n'aurait jamais été pris en compte par le routeur. Corrigé en passant les deux
chemins en relatif à `root` (`'./routes'` / `'./routeTree.gen.ts'`).

## Comment vérifier

1. `pnpm --filter @polenta/desktop dev`
2. Ouvrir un projet, aller sur une page avec du contenu (ex. un dashboard avec des
   widgets, ou Système → une exigence).
3. Cliquer sur l'icône Recherche (loupe) dans la barre d'activité.
4. Attendu : la zone de contenu principale (à droite) devient une page vide dédiée
   (icône loupe + message d'invitation), le panneau de recherche à gauche reste
   fonctionnel comme avant (query, filtres, remplacement, résultats qui naviguent
   vers l'élément au clic).
5. Naviguer Système → Suivi → Version → Projet → Recherche : aucune erreur, chaque
   panneau garde son comportement de navigation habituel.
