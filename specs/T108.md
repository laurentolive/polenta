# T108 — Nettoyer la redondance sidebar / page d'ouverture de projet

## Contexte

Quand aucun projet n'est ouvert, la route `/` (`HomePage`, `apps/desktop/src/renderer/routes/index.tsx`)
est affichée dans la zone principale **pendant que la sidebar reste visible** à gauche
(`AppLayout` monte toujours `ActivityBar` + `Sidebar`, cf. `deducePanel()` qui retourne `'project'`
par défaut pour toute route non reconnue, y compris `/`). La `Sidebar` affiche alors
`ProjectPanel` → `NoProjectPanel` (`apps/desktop/src/renderer/components/sidebar/ProjectPanel.tsx`).

Les deux zones affichent aujourd'hui un contenu redondant :

| Zone | Contenu actuel |
|------|-----------------|
| Sidebar (`NoProjectPanel`) | Liste "Récents" + 3 boutons : "Ouvrir un projet existant", "Ouvrir depuis un repo existant", "Créer un nouveau projet" |
| Page principale (`HomePage`) | Liste "Récents" (colonne gauche) + 3 formulaires fonctionnels : "Ouvrir un projet existant", "Ouvrir un projet depuis un repo existant", "Créer un nouveau projet" (colonne droite) |

Les 3 boutons de la sidebar sont de plus des leurres : les trois `onClick` font tous
`navigate({ to: '/' })` sans distinction — ils ne font qu'amener sur la page qui contient déjà
les vrais formulaires.

## Comportement attendu

1. **Sidebar (`NoProjectPanel`)** : supprimer les 3 boutons ("Ouvrir un projet existant",
   "Ouvrir depuis un repo existant", "Créer un nouveau projet"). Ne conserver que le header
   "Projet" et la liste "Récents" (comportement inchangé : masquée si `recents.length === 0`).
2. **Page principale (`HomePage`)** : supprimer le bloc "Récents" (colonne gauche + son `useEffect`/état
   `recents` si plus utilisé ailleurs dans le composant). Ne conserver que les 3 formulaires
   ("Ouvrir un projet existant", "Ouvrir un projet depuis un repo existant", "Créer un nouveau projet").
3. **Layout de la page principale** : puisque la colonne "Récents" disparaît, la page repasse
   systématiquement au layout aujourd'hui utilisé quand `recents.length === 0`
   (colonne unique centrée, `max-w-lg mx-auto`) — la logique conditionnelle
   `recents.length > 0 ? 'grid-cols-2' : 'max-w-lg mx-auto'` est supprimée avec la colonne.
4. **Redirection immédiate vers `/dashboard`** : le comportement existant où `init()` redirige
   automatiquement vers `/dashboard?projectId=…` si un `lastOpened` existe est **inchangé** —
   la page `/` avec ses formulaires ne s'affiche que quand aucun `lastOpenedId` n'est connu,
   exactement comme aujourd'hui.
5. Le point d'entrée pour accéder à un projet récent reste donc uniquement la **sidebar**
   (liste "Récents" cliquable, comportement `Link to="/schema"` inchangé) — la page principale
   ne propose plus que la création/l'ouverture d'un nouveau projet.

## Hors scope

- Pas de changement au wording des formulaires de la page principale (reste "Ouvrir un projet
  existant" / "Ouvrir un projet depuis un repo existant" / "Créer un nouveau projet" — l'alignement
  avec le wording "Charger un projet" / "Ouvrir un projet local" documenté dans
  `SPEC-PROJECT-MANAGEMENT.md` §8 n'est pas fait ici, il est déjà en décalage avec le code actuel
  et n'est pas demandé par le ticket).
- Pas de changement à la logique de récupération des projets récents (`api.workspace.listRecents`,
  `api.workspace.markRecent`) ni à `ProjectPanel`/`WithProjectPanel` (panneau affiché une fois un
  projet ouvert).
- Pas de changement à `AppLayout`/`ActivityBar`/`deducePanel` — la sidebar continue d'être montée
  sur la route `/`.
- Pas de sprint découpé : le changement tient dans un seul sprint (2 fichiers).

## Critères d'acceptation

- [ ] Sur `/` sans `lastOpenedId`, la sidebar n'affiche plus que "Projet" + "Récents" (si non vide) —
  aucun bouton "Ouvrir…"/"Créer…" dans la sidebar.
- [ ] Sur `/` sans `lastOpenedId`, la page principale n'affiche plus de bloc "Récents" —
  seulement les 3 formulaires, toujours centrés en colonne unique (avec ou sans projets récents
  existants par ailleurs).
- [ ] Cliquer un projet listé dans "Récents" (sidebar) navigue toujours vers `/schema` avec le bon
  `projectId`, exactement comme avant (comportement `Link` non modifié).
- [ ] Les 3 formulaires (Ouvrir / Ouvrir depuis repo / Créer) restent pleinement fonctionnels,
  aucune régression sur `handleOpen`/`handleCreateFromClone`/`handleCreateNew`.
- [ ] Aucune référence orpheline à l'état `recents`/`setRecents` dans `HomePage` si retiré de l'UI
  (garder uniquement si encore utilisé, ex. par `goToProject`/`markRecent` — à vérifier lors du dev).
- [ ] TypeScript/lint : zéro nouvelle erreur.
