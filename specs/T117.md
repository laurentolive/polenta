# T117 — "Exécuter" un test dans une campagne ne fait rien visuellement

## Root cause

`routes/campaign.$campaignId.execute.$testId.tsx` et `routes/campaign.$campaignId.run.$testId.tsx`
suivent la convention de nommage plat de TanStack Router (`campaign.$campaignId.execute.$testId.tsx`)
qui, en présence d'un fichier `campaign.$campaignId.tsx`, les enregistre automatiquement comme
**routes enfants** de celui-ci (`getParentRoute: () => CampaignCampaignIdRoute` dans
`routeTree.gen.ts`).

Or `CampaignDetailPage` (`campaign.$campaignId.tsx`) ne rend jamais de `<Outlet />` — son JSX
retourné est une page complète autonome (liste des runs de la campagne). Une route enfant ne
s'affiche que via l'`<Outlet />` de son parent : en son absence, naviguer vers la route enfant
avance bien le routeur (URL, `location.pathname`, historique) mais **rien de nouveau ne se
monte** — l'arbre de composants affiché reste celui de `CampaignDetailPage`, écran figé.

`ExecuteTestPage` et `TestRunViewPage` (les composants de ces deux routes) rendent chacun leur
propre `ViewHeader` + layout plein écran — clairement conçus comme des pages de remplacement
total, pas comme du contenu à afficher imbriqué dans la liste de la campagne. Le nommage de
fichier créait une hiérarchie de routing qui ne correspondait pas à l'intention.

Le "quirk de remount du root route component" cité comme cause probable dans le ticket
(`TabsContext.tsx` commentaire ~155-167) est un phénomène réel mais distinct, sans lien avec ce
bug : la preuve est que renommer les deux fichiers de route (sans toucher à `TabsContext.tsx`)
suffit à corriger le symptôme.

## Correctif appliqué

Renommage des deux fichiers de route avec le suffixe d'échappement `_` que TanStack Router
reconnaît pour sortir un fichier de l'imbrication automatique sous le parent dont le préfixe de
nom correspond :

- `campaign.$campaignId.execute.$testId.tsx` → `campaign.$campaignId_.execute.$testId.tsx`
- `campaign.$campaignId.run.$testId.tsx` → `campaign.$campaignId_.run.$testId.tsx`

`routeTree.gen.ts` régénéré en conséquence : les deux routes ont maintenant
`getParentRoute: () => rootRouteImport` (comme toutes les autres pages de détail de l'app —
`req.$reqId`, `test.$testId`…) au lieu d'être enfants de `CampaignCampaignIdRoute`. Le `path`/
`fullPath` exposé ne change pas (`/campaign/$campaignId/execute/$testId`,
`/campaign/$campaignId/run/$testId`) — le suffixe `_` est un signal de build, absent de l'URL
runtime. Aucun changement dans le code applicatif (les deux pages, `CampaignDetailPage`,
`AppLayout.deducePanel` qui matche déjà sur le préfixe `/campaign/` et reste donc correct pour
ces deux routes).
