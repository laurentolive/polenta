# T133 — Bug : le clic molette sur un onglet ne le ferme pas

## Description

Dans la barre d'onglets (TabBar), cliquer avec le bouton molette (clic milieu)
sur un onglet devait le fermer, comme dans un navigateur classique. Rien ne se
produisait — seul le curseur d'autoscroll natif du navigateur/Electron
apparaissait brièvement.

## Root cause

`apps/desktop/src/renderer/components/layout/TabBar.tsx` : le bouton de
chaque onglet ne gérait que `onClick` (activation de l'onglet) et le clic sur
la croix de fermeture (`stopPropagation` + `attemptCloseTab`). Aucun handler
n'écoutait le clic molette (`auxclick`, bouton 1) : l'événement remontait
sans effet applicatif, et le comportement par défaut du navigateur
(autoscroll au clic molette) restait actif.

## Correctif appliqué

Deux handlers ajoutés sur le `<button>` de l'onglet :
- `onMouseDown` : si `e.button === 1`, `e.preventDefault()` — supprime le
  curseur d'autoscroll natif dès l'appui du bouton.
- `onAuxClick` : si `e.button === 1`, appelle `attemptCloseTab(tab.id)` —
  même point d'entrée que la croix de fermeture et Ctrl+W, donc la
  confirmation de fermeture pour un onglet "dirty" (`pendingCloseId` /
  `ConfirmCloseTabModal`) s'applique aussi au clic molette.

Correctif minimal, pas de changement de `TabsContext.tsx`.

## Comment vérifier

1. Lancer l'app desktop (`skill run-desktop` ou `npm run dev` dans
   `apps/desktop`), ouvrir un projet avec au moins 2 onglets.
2. Clic molette sur un onglet non actif → l'onglet se ferme, l'onglet voisin
   devient actif (comportement identique à la croix).
3. Rendre un onglet "dirty" (ex. modifier un champ d'une exigence sans
   sauvegarder), clic molette dessus → la popup de confirmation de fermeture
   s'affiche au lieu de fermer directement.
4. Clic molette sur l'unique onglet restant → il repasse sur la route
   d'accueil au lieu de disparaître (même comportement que la croix sur le
   dernier onglet).
5. Vérifier qu'aucun autoscroll visuel n'apparaît au clic molette sur un
   onglet.
