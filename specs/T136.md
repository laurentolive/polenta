# T136 — bug : titre "Sans titre" périmé dans le dropdown d'ajout de lien (Vue Système)

## Reproduction

1. Vue Système, ouvrir un type d'exigence (ex. `root::exigence-systeme`).
2. Créer un nouvel élément (bouton `+`) → l'objet est créé côté serveur avec le titre
   par défaut `"Sans titre"` (`SystemViewContext.tsx::createItemObject`, ou le fallback
   équivalent de `SystemView.tsx::handleFlushEditValues`).
3. Renommer l'élément avec un vrai titre (ex. `"Démarrage rapide"`) — la sauvegarde
   aboutit, l'objet ouvert affiche bien le nouveau titre.
4. Ouvrir un **autre** objet (ou le même) et, dans la section Liens, taper dans le champ
   de recherche pour ajouter un lien vers l'élément renommé à l'étape 3.
5. **Constaté :** le candidat apparaît avec le bon ID mais le titre affiché à côté est
   toujours `"Sans titre"` (ou plus généralement le titre d'avant la dernière
   modification), alors que l'objet lui-même a bien le titre à jour.

## Root cause (double cause)

**1. Le renommage via l'arbre ne touchait jamais le champ `title` réel de l'objet.**
Le nom affiché partout dans la Vue Système (arbre, colonne "Label" en vue Excel,
champ "Nom" en vue Édition/Word) est `TypeTreeNode.name`, un champ de
`tree.yaml` — pas `Requirement.title` / `TestCase.title`. `handleRenameNode`
(`SystemView.tsx`) ne faisait que `renameNodeInTree` + `api.tree.save(...)` : le
`title` de l'objet, lui, n'était écrit qu'une seule fois, à la création (souvent
avec la valeur par défaut `"Sans titre"` — voir `createItemObject` dans
`SystemViewContext.tsx`), et plus jamais mis à jour ensuite. Confirmé en
reproduisant dans l'app buildée : renommer un objet via le champ "Nom" changeait
bien `tree.yaml`, mais `requirements/SYS-0001.yaml` gardait `title: Sans titre`.

**2. Même quand le titre change, le sélecteur de lien ne le voyait pas.**
`SystemView.tsx` charge deux requêtes React Query globales (tous nœuds/types
confondus) qui alimentent `candidateObjects`, la liste passée à `LinkCombobox` :

```ts
const { data: allRequirements = [] } = useQuery({ queryKey: ['requirements-all', repoPath], ... })
const { data: allTests = [] } = useQuery({ queryKey: ['tests-all', repoPath], ... })
```

Toutes les mutations qui créent ou modifient un objet invalidaient `['objects', ...]`
(liste filtrée du nœud/type courant, pour Excel/Word) et parfois `['object', ...]`
(objet en cours d'édition), mais **jamais** `['requirements-all', repoPath]` /
`['tests-all', repoPath]`. React Query ne les refetch donc pas après une
création/un renommage — seulement au montage du composant ou au refocus de la
fenêtre.

Les deux causes se cumulent : même en corrigeant seulement la 2ᵉ, le titre serait
resté affiché correctement... mais toujours égal à `"Sans titre"`, puisque jamais
réécrit sur disque par le renommage.

## Correctif appliqué

- `apps/desktop/src/renderer/components/system/SystemView.tsx`
  - `handleRenameNode` — après le renommage du nœud d'arbre, si ce nœud a un
    `objectId`, synchronise aussi `title` sur l'objet (`api.requirements.update`
    / `api.tests.update`). Chemin partagé par le renommage inline dans l'arbre,
    la vue Excel et la vue Word (`onRenameNode`).
  - Ajout d'un helper `invalidateCandidateObjects()` (invalide
    `requirements-all` + `tests-all`), appelé en plus de l'invalidation
    `objects` existante partout où un titre est créé ou modifié :
    `saveInlineEditsMutation.onSuccess`, `autoSaveMutation.onSuccess` (si
    `field === 'title'`), `handleEditBlurField` (création au blur du titre),
    `handleFlushEditValues` (update si `newTitle` défini, et création), et
    maintenant aussi `handleRenameNode`.
- `apps/desktop/src/renderer/contexts/SystemViewContext.tsx`
  - `createItemObject` — invalide aussi `requirements-all`/`tests-all` après
    création immédiate (insertion d'item / paste dans l'arbre).

Correctif ciblé sur la synchro manquante + les invalidations manquantes, pas de
changement de comportement ni de refactoring du flux de sauvegarde existant.

## Vérifié en conditions réelles

Reproduit et corrigé dans l'app buildée (`pnpm build` + driver Playwright,
`.claude/skills/run-desktop`) : création d'un objet SYS-0001 (`title: "Sans
titre"` sur disque), renommage via le champ "Nom" de la vue Édition →
`requirements/SYS-0001.yaml` passe bien à `title: Titre T136 v2`, et le
dropdown de recherche de la section Liens affiche immédiatement `SYS-0001
Titre T136 v2` (avant le fix : restait bloqué sur `SYS-0001 Sans titre`, à la
fois côté disque et côté dropdown).

## Comment vérifier

1. Lancer l'app, ouvrir un projet.
2. Reproduire les étapes 1-5 ci-dessus.
3. **Attendu après fix :** le titre affiché dans le dropdown de recherche du lien
   correspond immédiatement au titre réel de l'objet, sans avoir à recharger la
   Vue Système ou changer de fenêtre.
