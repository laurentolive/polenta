# T151 — Évolution : menu contextuel (élément / dossier) sur le bouton + du panneau latéral

## Description fonctionnelle

Dans les vues **Exigences** et **Tests**, l'arbre du panneau latéral (`ElementTree.tsx`)
propose déjà un menu contextuel complet — « Créer un élément » / « Créer un dossier » /
« Coller » — mais uniquement via clic droit dans la zone vide (`BgContextMenu`). Les deux
boutons `+` visibles en permanence dans l'UI (bouton de fin d'arbre, et bouton « Créer le
premier élément » affiché quand l'arbre est vide) court-circuitaient ce choix : ils
créaient un élément directement (`createItem(null, null, 'item')`), sans option dossier.

Cette évolution aligne le comportement de **tous** les déclencheurs `+` de l'arbre sur
celui déjà existant du clic droit : chaque `+` ouvre le même menu (`BgContextMenu`,
actions `create-item` / `create-folder` / `paste` si presse-papiers non vide), positionné
sous l'élément cliqué plutôt qu'au point de clic — au lieu de créer un élément
directement.

Périmètre revu après un premier retour utilisateur : le `+` inline au survol d'une ligne
dossier et le `+` de l'interstice entre deux lignes étaient initialement jugés hors
scope (raccourcis de position déjà non ambigus). En pratique, un utilisateur cliquant sur
n'importe quel `+` de l'arbre (notamment celui de l'interstice, infobulle « Créer un
élément ici ») s'attend au même choix élément/dossier — sinon le comportement paraît
buggé ("le menu ne marche pas"). Les quatre déclencheurs sont donc désormais unifiés.

## Hors scope

- **Vue Campagnes** (`CampaignNavList` dans `SystemPanel.tsx`) : décision utilisateur
  explicite — pas de notion de dossier dans le modèle de données des campagnes
  aujourd'hui (liste plate, pas de `TypeTreeNode`/`root`). Le bouton `+` du header
  Campagnes reste inchangé (création directe d'une campagne).

## Comportement attendu

Un menu « Créer un élément / Créer un dossier / Coller » (partagé, état `addMenu`) s'ouvre
à la position du déclencheur pour chacun des cas suivants, avec le point d'insertion
(`parentId`/`afterId`) déterminé par le déclencheur :

1. Bouton `+` de fin d'arbre (« Nouvel élément ») → insertion à la racine, en fin de
   liste (`parentId: null, afterId: null`).
2. Bouton « Créer le premier élément » (arbre vide) → idem, racine.
3. `+` inline au survol d'une ligne dossier (infobulle « Créer dans ce dossier ») →
   insertion à l'intérieur de ce dossier (`parentId: <dossier>, afterId: null`).
4. `+` de l'interstice entre deux lignes (infobulle « Créer un élément ici ») →
   insertion juste après le nœud survolé, au même niveau (`parentId: <parent du nœud>,
   afterId: <nœud>`).
5. Clic droit dans la zone vide de l'arbre → inchangé, racine (`parentId: null,
   afterId: null`), non régressé.
6. Vue Campagnes inchangée (voir Hors scope).

## Critères d'acceptation

- [ ] Cliquer sur le bouton `+` de fin d'arbre (exigences ou tests) affiche un menu avec
      deux options « Créer un élément » / « Créer un dossier ».
- [ ] Choisir « Créer un dossier » depuis ce menu crée un dossier à la racine de l'arbre,
      en mode renommage immédiat (comportement `createItem` existant).
- [ ] Sur un arbre vide, le bouton « Créer le premier élément » ouvre le même menu.
- [ ] Le `+` inline d'un dossier (survol de ligne) ouvre le menu et crée bien *dans* ce
      dossier (numérotation de section imbriquée, ex. `4.1`).
- [ ] Le `+` de l'interstice entre deux lignes ouvre le menu et insère bien juste après le
      nœud survolé, au même niveau (pas à la racine).
- [ ] Le clic droit dans le vide continue de fonctionner à l'identique (non régressé).
- [ ] Le bouton `+` du panneau Campagnes n'est pas modifié.
