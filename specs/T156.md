# T156 — Bug : `.polenta/tree.cache.yaml` versionné par erreur, bloque les gardes "repo propre"

## Contexte

Découvert en testant T155 (auto-pull) : peu après l'ouverture d'un projet, un repo apparaissait
systématiquement "modifié" à cause de `.polenta/tree.cache.yaml`, ce qui bloquait aussi bien le
bouton "Rafraîchir" (T153) que l'auto-pull (T155) — les deux exigent un working tree propre.

## Root cause

`WorkspaceTreeService.writeCache()` (`apps/desktop/src/main/services/workspace-tree.service.ts:224`)
écrit `<workspaceDir>/.polenta/tree.cache.yaml` avec un `generatedAt: new Date().toISOString()`
recalculé à chaque appel — et `nodes`/`logicalTree` changent légitimement à chaque
`rebuildTree()` (ajout/suppression/renommage de dépendance, propagation de pin). Ce fichier n'est
lu nulle part pour son `generatedAt` (`isCacheValid()` ne compare que `rootRepoHeadSha`) — c'est un
cache pur, régénérable à volonté, et `specs/T69-design.md` est explicite : il doit être
« hors de tout repo git », jamais versionné (chemins absolus locaux à la machine).

Le `.gitignore` existant ne le protège que par accident, et seulement dans un cas :
- `WorkspaceService.createNewProject()` écrit un `.gitignore` dans `rootRepoPath`
  (`workspace.service.ts:98-102`), mais le cache est écrit dans `workspaceDir` — le **conteneur
  parent** de `rootRepoPath` pour un nouveau projet (`initWorkspace(containerDir, rootRepoPath)`),
  pas le repo git lui-même. Sans effet dans le cas courant (le conteneur n'est généralement pas un
  repo git), mais aucune protection non plus si l'utilisateur choisit un conteneur qui se trouve
  être *dans* un repo existant.
- `WorkspaceService.openProject()` (adoption d'un repo git existant, `workspace.service.ts:80-87`,
  cas où `workspaceDir === rootRepoPath`, celui où le cache atterrit bien *dans* le repo suivi)
  **n'écrit aucun `.gitignore` du tout** — trou confirmé.

**Preuve concrète dans ce repo** : `apps/desktop/PL/Product` est un projet Polenta utilisé pour le
dogfooding, niché dans `apps/desktop/PL/` — un dossier qui n'est pas son propre repo git mais vit
à l'intérieur du monorepo `polenta` lui-même. `apps/desktop/PL/.polenta/tree.cache.yaml` s'est
retrouvé suivi par git (commit `68fb2fb`), avec un `generatedAt` figé et des `repoPath` locaux à
la machine.

## Correctif

**Un seul point de correction, à l'endroit où le fichier est réellement écrit** plutôt que de
corriger chaque appelant (`createNewProject`, `openProject`, et tout futur appelant) : Dans
`WorkspaceTreeService.writeCache()`, avant d'écrire le cache, `ensureCacheIgnored(workspaceDir)`
garantit qu'un `.gitignore` contenant `.polenta/tree.cache.yaml` existe dans `workspaceDir` —
créé s'il est absent, complété (sans doublon) s'il existe déjà avec un autre contenu. Un
`.gitignore` placé directement à côté du dossier `.polenta/` qu'il exclut est honoré par git quel
que soit l'ancêtre qui s'avère être la racine du repo — inutile de déterminer où est cette racine.
Si `workspaceDir` n'est pas du tout sous git (cas courant), le fichier est inerte.

**Nettoyage de ce repo** : `apps/desktop/PL/.polenta/tree.cache.yaml` retiré du suivi
(`git rm --cached`), et une règle `**/.polenta/tree.cache.yaml` ajoutée au `.gitignore` racine du
monorepo (protection immédiate pour ce cas de dogfooding imbriqué, en complément du correctif
applicatif qui ne s'appliquera qu'à la prochaine écriture du cache par l'app elle-même).

## Comportement attendu

1. **Nouveau `.gitignore`** : `workspaceDir` sans `.gitignore` → un fichier contenant exactement
   `.polenta/tree.cache.yaml\n` est créé.
2. **`.gitignore` existant, sans la ligne** : la ligne est ajoutée à la fin (avec un saut de ligne
   si le fichier n'en avait pas déjà un), le reste du contenu est préservé tel quel.
3. **`.gitignore` existant, ligne déjà présente** : aucune modification (idempotent — vérifié en
   appelant `writeCache()` deux fois de suite).
4. **`workspaceDir` non versionné** : le `.gitignore` créé est un fichier inerte, sans effet
   perceptible.

## Critères d'acceptation

- [ ] `writeCache()` garantit la présence de la ligne d'exclusion avant chaque écriture, sans
      dupliquer la ligne sur les appels répétés.
- [ ] Un `.gitignore` existant avec un autre contenu est complété, pas écrasé.
- [ ] `git check-ignore .polenta/tree.cache.yaml` confirme que le fichier est bien ignoré une fois
      le `.gitignore` en place (testé avec un vrai repo git).
- [ ] `apps/desktop/PL/.polenta/tree.cache.yaml` n'est plus suivi par git dans ce repo.
- [ ] Aucune régression sur `readCache()`/`isCacheValid()`/le reste de `WorkspaceTreeService`.

## Hors scope

- Ne pas modifier la fréquence de régénération du cache (`rebuildTree()` continue de tout
  réécrire, pas de diff partiel) — hors sujet, la véritable cause du problème était le suivi git,
  pas la fréquence d'écriture (cf. Root cause : `generatedAt` n'est même pas comparé nulle part).
- Ne pas toucher `createNewProject()`/`openProject()` individuellement — le correctif au niveau de
  `writeCache()` les couvre tous les deux (et tout futur appelant) sans duplication de logique.
