# T157 — Évolution : afficher l'adresse du repo GitHub sous le nom du projet

## Description fonctionnelle

Dans le panneau latéral "Projet" (`ProjectPanel.tsx`), seul le nom d'affichage du projet
(`label` du SystemNode `root`, ou nom du dossier) était visible sous l'en-tête "PROJET".
Ajout d'une ligne secondaire, sous ce nom, affichant l'URL du remote `origin` du repo root
(typiquement l'adresse GitHub), quand un remote est configuré.

## Comportement attendu

- Le remote `origin` du repo root est lu côté main process (`git.listRemotes`, même
  pattern que `getRemoteUrl`/`getRepoRemoteUrl` déjà utilisés dans `sync.service.ts` et
  `workspace-tree.service.ts`) et exposé dans `ProjectInfo.remoteUrl` (nouveau champ
  optionnel), retourné par `WorkspaceService.resolve()` — déjà l'unique point d'entrée
  IPC (`workspace:resolve`) consommé par `ProjectPanel`.
- `ProjectPanel` affiche cette URL en petit texte gris, tronquée avec `title` (tooltip)
  pour la valeur complète, juste sous la ligne du nom du projet — uniquement si
  `remoteUrl` est présent (repo local sans remote configuré → rien d'affiché, pas de
  changement de layout).
- Aucun changement pour les projets sans remote `origin` (cas actuel majoritaire des
  projets créés localement via "Nouveau projet").

## Hors scope

- Pas d'affichage du remote pour les composants/submodules dans la vue "Modèle de
  données" (StructureTab) — uniquement le repo root, dans le panneau latéral Projet.
- Pas de lien cliquable vers l'URL (juste informatif, cohérent avec le reste du panneau
  qui ne fait pas de liens externes).

## Fichiers modifiés

- `packages/types/src/workspace.ts` — `ProjectInfo.remoteUrl?: string`
- `apps/desktop/src/main/services/workspace.service.ts` — `resolve()` lit le remote
  `origin` via `git.listRemotes` (nouvelle méthode privée `readRemoteUrl`)
- `apps/desktop/src/renderer/components/sidebar/ProjectPanel.tsx` — affiche
  `project.remoteUrl` sous le nom du projet

## Comment tester manuellement

1. Ouvrir un projet Polenta dont le repo root a un remote `origin` configuré
   (`git remote -v` dans le repo root doit lister `origin`).
2. Vérifier que l'URL du remote apparaît en petit texte gris sous le nom du projet dans
   le panneau latéral "Projet".
3. Ouvrir un projet sans remote configuré (ex. créé via "Nouveau projet" dans l'app,
   jamais poussé) — vérifier qu'aucune ligne vide ni artefact visuel n'apparaît.
