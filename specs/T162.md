# T162 — Évolution : afficher/masquer les titres de dossiers dans les vues Excel et Word

## Contexte / problème

Dans la Vue Système, les vues **Excel** (`ExcelView.tsx`) et **Word** (`WordView.tsx`)
affichent toujours la structure de dossiers de l'arbre :

- **Excel** : chaque dossier est une **ligne de groupe** (`GroupRow`) collapsable, sur toute
  la largeur du tableau (ou, si la colonne `section` est visible, split numéro / nom).
- **Word** : chaque dossier devient un **titre de section** `H1`–`H6` (au-delà de la
  profondeur 6, style `H6` + indentation), avec chevron collapse.

Sur un arbre profond ou très fourni, ces titres consomment beaucoup de hauteur verticale et
« hachent » la lecture quand on veut simplement parcourir la liste des exigences / tests. Il
n'existe aujourd'hui aucun moyen de les masquer pour gagner en densité.

La roue crantée ⚙️ (`FieldConfigModal` dans `SystemView.tsx`) configure déjà, par onglet
**Excel** / **Word**, les colonnes/champs visibles — persistés par vue, par type d'élément,
par utilisateur (`.{githubaccount}.pref`, clé `fieldVisibility[<node>::<type>]`). C'est
l'endroit naturel pour ce nouveau réglage.

## Description fonctionnelle

Ajouter dans le panneau ⚙️, **pour chaque onglet Excel et Word**, une case à cocher
**« Afficher les titres des dossiers »** :

- **Cochée (défaut)** : comportement actuel inchangé (lignes de groupe en Excel, sections
  `Hn` en Word, chevrons collapse, etc.).
- **Décochée** : les titres de dossiers ne sont plus rendus dans la vue concernée. Les
  éléments s'affichent en **liste plate**, dans l'ordre de parcours de l'arbre (pré-ordre,
  identique à aujourd'hui, dossiers « aplatis »).

Le réglage est **indépendant par vue** : on peut masquer les titres en Excel et les garder
en Word (ou l'inverse).

### Comportement quand les titres sont masqués

| Aspect | Comportement |
|---|---|
| Éléments affichés | **Tous** les éléments de l'arbre (ou tous les résultats du filtre), à plat, dans l'ordre de l'arbre. L'état collapsé/déplié des dossiers est **ignoré** (il n'est plus pilotable sans titres visibles). |
| Numérotation de section | **Conservée** : la colonne `section` (Excel) et le préfixe numéroté (Word) continuent d'afficher la numérotation hiérarchique `2.1.3` de chaque élément. La colonne `section` reste par ailleurs masquable indépendamment via la liste des champs. |
| Indentation | Supprimée : plus de décalage visuel par profondeur (le `depth` ne sert plus au rendu). Liste plate homogène. |
| Filtre global / filtre par colonne (T51) | S'appliquent normalement ; le résultat est la liste plate des éléments qui matchent. La règle « les dossiers restent toujours affichés sous filtre » (SPEC §Filtre par colonne) ne s'applique pas quand les titres sont masqués — il n'y a pas de dossier à afficher. |
| Dossiers vides | Rien à afficher, aucune ligne. |
| Renommage inline de dossier | Non disponible depuis la vue (plus de cible) — se fait via l'arbre latéral. |

### Excel — drag & drop de réordonnancement

Le drag & drop de lignes (`ExcelView`) reste **actif** quand les titres sont masqués, mais
**restreint** :

- Réordonnancement **élément ↔ élément uniquement, entre éléments de même parent** : un dépôt
  « avant » / « après » n'est accepté que si l'élément déplacé et l'élément cible partagent le
  même dossier parent. Sinon : dépôt refusé (pas de déplacement inter-dossiers « à l'aveugle »).
- Plus de dépôt « à l'intérieur d'un dossier » (`position: 'inside'`) — aucune ligne de
  dossier n'est présente comme cible.
- Le déplacement d'un élément **d'un dossier à un autre** passe par l'arbre latéral ou par le
  réaffichage des titres.

Le drag & drop de **colonnes** (réordonnancement / figer les volets / redimensionnement) est
inchangé.

### Word

Word n'a pas de drag & drop : masquer les titres retire simplement les nœuds `Hn` du rendu
(`renderNodes` continue de descendre dans `node.children`). Les `ItemCard` sont rendues à la
suite, sans titre intercalé.

## Persistance

- Stockée **dans le même fichier** `.{githubaccount}.pref`, **au même endroit** que la config
  des champs : l'objet `fieldVisibility[<node>::<type>]` (aujourd'hui `{ excel, word, edit }`)
  est étendu pour porter aussi l'état « titres affichés » d'Excel et de Word (forme exacte à
  définir en Design — p. ex. deux booléens `foldersExcel` / `foldersWord`, ou un sous-objet
  `showFolders: { excel, word }`).
- **Par vue** (Excel / Word), **par type d'élément** (`<node>::<type>`), **par utilisateur**.
- **Rétrocompatibilité** : une préférence existante sans ce champ ⇒ titres **affichés**
  (défaut). Aucune migration de fichier.
- L'IPC `pref:get-field-visibility` / `pref:set-field-visibility` et le type
  `Api['pref']` (`packages/api-client`) sont étendus en conséquence.
- **« Réinitialiser par défaut »** (bouton existant du panneau, par onglet) remet aussi
  « Afficher les titres des dossiers » à **coché**.

## Hors scope

- **Vue Édition** : ne liste qu'un élément à la fois, aucune notion de dossier — pas
  concernée. (L'onglet « Édition » du panneau ⚙️ n'existe d'ailleurs pas, cf. SPEC-AUDIT.)
- **Arbre latéral** (`ElementTree`) : inchangé — il garde toujours ses dossiers et son
  collapse/expand.
- **Exports PDF / Word / Excel** (`print.requirements.tsx`, `print.tests.tsx`, services
  `export/*.xlsx.ts` / `*.docx.ts`) : hors périmètre, comportement inchangé (les titres y
  restent). Un éventuel alignement export ↔ écran fera l'objet d'un autre ticket.
- Pas de nouveau raccourci clavier pour basculer le réglage.
- Pas de bascule « tout replier / tout déplier » (différent : ça garde les titres visibles).
- Pas de changement du rendu des titres quand ils **sont** affichés (tailles `Hn`,
  split colonne `section`, chevrons… inchangés).

## Critères d'acceptation

1. Panneau ⚙️, onglet **Excel** : une case « Afficher les titres des dossiers », cochée par
   défaut. Idem onglet **Word**, indépendante.
2. Décocher la case en onglet Excel → la vue Excel n'affiche plus aucune ligne de groupe ;
   tous les éléments de l'arbre apparaissent à plat, dans l'ordre de l'arbre, y compris ceux
   qui étaient dans un dossier collapsé.
3. La vue Word n'est pas affectée tant que sa propre case reste cochée (et réciproquement).
4. Titres masqués : la colonne `section` (si visible) affiche toujours `1`, `1.1`, `1.2`,
   `2`… pour les éléments ; en Word le préfixe numéroté reste affiché sur les cartes.
5. Le réglage survit à un changement de type puis retour, à une fermeture/réouverture du
   projet, et n'affecte pas les autres types d'éléments ni les autres utilisateurs.
6. « Réinitialiser par défaut » (onglet Excel) → la case repasse cochée et les titres
   réapparaissent.
7. Excel, titres masqués : glisser un élément sur un autre élément **du même dossier** →
   réordonnancement effectué. Glisser sur un élément d'un **autre** dossier → aucun
   déplacement (retour à l'état initial), pas d'erreur.
8. Excel, titres masqués + filtre actif (global ou par colonne) → seule la liste plate des
   éléments filtrés s'affiche, sans ligne de dossier.
9. Rétrocompat : ouvrir un projet dont le `.{user}.pref` contient déjà des
   `fieldVisibility` (sans le nouveau champ) → titres affichés, aucun crash.
10. Aucune régression TypeScript / lint.
