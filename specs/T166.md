# T166 — Bug : le mode du filtre global (casse / mot entier / regex) n'était pas honoré par les Vues Word/Excel

## Root cause

La barre de filtre du panneau latéral Vue Système porte 3 options (`FilterOptions` :
`caseSensitive`, `wholeWord`, `regex`), stockées dans `SystemViewContext.filterOptions`.

- **L'arbre latéral** (`treeVisibleNodes` → `getMatchingIds`, `useTreeState.ts`) construisait
  bien une `RegExp` selon le mode — mais avec sa **propre** implémentation, distincte de
  `buildFilterRegex` (`lib/textFilter.ts`), et avec une sémantique différente sur regex
  invalide : `getMatchingIds` faisait `test = () => false` (⇒ arbre vidé), là où
  `buildFilterRegex` renvoie `null` (⇒ on n'exclut rien). Périmètre : nom du nœud + `objectId`
  uniquement.
- **Les vues document** ignoraient complètement `filterOptions` :
  - `SystemView` ne passait que `filter` (chaîne brute) à `WordView` / `ExcelView`, jamais
    `filterOptions` ;
  - `WordView.itemMatchesFilter` : `objStr.toLowerCase().includes(filter.toLowerCase())` ;
  - `ExcelView.itemMatchesFilters` (filtre **global** ; le filtre par colonne T51 utilisait déjà
    `buildFilterRegex`) : `haystack.includes(filterLower)`.

Conséquence principale : **mode regex actif**, une saisie type `SW.*01` matchait dans l'arbre
mais `.includes('sw.*01')` échouait pour toutes les lignes → la vue document se vidait alors que
l'arbre montrait des résultats. Le *goto* de T164 devenait alors un no-op silencieux sur tous
les résultats. Modes **mot entier** / **sensible à la casse** : filtre document plus permissif
que l'arbre.

## Décision Spec

**Périmètre de recherche unifié** (question tranchée avec l'humain) : l'arbre latéral, la Vue
Tableau et la Vue Document cherchent **tous** dans le **nom du nœud + l'`objectId` + toutes les
valeurs de champs** (champs masqués de la vue inclus). Avant : l'arbre ne cherchait que dans
nom + `objectId`.

Une `RegExp` invalide en mode regex n'exclut **aucune** ligne ni **aucun** nœud (pas d'erreur),
comme le filtre par colonne T51.

## Correctif appliqué

| Fichier | Changement |
|---------|-----------|
| `lib/textFilter.ts` | Export d'une constante partagée `NO_FILTER_OPTIONS` (mode neutre). |
| `hooks/useSystemObjects.ts` | **Nouveau** — extraction de la query `['objects', repoPath, category, nodeId, typeId]` (auparavant inline dans `SystemView`) pour la partager avec `SystemPanel` sans dupliquer le fetch (même `queryKey` ⇒ cache mutualisé, invalidations existantes conservées). |
| `hooks/useTreeState.ts` | `treeVisibleNodes` / `getMatchingIds` : remplacent leur `RegExp` maison par `buildFilterRegex` (⇒ regex invalide n'exclut plus rien, unification avec le reste de l'app). Nouveau paramètre optionnel `searchTextByObjectId: Map<string,string>` — texte additionnel fouillé par objet. `escapeRegex` local supprimé (devenu inutilisé). |
| `components/system/ElementTree.tsx` | Nouvelle prop `searchTextByObjectId`, transmise à `treeVisibleNodes` ; type `filterOptions` resserré sur `FilterOptions`. |
| `components/sidebar/SystemPanel.tsx` | Charge les objets via `useSystemObjects`, construit `searchTextByObjectId` (`Object.values(normalizeObject(obj)).join(' ')`) et le passe à `ElementTree`. |
| `components/system/SystemView.tsx` | Utilise `useSystemObjects` ; passe `filterOptions` à `WordView` et `ExcelView`. |
| `components/system/WordView.tsx` | `itemMatchesFilter` : `buildFilterRegex(filter, filterOptions ?? NO_FILTER_OPTIONS)` ; chaque valeur (nom, `objectId`, valeurs de champs) testée séparément (pas de haystack joint → une regex ne matche pas à cheval sur deux champs). |
| `components/system/ExcelView.tsx` | Idem pour le filtre **global** `itemMatchesFilters` (le filtre par colonne T51 est inchangé). `dndEnabled` / `hasActiveFilter` basculent de `filterLower` vers `filterRe`. |

`buildFilterRegex` n'ayant pas le flag `g`, `re.test()` n'est pas *stateful* — sûr dans les
boucles `.some()`.

## Comment vérifier

1. Lancer l'app, ouvrir un projet avec plusieurs exigences (gabarit `electro-domestic-battery`).
2. Vue Système → sélectionner un composant/type ayant des IDs type `SYS-001`, `SYS-002`…
3. Barre de filtre : activer le mode **regex** (`.*`), taper `SYS-00[12]`.
   - **Attendu** : l'arbre **et** la Vue Word **et** la Vue Tableau montrent exactement
     `SYS-001` et `SYS-002`. (Avant : arbre OK, vues document vides.)
4. Cliquer un résultat dans l'arbre → le *goto* défile bien jusqu'à la carte/ligne (plus de
   no-op).
5. Mode **mot entier** : taper `eco` → seuls les éléments contenant le mot isolé « eco »
   matchent (pas « ecologie »), dans les trois vues à l'identique.
6. Mode **sensible à la casse** : `Turbo` vs `turbo` → même résultat dans les trois vues.
7. Mode **regex** avec une expression invalide (`SW(` ) → aucune ligne exclue, aucune erreur,
   dans l'arbre comme dans les vues.
8. Filtre par un texte présent **uniquement dans un champ** (ex. un mot du champ `rationale`) →
   l'arbre latéral trouve maintenant l'élément (périmètre unifié).
9. Recharger : filtre par colonne T51 (icône d'en-tête d'une colonne en Vue Tableau) toujours
   fonctionnel et combiné en ET avec le filtre global.
