# T177 — Bug : champs « Label affiché » / « Description » absents à l'ajout d'un composant

## Root cause

`AddDependencyModal.tsx` n'affichait le bloc « Label affiché » / « Description » qu'en mode
édition (`isEdit && …`). Côté `StructureTab.tsx`, le chemin « composant local » écrivait déjà
`values.label` / `values.description` sur le nouveau `SystemNode`, mais le chemin « dépendance
git » (composant ou interface distante) les ignorait.

## Correctif

- `AddDependencyModal.tsx` : le bloc label/description est affiché en ajout comme en édition
  (composant local, composant distant, interface).
- `StructureTab.tsx` / `handleSubmitDependency` (dépendance distante) : après le montage, le label
  et la description saisis sont écrits sur le node `root` du `schema.yaml` de la dépendance, dans
  la même sauvegarde que l'amorçage des types d'objets par défaut. Un champ laissé vide ne touche
  pas la valeur existante (un repo existant garde son propre label). L'arbre est rechargé pour que
  le nouveau label s'affiche. Best-effort, comme l'amorçage : un échec est loggé et n'annule pas
  l'ajout.

Hors scope (inchangé, choix T110) : « Rôles exposés », « Rôles joués » et « Interfaces
implémentées » restent réservés à l'édition.

## Comment vérifier

1. Structure → « + Composant » : les champs « Label affiché » et « Description » sont présents.
2. Composant local coché, label « Moteur » → la ligne de l'arbre affiche « Moteur ».
3. Composant distant (URL git), label + description → l'arbre affiche le label ; la popup
   d'édition du composant les montre pré-remplis ; le `schema.yaml` du composant les contient.
4. Composant distant vers un repo qui a déjà un label, champ laissé vide → label existant conservé.
5. « + Interface » : mêmes champs, même comportement que 3.
