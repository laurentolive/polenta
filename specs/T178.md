# T178 — Bug : nom de montage affiché à côté du label des composants (vues Exigences/Tests)

## Root cause

`SystemViewContext.tsx` (construction de `componentOptions`, source du combobox
composant/type des vues Exigences et Tests) : pour un repo à un seul `SystemNode`, le libellé
était `` `${n.name} — ${localLabel}` `` (héritage T120/T73 : désambiguïser des repos partageant
le label par défaut du template). L'en-tête de groupe (`groupLabel`, workspace multi-repos)
utilisait aussi le nom de montage.

## Correctif

- Libellé d'un repo mono-node : label du node local, sinon label du repo (`WorkspaceTreeNode.label`),
  sinon nom de montage (repli quand aucun label n'est configuré).
- En-tête de groupe : label du repo, sinon nom de montage.
- Identifiants internes (`repoName`, URL `repo=`) inchangés.

Conséquence assumée : deux repos portant le même label ne sont plus distingués dans la liste —
renseigner des labels distincts (T177 permet de les saisir dès l'ajout).

## Comment vérifier

1. Projet avec composants labellisés → vue Exigences : le sélecteur affiche « Moteur / Exigence »
   et non « motor-control — Moteur / Exigence ».
2. Idem vue Tests.
3. Composant sans label → le nom de montage s'affiche (repli).
4. Workspace multi-repos avec plusieurs nodes locaux : les en-têtes de groupe affichent le label du repo.
