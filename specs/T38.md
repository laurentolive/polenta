# T38 — Correction : changement de statut impossible dans les vues Excel, Word et Test

## Root cause

Dans `apps/desktop/src/renderer/components/system/SystemView.tsx`, la mutation `autoSaveMutation` (utilisée par `handleAutoInlineEdit`) contenait ce bloc :

```ts
if (field === 'status') {
  if (cat === 'requirement') return api.requirements.transition(repoPath, objectId, { toStatus: value })
  return // tests: no direct status transition API
}
```

Pour les cas de test (`cat === 'test'`), le changement de statut était silencieusement ignoré — la fonction retournait sans rien envoyer au backend. Or :

1. `UpdateTestCaseDto` (défini dans `packages/zod-schemas/src/test.schema.ts`) expose bien un champ `status: z.string().optional()`.
2. `TestsService.update()` (dans `apps/desktop/src/main/services/tests.service.ts`) traite ce champ : `...(dto.status && { status: dto.status })`.
3. L'API IPC `tests:update` est bien enregistrée.

Il n'existe aucune raison d'exclure les tests de la sauvegarde du statut — le commentaire "no direct status transition API" était incorrect.

Ce bug affectait les trois vues :
- **Excel** : le `<select>` de statut dans `InlineCell` appelle `onInlineEdit` → `handleAutoInlineEdit` → mutation cassée.
- **Word** : le `<select>` de statut dans `ItemCard` suit le même chemin.
- **Test** (vue Excel/Word pour les types `category: test`) : même chemin.

Les exigences (`category: requirement`) n'étaient pas affectées car elles passaient par `api.requirements.transition`.

## Correctif appliqué

**Fichier modifié :** `apps/desktop/src/renderer/components/system/SystemView.tsx`

Ajout de la branche manquante pour `cat === 'test'` dans `autoSaveMutation` :

```ts
// Avant
if (field === 'status') {
  if (cat === 'requirement') return api.requirements.transition(repoPath, objectId, { toStatus: value })
  return // tests: no direct status transition API
}

// Après
if (field === 'status') {
  if (cat === 'requirement') return api.requirements.transition(repoPath, objectId, { toStatus: value })
  if (cat === 'test') return api.tests.update(repoPath, objectId, { status: value } as UpdateTestCaseDto)
  return
}
```

## Comment vérifier manuellement

1. Lancer l'application Electron (`pnpm --filter @polenta/desktop dev`).
2. Ouvrir un projet contenant des cas de test (type `category: test`).
3. **Vue Excel** : afficher la colonne "Statut", cliquer sur le statut d'un cas de test, sélectionner un autre statut. Vérifier que la sauvegarde a lieu (le statut reste après rechargement).
4. **Vue Word** : cliquer sur le badge de statut d'une carte de test, sélectionner un autre statut. Même vérification.
5. Répéter pour des **exigences** (`category: requirement`) pour s'assurer qu'elles ne sont pas régressées.
