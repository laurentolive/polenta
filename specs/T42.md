# T42 — Support des tableaux dans richtext (insertion, édition, menu contextuel, collage Excel)

## Contexte

Les champs `richtext` utilisent TipTap (`@tiptap/core`, `@tiptap/react`,
`@tiptap/starter-kit`) avec sérialisation Markdown via `tiptap-markdown`
(stockage en chaîne Markdown, pas en JSON ProseMirror). Aucune extension table
n'est montée aujourd'hui (`@tiptap/extension-table` et associés absents du
`package.json` et de `node_modules`) : il n'existe donc actuellement aucun
moyen d'insérer, d'éditer, ni même de coller un tableau structuré dans un
champ richtext. Coller une sélection depuis Excel produit aujourd'hui un
comportement dégradé (image ou texte brut selon le chemin de collage) au lieu
d'un tableau.

`T75` a établi un pattern de menu contextuel clic droit pour les blocs média
(`NodeContextMenu.tsx`, `ResizableMediaFrame.tsx`) et un pattern de bouton
toolbar dédié (`DrawioInsertButton.tsx`) dans les deux points d'édition
richtext existants : `RichTextField.tsx` (toolbar inline) et
`RichTextToolbar.tsx` (toolbar externe pilotée par `RichTextContext`).
`RichTextViewer.tsx` reste un rendu lecture seule (`editable: false`, pas de
toolbar, pas d'interaction).

Ce ticket était initialement limité au collage Excel (« copier des tableaux
excel dans rich text doit faire un tableau pas une image ») ; son périmètre a
été élargi (décision humaine) pour couvrir le support général des tableaux
dans richtext, le collage Excel n'en étant qu'un des points d'entrée.

## Décisions (validées avec l'humain avant rédaction de cette spec)

1. **Tableaux simples uniquement** — grille régulière lignes/colonnes, **sans
   fusion de cellules** (pas de colspan/rowspan). Raison : le stockage est en
   Markdown, et la syntaxe GFM standard (`| a | b |` + ligne séparateur `| ---
   | --- |`) ne supporte pas la fusion. Rester sur ce format standard garantit
   un round-trip stable et diff-friendly dans Git, sans avoir à introduire un
   bloc fenced JSON custom comme pour les images/drawio (`T75`).
2. **Insertion manuelle** via un bouton toolbar (« Insérer un tableau ») dans
   `RichTextField.tsx` et `RichTextToolbar.tsx`, avec choix du nombre initial
   de lignes/colonnes à l'insertion.
3. **Édition via menu contextuel clic droit** dédié aux tableaux : ajouter
   ligne au-dessus/dessous, supprimer la ligne, ajouter colonne à
   gauche/droite, supprimer la colonne, supprimer le tableau. Ce menu est
   distinct de celui des blocs média (`NodeContextMenu.tsx` de `T75`) —
   pas de redimensionnement, pas de rognage, pas de fusion : il peut réutiliser
   le composant `NodeContextMenu.tsx` générique avec sa propre liste
   d'actions.
4. **Collage depuis Excel** : coller une sélection de cellules Excel dans un
   champ richtext doit créer un tableau structuré (lignes/colonnes/cellules
   éditables), jamais une image bitmap du tableau collé.
5. **`RichTextViewer.tsx`** affiche un tableau existant en lecture seule, sans
   aucune interaction (pas de menu contextuel, pas de toolbar) — cohérent avec
   le comportement déjà établi pour les blocs média en `T75`.

## Comportement attendu

### Insertion manuelle

1. Un bouton toolbar « Insérer un tableau » est disponible dans
   `RichTextField.tsx` et `RichTextToolbar.tsx` (désactivé en mode Raw, comme
   les autres boutons d'insertion).
2. Le clic ouvre un petit sélecteur du nombre de lignes et de colonnes
   souhaité (le détail d'interaction — grille visuelle ou champs numériques —
   est laissé à `T42-design.md`).
3. Le tableau inséré comporte une ligne d'en-tête (header) et le nombre de
   lignes de données/colonnes choisi, toutes les cellules vides.
4. Le texte dans les cellules s'édite normalement, y compris le formatage
   inline de base déjà supporté par l'éditeur (gras, italique, lien).

### Édition via menu contextuel

5. Un clic droit sur une cellule d'un tableau (en édition uniquement) ouvre un
   menu contextuel positionné au curseur, fermé sur clic extérieur ou
   `Échap` (même comportement de fermeture que `NodeContextMenu.tsx`).
6. Actions disponibles : Ajouter une ligne au-dessus, Ajouter une ligne
   en dessous, Supprimer la ligne, Ajouter une colonne à gauche, Ajouter une
   colonne à droite, Supprimer la colonne, Supprimer le tableau.
7. Chaque action s'applique immédiatement et s'intègre à la pile
   undo/redo standard de l'éditeur (`StarterKit` inclut déjà l'historique).

### Collage depuis Excel

8. Coller une plage de cellules copiée depuis Excel dans un champ richtext en
   édition crée un tableau TipTap natif reflétant les lignes/colonnes et le
   contenu texte collés.
9. Si la plage collée contient des cellules fusionnées côté Excel, le
   comportement de dégradation (répétition de la valeur dans chaque cellule
   couverte, ou aplatissement) est précisé en Design (cf. Décision 1 —
   pas de fusion supportée côté richtext).

### Sérialisation

10. Le tableau est sérialisé en Markdown GFM standard (`| a | b |` + ligne
    séparateur), cohérent avec le support déjà présent dans `tiptap-markdown`
    pour les tableaux sans fusion.
11. Le round-trip (sauvegarde puis rechargement du document) restitue le même
    tableau, sans churn Git superflu à l'ouverture/fermeture du champ sans
    modification réelle.

## Cas limites

- Un tableau ne peut pas être vidé de toutes ses lignes de données ni de sa
  ligne d'en-tête via les actions « Supprimer la ligne »/« Supprimer la
  colonne » individuelles — le detail exact (dernière ligne/colonne
  protégée, ou action équivalente à « Supprimer le tableau ») est tranché en
  Design.
- Cellule vide → sérialisée comme cellule Markdown vide (`|  |`), valide.
- Collage Excel avec une cellule contenant une formule → seule la valeur
  affichée (texte calculé) est collée, jamais la formule.
- Collage Excel avec cellules fusionnées → cf. point 9, comportement de
  dégradation à définir en Design, jamais un crash ou une perte silencieuse de
  contenu.
- Tableau en tout début ou toute fin de document → comportement standard
  TipTap, pas de contrainte additionnelle.
- Undo/redo doit couvrir l'insertion du tableau et toutes les actions du menu
  contextuel (ajout/suppression ligne/colonne, suppression du tableau).

## Hors scope explicite

- Fusion de cellules (colspan/rowspan) — cf. Décision 1.
- Redimensionnement manuel de la largeur des colonnes (glisser-déposer un
  bord de colonne) — largeur automatique/répartie uniquement.
- Tableaux imbriqués (tableau à l'intérieur d'une cellule de tableau).
- Styles avancés de cellule (couleur de fond, bordures personnalisées) —
  rendu visuel standard uniquement.
- Tri ou filtre des lignes d'un tableau — reste un élément de mise en forme,
  pas une grille de données interactive.
- Export Word/Excel (`T43`) du rendu tableau richtext — traité dans le ticket
  d'export si besoin.
- Toute interaction d'édition dans `RichTextViewer.tsx` (lecture seule) — cf.
  Décision 5.

## Critères d'acceptation

- [ ] Un bouton toolbar « Insérer un tableau » est présent dans
      `RichTextField.tsx` et `RichTextToolbar.tsx`
- [ ] L'insertion crée un tableau avec ligne d'en-tête et le nombre de
      lignes/colonnes choisi
- [ ] L'édition du texte dans les cellules fonctionne normalement (y compris
      gras/italique/lien)
- [ ] Un clic droit sur une cellule ouvre un menu contextuel avec les actions
      ligne/colonne/suppression du tableau
- [ ] Chaque action du menu contextuel modifie correctement la structure du
      tableau
- [ ] Coller un tableau depuis Excel produit un tableau TipTap structuré,
      jamais une image
- [ ] Le tableau est sérialisé en Markdown GFM standard, stable au
      rechargement (round-trip sans churn)
- [ ] Undo/redo couvre l'insertion et toutes les actions d'édition du tableau
- [ ] `RichTextViewer.tsx` affiche un tableau en lecture seule sans aucune
      interaction (pas de menu contextuel, pas de toolbar)
