# T51 — Filtre par colonne dans la vue Excel

## Contexte

La vue Excel (`ExcelView.tsx`) affiche déjà un filtre **global** : une barre
de recherche au-dessus de l'arbre (`SystemPanel.tsx` → `FilterBar`, état
partagé via `SystemViewContext` — `filter`/`filterOptions`) qui masque les
lignes dont **aucune** colonne ne contient le texte recherché (`ExcelView.tsx`
ligne ~956, comparaison `includes` insensible à la casse ; les options
casse/mot entier/regex de la barre globale ne sont aujourd'hui appliquées que
côté arbre `ElementTree`, pas dans `ExcelView`). Ce filtre reste utile pour une
recherche large, mais ne permet pas de cibler la valeur d'une colonne en
particulier (ex : ne garder que les exigences dont le statut est `draft`, en
ignorant les autres colonnes qui pourraient accidentellement contenir "draft"
ailleurs).

T51 ajoute un filtre **par colonne**, propre à la vue Excel.

## Décisions issues du cadrage humain

- **Interaction** (révisé après premier retour — pas de ligne de filtres
  permanente, jugée trop encombrante à l'affichage) : chaque en-tête de
  colonne filtrable porte une icône discrète (ex. flèche `▼`). Cliquer dessus
  ouvre un popover de filtrage ancré sous l'en-tête, plutôt qu'un champ
  toujours visible.
- **Options du popover** : identiques à la barre de filtre globale existante
  (`FilterBar` dans `SystemPanel.tsx`) — un champ texte + les 3 boutons
  bascule **Aa** (sensible à la casse), **[W]** (mot entier), **.\*** (regex).
  Même moteur de correspondance que le filtre global (`buildCampaignFilterRe`
  dans `SystemPanel.tsx`/`CampaignListView.tsx` : échappement du texte sauf en
  mode regex, `\b...\b` en mode mot entier, flag `i` sauf en mode casse
  sensible). Pas de liste de valeurs distinctes à cocher (façon AutoFiltre
  Excel) — ce n'est pas ce qui est demandé, seulement le même texte+options
  que la recherche générale, rendu par colonne.
- **Options indépendantes par colonne** (assumé, à confirmer) : chaque popover
  de colonne a son propre jeu d'options (casse/mot entier/regex) et son propre
  texte — pas un réglage global partagé par toutes les colonnes.
- **Icône discrète mais visible en permanence** (assumé, à confirmer) : teinte
  neutre/atténuée par défaut (cohérent avec "discrète"), mise en évidence
  (couleur active, ex. bleu comme les boutons Aa/[W]/.\* déjà actifs dans
  `FilterBar`) dès qu'un filtre est actif sur la colonne — pour rester
  repérable même popover fermé, sans être un élément visuel lourd au repos.
- **Coexistence avec le filtre global** (inchangé) : les deux filtres se
  combinent en **ET**. Le filtre global (barre au-dessus de l'arbre) reste
  inchangé et continue de filtrer sur toutes les colonnes ; le filtre par
  colonne s'ajoute en complément pour affiner l'affichage à l'intérieur de la
  vue Excel.

## Comportements attendus

1. Chaque en-tête de colonne filtrable affiche une icône discrète (ex. `▼`),
   dans `ExcelView` uniquement (pas dans `WordView`). Colonnes filtrables :
   tous les champs personnalisés, `id`, `name`, `status`, les champs système
   (`section`, `createdAt`, `updatedAt`, `author`, `objectTypeRef`,
   `version`), et les colonnes de lien (`link::<type>`, filtrées sur la même
   valeur texte que celle affichée dans la cellule : IDs des objets liés).
2. La colonne `steps` (nombre d'étapes) n'a pas d'icône de filtre — pas de
   valeur texte pertinente à filtrer, cohérent avec le fait qu'elle n'est déjà
   pas prise en compte par le filtre global.
3. Cliquer sur l'icône ouvre un popover ancré sous l'en-tête de la colonne,
   contenant un champ texte et les 3 boutons bascule Aa/[W]/.\* (case
   sensitive/mot entier/regex), répliquant `FilterBar`. Un seul popover de
   filtre colonne ouvert à la fois (cohérent avec les popovers lien/richtext
   déjà présents dans `ExcelView` — s'ouvrir en ferme un autre déjà ouvert).
4. Le filtre se réévalue à chaque frappe dans le champ texte ou bascule
   d'option (pas de bouton "Appliquer"), cohérent avec le filtre global.
5. Le popover se ferme au clic en dehors (mousedown extérieur) ou à la touche
   `Échap`. `Échap` vide aussi le champ texte de la colonne (cohérent avec le
   comportement du filtre global — `SystemPanel.tsx` ligne ~43), les options
   (casse/mot entier/regex) sont conservées pour la prochaine ouverture.
6. Saisir du texte dans le filtre d'une colonne masque, parmi les lignes
   d'éléments (`kind: 'item'`), celles dont la valeur affichée de **cette
   colonne** ne correspond pas au texte selon les options actives de cette
   colonne (recherche "contient" par défaut ; mot entier délimite par `\b` ;
   regex interprète le texte comme une expression régulière ; casse
   sensible désactive l'insensibilité par défaut) — même moteur que le
   filtre global.
7. Une expression régulière invalide dans le filtre d'une colonne n'exclut
   aucune ligne (comportement identique au filtre global — `try/catch` autour
   de la construction du `RegExp`), plutôt que de casser l'affichage.
8. Plusieurs filtres de colonnes actifs simultanément se combinent en **ET** :
   une ligne doit satisfaire chaque filtre de colonne renseigné pour rester
   visible.
9. Le filtre par colonne se combine en **ET** avec le filtre global existant
   (`filter`/`filterOptions` de `SystemViewContext`) : une ligne doit
   satisfaire le filtre global **et** tous les filtres de colonnes actifs.
10. Les lignes de dossier (`kind: 'folder'`) restent toujours affichées quand
    un filtre (global et/ou colonne) est actif — comportement identique à
    l'existant (`ExcelView.tsx` ligne ~958, "always show folders when
    filtering"), non modifié par ce ticket.
11. L'icône d'une colonne dont le filtre est actif (texte non vide) se
    distingue visuellement (couleur active) de celle d'une colonne sans
    filtre — repérable même popover fermé.
12. Aucune ligne ne correspond à la combinaison des filtres actifs → l'état
    vide existant `Aucun élément` s'affiche (comportement déjà en place pour
    le filtre global, doit rester cohérent avec le filtre par colonne).
13. L'état des filtres de colonnes (texte + options par colonne) est local à
    la vue Excel (comme `colWidths`, `collapsedFolders` aujourd'hui) : il
    n'est pas persisté et se réinitialise à la navigation vers un autre
    composant/type ou à la fermeture du projet. Si une colonne est retirée de
    `visibleFields`, son filtre est oublié (pas de filtre "fantôme" actif sur
    une colonne non affichée).

## Hors scope

- Filtre façon AutoFiltre Excel (liste déroulante de valeurs distinctes à
  cocher) — écarté au cadrage ; seul un champ texte + options (identique au
  filtre global) est demandé, pas une énumération des valeurs présentes dans
  la colonne.
- Réglage global unique d'options (casse/mot entier/regex) partagé entre
  toutes les colonnes — chaque colonne a son propre jeu d'options (voir
  Décisions ; à confirmer si le cadrage souhaitait en réalité un réglage
  partagé).
- Filtre par colonne dans la vue Word (`WordView.tsx`) — le ticket cible
  explicitement la vue Excel.
- Filtrage sur le contenu des étapes de test (colonne `steps`) — déjà hors
  scope du filtre global existant.
- Persistance des filtres de colonnes (texte et options) entre sessions ou
  navigations — comportement local et volatile, cohérent avec les autres
  réglages d'affichage de la vue Excel (largeurs de colonnes, dossiers
  repliés).
- Consolidation de la duplication préexistante de `buildCampaignFilterRe`
  (présente à l'identique dans `SystemPanel.tsx` et `CampaignListView.tsx`) —
  la phase Design tranchera si le filtre par colonne réutilise l'une de ces
  implémentations, en extrait une commune, ou duplique localement ; ce n'est
  pas un pré-requis fonctionnel du ticket.
- Application rétroactive des options casse/mot entier/regex au filtre
  **global** tel qu'appliqué aujourd'hui dans `ExcelView`/`WordView` (qui
  ignore `filterOptions` et fait un simple `includes` insensible à la casse,
  contrairement à `ElementTree` qui les respecte) — incohérence préexistante,
  non introduite ni aggravée par ce ticket. Le filtre par colonne, lui,
  applique bien les options dès sa création (cf. Comportements attendus).

## Critères d'acceptation

- [ ] Chaque colonne filtrable de la vue Excel affiche une icône discrète
      dans son en-tête (toutes sauf `steps`).
- [ ] Cliquer sur l'icône ouvre un popover avec un champ texte et les 3
      boutons bascule (casse/mot entier/regex), identiques à ceux de la barre
      de filtre globale.
- [ ] Saisir du texte dans le popover d'une colonne masque en direct les
      lignes dont la valeur affichée de cette colonne ne correspond pas
      (mode "contient" par défaut).
- [ ] Activer "mot entier" sur une colonne ne garde que les lignes où le
      texte apparaît comme mot entier dans la valeur de cette colonne.
- [ ] Activer "regex" sur une colonne interprète le texte comme une
      expression régulière ; une regex invalide n'exclut aucune ligne (pas de
      crash/écran blanc).
- [ ] Activer "casse sensible" sur une colonne rend la comparaison sensible à
      la casse pour cette colonne.
- [ ] Deux filtres de colonnes actifs simultanément se combinent en ET
      (une ligne doit satisfaire les deux pour rester visible).
- [ ] Un filtre de colonne actif en même temps que le filtre global
      (barre au-dessus de l'arbre) se combine en ET avec lui.
- [ ] Les dossiers restent affichés quand un filtre (global ou colonne) est
      actif, sans régression du comportement existant.
- [ ] L'icône d'une colonne filtrée est visuellement distincte de celle d'une
      colonne non filtrée, popover fermé.
- [ ] `Échap` dans le popover vide le texte du filtre de la colonne (les
      options restent) ; un clic en dehors ferme le popover.
- [ ] Aucune ligne ne correspond → message `Aucun élément` affiché.
- [ ] Changer de composant/type ou fermer puis rouvrir le projet réinitialise
      les filtres de colonnes.
- [ ] Retirer une colonne de l'affichage (masquage/réordonnancement) ne
      laisse pas de filtre actif invisible sur cette colonne.
- [ ] Aucune régression sur le filtre global existant (recherche large,
      options casse/mot entier/regex sur l'arbre).
- [ ] TypeScript compile sans nouvelle erreur ; `/code-review` passé sur le
      diff.
