# T53 — Correction staging des fichiers supprimés

## Root cause

Dans `apps/desktop/src/main/services/sync.service.ts`, la méthode `stage()` appelait systématiquement `git.add()` de la bibliothèque isomorphic-git pour indexer n'importe quel fichier.

**Le problème** : `git.add()` lit le fichier depuis le disque. Quand un fichier a été **supprimé** (statut `head=1, workdir=0, stage=1`, marqueur `'D'`), le fichier n'existe plus sur le système de fichiers. L'appel `git.add()` lève alors une erreur `ENOENT` (file not found), et l'opération de staging échoue silencieusement côté renderer (la mutation React Query rejette, le fichier reste en état "Modifications" non stagé).

La même logique manquait dans `stageAll()` : `git.add({ filepath: '.' })` ne supprime pas les entrées d'index correspondant aux fichiers supprimés.

Pour **stager une suppression**, isomorphic-git expose l'API `git.remove()` qui retire l'entrée de l'index sans toucher au disque.

## Correction appliquée

**Fichier modifié** : `apps/desktop/src/main/services/sync.service.ts`

### Méthode `stage()`

Avant :
```ts
async stage(repoPath: string, filepath: string): Promise<void> {
  await git.add({ fs, dir: repoPath, filepath })
}
```

Après :
```ts
async stage(repoPath: string, filepath: string): Promise<void> {
  // For deleted files (no longer on disk), git.add() throws ENOENT.
  // Use git.remove() to stage the deletion instead.
  const absPath = path.join(repoPath, filepath)
  try {
    await fsP.access(absPath)
    // File exists on disk → normal add
    await git.add({ fs, dir: repoPath, filepath })
  } catch {
    // File absent from disk → stage the deletion
    await git.remove({ fs, dir: repoPath, filepath })
  }
}
```

### Méthode `stageAll()`

Avant :
```ts
async stageAll(repoPath: string): Promise<void> {
  await git.add({ fs, dir: repoPath, filepath: '.' })
}
```

Après :
```ts
async stageAll(repoPath: string): Promise<void> {
  const matrix = await git.statusMatrix({ fs, dir: repoPath })
  for (const [filepath, head, workdir] of matrix) {
    // Deleted file: exists in HEAD but absent from workdir
    if (head === 1 && workdir === 0) {
      await git.remove({ fs, dir: repoPath, filepath })
    }
  }
  // Stage all present files (new + modified)
  await git.add({ fs, dir: repoPath, filepath: '.' })
}
```

## Comment reproduire le bug (avant fix)

1. Ouvrir un projet dans l'appli Polenta Desktop.
2. Dans le dossier du projet git, supprimer manuellement un fichier suivi (ex: `rm requirements/SYS/SYS-001.yaml`).
3. Ouvrir le panneau **Version** dans la sidebar.
4. Le fichier supprimé apparaît dans la section **Modifications** avec le marqueur rouge `D`.
5. Cliquer sur `+` pour stager ce fichier.
6. Rien ne se passe (ou une erreur apparaît dans les logs Electron). Le fichier reste en "Modifications" et ne passe pas dans "Stagés".

## Comment vérifier le fix

1. Répéter les étapes 1–4 ci-dessus avec la version corrigée.
2. Cliquer sur `+` pour stager le fichier supprimé.
3. Le fichier doit passer de **Modifications** vers **Stagés** avec le marqueur `D`.
4. Il est ensuite possible de committer normalement.
5. Vérifier également le bouton `+` global (stager tout) : les fichiers supprimés doivent aussi être stagés.
6. Vérifier que `git log --oneline` dans le dépôt confirme la suppression après commit.
