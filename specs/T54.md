# T54 — Bug : retour depuis édition restaure la vue word

## Root cause

Dans `SystemView.tsx`, la fonction `handleEditBack` appelée quand l'utilisateur
clique le bouton "Retour" dans `EditView` contenait un retour hardcodé vers `'excel'`
quel que soit la vue précédente :

```ts
// AVANT (ligne ~638)
const handleEditBack = useCallback(() => {
  if (backHistory.length > 0) {
    handleGoBack()
  } else {
    setEditingNodeId(null)
    setViewMode('excel')   // ← toujours 'excel', même si on venait de 'word'
  }
}, [backHistory, handleGoBack, setEditingNodeId])
```

Il n'existait aucun mécanisme pour mémoriser la vue active (`'excel'` ou `'word'`)
avant d'entrer en mode `'edit'`.

## Correctif appliqué

**Fichier modifié** : `apps/desktop/src/renderer/components/system/SystemView.tsx`

Ajout d'un `prevViewModeRef` (ref React) initialisé à `'excel'`, mis à jour
uniquement quand `viewMode` prend une valeur non-edit (`'excel'` ou `'word'`)
via l'effet `useEffect` qui persiste la vue dans localStorage :

```ts
const prevViewModeRef = useRef<'excel' | 'word'>('excel')

useEffect(() => {
  if (repoPath && (viewMode === 'excel' || viewMode === 'word')) {
    localStorage.setItem(`polenta:viewMode:${repoPath}`, viewMode)
    prevViewModeRef.current = viewMode   // ← mémorise la dernière vue non-edit
  }
}, [viewMode, repoPath])
```

La restauration depuis localStorage initialise aussi le ref :

```ts
if (stored === 'excel' || stored === 'word') {
  setViewMode(stored)
  prevViewModeRef.current = stored
}
```

`handleEditBack` utilise le ref au lieu de la valeur hardcodée :

```ts
const handleEditBack = useCallback(() => {
  if (backHistory.length > 0) {
    handleGoBack()
  } else {
    setEditingNodeId(null)
    setViewMode(prevViewModeRef.current)  // ← restaure 'word' ou 'excel'
  }
}, [backHistory, handleGoBack, setEditingNodeId])
```

## Pourquoi une ref plutôt qu'un état React

Une ref (pas un état) convient ici car :
- La valeur est lue une seule fois au moment du clic "Retour"
- Elle n'a pas besoin de déclencher un re-render quand elle change
- Elle n'est jamais `'edit'` — c'est un curseur stable sur la dernière vue document

## Comment reproduire le bug (avant correctif)

1. Ouvrir la vue Word (icône document dans la toolbar)
2. Cliquer sur le bouton crayon/édition d'un objet → la vue passe en mode Edit
3. Cliquer sur "← Retour" dans EditView
4. **Bug** : la vue affichée est Excel au lieu de Word

## Comment vérifier le correctif

1. Ouvrir la vue Word
2. Cliquer sur le bouton édition d'un objet (icône crayon dans WordView)
3. Cliquer sur "← Retour" dans EditView
4. **Attendu** : la vue Word est restaurée
5. Répéter depuis la vue Excel → retour doit restaurer la vue Excel
6. Vérifier que la navigation via liens (`navigateToObject`) fonctionne toujours :
   - Depuis Word, cliquer sur un lien → EditView d'un autre objet → Retour → Word
   - Depuis Excel, cliquer sur un lien → EditView → Retour → Excel
