# T56 — Nom d'élément perdu après navigation

## Root cause

`handleRootChange` dans `SystemPanel.tsx` (sidebar) ne sauvegardait que l'état React local
via `setRoot(newRoot)` sans persister en backend. Quand l'utilisateur naviguait vers une autre
vue et revenait, `SystemViewContext` re-fetait l'arbre depuis le backend (qui n'avait pas
le nouveau nom) — le renommage était perdu.

Le même bug affectait tous les changements d'arbre déclenchés depuis le panel latéral :
renommage, déplacement (DnD dans la sidebar), etc.

Dans `SystemView.tsx`, les handlers `handleRenameNode` et `handleRootChangeDnd` appellent
déjà `api.tree.save(...)` après `setRoot`. Le panel latéral avait omis ce save.

## Correctif appliqué

**Fichier :** `apps/desktop/src/renderer/components/sidebar/SystemPanel.tsx`

Ajout de `const qc = useQueryClient()` dans `SystemPanel` et mise à jour de
`handleRootChange` pour appeler `api.tree.save` immédiatement après `setRoot`,
en passant `newRoot` explicitement (car `root` en état React n'est pas encore mis
à jour au moment de l'appel asynchrone).

```typescript
const handleRootChange = useCallback((newRoot: TypeTreeNode[]) => {
  setRoot(newRoot)
  if (repoPath && effectiveNodeId && effectiveTypeId) {
    api.tree.save(repoPath, { nodeId: effectiveNodeId, typeId: effectiveTypeId, root: newRoot })
      .then(() => qc.invalidateQueries({ queryKey: ['tree', repoPath, effectiveNodeId, effectiveTypeId] }))
      .catch(err => console.error('[SystemPanel] Erreur save tree:', err))
  }
}, [repoPath, effectiveNodeId, effectiveTypeId, setRoot, qc])
```

## Comment vérifier

1. Lancer l'application
2. Ouvrir la vue Système (panel latéral avec l'arbre d'exigences)
3. Créer un nouvel élément (bouton +) → il apparaît avec le nom par défaut "Sans titre"
4. Double-cliquer sur son nom dans le panel et le renommer en "Mon exigence test"
5. Naviguer vers la vue Version (ou toute autre vue)
6. Revenir sur la vue Système
7. **Attendu :** l'élément affiche "Mon exigence test"
8. **Avant fix :** l'élément revenait à "Sans titre"
