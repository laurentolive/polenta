# T58 — Baseline fantôme après suppression du tag git

## Root cause

Les baselines sont persistées dans `.polenta/baselines.yaml` (fichier YAML local,
pas de base de données). Lors de l'appel `baseline:list`, le service lisait
**uniquement ce fichier YAML** sans vérifier l'existence réelle du tag git correspondant.

Si le tag git d'une baseline est supprimé (via l'UI graph, `git tag -d`, ou
toute opération externe), la baseline reste présente dans `baselines.yaml` et
continue d'apparaître dans la liste — c'est un **enregistrement orphelin**.

Chemin de code concerné :
- `apps/desktop/src/main/services/baseline.service.ts` — méthode `list()`
- `apps/desktop/src/main/ipc/index.ts` — handler `baseline:list`
- `apps/desktop/src/renderer/routes/graph.tsx` — mutation `deleteTagMut`
  (invalide uniquement `['sync:tags']` et `['sync:graph']`, pas `['baseline:list']`)

## Correctif appliqué

### `apps/desktop/src/main/services/baseline.service.ts`

La méthode `list()` :
1. Lit `baselines.yaml` comme avant
2. Vérifie chaque entrée via `git.resolveRef({ ref: 'refs/tags/<tag>' })`
3. Filtre les entrées dont le tag n'existe plus
4. **Prune automatiquement** le fichier YAML si des orphelins sont détectés
   (auto-guérison — les entrées invalides sont retirées de façon permanente)

Ce correctif est **défensif** : il fonctionne quelle que soit la façon dont le
tag a été supprimé (UI Polenta, git CLI, synchronisation remote, etc.).

## Comment reproduire le bug (avant correctif)

1. Ouvrir un projet dans Polenta Desktop
2. Aller sur la page Baselines (`/baseline?projectId=...`)
3. Créer une baseline (ex : tag `v1.0.0`)
4. Vérifier que la baseline apparaît dans la liste de droite
5. Aller sur la page Graph (`/graph`)
6. Clic droit sur le tag `v1.0.0` → "Supprimer le tag" (confirmation 2 clics)
7. Retourner sur la page Baselines
8. **Bug** : la baseline `v1.0.0` est toujours listée malgré la suppression du tag

## Comment vérifier le fix

1. Reproduire les étapes 1–7 ci-dessus
2. Après suppression du tag git et retour sur la page Baselines :
   - La baseline `v1.0.0` ne doit **plus** apparaître dans la liste
   - Le fichier `.polenta/baselines.yaml` ne doit **plus** contenir l'entrée `v1.0.0`
3. Vérification alternative via le fichier YAML :
   ```bash
   # Avant suppression du tag
   cat .polenta/baselines.yaml  # contient v1.0.0
   git tag -d v1.0.0
   # Appeler baseline:list (reload de la page Baselines)
   cat .polenta/baselines.yaml  # v1.0.0 doit avoir disparu
   ```
