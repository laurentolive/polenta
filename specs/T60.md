# T60 — Correction backgrounds non dark-mode-aware

## Ticket

T60 : Dans les pages modèle de données / composant / champs / Type, le background des listes est blanc en dark mode — illisible.

## Root cause

Trois types de problèmes coexistaient :

**1. Classes `bg-white` et `bg-gray-*` sans dark mode**

`AccountMenu.tsx` utilisait `bg-white`, `hover:bg-gray-100`, `hover:bg-gray-50` sans aucun équivalent dark. En dark mode, le menu déroulant restait blanc sur fond sombre.

**2. Modificateurs d'opacité dans les classes dark mode (`dark:bg-*/NN`) non générés**

Le projet n'utilise pas les CSS variables avec modificateurs d'opacité (ex: `bg-hover/30`) — Tailwind ne génère pas ces classes. Par conséquent, toutes les classes de type `dark:bg-blue-900/30`, `dark:bg-slate-700/50`, `dark:bg-green-900/30`, etc. étaient silencieusement ignorées, laissant les badges de statut, les lignes sélectionnées et les inputs en édition avec leur couleur light (blanc cassé / bleu clair) même en dark mode.

**3. `<select>` avec `bg-transparent` : la règle base layer est écrasée par la utility Tailwind**

Dans `schema.tsx`, la constante `cellInput` contient `bg-transparent`. Cette classe est partagée entre les `<input>` et un `<select>` (sélecteur de type de champ dans `FieldsTable`). Pour les `<input>`, `bg-transparent` est correct (l'input devient transparent sur la cellule `bg-surface` de la `<td>`). Pour les `<select>`, c'est problématique :

- `index.css` définit au niveau `@layer base` : `select { background-color: var(--surface) }` — ce qui donnerait le bon fond sombre en dark mode.
- Mais la utility Tailwind `bg-transparent` (couche utilities) a une spécificité plus haute et génère `background-color: transparent`, écrasant la règle base layer.
- En dark mode, un `<select>` transparent dans Electron/Chromium affiche le fond blanc par défaut du système (le parent `bg-surface` ne transparaît pas car les selects natifs ont leur propre contexte de rendu).

Le même problème existait dans `project.$id.tsx` pour le sélecteur de baseline (branche `prj-`).

## Comment vérifier manuellement

1. Lancer l'application (`pnpm dev` depuis la racine)
2. Ouvrir un projet existant
3. Activer le dark mode (clic sur l'icône en bas de l'activity bar)
4. Naviguer vers **Modèle de données** (icône projet → "Modèle de données") :
   - Onglet **Composants** : le tableau doit avoir un fond sombre
   - Onglet **Éléments** → ouvrir un type → tableau **Champs** et tableau **Statuts** : fond sombre, texte lisible
   - Onglet **Éléments** → tableau **Champs** → colonne **Type** : le `<select>` doit avoir un fond sombre (`bg-surface`), pas blanc
   - Onglet **Liens** → les chips "Refs" actives (bleues) doivent être sombres, pas bleu clair
5. Vérifier le **menu Compte** (coin supérieur droit) : fond sombre, textes lisibles
6. Sur la page **Tableau de bord** (page projet) : le sélecteur de baseline (branche `prj-`) doit avoir un fond sombre
7. Dans la **vue système** (composant/exigences) :
   - Vue tableau (Excel) : cliquer sur une ligne pour la sélectionner — fond bleu sombre (pas blanc)
   - Cliquer sur une cellule pour l'éditer — fond bleu sombre (pas bleu clair)
   - Badges de statut (vue Word) : couleurs sombres cohérentes

## Règle à retenir

**Ne jamais utiliser `bg-transparent` sur un élément `<select>` dans ce projet.** Les selects natifs dans Chromium n'héritent pas du fond de leur parent quand leur background est transparent — ils affichent un fond blanc système. Utiliser `bg-surface` à la place. Pour les `<input>`, `bg-transparent` reste correct (l'input transparaît sur la cellule/conteneur parent).
