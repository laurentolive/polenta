# T62 — Bug : campagne logicielle HMI affiche des tests produit

## Symptôme

Lors de la création d'une campagne depuis le composant HMI avec le type
`verification_sw` (niveau logiciel), la liste des cas de test disponibles
incluait **tous** les tests du repo — y compris les tests d'autres composants
(ex. PROD, SYS) — au lieu de n'afficher que les tests HMI.

## Root cause

Dans `apps/desktop/src/renderer/routes/campaign.new.tsx`, la requête de
récupération des cas de test appelait `api.tests.list(repoPath)` **sans
aucun filtre**, retournant l'intégralité des `TestCase` du repo.

Les paramètres `component` (= nom du nœud, ex. `hmi`) et `level` (= nom du
type d'objet, ex. `verification_sw`) sont bien présents dans l'URL de la
route (passés par `SystemView` via `CampaignListView` → navigation `/campaign/new`)
mais n'étaient jamais utilisés pour filtrer la liste des tests proposés à
la sélection.

Chaque `TestCase` possède un champ `objectTypeRef` au format
`"<component>::<level>"` (ex. `"hmi::verification_sw"`). Ce champ est la
clé de filtrage correcte.

## Correctif appliqué

Fichier modifié : `apps/desktop/src/renderer/routes/campaign.new.tsx`

Après la requête `api.tests.list`, un filtre est appliqué en mémoire :

```ts
const tests = allTests.filter(t => {
  if (component && level) return t.objectTypeRef === `${component}::${level}`
  if (component) return t.objectTypeRef.startsWith(`${component}::`)
  if (level)     return t.objectTypeRef.endsWith(`::${level}`)
  return true
})
```

- Si `component` **et** `level` sont définis (cas nominal depuis SystemView),
  seuls les tests dont l'`objectTypeRef` est exactement `"hmi::verification_sw"`
  sont proposés.
- Les cas partiels (component seul, level seul) sont aussi couverts pour la
  robustesse.
- Sans paramètre (accès direct à `/campaign/new` sans contexte), tous les
  tests restent visibles — comportement non régressif.

## Comment reproduire le bug (avant fix)

1. Ouvrir un projet avec plusieurs composants (ex. `hmi` et `prod`), chacun
   ayant des types de test (`verification_sw` pour HMI, `verification` pour
   PROD).
2. Dans la sidebar System, sélectionner le composant HMI / type
   `verification_sw` (catégorie `campaign`).
3. Cliquer sur « + Nouvelle campagne ».
4. Observer : la liste des cas de test affichait les tests PROD (et tous les
   autres), pas seulement les tests HMI.

## Comment vérifier le fix

1. Même scénario : ouvrir composant HMI / `verification_sw`.
2. Cliquer sur « + Nouvelle campagne ».
3. Vérifier : seuls les tests dont l'`objectTypeRef` commence par `"hmi::"`
   (et dont le type est `verification_sw`) apparaissent dans la liste de
   sélection.
4. Naviguer vers un autre composant (ex. PROD / `verification`) et recréer
   une campagne : seuls les tests PROD apparaissent.
5. Créer la campagne et vérifier que le YAML généré dans `campaigns/` ne
   contient que des IDs de tests HMI.
