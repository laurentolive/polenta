# T63 — Correction ordre `covered`/`validated` dans `computeCoverageStatus`

## Contexte

Bug identifié dans la fonction `computeCoverageStatus` de `apps/api/src/modules/traceability/traceability.service.ts`.

---

## Root cause

**Fichier** : `apps/api/src/modules/traceability/traceability.service.ts`, ligne 434.

La fonction `computeCoverageStatus` gérait dans le mauvais ordre les conditions `covered` et `validated`.

### Avant le correctif (code incorrect)

```typescript
if (cells.some((c) => c.status === 'pass')) return 'validated'
return 'covered'
```

### Après le correctif (code corrigé)

```typescript
if (cells.some((c) => c.status === 'not_run')) return 'covered'
return 'validated'
```

### Explication de l'inversion

La spec (SPEC-TRACEABILITY.md §2.2) définit la **priorité de calcul** comme suit :

```
needs_revalidation > failing > covered > validated > not_covered
```

Les définitions des statuts sont :

| Statut | Condition |
|--------|-----------|
| `covered` | Au moins un TestCase lié, mais **aucune exécution PASS** |
| `validated` | Au moins un TestCase avec **au moins une exécution PASS** |

L'inversion se manifestait dans le cas où une exigence est liée à plusieurs TestCases dont certains ont un run PASS (`pass`) et d'autres n'ont jamais été exécutés (`not_run`) :

- **Avant** : la présence d'un seul `pass` retournait `validated`, ignorant les `not_run`.
- **Après** : si un `not_run` existe, on retourne `covered` (priorité supérieure spec), sinon `validated`.

La condition précédente `cells.some(c => c.status === 'pass')` ne vérifiait pas si TOUS les tests avaient passé — elle retournait `validated` dès qu'au moins un test avait passé, même si d'autres n'avaient jamais été exécutés. La condition correcte est : `covered` si au moins un test n'a pas encore de run, `validated` si tous les tests liés ont au moins un run PASS (aucun `not_run` restant une fois éliminés `needs_revalidation` et `failing`).

---

## Correctif appliqué

**1 ligne modifiée** dans `computeCoverageStatus` (ligne 434) :

Remplacement de :
```typescript
if (cells.some((c) => c.status === 'pass')) return 'validated'
```
par :
```typescript
if (cells.some((c) => c.status === 'not_run')) return 'covered'
```

La branche `return 'validated'` reste en fallback (ligne 435) : elle s'applique quand toutes les cellules non-revalidation/non-failing ont un run PASS.

---

## Comment vérifier

### Cas de test manuel

Créer une exigence avec deux TestCases liés :
- `TC-A` : dernier run = PASS
- `TC-B` : aucun run (jamais exécuté)

**Avant le fix** : la matrice affiche `validated` (icône ✓).  
**Après le fix** : la matrice affiche `covered` (icône ◑), conforme à la spec.

### Cas de test unitaire (à écrire dans traceability.service.spec.ts)

```typescript
it('returns covered when some cells are not_run even if others are pass', () => {
  const cells: MatrixCell[] = [
    { testCaseId: 'TC-001', coverageType: 'full', status: 'pass', lastRunId: 'r1', lastRunDate: '2026-01-01' },
    { testCaseId: 'TC-002', coverageType: 'full', status: 'not_run', lastRunId: null, lastRunDate: null },
  ]
  expect(computeCoverageStatus(cells)).toBe('covered')
})

it('returns validated when all cells are pass', () => {
  const cells: MatrixCell[] = [
    { testCaseId: 'TC-001', coverageType: 'full', status: 'pass', lastRunId: 'r1', lastRunDate: '2026-01-01' },
    { testCaseId: 'TC-002', coverageType: 'full', status: 'pass', lastRunId: 'r2', lastRunDate: '2026-01-02' },
  ]
  expect(computeCoverageStatus(cells)).toBe('validated')
})
```
