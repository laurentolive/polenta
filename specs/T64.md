# T64 — Normalisation enum statuts CampaignRun

## Convention choisie

Source : `specs/SPEC-TESTS.md` §4.2 (CampaignRun) et §3.3 (TestRun).

| Enum | Valeurs spec | Valeurs avant T64 |
|------|-------------|-------------------|
| `CampaignStatus` | `planned` / `in_progress` / `completed` / `abandoned` | `planned` / `in-progress` / `completed` / `abandoned` (tiret au lieu d'underscore) |
| `TestRunStatus` (statut par test dans une campagne) | `pending` / `PASS` / `FAIL` / `BLOCKED` / `INCOMPLETE` | `pending` / `passed` / `failed` / `blocked` / `skipped` (minuscules + `skipped` non conforme) |

**Règle** : les valeurs `TestRun.result` et `StepResult.result` (`PASS`, `FAIL`, `BLOCKED`, `INCOMPLETE`, `SKIP`, `NOT_EXECUTED`) sont en MAJUSCULES depuis l'origine — T64 aligne `CampaignTestRun.status` sur la même convention.

Note : `CellStatus` (`pass` / `fail` / `blocked` / `not_run`) dans `packages/types/src/traceability.ts` est un type interne à la matrice de traçabilité et n'est pas concerné par ce ticket.

## Comment vérifier

1. **Types TypeScript** : `pnpm --filter @polenta/types exec tsc --noEmit` → 0 erreur
2. **Runtime** : créer une campagne, exécuter un test → le statut doit passer de `pending` à `PASS`/`FAIL`/`BLOCKED`/`INCOMPLETE` (plus de `passed`/`failed`/`skipped`)
3. **Persistance** : vérifier dans le YAML généré que `status: in_progress` (underscore) et non `status: in-progress`
4. **Affichage** : badge de statut de campagne doit afficher la couleur bleue pour `in_progress`
