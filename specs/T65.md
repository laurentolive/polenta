# T65 — Copie d'élément crée un `objectId` fantôme sans objet backend

## Root cause

`treeDeepCopyWithNewIds` (dans `useTreeState.ts`) génère un nouvel `objectId` via `generateId()` — un timestamp local — pour chaque nœud `item` copié. Cet ID est inséré dans l'arbre local (via `onRootChange`) mais **aucun objet correspondant n'est créé en base** (`api.requirements.create` / `api.tests.create` ne sont jamais appelés).

Résultat : après coller, les nœuds affichés pointent vers des `objectId` inexistants côté serveur. L'ouverture ou l'édition d'un tel nœud échoue silencieusement ou charge des données vides.

Le bug affecte trois points d'entrée de la fonctionnalité coller :

| Fichier | Fonction | Description |
|---|---|---|
| `ElementTree.tsx` | `paste()` | Coller sur un nœud cible (dossier ou item) |
| `ElementTree.tsx` | `handleBgContextAction()` | Coller via clic-droit sur fond vide |
| `ExcelView.tsx` | `paste()` | Coller dans la vue tableur |

## Correctif appliqué

### 1. `SystemViewContext.tsx` — extension de `createItemObject`

La signature de `createItemObject` a été étendue :

```ts
createItemObject(nodeId: string, sourceObjectId?: string): Promise<void>
```

- Quand `sourceObjectId` est fourni (coller sans couper), la fonction récupère l'objet source via `api.requirements.get` / `api.tests.get` et copie son `title`, `fields` et `steps` dans le DTO de création.
- Quand `sourceObjectId` est absent (insertion normale ou couper-coller), un objet vide est créé comme avant.
- En cas d'erreur de récupération de la source (objet supprimé entre-temps), le fallback est un objet vide.

### 2. `ElementTree.tsx` — appel de `onItemNodeAdded` après coller

Deux helpers ajoutés :

- `collectItemNodes(nodes)` — collecte tous les nœuds `item` d'un sous-arbre en pré-ordre.
- `notifyPastedItems(copies, originals, isCut)` — pour chaque nœud item copié, appelle `onItemNodeAdded(copy.id, sourceObjectId)` en passant l'`objectId` de l'original (sauf si c'est un couper).

Les deux sites d'appel (`paste` et `handleBgContextAction`) capturent les nœuds originaux avant toute mutation de state, puis appellent `notifyPastedItems`.

### 3. `ExcelView.tsx` — ajout de `onItemNodeAdded` et appel après coller

- Prop `onItemNodeAdded?(nodeId: string, sourceObjectId?: string)` ajoutée à `Props`.
- Logique identique à `ElementTree.tsx` ajoutée à la fin de la fonction `paste`.

### 4. `SystemView.tsx` — transmission de `createItemObject` à `ExcelView`

`createItemObject` est désormais extrait de `useSystemView()` et passé à `ExcelView` via `onItemNodeAdded={readOnly ? undefined : createItemObject}`.

## Vérification manuelle

1. Ouvrir un projet avec des exigences existantes.
2. Dans le panneau latéral (arbre), clic droit sur une exigence → **Copier**.
3. Clic droit sur un autre nœud → **Coller**.
4. Vérifier que le nœud collé s'affiche avec les mêmes données que l'original (titre, champs).
5. Double-cliquer sur le nœud collé → la vue édition doit s'ouvrir et afficher les données.
6. Recharger l'application → le nœud collé doit toujours être présent avec ses données.
7. Répéter en vue Excel (tableur) : copier une ligne, coller sur une autre → mêmes vérifications.
8. Tester le **couper-coller** : l'élément doit se déplacer sans créer de doublon en base.
9. Tester la copie d'un **dossier contenant plusieurs items** : tous les items enfants doivent avoir leur objet backend créé.
