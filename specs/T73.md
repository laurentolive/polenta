# T73 — Bug : combobox Composant affiche "Produit" plusieurs fois

## Reproduction

Dans le workspace `polenta-prj2` (racine + `HMI`, `BMS`, `iface-bus-uart`, `comp-controller`,
`comp-sensor`), le combobox Composant de la vue Système affiche "Produit" pour trois entrées
différentes (`polenta-prj2`, `HMI`, `BMS`), rendant impossible de les distinguer sans les
sélectionner une par une.

## Root cause

Le code de `SystemViewContext.tsx` (T72) calculait le libellé du combobox ainsi :

```ts
label: schemasByRepoPath.get(n.repoPath)?.nodes?.[0]?.label || n.name,
```

— le libellé du `SystemNode` local **remplace** le mount name dès qu'il est présent, au lieu de
le compléter. Or trois repos partagent ici le même libellé "Produit" pour des raisons
indépendantes :
- `polenta-prj2` (racine) : c'est son vrai libellé de nœud produit — légitime.
- `HMI` : son propre `schema.yaml` déclare aussi `label: Produit` (template jamais renommé côté
  utilisateur) — donnée existante, pas introduite par ce ticket.
- `BMS` : n'a pas de `.polenta/schema.yaml` du tout ; `SchemaService.readFromDisk` retombe sur
  `DEFAULT_SCHEMA`, dont le nœud `root` a lui aussi `label: 'Produit'` en dur.

Cette implémentation contredit par ailleurs ce qui a été documenté dans le même ticket T72, dans
`SPEC-SYSTEM-VIEW.md` § Combobox Composant : *"Libellé de chaque entrée : le mount name du repo,
suffixé par le label du premier SystemNode de son propre schema.yaml si présent."* — le code ne
faisait pas ce que le spec disait.

## Correctif appliqué

`apps/desktop/src/renderer/contexts/SystemViewContext.tsx` — le mount name est désormais toujours
conservé dans le libellé affiché, suffixé par le label local seulement s'il diffère du mount name
lui-même :

```ts
const label = localLabel && localLabel !== n.name ? `${n.name} — ${localLabel}` : n.name
```

Résultat pour `polenta-prj2` : `polenta-prj2 — Produit`, `HMI — Produit`, `BMS — Produit`,
`iface-bus-uart — Interface Bus UART`, `comp-controller — Contrôleur (maître bus UART)`,
`comp-sensor — Capteur (esclave bus UART)` — chaque entrée reste identifiable même quand le
libellé local est générique ou dupliqué.

Correctif minimal : pas de changement à `SPEC-SYSTEM-VIEW.md` (le comportement corrigé
correspond déjà exactement à ce qui y était décrit), pas de changement aux données `HMI`/`BMS`
(hors périmètre — un libellé de schéma dupliqué ou un schéma absent restent des états valides,
seul l'affichage du combobox doit rester désambigüé dans tous les cas).

## Comment vérifier

1. Ouvrir `polenta-prj2` → Vue Système.
2. Le combobox Composant doit afficher 6 entrées toutes visuellement distinctes :
   `polenta-prj2 — Produit`, `HMI — Produit`, `BMS — Produit`, `iface-bus-uart — Interface Bus
   UART`, `comp-controller — Contrôleur (maître bus UART)`, `comp-sensor — Capteur (esclave bus
   UART)`.
3. Sélectionner chacune n'affecte que le libellé affiché — comportement de sélection et de
   rechargement des données inchangé (déjà couvert par `specs/T72-tests.md`).
