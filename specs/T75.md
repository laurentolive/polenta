# T75 — Images et diagrammes draw.io redimensionnables/rognables dans richtext, via menu contextuel

## Contexte

`T47` a ajouté l'insertion et le rendu de diagrammes draw.io dans les champs
`richtext` (nœud TipTap custom `DrawioEmbed`, rendu via le viewer officiel
draw.io vendoré dans `DrawioEmbedView.tsx`). Les images utilisent l'extension
standard `@tiptap/extension-image` (`Image.configure({ inline: false,
allowBase64: true })`), sans attribut de dimension ni interaction de
redimensionnement — une image insérée s'affiche à sa taille native, contrainte
uniquement par `max-w-full` en CSS.

Aujourd'hui, ni les images ni les diagrammes draw.io ne sont redimensionnables,
rognables, ou éditables via un menu contextuel dans le richtext. Seule
interaction existante sur un bloc draw.io : double-clic pour ouvrir le fichier
dans l'application draw.io externe (`DrawioEmbedView.tsx`, `handleDoubleClick`).

Cette évolution s'applique aux deux points d'édition richtext existants :
`RichTextField.tsx` (mode toolbar inline et mode contexte via
`RichTextContext`). `RichTextViewer.tsx` reste en lecture seule
(`editable: false`, pas de toolbar, pas de boutons d'insertion) : ce ticket ne
lui ajoute aucune interaction — un bloc image/drawio y reste un rendu statique,
cohérent avec le comportement actuel du composant.

## Décisions (validées avec l'humain avant rédaction de cette spec)

1. **Crop drawio = cadrage du viewport affiché**, pas une modification du
   fichier `.drawio` source. Le rognage définit une fenêtre (zoom + pan, ou
   région rectangulaire) qui limite la zone du diagramme rendue dans le bloc
   richtext ; le fichier `.drawio` référencé (et son XML) n'est jamais modifié
   par cette évolution. Le cadrage est stocké comme attribut du bloc
   `drawioEmbed` (nouveaux attributs, à définir en Design — ex. `viewBox` ou
   `crop: {x, y, width, height}` en coordonnées diagramme).
2. **Crop image = rognage bitmap classique** : une région rectangulaire de
   l'image source est sélectionnée ; le rendu affiché est recadré sur cette
   région (recadrage d'affichage — voir Design pour trancher entre stockage
   d'un nouveau bitmap recadré vs. attributs de crop + `object-fit`/`clip-path`
   sur l'image source conservée intacte).
3. **Redimensionnement à ratio conservé par défaut** (image et drawio) :
   les poignées de coin redimensionnent proportionnellement. Le detail de
   variante libre (touche modificatrice, poignée de bord dédiée) est laissé à
   `T75-design.md`.
4. **Menu contextuel (clic droit)** : tronc commun aux deux types (au minimum
   redimensionner, rogner, remplacer le fichier, supprimer) complété d'actions
   spécifiques à drawio (ouvrir dans l'application draw.io externe — déjà
   existant via double-clic, à reprendre dans le menu ; changer la page/le
   node-id référencé sans ré-insérer le bloc).
5. Cette évolution ne s'applique qu'en édition (`RichTextField.tsx`) — pas dans
   `RichTextViewer.tsx` (lecture seule), cohérent avec l'absence actuelle de
   toute toolbar/interaction d'édition dans ce composant.

## Comportement attendu

### Redimensionnement

1. Une image ou un bloc drawio sélectionné dans l'éditeur affiche des poignées
   de redimensionnement (coins au minimum).
2. Le glissement d'une poignée de coin redimensionne le bloc en conservant le
   ratio largeur/hauteur d'origine (cf. Décision 3).
3. La taille choisie est persistée dans le document (attributs de dimension
   sur le nœud `image` / `drawioEmbed`) et sérialisée de façon stable et
   diffable dans le Markdown stocké — cohérent avec l'exigence T47 de
   représentation stable en Git (pas de dimensions recalculées à chaque
   sauvegarde).
4. Le rendu en édition (`RichTextField.tsx`) respecte la dimension stockée dès
   le chargement du document (pas de saut visuel entre le rendu initial et
   l'affichage post-interaction).

### Rognage (crop)

5. Un mode "rogner" (déclenché depuis le menu contextuel) affiche une zone de
   sélection rectangulaire ajustable par poignées sur le rendu actuel (image
   ou viewport draw.io).
6. Valider le rognage met à jour l'attribut de cadrage du bloc ; annuler laisse
   le bloc inchangé.
7. Pour une image : le fichier source original n'est pas altéré sur disque —
   seul l'attribut de crop du bloc change (cohérent avec le stockage base64
   inline existant : recadrer ne doit pas dupliquer indéfiniment des données
   binaires à chaque édition).
8. Pour un diagramme draw.io : le fichier `.drawio` référencé n'est jamais
   modifié par le rognage (cf. Décision 1) — seul le cadrage d'affichage du
   bloc change.

### Menu contextuel (clic droit)

9. Un clic droit sur une image ou un bloc drawio dans l'éditeur ouvre un menu
   contextuel positionné au curseur (fermeture sur clic extérieur ou `Échap`,
   cohérent avec le `ContextMenu` déjà utilisé dans `ElementTree.tsx` pour
   l'arbre latéral — réutiliser ce pattern d'implémentation en Design plutôt
   qu'en réinventer un nouveau).
10. Actions communes : **Redimensionner** (active les poignées si non déjà
    actives), **Rogner** (active le mode crop, cf. point 5), **Remplacer le
    fichier** (rouvre le sélecteur de fichier — image ou `.drawio` selon le
    type — et remplace la `src`/le `path` en conservant position et dimensions
    actuelles), **Supprimer** (retire le bloc du document).
11. Actions spécifiques drawio : **Ouvrir dans draw.io** (identique au
    double-clic existant), **Changer de page/node-id** (rouvre le sélecteur de
    page déjà utilisé à l'insertion, cf. `T47`, pour re-cibler le même
    fichier sans le remplacer).

## Cas limites

- Redimensionnement en dessous d'une taille minimale (bloc illisible ou
  poignées inutilisables) → une taille plancher est imposée (valeur exacte
  laissée à `T75-design.md`).
- Rognage réduisant la zone visible à une région vide ou hors des bornes du
  contenu source → validation bloquée ou recadrée automatiquement dans les
  bornes valides, jamais un crop vide silencieusement accepté.
- "Remplacer le fichier" sur un bloc drawio avec un `nodeId` déjà défini et le
  nouveau fichier n'ayant pas ce node-id → retombe sur la première page du
  nouveau fichier (même logique de repli que l'insertion initiale T47), sans
  crash.
- Undo/redo TipTap (`StarterKit` inclut déjà l'historique) : redimensionner,
  rogner, remplacer doivent s'intégrer à la pile d'historique standard de
  l'éditeur (pas de mécanisme d'annulation séparé et incohérent).
- Bloc drawio en état d'erreur (`not-found`, `invalid`, cf. `T47`) → le menu
  contextuel reste accessible pour **Remplacer le fichier** et **Supprimer**,
  mais **Rogner** est désactivé (rien à cadrer sur un rendu en erreur).
- Copier-coller d'un bloc redimensionné/rogné vers un autre champ richtext →
  les attributs de dimension et de crop sont copiés avec le bloc (même
  comportement que la copie de référence de fichier drawio déjà spécifiée en
  T47).

## Hors scope explicite

- Toute interaction d'édition dans `RichTextViewer.tsx` (lecture seule) — cf.
  Décision 5.
- Modification du fichier `.drawio` source (déplacement de formes, édition du
  contenu) — reste exclusivement du ressort de l'application draw.io externe,
  cohérent avec le hors-scope de `T47` ("pas d'éditeur draw.io intégré").
- Rotation d'image ou de diagramme, filtres/effets visuels (luminosité,
  contraste...) — non demandés, non traités ici.
- Rognage destructif du fichier binaire source d'une image (écraser le
  fichier original recadré sur disque) — le rognage reste un attribut
  d'affichage du bloc (cf. Décision 2 et point 7).
- Export Word/Excel (`T43`) tenant compte des dimensions/crop du rendu inline
  — à traiter dans le ticket d'export si besoin.
- Redimensionnement/rognage tactile ou sur périphériques à écran tactile —
  hors scope (interactions souris uniquement, cohérent avec le reste de
  l'application desktop).

## Critères d'acceptation

- [ ] Sélectionner une image ou un bloc drawio dans l'éditeur richtext affiche
      des poignées de redimensionnement
- [ ] Glisser une poignée de coin redimensionne proportionnellement (ratio
      conservé) et persiste la nouvelle taille dans le document
- [ ] La taille persistée est restaurée correctement au rechargement du
      document (round-trip Markdown stable)
- [ ] Un clic droit sur une image ou un bloc drawio ouvre un menu contextuel
      avec au moins : Redimensionner, Rogner, Remplacer le fichier, Supprimer
- [ ] Le menu contextuel d'un bloc drawio propose en plus : Ouvrir dans
      draw.io, Changer de page/node-id
- [ ] "Rogner" sur une image permet de sélectionner une région rectangulaire
      et le rendu affiché respecte ensuite ce cadrage
- [ ] "Rogner" sur un bloc drawio cadre le viewport affiché sans modifier le
      fichier `.drawio` référencé sur disque
- [ ] "Remplacer le fichier" change la source (image ou chemin drawio) en
      conservant position, dimensions et crop existants
- [ ] "Supprimer" retire le bloc du document
- [ ] Undo/redo standard de l'éditeur couvre ces nouvelles actions
- [ ] Aucune de ces interactions n'est disponible/active dans
      `RichTextViewer.tsx` (lecture seule)
