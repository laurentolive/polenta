# T78 — Refonte du panneau latéral Version : arbre multi-repo

## Contexte

`VersionPanel.tsx` (panneau latéral de l'onglet Version) n'opère aujourd'hui que sur le
repo root du workspace (`currentProjectId` → `api.workspace.resolve` → `localPath`). Un
workspace Polenta est pourtant potentiellement composé de plusieurs repos (root +
composants + interfaces), chacun avec son propre état git (branche/tag/commit courant,
fichiers stagés/modifiés). Il n'existe aujourd'hui aucun moyen de consulter ou d'agir sur
l'état git d'un composant depuis la vue Version — il faut naviguer dans le repo sur disque
ou passer par un outil externe.

T78 remplace le panneau mono-repo actuel par un arbre : un dossier ouvrable/fermable par
repo du workspace, chacun scopé sur son propre `repoPath` via les endpoints `api.sync.*`
(déjà tous paramétrés par `repoPath`, aucun changement côté main process nécessaire).

## Description fonctionnelle

### Source de données de l'arbre

Réutilise le hook `useWorkspaceStructure(workspaceDir, repoPath)`
([useWorkspaceStructure.ts](../apps/desktop/src/renderer/hooks/useWorkspaceStructure.ts)),
déjà utilisé par `StructureTab` (onglet Structure du Modèle de données). `tree` (la
`logicalTree` à une racine) donne l'arbre hiérarchique root → composants/interfaces à
plat, avec pour chaque nœud `{ name, repoPath, url, pin, isInterface, children }`.

Le pattern d'arbre ouvrable/fermable (chevron, indentation par profondeur, état `open`
local par nœud) est repris de `RepoRow` dans
[StructureTab.tsx](../apps/desktop/src/renderer/components/schema/StructureTab.tsx) —
composant récursif à dupliquer/adapter, pas à importer tel quel (son contenu de ligne est
spécifique aux types d'éléments du schéma ; T78 a besoin d'un contenu de ligne différent :
statut git au lieu d'ObjectType).

### Dossier fermé

Affiche :
- icône dossier (`FolderGit2` pour un composant standard, `GitFork` pour une interface —
  cohérent avec `RepoRow`) + nom du repo (mount name)
- **vignette checkout** : réf courante (branche, tag, ou SHA court si HEAD détaché),
  obtenue via `api.sync.status(repoPath).branch` — même source que l'actuelle
  `BranchCombobox`/`currentBranch`. Un tag/SHA n'est pas distingué visuellement d'une
  branche dans cette vignette (l'utilisateur ouvre le dossier pour le détail via le
  combobox existant, qui liste déjà branches et tags séparément)
- **badge "dirty"** si `staged.length + unstaged.length > 0` pour ce repo (via
  `api.sync.status(repoPath)`) — puce visuelle simple (point coloré ou texte court, à
  affiner en phase Design), pas de détail de fichiers tant que le dossier est fermé

### Dossier ouvert

Affiche, pour ce repo précis, l'intégralité du contenu actuel de `VersionPanel` scopé sur
`repoPath` du nœud (pas sur le root global) :
- section Checkout : `BranchCombobox` existant (branches + tags + création/suppression de
  branche), réutilisé tel quel avec `repoPath` du nœud au lieu du root
- section Stagés (liste, stage/unstage, bouton Committer…)
- section Modifications (liste, stage/unstage/discard)
- modale de commit, modale de confirmation de checkout avec modifications en attente —
  logique identique à l'existant, dupliquée par repo (chaque dossier ouvert a son propre
  état de modale)

Aucune restriction sur quel(s) repo(s) peuvent être checkoutés depuis ce panneau — tous
les nœuds de l'arbre (root, composants, interfaces) exposent la même UI de checkout. Le
champ `SystemNode.readonly` du schéma (lecture seule des *éléments* d'un repo composant)
est indépendant de cette fonctionnalité et n'est pas consulté ici.

### État d'ouverture par défaut et multi-ouverture

- Tous les dossiers sont **ouverts par défaut** à l'affichage du panneau.
- Le repo root est **sélectionné** par défaut (mis en évidence visuellement — à préciser
  en phase Design, ex. léger fond ou bordure) : c'est la ligne visible en premier au
  chargement, cohérent avec l'usage actuel où le root est la seule cible.
- Plusieurs dossiers peuvent être ouverts simultanément, indépendamment les uns des
  autres (état `open` local par nœud, pas d'accordéon exclusif) — même mécanique que
  `RepoRow`.

### Rafraîchissement du statut git

Chaque repo affiché dans l'arbre a sa propre requête `api.sync.status(repoPath)` (badge
dirty + vignette checkout), avec un `refetchInterval` (à reprendre : 3000ms, comme
l'actuel `VersioningContext`). Ces requêtes sont montées/démontées avec le panneau Version
lui-même (elles vivent dans les composants de l'arbre du panneau, pas dans un contexte
global) — le git status par repo n'est donc interrogé que lorsque la vue Version est
affichée, pas en permanence pour tout le workspace comme le ferait un contexte partagé
app-wide.

Ceci est indépendant de `VersioningContext` (statut du root, utilisé pour le badge
"lecture seule" du header et les gardes d'édition ailleurs dans l'app) : T78 ne touche
pas `VersioningContext`, qui continue de ne suivre que le root repo pour ces usages
transverses.

### Header du panneau

Inchangé fonctionnellement : titre "Version", icônes Baselines / Historique / Comparer
(`navigate` vers `/baseline`, `/graph`, `/version-diff`). L'icône `Lock` (lecture seule)
reste basée sur `useVersioning().isReadonly` (root uniquement) — hors scope T78.

### Bouton "Publier"

Supprimé. Le placeholder désactivé actuel (`T30-E`, sans action) n'a pas de sens dans un
panneau multi-repo où l'on ne sait pas a priori à quel repo il s'appliquerait. Sera
réintroduit par T83 avec une vraie logique par repo (workflow "faire une modification" /
"Publier").

## Hors scope

- Toute logique de "Publier"/merge automatique vers une branche d'intégration (T83, T84)
- Écriture du pin dans `polenta-repo.yaml` du parent lors d'un checkout de composant (T82)
- Renommage de la nomenclature de branches `prj-`/`tck-` → `int-`/`dev-` (T81) — le
  panneau réutilise `BranchInfo.type` tel quel
- Filtrage/masquage des repos "à jour" dans l'arbre — tous les repos du workspace sont
  toujours listés
- Adaptation de `version-diff.tsx` pour suivre le repo sélectionné dans l'arbre (T80)
- Baseline multi-composant (T79)

## Critères d'acceptation

1. Le panneau Version liste tous les repos du workspace (root + composants + interfaces),
   même ensemble que l'onglet Structure (`useWorkspaceStructure`)
2. Chaque dossier fermé affiche sa réf courante et un badge dirty si applicable, sans
   nécessiter de l'ouvrir
3. Ouvrir un dossier affiche le stage/modifications et le combobox de checkout scopés
   uniquement sur ce repo — les actions (stage/unstage/discard/commit/checkout/créer ou
   supprimer une branche) n'affectent que ce repo
4. Deux dossiers différents peuvent être ouverts en même temps sans interférence d'état
   (ex. une modale de commit ouverte sur l'un n'affecte pas l'autre)
5. Tous les dossiers sont ouverts par défaut, root sélectionné, au premier affichage du
   panneau
6. Fermer le panneau Version (changer d'onglet sidebar) arrête le polling de statut git
   par repo (pas de requête `sync:status` résiduelle pour les composants)
7. Le bouton "Publier" n'apparaît plus dans le panneau
8. Aucune régression sur les fonctionnalités déjà présentes pour le repo root (Committer,
   stage/unstage/discard, checkout avec confirmation si modifications en attente, création/
   suppression de branche)
