# T80 — La page de diff suit le repo sélectionné dans l'arbre Version

## Contexte

`version-diff.tsx` (page "Comparer deux versions") ne connaît aujourd'hui que le repo
root du workspace (`api.workspace.resolve(projectId).localPath`) : les refs comparées
(Objet A / Objet B) viennent toujours de `api.sync.resolveRefs(rootRepoPath)`, quel que
soit le composant qu'on souhaiterait comparer.

Depuis T78, le panneau latéral Version (`VersionPanel.tsx` / `VersionRepoFolder.tsx`)
affiche un arbre multi-repo (root + composants + interfaces), mais **sans notion de
sélection** : cliquer sur une ligne de repo ouvre/ferme uniquement son dossier
(`open`/`setOpen` local à chaque `VersionRepoFolder`). Seul le root reçoit une mise en
évidence visuelle statique (`isRoot`), indépendante de toute interaction utilisateur.
T78 a explicitement laissé à T80 le soin de définir ce mécanisme de sélection
(cf. `T78-design.md` décision 4).

T80 introduit donc la sélection réelle d'un repo dans l'arbre Version, et fait de ce
repo sélectionné une troisième dimension de comparaison sur `version-diff.tsx`, aux
côtés des deux refs déjà comparées.

## Décisions issues du cadrage humain

- **Sélection = clic sur la ligne existant.** Pas de nouvelle affordance (pastille,
  radio…) : le même clic qui bascule aujourd'hui l'ouverture/fermeture d'un dossier
  sélectionne également ce repo. Un seul geste, aucun nouvel élément visuel introduit
  dans l'arbre au-delà de la mise en évidence de la ligne sélectionnée.
- **Suivi en direct.** Le panneau Version (sidebar) et la page `/version-diff`
  (contenu principal) peuvent être visibles simultanément. Le repo sélectionné est un
  état partagé entre les deux : si l'utilisateur change la sélection dans l'arbre
  pendant que `/version-diff` est affichée, la page se met à jour immédiatement, sans
  reclic sur l'icône "Comparer" ni rechargement de page.

## Description fonctionnelle

### Sélection dans l'arbre Version

- Chaque `VersionRepoFolder` devient sélectionnable : cliquer sur sa ligne sélectionne
  ce repo (en plus de basculer `open`, comportement actuel inchangé).
- Un seul repo est sélectionné à la fois dans tout l'arbre (sélection exclusive, pas de
  multi-sélection).
- Fermer un dossier sélectionné ne le désélectionne pas — la ligne fermée reste mise en
  évidence, avec sa vignette checkout (réf courante) déjà affichée aujourd'hui pour les
  dossiers fermés.
- Au premier affichage du panneau Version (ouverture du projet), le repo root est
  sélectionné par défaut — reformulation, en sélection réelle, du comportement déjà
  acquis en T78 ("root mis en évidence par défaut").
- La mise en évidence visuelle actuelle du root (`isRoot`, texte bleu) est remplacée par
  la mise en évidence de sélection, appliquée au nœud sélectionné quel qu'il soit (le
  root reste visuellement mis en évidence tant qu'il reste le repo sélectionné, par
  simple effet du défaut).

### État partagé "repo sélectionné"

- Le repo sélectionné est un état partagé entre le panneau Version et la page
  `/version-diff`, tous deux montés sous la mise en page applicative commune
  (`AppLayout.tsx`), sur le modèle des contextes déjà en place pour ce périmètre
  (`VersioningProvider`, `SystemViewProvider`).
- Portée : le temps de vie du projet ouvert. Pas de persistance disque/`localStorage` —
  à la réouverture du projet ou au redémarrage de l'app, la sélection retombe sur le
  root par défaut (même règle que T78 pour l'état d'ouverture des dossiers).
- Pour un lien direct ou un rechargement de `/version-diff` (ex. F5 en dev, ou lien
  partagé), l'URL porte un paramètre `repoPath` reflétant le repo ciblé, sur le modèle
  des paramètres `ref1`/`sha1`/`ref2`/`sha2` déjà présents. En l'absence de ce
  paramètre (ou d'état partagé déjà initialisé), la page retombe sur le repo root.

### Page `/version-diff`

- Les combobox Objet A / Objet B sont alimentés par `api.sync.resolveRefs(repoPath)` du
  **repo sélectionné**, plus uniquement du root.
- La page affiche le nom du repo actuellement ciblé (ex. dans l'en-tête "Comparer"),
  pour que l'utilisateur sache sans ambiguïté sur quel repo portent les refs listées —
  cette information était jusqu'ici implicite (toujours le root) et cesse de l'être.
- **Changer de repo sélectionné réinitialise Objet A, Objet B et le fichier
  sélectionné** (une branche/tag/commit d'un repo n'a aucune raison d'exister dans un
  autre) — que ce changement ait lieu avant d'entrer sur `/version-diff` (nouvelle
  navigation) ou pendant que la page est déjà affichée (suivi en direct).
- L'icône "Comparer" (`GitCompare`) du header de `VersionPanel` navigue vers
  `/version-diff` en conservant le comportement de réinitialisation des refs déjà
  existant (`ref1`/`sha1`/`ref2`/`sha2` à `undefined`), désormais scopé sur le repo
  sélectionné au moment du clic.

## Hors scope

- Comparer simultanément plusieurs repos, ou des refs appartenant à deux repos
  différents sur une même page — un seul repo actif à la fois sur `/version-diff`.
- Persistance de la sélection au-delà de la session du projet ouvert (redémarrage app).
- Filtrage/masquage de repos dans l'arbre Version (déjà hors scope T78).
- Toute évolution de la page `/diff` (diff d'un seul fichier stagé/modifié, ouverte
  depuis les sections Stagés/Modifications de l'arbre) — cette page cible déjà
  implicitement le bon repo via `filepath`/`projectId` actuels et n'est pas concernée.
- Baseline multi-composant (T79), écriture de pin (T82), workflow Publier (T83/T84/T85).

## Critères d'acceptation

1. Cliquer sur la ligne d'un repo dans l'arbre Version le sélectionne (mise en
   évidence visuelle) sans changer le comportement d'ouverture/fermeture existant.
2. Un seul repo est mis en évidence comme sélectionné à la fois dans l'arbre.
3. Au premier affichage du panneau Version, le root est sélectionné par défaut.
4. Fermer le dossier du repo sélectionné ne change pas la sélection.
5. Cliquer sur l'icône "Comparer" ouvre `/version-diff` avec les combobox Objet A/B
   alimentés par les refs du repo sélectionné au moment du clic (pas toujours le root).
6. `/version-diff` affiche visiblement le nom du repo ciblé.
7. Si `/version-diff` est déjà affichée et que l'utilisateur sélectionne un autre repo
   dans l'arbre Version (toujours visible en sidebar), la page se met à jour sans
   reclic ni rechargement : nouvelles refs listées, Objet A/B et fichier sélectionné
   réinitialisés.
8. Changer la sélection de repo avant d'ouvrir `/version-diff` a le même effet de
   réinitialisation que d'en changer pendant que la page est déjà ouverte.
9. Un lien vers `/version-diff` avec un paramètre d'URL `repoPath` valide ouvre la page
   scopée sur ce repo ; en son absence, retombe sur le repo root.
10. Aucune régression sur le comportement de comparaison existant pour le repo root
    (cas mono-repo actuel).
