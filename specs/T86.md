# T86 — Suppression Tableau de bord/Droits de la vue Projet ; déplacement du sélecteur de branche d'intégration et ajout d'un sélecteur de branche par repo dans l'arbre Structure

## Contexte

Le panneau latéral "Projet" (`ProjectPanel.tsx`) liste aujourd'hui trois entrées : "Tableau de bord" (route `/project/$id`), "Modèle de données" (route `/schema`), et "Droits" (stub désactivé, `(bientôt)`, sans route ni implémentation).

Depuis T77 (dashboards personnalisables), le "Tableau de bord" ne contient plus que deux éléments (cf. commentaire `project.$id.tsx:154-158`) :
- `IntBranchSelector` — un widget libellé **"Baseline"** dans l'UI, qui ne gère en réalité pas de baseline (snapshot git tag, cf. `SPEC-FORKS-BRANCHES-BASELINES.md` §5) mais la **branche d'intégration** du repo (`int-*`, lue/écrite via `api.baseline.getIntegrationBranch`/`setIntegrationBranch`, qui persistent `integrationBranch` dans `config/project.yaml`). Le vrai mécanisme de baseline (tags, snapshot, comparaison) vit ailleurs, route `/baseline`, accessible depuis le panneau Version — il n'est pas concerné par ce ticket.
- `SyncBar` — barre fixe en bas de page (fichiers modifiés / push) pour le repo root uniquement, redondante avec le commit/push par repo déjà disponible dans le panneau latéral Version (`VersionRepoFolder.tsx`, qui couvre déjà le root et tous les composants).

Par ailleurs, l'arbre "Structure" du Modèle de données (`StructureTab.tsx`, `RepoRow`) affiche déjà, pour chaque repo non-root, un `pin` (SHA/branche tronqué) et un bouton crayon "Modifier" qui ouvre `AddDependencyModal` — dont le champ "Branche" est un **texte libre** (`AddDependencyModal.tsx:99-102`, pas de liste réelle des branches du repo). Le repo root, lui, n'a aucun affichage/contrôle de branche dans cet arbre (contrairement au panneau Version, où `VersionRepoFolder` — la même structure d'arbre — affiche déjà un vrai sélecteur de branches/tags avec checkout réel, `BranchCombobox`, pour le root comme pour chaque composant).

## Décision

1. **Suppression** des entrées "Tableau de bord" et "Droits" du panneau `ProjectPanel.tsx`, de la route `/project/$id` (`project.$id.tsx`), et du composant `SyncBar.tsx` (plus aucun appelant après suppression de la route — pas de reprise fonctionnelle ailleurs, cf. accord explicite : redondant avec le panneau Version).
2. **Déplacement** du sélecteur de branche d'intégration (actuellement `IntBranchSelector`) dans `StructureTab.tsx`, affiché à côté du nom du repo **root** de l'arbre (la racine du workspace, nœud sans `parentRepoPath`). Le libellé "Baseline" est corrigé en "Branche d'intégration" (le comportement — choix/création d'une branche `int-*`, bouton "Définir comme branche d'intégration", bandeau lecture-seule — reste inchangé).
3. **Ajout**, pour **chaque repo** de l'arbre Structure (root et composants/interfaces), d'un sélecteur de branche inline affiché à droite du nom du repo, permettant un vrai checkout et une vraie création de branche (même mécanisme que `BranchCombobox` + `api.sync.branches`/`api.sync.checkoutBranch`/`api.sync.createBranch` déjà utilisés par `VersionRepoFolder.tsx`). Pour un repo non-root, le checkout via ce sélecteur écrit le même pin que la modale "Modifier" existante (`AddDependencyModal`) — c'est un raccourci vers la même donnée, pas un mécanisme parallèle.
4. Ce sélecteur respecte la sémantique de branches déjà en vigueur (`SPEC-FORKS-BRANCHES-BASELINES.md` §2.2, §3) :
   - Branche courante `int-*` : lecture seule dans l'UI (cohérent avec `VersioningContext.isReadonly`) — le sélecteur reste utilisable pour *choisir* une autre branche d'intégration existante, mais pas pour éditer le contenu du repo dessus.
   - Branche courante `dev-*` (modification en cours, workflow T83) : le sélecteur **n'autorise ni checkout ni création** de branche — il affiche uniquement le nom de la branche `dev-*` courante, en lecture seule. Changer de branche pendant une modification passe exclusivement par "Publier"/"Annuler" (déjà implémenté ailleurs, T83), jamais par ce sélecteur.

## Hors scope

- Le vrai mécanisme de baseline (git tag, `baseline.service.ts`, route `/baseline`) : aucun changement.
- Le module Dashboards personnalisables ("Suivi", T77) : aucun changement.
- L'implémentation de l'onglet "Droits" (permissions) : reste non implémenté, seule l'entrée de menu stub disparaît. Un futur ticket pourra le réintroduire ailleurs si besoin.
- Le bouton "Faire une modification" / "Publier" / "Annuler" (T83) : comportement inchangé, seulement référencé pour la règle de désactivation ci-dessus.
- Toute modification du format de `polenta-repo.yaml` ou de `config/project.yaml`.

## Comportement attendu

1. **Panneau latéral Projet** : n'affiche plus que "Modèle de données". Plus d'entrée "Tableau de bord" ni "Droits".
2. **Route `/project/$id`** : supprimée. Toute navigation résiduelle vers cette route (ex. lien profond, `handleDiamondCancel` dans `StructureTab.tsx:809` qui y navigue aujourd'hui en cas d'annulation de conflit diamant) est redirigée vers une route existante pertinente (`/schema`).
3. **Arbre Structure, ligne du repo root** : affiche à droite du nom un sélecteur de branche générique (checkout/création réelle) **et** le widget "Branche d'intégration" (renommé), tous deux à droite du nom, dans cet ordre visuel à définir en Design.
4. **Arbre Structure, ligne d'un composant/interface** : affiche à droite du nom le même sélecteur de branche générique que le root (pas de widget "Branche d'intégration" par repo — celui-ci reste uniquement sur le root, comme demandé).
5. **Repo sur une branche `int-*`** : le sélecteur de branche générique permet de changer de branche `int-*` (choix dans la liste), mais le repo reste en lecture seule pour l'édition de contenu (comportement déjà existant, inchangé).
6. **Repo sur une branche `dev-*`** : le sélecteur de branche générique est désactivé (pas de checkout, pas de création), affiche uniquement le nom de la branche `dev-*` courante.
7. **Modale "Modifier" (`AddDependencyModal`)** : le champ "Branche" existant est conservé tel quel (texte libre, pour déclarer un pin sans forcément checkouter) — le nouveau sélecteur inline est un raccourci additionnel, pas un remplacement de cette modale.

## Critères d'acceptation

- [ ] "Tableau de bord" et "Droits" ont disparu de `ProjectPanel.tsx`
- [ ] La route `/project/$id` et le composant `SyncBar.tsx` sont supprimés (plus aucune référence dans le code)
- [ ] Le widget de branche d'intégration (renommé "Branche d'intégration") est fonctionnel à côté du repo root dans l'arbre Structure, avec le même comportement qu'avant (choix/création `int-*`, désignation comme branche d'intégration, bandeau lecture-seule)
- [ ] Chaque ligne de repo (root + composants + interfaces) dans l'arbre Structure a un sélecteur de branche à droite du nom, avec checkout et création réels
- [ ] Sur une branche `dev-*`, ce sélecteur est en lecture seule (pas d'interaction de checkout/création possible)
- [ ] Un checkout via ce sélecteur sur un composant met à jour le même pin que la modale "Modifier" (pas de double source de vérité)
- [ ] Aucune régression sur le flux "Publier"/"Annuler" (T83) ni sur le mécanisme de baseline réel (route `/baseline`)
- [ ] Zéro référence résiduelle à `/project/$id` dans le code (navigation, tests, routeTree généré)
