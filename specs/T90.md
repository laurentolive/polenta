# T90 — bug vue Word : champs dupliqués, version absente, labels FR/EN mélangés

## Root cause

Trois bugs distincts dans la vue Document (Word) et son panneau "Champs visibles" (`⚙`), partagé avec la vue Tableau (Excel) :

1. **Duplication titre/corps** — `ItemCard` (`WordView.tsx`) affiche déjà `section`, `id`, `status` et `version` dans l'en-tête de la carte (ligne ~420-456), indépendamment de `visibleFields`. Mais le corps de la carte (`fields.map`, ligne ~485) ne filtrait que le champ `name` avant affichage — pas `section`/`id`/`status`/`version`. Résultat : ces champs, quand cochés dans "Champs visibles", s'affichaient une seconde fois dans le corps, en doublon avec le titre. Et comme le titre les affiche de toute façon, cocher/décocher leur case dans le panneau n'avait aucun effet perceptible sur l'essentiel de l'affichage (seul le doublon apparaissait/disparaissait) — d'où l'impression que "cocher/décocher ne fait rien".

2. **`version` absent du panneau** — `FieldConfigModal` (`SystemView.tsx`) construit la liste `allFields` à partir de `systemFields = ['section', 'name', 'id', 'status', 'createdAt', 'author']` : `version` n'y figurait pas, ni dans `systemFieldLabels`. Impossible de le cocher/décocher pour la vue Tableau (où il est pertinent, à la différence de la vue Word).

3. **Labels FR/EN mélangés** — dans la liste du panneau, chaque champ affichait `systemFieldLabels[f] ?? f` : pour les champs système, le libellé français codé en dur (`Section`, `Statut`, `Auteur`…) ; pour les champs custom (définis dans `schema.yaml`), aucun lookup vers `typeDef.fields[].label` — juste le nom technique brut du champ (`priority`, `statement`, `acceptanceCriteria`…, généralement en anglais). D'où le mélange.

## Correctif appliqué

- `apps/desktop/src/renderer/components/system/WordView.tsx` (`ItemCard`) : `fields` exclut désormais aussi `section`, `id`, `status`, `version` (en plus de `name`) — ces champs restent uniquement dans l'en-tête de la carte, jamais dupliqués dans le corps, quel que soit l'état de la case dans "Champs visibles".
- `apps/desktop/src/renderer/components/system/SystemView.tsx` (`FieldConfigModal`) :
  - `version` ajouté à `systemFields` et `systemFieldLabels` (label `Version`) — apparaît maintenant dans le panneau, cochable indépendamment pour la vue Tableau.
  - Le label affiché pour un champ custom retombe désormais sur `typeDef.fields.find(...).label` avant de retomber sur le nom technique brut (`systemFieldLabels[f] ?? typeDef?.fields.find(cf => cf.name === f)?.label ?? f`).

Aucun changement de `defaultFields` / valeurs initiales : `version` n'était déjà pas dans les défauts (`['section', 'name', 'id', 'status', ...]`), ce qui reste cohérent avec le point 1 (pas besoin de le cocher par défaut en vue Word puisqu'il est toujours visible dans le titre).

## Complément (retour de test manuel)

Après le premier correctif, `section`/`id`/`status`/`version` ne s'affichaient plus en double dans le corps de la carte (comportement voulu), mais restaient proposés dans "Champs visibles" pour l'onglet Document — où cocher/décocher n'avait alors plus aucun effet puisque `ItemCard` les exclut désormais inconditionnellement du corps. Des cases à cocher sans effet observable sont pires qu'utiles.

Correctif complémentaire : dans `FieldConfigModal` (`SystemView.tsx`), la liste `allFields` masque maintenant `section`/`name`/`id`/`status`/`version` quand l'onglet actif est **Document** (ils restent proposés normalement dans l'onglet **Tableau**, où ce sont de vraies colonnes optionnelles). Le panneau ne montre donc plus, pour la vue Word, que les champs qui ont réellement un effet quand on les coche/décoche.

## Comment vérifier

1. Ouvrir un type d'objet avec des exigences en vue Document (Word).
2. Ouvrir "Champs visibles" (⚙), onglet **Document** : `Section`/`Label`/`ID`/`Statut`/`Version` ne doivent plus apparaître dans la liste (ils sont toujours dans le titre de la carte, non paramétrables ici) ; les champs custom gardent un libellé cohérent (celui du schéma, pas le nom technique).
3. Cocher un champ custom (ex. `priority`) : il doit apparaître dans le corps avec sa vraie valeur, sans affecter les autres cartes.
4. Basculer sur l'onglet **Tableau** du même panneau : `Section`/`ID`/`Statut`/`Version`/`Label` réapparaissent normalement dans la liste et restent cochables/décochables pour ajouter/retirer la colonne correspondante (comportement inchangé, contrairement à la vue Word).
