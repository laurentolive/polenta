# T96 — Page Préférences dédiée dans le panneau latéral

## Contexte

T94 avait mis `autoPropagatePin` dans un onglet de la page `/schema`. T95 l'avait déplacé en case
inline dans le panneau latéral, sous le lien « Modèle de données ». Retour utilisateur : il faut
plutôt une **page dédiée** `/preferences`, chargeable depuis son propre item de panneau latéral
(au même niveau que « Modèle de données »), pas une case inline dans la liste. Cette page n'affiche
qu'une option pour l'instant, mais est structurée pour en accueillir d'autres plus tard.

## Description fonctionnelle

- Nouvelle route `/preferences` (`apps/desktop/src/renderer/routes/preferences.tsx`), même squelette
  que la page Modèle de données (`ViewHeader`, dirty state, Enregistrer/Annuler, Échap/Entrée) mais
  sans onglets — un seul formulaire, `EditorState` prête à recevoir d'autres champs.
- Nouvel item « Préférences » dans le panneau latéral Projet (`ProjectPanel.tsx`), juste sous
  « Modèle de données », menant à `/preferences?repoPath=…&projectId=…`.
- `ProjectPanel.tsx` redevient un simple panneau de liens (retrait de la case à cocher inline
  ajoutée en T95, retrait de `useProjectSchema`/mutation qui n'ont plus leur place ici).
- `schema.yaml` du repo reste la source de vérité (`ProjectSchema.preferences`, inchangé depuis
  T94) — cette page en est juste un point d'édition alternatif à `/schema`.

## Comportements attendus

1. Panneau latéral Projet : lien « Préférences » visible sous « Modèle de données ».
2. Page `/preferences` : case `autoPropagatePin` reflète l'état courant du schéma, décochée par
   défaut si absente.
3. Modifier puis Enregistrer écrit dans `.polenta/schema.yaml` sans toucher au reste du schéma
   (nodes, linkTypes, roles, implements inchangés).
4. Annuler (Échap / bouton) restaure l'état sauvegardé.
5. La page `/schema` (Structure/Liens/Interfaces) ne référence plus `preferences` en édition —
   elle le passe tel quel lors d'un save (déjà le cas depuis T95, inchangé ici).

## Notes techniques

`routeTree.gen.ts` est normalement régénéré par le plugin `@tanstack/router-vite-plugin` au build.
Dans cet environnement, `electron-vite build` échoue à régénérer ce fichier (bug de résolution de
chemin du plugin avec la config `root: './src/renderer'` d'electron-vite — double `src/renderer/src/renderer/routes`,
sans rapport avec ce ticket) ; le fichier a donc été mis à jour à la main pour la nouvelle route
`/preferences`, en suivant exactement le motif mécanique des routes existantes (import, `.update()`,
entrées dans les interfaces `FileRoutesBy*`/`FileRouteTypes`/`RootRouteChildren`, `declare module`,
`rootRouteChildren`). `npm run typecheck` valide la cohérence du résultat. À régénérer proprement
la prochaine fois que quelqu'un lance l'app en dev sur une machine où le bug ne se reproduit pas,
ou à investiguer séparément si le bug est reproductible en dev normal.
