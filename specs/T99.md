# T99 — bug : impossible de supprimer un test d'une campagne

## Root cause

La suppression d'un test d'une campagne n'a jamais été implémentée : seule l'ajout
(`addTests`) existait, de bout en bout (service, IPC, client API, UI). Aucun bouton de
retrait par ligne de test n'était présent dans `campaign.$campaignId.tsx`.

## Correctif appliqué

- `apps/desktop/src/main/services/campaigns.service.ts` : ajout de
  `removeEntries(repoPath, campaignId, entryIds)` — retire les entrées `runs` ciblées par
  `entryId`, et une seule occurrence du `testCaseId` correspondant dans `testCaseIds` par
  entrée retirée (même garde-fou que `addTests` : refus si la campagne est
  `completed`/`abandoned`).
- `apps/desktop/src/main/ipc/index.ts` : handler `campaigns:remove-entries`.
- `packages/api-client/src/types.ts` et `ipc-client.ts` : méthode `campaigns.removeEntries`.
- `apps/desktop/src/renderer/routes/campaign.$campaignId.tsx` : bouton (icône corbeille)
  sur chaque ligne de test de la liste, visible tant que la campagne est active
  (`planned`/`in_progress`), appelant `removeEntries` avec l'`entryId` de la ligne et
  invalidation des queries `campaign` et `campaigns`.

### Note de réconciliation avec T97 sprint 2

Le développement de ce correctif a chevauché le merge de la branche `T97` (paramètres de
test en campagne) dans `master`, qui a introduit `entryId` — une même campagne peut
désormais inclure plusieurs fois le même test (instances paramétrées différentes). Le
correctif a donc été conçu directement sur ce modèle (retrait par `entryId`, pas par
`testCaseId`) plutôt que par `testCaseId` seul, pour ne retirer que l'instance ciblée par
le clic et laisser intactes les autres instances du même test dans la campagne.

## Comment vérifier

1. Créer/ouvrir une campagne au statut `planned` ou `in_progress`.
2. Ajouter un test via « + Ajouter des tests ».
3. Cliquer sur l'icône corbeille de la ligne du test ajouté → le test disparaît de la
   liste (et de `campaigns/{id}.yaml` : `testCaseIds` et `runs`).
4. Pour un test paramétré dupliqué (T97 sprint 2) : vérifier que retirer une instance
   laisse les autres instances du même test intactes (statut, `paramValues`).
5. Vérifier qu'aucune suppression n'est proposée si la campagne est `completed` ou
   `abandoned` (bouton absent car `isActive` est faux).
